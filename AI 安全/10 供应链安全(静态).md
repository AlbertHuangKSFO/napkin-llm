[[10 供应链安全(静态)|供应链安全(静态)]]说的是:你的模型还没运行,毒就已经埋进来了——风险在你**拉取一个预训练模型、一个数据集、一个依赖**的那一刻就已确定。这是 OWASP LLM Top 10 里的 **LLM03**,治理对象是三类静态资产:**模型权重、训练/微调数据、软件依赖**。它与 [[09 数据与模型投毒|数据投毒]] 是上下游关系(投毒是把毒注进数据/模型,本篇管的是这些被投毒资产如何顺着供应链流进你的系统);与运行时的 [[20 Agentic 供应链与 MCP 安全|Agentic 供应链]] 互补——后者管 agent 跑起来后动态拉工具/MCP server 的风险,本篇只管静态制品。

## 攻击面:三类静态资产
- **被污染的预训练模型**:HuggingFace 等模型库上传几乎无门槛(百万级模型,极少经安全审核),攻击者可上传**带后门的权重**或用**仿冒账号/抢注名**(typosquatting)伪装成知名模型。下游一旦 `from_pretrained` 即引入。
- **不安全反序列化(本篇核心技术风险)**:PyTorch 默认的 `torch.save`/`torch.load` 底层用 Python **pickle**。pickle 可序列化任意 Python 对象,反序列化(unpickle)时会**执行其中嵌入的代码**——所以"加载一个不可信模型 = 在你机器上执行任意代码",可被用于窃取密钥、装后门、横向移动。这不是漏洞而是 pickle 的设计本性。
- **恶意数据集**:投毒样本或带触发器的样本混进训练/微调数据,使下游模型被植入后门(详见 [[09 数据与模型投毒|数据投毒]])。
- **依赖风险**:`transformers`、`torch` 及其传递依赖,或 PyPI 上被投毒/抢注的包,等同传统软件供应链攻击(SolarWinds 式),只是落在 ML 栈上。

## 脆弱代码 vs 缓解代码
脆弱:用 pickle 后端加载不可信权重 = 把控制权交给文件作者。
```python
# ❌ 脆弱:torch.load 默认走 pickle,加载即可任意代码执行
import torch
model = torch.load("downloaded_model.pt")        # 不可信来源 → RCE
# from_pretrained 加载 .bin (pickle) 时同理有风险
```
缓解:换 **safetensors** 格式——它**只存数值张量 + 元数据,没有执行任意代码的能力**(还顺带快很多,加载 BERT 可达约 3x);并校验来源。
```python
# ✅ 缓解:safetensors 只反序列化张量,无代码执行路径
from safetensors.torch import load_file
state_dict = load_file("model.safetensors")      # 安全:不会执行嵌入代码
model.load_state_dict(state_dict)

# 若必须用 .pt:PyTorch 2.6 起 torch.load 默认 weights_only=True(只反序列化张量)
model = torch.load("model.pt", weights_only=True) # 退路,仍不如 safetensors
```

## 对比表
| 维度 | pickle (.pt/.bin) | safetensors |
|---|---|---|
| 能存什么 | 任意 Python 对象(含可执行代码) | 仅张量 + 元数据 |
| 加载风险 | 反序列化即可 RCE | 无代码执行路径 |
| 加载速度 | 慢 | 快(可达约 3x) |
| 何时仍出现 | 老模型、含自定义对象的 checkpoint | HuggingFace 已大面积默认 |

## 防御:溯源 + 完整性 + 准入
- **safetensors 优先**:能换格式就换;必须用 pickle 时上 `picklescan`/`weights_only=True`,且只信任来源。
- **模型签名(Sigstore)**:OpenSSF 联合 Google、NVIDIA、HiddenLayer 推出 **OMS(OpenSSF Model Signing)** 规范并发布 model-signing v1.0,把模型**密码学签名并绑定作者身份**,所有签名事件进 **Sigstore 透明日志**,形成可审计、防仿冒账号的来源链。
- **AIBOM(AI Bill of Materials)**:像 SBOM 之于软件——一份标准化、可审计的清单,列出系统用到的**模型、数据集、训练流程、软件依赖及其来源/血统**,是事件响应和合规追溯的底座。
- **依赖治理**:锁版本 + 哈希校验 + 漏洞扫描;制品入私有仓库,禁止生产环境直连公网模型库。
- **准入门禁**:新模型/数据集进库前过扫描与人审闸门(见 [[24 沙箱、最小权限与人审闸门|人审闸门]]),失陷后靠 [[25 监控、可观测与事件响应|事件响应]] 兜底。

## 工业界实践

AI 静态供应链的工业界打法,本质是把成熟的**软件供应链治理(SBOM/签名/私有仓库/扫描)** 平移到 ML 制品(模型权重 + 数据集 + 依赖)上,再补 pickle 这一 ML 特有的 RCE 面。

**真实事件 / 案例:**

- **HuggingFace 恶意 pickle 模型(JFrog 2024 调查)**:JFrog 在 HuggingFace 上发现**约 100 个**含恶意 payload 的模型,加载即反弹 shell / 建立 C2 连接——印证「加载不可信 `.pt`/`.bin` = RCE」非理论。
- **picklescan 绕过(2025)**:研究者发现 picklescan 的黑名单可被绕过(用未覆盖的危险 opcode / 模块),说明**扫描器不是万能**,safetensors 换格式才是治本。
- **typosquatting / 仿冒账号**:攻击者抢注与知名模型相近的名字或冒充官方组织上传带后门权重,下游 `from_pretrained` 即中招。

**主流工具 / 防护能力:**

- **safetensors(Hugging Face)**:只存张量 + 元数据,**无代码执行路径**,加载更快(BERT 约 3x);HF 已大面积默认。**首选**。
- **picklescan / ModelScan(Protect AI)/ Fickling(Trail of Bits)**:必须用 pickle 时静态扫危险 opcode,但有绕过风险,仅作辅助。
- **模型签名**:**OpenSSF model-signing v1.0**(2025,OpenSSF + Google + NVIDIA + HiddenLayer 的 OMS 规范),用 **Sigstore** 给模型签名并绑定作者身份,签名进透明日志;能处理模型「目录树」级别的大体量制品。
- **AIBOM / ML-BOM**:**OWASP CycloneDX**(v1.7,2025-10)支持 **ML-BOM/AI-BOM**,列出模型、数据集、训练流程、依赖及来源血统;`cdxgen` 可自动生成。是事件响应与合规追溯底座。
- **私有制品仓库**:JFrog Artifactory / 私有 HF Hub 镜像,**禁止生产直连公网模型库**,制品先入私仓过扫描。

**纵深防御架构:** 拉取侧(safetensors 优先 + 来源白名单 + 哈希/签名校验)→ 扫描侧(picklescan/ModelScan + 漏洞扫描)→ 准入侧(人审闸门 + AIBOM 登记)→ 仓库侧(私有仓 + 禁直连公网)→ 运行侧([[25 监控、可观测与事件响应|监控]] 兜底)。

**最佳实践规则片段:**

```python
# 模型准入门禁:格式优先 + 签名/哈希校验 + 扫描
def admit_model(path, manifest):
    if not path.endswith(".safetensors"):
        scan = modelscan.scan(path)               # pickle 必须扫(仍可能被绕)
        if not scan.clean: reject("pickle_threat")
    if not sigstore.verify(path, manifest.signer): # OMS/Sigstore 签名校验
        reject("signature_invalid")
    if sha256(path) != manifest.hash:              # 完整性
        reject("hash_mismatch")
    aibom.register(path, manifest)                 # 登记进 AIBOM,可追溯
```

## 面试高频

**攻击原理 + 缓解 + 为何不彻底:** 风险在「拉取一个模型/数据集/依赖」的那一刻就已确定;pickle 反序列化即可 RCE,带后门权重/仿冒账号顺供应链流入。缓解靠 safetensors + 签名 + 完整性 + 私仓准入。**不彻底**:扫描器有绕过(picklescan)、签名生态未全覆盖、依赖传递链深、数据集后门不在格式层(safetensors 防不了「张量本身被投毒」)。

- **Q:为什么 `torch.load` 一个不可信模型 = 任意代码执行?**
  A:`torch.save`/`torch.load` 底层用 Python **pickle**,pickle 可序列化任意对象,**反序列化(unpickle)时会执行其中嵌入的代码**(`__reduce__`)。所以加载不可信文件 = 在你机器上跑作者的代码。**这是 pickle 的设计本性,不是某个 bug。**
  *追问:怎么防?* 换 **safetensors**(只存张量,无代码路径);必须用 .pt 则 **PyTorch 2.6 起 `weights_only=True` 默认**(只反序列化张量)+ picklescan,且只信任来源。
  *陷阱:* 「`weights_only=True` 就绝对安全」要谨慎——它大幅降风险但历史上有过绕过研究;safetensors 仍是更彻底的解。

- **Q:safetensors 为什么安全?它能防住所有供应链投毒吗?**
  A:safetensors **只反序列化数值张量 + 元数据,没有执行代码的路径**,所以杜绝「加载即 RCE」。但**防不了「张量本身被投毒/植入后门」**——那是 [[09 数据与模型投毒|数据投毒]] 的范畴,要靠行为评估/红队,不是格式能解决的。格式安全 ≠ 模型行为安全。

- **Q:本篇供应链(静态)和 Agentic 供应链(动态)什么区别?**
  A:本篇管**静态制品**——拉取时就确定的模型权重/数据集/依赖;[[20 Agentic 供应链与 MCP 安全|Agentic 供应链]] 管 **agent 运行时动态拉取的工具/MCP server**。一个是「造模型时引入的毒」,一个是「跑起来后动态接入的不可信工具」。

- **Q:AIBOM 是什么,解决什么问题?**
  A:AI Bill of Materials,像 SBOM 之于软件——一份标准化、可审计的清单,列出系统用到的模型、数据集、训练流程、依赖及其来源/血统。解决「出事时不知道用了什么、来自哪」的追溯问题,是事件响应与合规底座(CycloneDX ML-BOM 已标准化)。
