[[01 AI 安全总览与三层栈|AI 安全]]的本质,是一句反直觉的论断:**到 2026 年,AI 安全不再是「给模型加个过滤器」,而是一套分三层的栈——模型层、Agent 层、协议层——每层各对应一套独立的 OWASP 框架,且任一层的漏洞会沿栈向下级联放大**。这篇是本域的枢纽:它把后面 25 篇按「哪一层、哪个威胁」归位。

## 三层栈:每层一套 OWASP 框架

![[sec-三层安全栈.png]]

把一个真实的 AI 系统从底层调用到上层自治拆开,恰好分三层,而 OWASP 也确实分别立了三套框架:

- **① 模型层(Model)**:一次孤立的 LLM 调用。攻击面是 prompt、输出、权重、训练数据。对应 **OWASP LLM Top 10 v2(2025 版)**,由 OWASP GenAI Security Project 维护。覆盖 [[05 Prompt Injection 提示注入|提示注入]]、[[07 敏感信息泄露与 System Prompt 泄露|信息泄露]]、[[08 不安全输出处理|输出处理]]、[[09 数据与模型投毒|投毒]]、[[11 向量与嵌入弱点与 RAG 投毒|向量嵌入弱点]]、[[12 Unbounded Consumption 成本型 DoS|无界消耗]] 等。
- **② Agent 层(Agentic)**:模型进入自主循环——会规划、调工具、读写记忆、与其他 agent 协作。对应 **OWASP Agentic Security Initiative(ASI)Top 10**,2025-12-09 发布,集 100+ 安全专家、经 NIST / 欧盟委员会 / 图灵研究所组成的专家评审委员会评议,并被微软的 agentic 失败模式文档、NVIDIA 的 agentic 系统安全框架引用背书。覆盖 [[14 Excessive Agency 与 Goal Hijack|目标劫持]]、[[15 Tool Misuse 与意外代码执行|工具滥用]]、[[16 Agent 身份与权限滥用(非人类身份 NHI)|身份滥用]]、[[17 Memory 与 Context Poisoning|记忆投毒]]、[[18 Agent 间通信安全与级联失败|级联失败]]、[[19 人机信任利用与 Rogue Agents|Rogue Agents]]。
- **③ 协议层(Protocol)**:agent 之间、agent 与工具之间靠协议互联(MCP、A2A)。对应 **OWASP MCP Top 10**(MCP01–10,2025 beta,living document)。覆盖 [[20 Agentic 供应链与 MCP 安全|MCP 与 Agentic 供应链]]——token 失管、工具投毒(tool poisoning)、shadow MCP server、上下文越界共享。

栈越往上,**自主性越强、信任边界越模糊、单点漏洞的现实后果越大**。

## 核心机制:漏洞沿栈级联

三层不是独立的清单,而是一条**放大链**。一个在模型层看起来只是「不安全文本」的东西,沿栈向下会变成现实动作:

> 一段被投毒进检索文档的指令(模型层:间接 [[05 Prompt Injection 提示注入|提示注入]])→ 被 agent 读进 prompt,触发一次工具调用(Agent 层:[[15 Tool Misuse 与意外代码执行|工具滥用]])→ 经 MCP server 调到真实 API,删库或转账(协议层)。

同一个 payload,在模型层只是「字符串」,到 Agent 层就是「一次 API 调用」,到协议层就是「一次跨系统的现实后果」。**这就是为什么不能只在某一层设防——必须 [[21 Guardrails 与输入输出防护|纵深防御 defense-in-depth]]**:输入侧 guardrails、模型对齐、工具层 [[24 沙箱、最小权限与人审闸门|最小权限与沙箱]]、运行时 [[25 监控、可观测与事件响应|监控]],层层冗余。

## 为何传统 AppSec 不够

![[sec-为何传统AppSec不够.png]]

AppSec(认证、网络隔离、参数化查询)仍是地基,但它的三条隐含假设全被 LLM 系统打破:

1. **代码与数据分离 → 自然语言成为新攻击载体**。传统注入靠「转义/参数化」把数据和指令分开;但 LLM 里指令与数据共用一个通道(prompt),**没有「转义」一说**,这是 [[05 Prompt Injection 提示注入|提示注入]] 至今无法被根治、只能缓解的根因。
2. **行为确定可枚举 → 非确定性**。同一 prompt 多次采样输出不同,攻击面无穷,白名单/签名失效,只能上**概率性**防御。
3. **信任边界清晰固定 → 信任边界溶解**。检索文档、工具返回值、agent 间消息都可能夹带指令——「可信通道里藏着不可信内容」,这是 [[02 LLM 攻击面与威胁建模|威胁建模]] 必须重画边界的原因。

## 两根正交的轴:被保护 vs 被武器化

本域不止「怎么保护 AI 系统」一根轴,还有两个容易混淆的关切要先厘清,它们在后续篇里反复出现:

- **[[03 内容安全与对齐边界|Safety(对齐) ≠ Security(对抗)]]**:safety 管「模型自己别说有害的话」,security 管「攻击者别能让模型做坏事」。本域 04–26 主讲 security,03 篇补 safety 半边。
- **[[04 AI 赋能的攻击(Offensive AI)|Offensive AI]]**:另一根轴——AI 当**武器**而非被保护对象(自动化攻击、深伪、slopsquatting)。

整张图的治理与框架收口在 [[26 安全框架与治理地图|安全框架与治理地图]],对抗测试方法见 [[22 AI 红队与对抗测试|AI 红队]]。

## 工业界实践

真实企业不会「自研一套防御」,而是**按三层栈拼装现成组件 + 自家策略**,围绕「纵深防御」组织。下面给一张产品地图与一份参考架构。

### 三层栈对应的工业组件地图

| 栈层 | 该层主流工业产品/框架 | 定位 |
|---|---|---|
| 模型层(输入输出) | **Llama Guard 3**(Meta,内容安全分类器)、**Prompt Guard 2**(Meta,BERT 风格越狱/注入检测)、**NVIDIA NeMo Guardrails**(可编程护栏,用 Colang DSL 写策略)、**AWS Bedrock Guardrails**(托管,含 prompt-attack 过滤、话题控制、PII 脱敏)、**Lakera Guard**(托管 API,主打注入/PII)、**Azure AI Content Safety + XPIA 分类器** | 在模型调用前后挂闸,见 [[21 Guardrails 与输入输出防护|Guardrails]] |
| Agent 层(执行/对齐) | **Meta LlamaFirewall**(开源 agent 护栏框架,三件套:PromptGuard 2 + AlignmentCheck + CodeShield)、**沙箱/最小权限框架**、**人审闸门** | 拦工具滥用、目标劫持,见 [[24 沙箱、最小权限与人审闸门|沙箱与最小权限]] |
| 协议层(MCP/A2A) | MCP server 鉴权与白名单、工具签名校验、shadow-server 检测 | 见 [[20 Agentic 供应链与 MCP 安全|Agentic 供应链与 MCP]] |
| 全栈红队 | **Microsoft PyRIT**(编排式自动红队,含 Crescendo/TAP/Skeleton Key)、**NVIDIA garak**(漏洞扫描,~100 攻击向量)、**Promptfoo**(评测 + 自适应攻击生成) | 攻防演练,见 [[22 AI 红队与对抗测试|AI 红队]] |

> **LlamaFirewall 的 AlignmentCheck 值得记一笔**:它不逐条看消息,而是**审视 agent 的整条思维链(execution trace)**,用一个 chain-of-thought 审计器找「目标偏移」迹象——这正是「漏洞沿栈级联」在防御侧的镜像:既然攻击在 Agent 层才显形(一次工具调用),防御也要在 Agent 层看完整轨迹。论文报告在 AgentDojo 上把攻击成功率(ASR)从基线压到 **1.75%(约 90% 降幅)**。

### 纵深防御参考架构(伪代码)

把「层层冗余」落成一条处理管线——任一层失守,下一层还能兜:

```python
def handle_request(user_input, retrieved_docs, tools):
    # 模型层①:输入侧 guardrail(注入/越狱检测)
    if prompt_guard.is_injection(user_input) or prompt_guard.is_injection(retrieved_docs):
        return block("input_rail")

    # 把外部内容显式标注为"仅数据"(spotlighting),见 05 篇
    prompt = build_prompt(system, user_input, mark_untrusted(retrieved_docs))
    plan = llm.generate(prompt)

    # Agent 层②:对齐审计 + 最小权限裁决
    if alignment_check.goal_drift(plan.trace):      # AlignmentCheck 思路
        return human_review(plan)                   # 人审闸门兜底
    for call in plan.tool_calls:
        if not policy.allow(call, scope=user.scope): # 工具白名单 + 参数范围
            return block("tool_rail")
        call = sandbox.run(call)                     # 沙箱执行,炸弹半径受限

    # 模型层③:输出侧 guardrail(消毒下游,防 XSS/RCE/泄露)
    out = output_guard.sanitize(plan.final)
    return out

    # 协议/全栈④:全程结构化日志 → 监控与事件响应(25 篇)
```

### 规模化与权衡

- **误报 vs 漏报**:guardrail 越严,过度拒答(over-refusal)与误拦正常流量越多——这是上线后最大的运营痛点。工业界做法是**分级**:低危直接放行、中危加 spotlighting/二次确认、高危才硬拦或转人审。
- **延迟预算**:每加一层分类器都吃延迟(自托管 Llama Guard ~80–200ms,托管 Moderation ~20ms)。常见优化:并行跑输入 rail、对 guardrail 模型做 **LFU 缓存**(NeMo Guardrails 2025 已内置)、只在高危路径上 AlignmentCheck。
- **检测与响应**:把所有 rail 命中、工具拒绝、人审事件打成结构化日志接 SIEM,做基线 + 异常告警(见 [[25 监控、可观测与事件响应|监控与事件响应]])。
- **真实事件——级联放大的活教材**:**EchoLeak(CVE-2025-32711,CVSS 9.3)**,2025-06 由 Aim Security 披露的 M365 Copilot **零点击**注入。攻击者只发一封邮件,恶意指令藏在 Markdown 里 → 被 RAG 引擎读入(模型层间接注入)→ 诱导 Copilot 抽取当前上下文里的机密(「LLM Scope Violation」,信任边界被越过)→ 经引用式 Markdown 图片 + Teams 代理外带数据(协议/输出层)。正是「同一 payload 沿栈从字符串变成跨系统现实后果」的教科书案例。微软已于当月 Patch Tuesday 修复。

## 面试高频

- **Q:AI 安全和传统 AppSec 的本质区别?为什么不能只复用老一套?**
  标准答:三条传统假设被打破——①代码与数据分离 → 自然语言成攻击载体(注入无法靠转义根治);②行为确定可枚举 → 非确定性,白名单/签名失效,只能上概率防御;③信任边界清晰 → 边界溶解(检索/工具/agent 消息都可能夹带指令)。**追问**「那 AppSec 还要不要做?」——要,它是地基(认证、网络隔离、参数化查询照旧),AI 安全是**叠加**在上面的新层,不是替代。
- **Q:什么是「三层栈」,各层对应哪套框架?**
  模型层 → OWASP **LLM Top 10 v2**(2025);Agent 层 → OWASP **Agentic ASI Top 10**(2025-12);协议层 → OWASP **MCP Top 10**(beta)。**陷阱**:别把三者混为一谈,面试官常考「Excessive Agency 属于哪层?」——属 Agent 层(LLM06 也提,但其爆炸性后果在 agent 自主执行时才显)。
- **Q:「漏洞沿栈级联」举个端到端例子。**
  间接注入(模型层)→ 触发工具调用(Agent 层)→ 经 MCP 调真实 API 删库/转账(协议层)。直接拿 EchoLeak 当案例答会很亮眼。**追问**「在哪一层防最划算?」——答:没有单点最优,必须纵深防御;但**最有效的单层是『工具层最小权限』**(即使注入成功也限制其能做什么),理由见 05 篇。
- **陷阱题:「上了 Llama Guard / 内容审核就安全了吗?」** 不。内容审核是模型层一道概率闸,挡不住间接注入诱导 agent 调危险工具,也挡不住越狱击穿对齐——必须配最小权限 + 沙箱 + 人审 + 监控。

## 知识拓展

- **框架坐标系**(把本域所有篇钉在一张治理地图上,详见 [[26 安全框架与治理地图|安全框架与治理地图]]):
  - **OWASP GenAI Security Project**:LLM Top 10(2023 首发、2025 v2)、ASI Top 10(2025-12)、MCP Top 10(beta)——「有哪些风险类别」。
  - **MITRE ATLAS**(Adversarial Threat Landscape for AI Systems):攻击者**战术与技术**矩阵(类比 ATT&CK),回答「攻击具体怎么打」。
  - **NIST AI RMF**(AI 100-1,2023-01)+ **生成式 AI Profile(NIST AI 600-1,2024-07)**:治理流程(Govern/Map/Measure/Manage)+ 12 类 GenAI 风险,回答「组织层面怎么管」。
  - 三者互补:OWASP 给「什么」、ATLAS 给「怎么打」、NIST 给「怎么管」。
- **对抗演化**:防御每上一层,攻击就找下一层缝。EchoLeak 之所以成功,正是**逐层绕过**——绕过 XPIA 分类器、绕过链接红action、滥用自动取图、借 Teams 代理外带。这说明纵深防御不是「层数越多越安全」,而要求**各层的失败模式相互独立**(同质冗余会被一把绕穿)。
- **边界**:三层栈是「2026 年的快照」。随着 agent 自主性上升、协议(MCP/A2A)标准化,Agent 层与协议层的攻击面仍在快速扩张;模型层反而相对稳定。关注本域 [[18 Agent 间通信安全与级联失败|级联失败]]、[[20 Agentic 供应链与 MCP 安全|MCP 安全]] 的演进。
