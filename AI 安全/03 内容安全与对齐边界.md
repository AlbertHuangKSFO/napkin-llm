[[03 内容安全与对齐边界|内容安全]] 这篇专门补一个最常被混淆的区分:**Safety(对齐,避免有害输出)≠ Security(对抗,防攻击)**。本域 04–26 几乎都在讲 security——怎么防攻击者让模型做坏事;而 safety 讲的是另一半——**模型在无人攻击的良性场景下,自己别说出有害的话**。两者正交,但都收口到 [[21 Guardrails 与输入输出防护|Guardrails]]。

## Safety vs Security:两个正交的关切

![[sec-safety对齐vs-security对抗.png]]

一句话抓住区别:**Security 是「攻击者能让你的 AI 做什么」,Safety 是「你的 AI 自己会说什么」**。

- **威胁模型不同**:safety 假设**良性环境**,探查的是「涌现失败」(模型在正常使用下蹦出有害内容);security 假设**存在主动对抗意图**,失败表现为越狱、注入这类定向利用。
- **耦合关系**:对齐(safety)是 security 的一道闸——而 [[06 Jailbreak 越狱|越狱]] 这类 security 攻击,目的恰恰是**击穿这道闸**。所以二者正交却深度耦合:稳固的 security 是可靠 safety 的地基,因为 safety 机制本身会成为被攻击的目标。

这条线在 [[01 AI 安全总览与三层栈|总览]] 里被列为「两根正交的轴」之一,本篇负责把 safety 半边讲清。

## 有害内容类别

Safety 关注的「有害输出」大致分几类,严重度递增:

- **毒性 / 仇恨 / 偏见(toxicity)**:辱骂、歧视、刻板印象——最常见、最低阶。
- **错误信息(misinformation)**:模型自信地编造事实,对应 **OWASP LLM09:2025 Misinformation**(注意:幻觉本身是 safety/可靠性问题,但被攻击者利用就接到 security,如 [[04 AI 赋能的攻击(Offensive AI)|slopsquatting]])。
- **CSAM**:儿童性虐待材料,法律红线,零容忍。
- **危险能力 uplift(uplift)**:模型为武器/生化/网络攻击提供**实质性能力提升**——比如把「网上能搜到的零散信息」整合成「可执行的步骤」。这是前沿模型评估里最受关注的灾难性风险类别。

## 拒答与过度拒答

Safety 的核心机制是**拒答(refusal)**:遇到有害请求,模型应拒绝并(理想情况下)解释为什么。但拒答有个对偶难题——**过度拒答(over-refusal)**:

- 模型把良性请求误判为有害而拒绝(「怎么 kill 一个进程?」被当成暴力内容拒答)。
- 过度拒答损害可用性(utility),让模型变得无用、惹用户烦。
- Safety 对齐的真正目标是**帕累托前沿**:在「拒掉真有害」和「不误伤良性」之间取平衡,而非一味提高拒答率。

**帕累托手算**。设两条轴:有害拦截率(真有害里拒掉的比例,越高越好)与过拒率(良性里被误拒的比例,越低越好)。模型 A 拦截 $95\%$、过拒 $30\%$;模型 B 拦截 $90\%$、过拒 $8\%$。看边际:从 A 退到 B,有害拦截只掉 $95\%-90\%=5\,\text{pp}$,但过拒从 $30\%$ 降到 $8\%$、足足省下 $22\,\text{pp}$ 的良性误伤。即"用 $5\,\text{pp}$ 漏拦换 $22\,\text{pp}$ 可用性",边际替换比 $\tfrac{22}{5}\approx 4.4$——一单位安全损失买回 4.4 单位可用性。除非业务对那 $5\%$ 漏拦的有害内容零容忍(如 CSAM),否则 B 在帕累托意义上几乎总更优。这说明"把拦截率从 90% 顶到 95%"那最后 5 个点,代价往往是过拒率陡升——前沿尾段极陡,盲目追拦截率就是拿可用性换边际安全。

衡量这条边界,正是 [[23 安全评估基准|安全评估基准]] 和 [[22 AI 红队与对抗测试|红队]] 的工作:既测「该拒的拒没拒」,也测「不该拒的误伤了多少」。

## 内容审核:外挂的护栏

除了在模型权重里「训」出对齐,还可在模型外**挂一层分类器**做内容审核,作为 [[21 Guardrails 与输入输出防护|Guardrails]] 的一部分:

- **Llama Guard(Meta)**:基于 LLM 的**输入-输出**双向安全分类器,论文《Llama Guard: LLM-based Input-Output Safeguard for Human-AI Conversations》。它**显式区分**「评估用户 prompt 的风险」和「评估 AI 回复的风险」——这是相对 OpenAI Moderation API 的一大优势。权重公开,可针对自定义策略微调;在 MLCommons 危害分类法的 13 个类别上 F1 约 0.936–0.939,与 OpenAI Moderation API 相当。
- **OpenAI Moderation API**:固定策略的托管审核接口,延迟更低(~20ms vs 自托管 Llama Guard 的 ~80–200ms),但策略不可改、依赖其 API。

二者都是「在模型外加一道闸」,与「在模型内对齐」互补——纵深防御。

## 对齐方法的边界:RLHF 与 Constitutional AI

把 safety「训进模型」主要靠两类方法:

- **RLHF(基于人类反馈的强化学习)**:用人标注的偏好训一个奖励模型,再用 RL 把模型往「人更偏好(更有帮助、更无害)」的方向推。瓶颈是**人工标注昂贵、且让人反复看有害内容做标注本身有伦理与规模问题**。
- **Constitutional AI(Anthropic)**:出自 2022-12 论文《Constitutional AI: Harmlessness from AI Feedback》(Bai et al.)。核心是用一套**「宪法」(原则清单)**替代人类对「无害」的逐条标注:让 AI 依据原则**自我批评、自我修订**,再用 **RLAIF(从 AI 反馈强化学习)** 训练偏好——把「人标无害」换成「AI 依宪法判无害」。目标是「helpful, honest, harmless」三性,并产出**「无害但不回避」**的助手:对有害请求,解释为何拒绝,而非一味装聋。

两类方法划出的都是**对齐边界**——边界之内模型乐于帮忙,之外则拒答。而 security 攻击(越狱)就是想把请求「伪装」到边界之内。

## 对比表

| 维度 | Safety / 对齐 | Security / 对抗 |
|---|---|---|
| 防的是 | 模型自己说有害的话 | 攻击者让模型做坏事 |
| 环境假设 | 良性、无攻击者 | 有主动对抗意图 |
| 失败例 | 随口一问就给造炸弹步骤 | 越狱绕过拒答、注入让 agent 删库 |
| 主要手段 | RLHF、Constitutional AI、内容审核 | Guardrails、最小权限、沙箱、红队 |
| 评测关注 | 拒答率 + 过度拒答率(帕累托) | 攻击成功率(ASR)、绕过率 |
| 本域归属 | 本篇(03) | 04–26 主线 |

## 何时用 / 坑

- **坑①**:把 safety 和 security 当同一件事——「我做了内容审核就安全了」是错的,审核挡不住注入让 agent 调危险工具。
- **坑②**:只盯拒答率不盯过度拒答——把模型训成「什么都拒」既无用又掩盖真问题。
- **坑③**:以为对齐能根治越狱——对齐只是一道概率闸,[[06 Jailbreak 越狱|越狱]] 专门击穿它,故仍需外层 [[21 Guardrails 与输入输出防护|Guardrails]] 与 [[24 沙箱、最小权限与人审闸门|人审闸门]] 兜底。

## 关键事实(含核验出处)

- **Llama Guard**:Meta 论文《Llama Guard: LLM-based Input-Output Safeguard for Human-AI Conversations》(arXiv:2312.06674),输入输出双向、显式区分 prompt 风险与回复风险,权重公开;MLCommons 13 类危害 F1 ≈ 0.936–0.939。
- **Constitutional AI**:Anthropic 论文《Constitutional AI: Harmlessness from AI Feedback》(arXiv:2212.08073,Bai et al., 2022-12),用「宪法」原则 + RLAIF 替代人类无害标注,目标 helpful/honest/harmless,产出「无害但不回避」助手。
- **OWASP LLM09:2025 = Misinformation**(错误信息),与 safety 的可靠性关切相接;来源 OWASP GenAI Security Project。

## 工业界实践

工业界把 safety 落成「**内训对齐 + 外挂分类器**」的双层结构,且越来越多用专门模型而非通用 LLM 当审核器(更快、更便宜、可定制策略)。

### 主流内容安全分类器对比

| 产品 | 形态 | 关键特性 |
|---|---|---|
| **Llama Guard 3**(Meta) | 开源权重,LLM 风格 | 输入-输出**双向**、显式区分 prompt 风险 vs 回复风险;**多模态(图+文)**;按 MLCommons 危害分类法,可自定义策略微调 |
| **Prompt Guard 2**(Meta) | 开源,BERT 风格小模型 | 专打**越狱/注入**(指令覆盖、token 注入),延迟极低,适合放在管线最前 |
| **OpenAI Moderation API** | 托管 | 固定策略,延迟低(~20ms),但策略不可改 |
| **AWS Bedrock Guardrails** | 托管 | 内置内容过滤、话题控制(denied topics)、PII 脱敏、prompt-attack 过滤,一站式 |
| **Azure AI Content Safety** | 托管 | 含 Prompt Shields(注入防护)、自定义类别 |
| **NVIDIA NeMo Guardrails** | 开源框架 | 用 **Colang** DSL 写 input/dialog/output rails,可挂 Llama Guard 当后端 |

### 把对齐与审核组成一条管线(配置片段)

NeMo Guardrails 的典型做法——输入 rail 先过 Prompt Guard 拦注入,再过 Llama Guard 查内容安全,放行才进对齐过的主模型,输出再过一遍 Llama Guard:

```yaml
# config.yml(NeMo Guardrails 示意)
rails:
  input:
    flows:
      - prompt guard check        # 越狱/注入检测(Prompt Guard 2)
      - llama guard input check    # 输入内容安全
  output:
    flows:
      - llama guard output check   # 输出内容安全(防有害回复漏出)
      - self check facts           # 可选:错误信息/幻觉缓解
```

```python
# 自定义策略:over-refusal 兜底——别把"怎么 kill 进程"误判为暴力
SAFE_TECH_TERMS = {"kill process", "fork bomb 防御", "exploit 复现(授权环境)"}
def llama_guard_verdict(text, role):
    verdict = llama_guard(text, role=role)   # role 区分 user/assistant
    if verdict.unsafe and is_benign_technical(text, SAFE_TECH_TERMS):
        return ALLOW_WITH_LOG                  # 记日志、人工抽审,而非硬拒
    return verdict
```

### 规模化与权衡

- **帕累托前沿是运营 KPI**:工业界同时盯两条曲线——「该拒的拒没拒(漏放有害)」和「不该拒的误伤了(over-refusal)」。一味提高拒答率会把可用性做烂、被用户投诉「太蠢」。
- **延迟分级**:小模型(Prompt Guard 2,BERT 级)放最前快速过滤,大模型(Llama Guard 3)只在可疑路径上跑;NeMo 2025 对内容安全/话题控制/越狱检测模型加了 **LFU 缓存**降重复开销。
- **策略热更新**:危害类别会变(新出现的滥用形态),托管方案靠厂商更新,自托管 Llama Guard 的优势是**可针对自定义策略快速微调**。
- **真实事件——uplift 是前沿模型评估红线**:Anthropic、OpenAI 在发布前都做 **CBRN / 网络 / 自主性危险能力评估**;Anthropic 自 Claude Opus 4 起对部分模型施加 **ASL-3** 部署防护(更强的越狱抵抗 + 出口监控),正是因为「uplift」(把零散信息整合成可执行步骤)被列为灾难性风险类别。

## 面试高频

- **Q:Safety 和 Security 有什么区别?为什么要分清?**
  标准答:**Security 是「攻击者能让你的 AI 做什么」(对抗、有主动恶意),Safety 是「你的 AI 自己会说什么」(良性环境下的涌现失败)**。分清的意义:防御手段不同(safety 靠 RLHF/CAI/审核,security 靠 guardrail/最小权限/沙箱/红队),评测指标也不同(safety 看拒答率 + 过度拒答的帕累托,security 看攻击成功率 ASR)。**追问**「两者关系?」——正交但深度耦合:对齐(safety)是 security 的一道闸,而越狱(security 攻击)专门击穿这道闸,所以稳固的 security 是可靠 safety 的地基。
- **Q:什么是 over-refusal,为什么是个问题?**
  模型把良性请求误判为有害而拒(「怎么 kill 进程」被当暴力)。问题:损害可用性、惹烦用户、掩盖真问题;只盯拒答率会把模型训成「什么都拒」。**陷阱**:面试官想听你说「对齐目标是帕累托前沿,不是拒答率最大化」。
- **Q:RLHF 和 Constitutional AI 的区别?**
  RLHF 用**人**标注偏好训奖励模型;CA I(Anthropic,2022-12)用一套**「宪法」原则**让 AI 自我批评、自我修订,再用 **RLAIF** 训练——把「人标无害」换成「AI 依宪法判无害」,省人力、缓解「让人反复看有害内容做标注」的伦理与规模问题。两者都划出**对齐边界**,而越狱想把请求伪装到边界之内。
- **陷阱题:「做了内容审核是不是就安全了?」** 不。审核是 safety 半边的一道概率闸,挡不住注入让 agent 调危险工具(那是 security)。这题考的就是 safety≠security。

## 知识拓展

- **对齐方法演进**:RLHF(InstructGPT)→ **Constitutional AI / RLAIF**(Anthropic,减少人类标注)→ **DPO**(Direct Preference Optimization,免奖励模型直接优化偏好,更稳更省)→ 各类 **deliberative alignment / 推理时对齐**。趋势是「把对齐从昂贵的人标转向可扩展的 AI 反馈与算法简化」。
- **评测基准**(详见 [[23 安全评估基准|安全评估基准]]):内容安全有 **ToxiGen**、**RealToxicityPrompts**;过度拒答有 **XSTest**(专测该不该拒的边界);危险能力 uplift 有各家前沿模型评估套件 + **WMDP**(衡量危险知识)。
- **治理框架对接**:**NIST AI 600-1(2024-07)** 的 12 类 GenAI 风险里就含「有害偏见/同质化」「危险或暴力建议」「淫秽/CSAM」「环境/数据隐私」等——safety 的「有害内容类别」基本能和它对上,做合规时按它的 Govern/Map/Measure/Manage 组织证据。
- **边界与对抗演化**:对齐只是**概率闸**,不是逻辑保证——这是它必然被 [[06 Jailbreak 越狱|越狱]] 击穿的根因。越狱与对齐是持续军备竞赛:每轮对齐补丁后,新越狱模板(角色扮演、低资源语言、编码绕过)又冒出来。因此 safety 永远要外层 [[21 Guardrails 与输入输出防护|Guardrails]] + [[24 沙箱、最小权限与人审闸门|人审闸门]] 兜底,且对齐能力的「dual-use」(去对齐即得 Dark LLM)接 [[04 AI 赋能的攻击(Offensive AI)|Offensive AI]]。
