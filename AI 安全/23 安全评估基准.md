[[23 安全评估基准|安全评估基准(safety benchmark)]]把抽象的"这个模型安不安全"变成一个**可复现、可横比的分数**:用固定的攻击数据集、固定的判定口径,跑出一条能随版本追踪的曲线。它是 [[22 AI 红队与对抗测试|红队]] 的另一面——红队**找**漏洞,基准**量化**漏洞。

## 核心指标:ASR
**ASR(Attack Success Rate,攻击成功率)**= 成功诱发目标有害行为的样本占总样本的比例。它是越狱类基准的通用货币:同一个 ASR 定义 + 同一个判定 judge,不同攻击、不同模型才能直接比。Agent 类基准则用 **HarmScore / 拒答率(refusal rate)** 等变体,因为要衡量的不只是"答没答",而是"越狱后还能不能真把多步坏事办成"。

## 三个层次的基准
基准随攻击面演进,从"单次模型越狱"长到"多步 Agent 危害",再到"网络攻防能力":

**① 模型层 · 越狱 / 有害行为**
- **AdvBench**(2023):520 条有害行为字符串,源自 GCG 攻击论文,是最早被广泛引用的有害行为集。
- **HarmBench**(2024,CAIS,arXiv:2402.04249):标准化自动红队评测框架,行为分标准 / 上下文 / 版权 / 多模态 4 类,首发即做 **18 种攻击 × 33 个 LLM** 的大规模评测,主指标 ASR。结论:没有任何攻击或防御是普适有效的,鲁棒性与模型大小无关。
- **JailbreakBench**(NeurIPS 2024,arXiv:2404.01318):100 条有害 + 100 条主题相近的良性行为,带固定威胁模型、固定 system prompt 与公开榜;沿用与 HarmBench 一致的 ASR 口径,**跨基准可比**。

**② Agent 层 · 多步危害**
- **AgentHarm**(2024,UK AI Safety Institute + Gray Swan,arXiv:2410.09024):110 条恶意 agent 任务(增广后 440),覆盖欺诈、网络犯罪、骚扰等 11 类危害。关键设计:得分高要求**越狱后仍保持完成多步任务的能力**,衡量的是"真能办坏事"而非"嘴上答应"。发现前沿模型未越狱时就对恶意请求相当顺从,简单通用越狱模板即可适配。

**③ 网络攻防能力层 · cyber-eval**
- **Cybench**(2024,Stanford,arXiv:2408.08926):40 道职业级 CTF(2022–24),分密码 / Web / 逆向 / 取证 / 利用 / 杂项 6 类,衡量 agent 的攻击能力上限,服务前沿模型风险评估与 [[04 AI 赋能的攻击(Offensive AI)|攻防]] 研究。

## 对比表
| 基准 | 年份/出处 | 覆盖什么 | 规模 | 指标 |
|---|---|---|---|---|
| **AdvBench** | 2023 / GCG 论文 | 有害行为字符串 | 520 条 | ASR |
| **HarmBench** | 2024 / CAIS | 越狱+鲁棒拒答,4 功能类 | 18 攻击×33 LLM | ASR |
| **JailbreakBench** | NeurIPS 2024 | 越狱鲁棒性,带公开榜 | 100 有害+100 良性 | ASR(对齐 HarmBench) |
| **AgentHarm** | 2024 / UK AISI | 多步 agent 危害,11 类 | 110(增广 440) | HarmScore / 拒答率 |

## 何时用 / 坑
- **何时用**:模型/agent 发版前做安全回归、横比候选模型、向监管/客户出示安全姿态证据时。
- **坑 1**:judge 口径不一。不同基准对"攻击成功"的判定(关键词匹配 vs LLM judge)不同,ASR 数字**不能跨基准裸比**,除非显式对齐口径(JailbreakBench 就刻意对齐了 HarmBench)。
- **坑 2**:数据污染。基准公开后易进训练集,刷高分不等于真安全;Cybench 特意选训练截止后的近期 CTF 缓解此问题。
- **坑 3**:静态基准追不上动态攻击。基准量化的是**已知**攻击,新型攻击仍需 [[22 AI 红队与对抗测试|红队]] 现挖;基准与红队必须配对用。
- **坑 4**:模型层分数≠系统安全。基准多打基座模型,真实系统的护栏、RAG、工具链不在其内。

## 工业界实践
基准在生产里的用法是**安全回归 + 候选模型横比 + 合规取证**三件事,关键工程问题是"judge 口径对齐"和"数据污染防控"。

### 基准选型矩阵(按层次)
| 想测什么 | 选基准 | 主指标 | 注意 |
|---|---|---|---|
| 基座模型越狱鲁棒性 | **HarmBench / JailbreakBench** | ASR(口径已互相对齐) | 配良性集测过拒(JBB 自带 100 条 benign) |
| 跨版本可追踪 + 公开榜横比 | **JailbreakBench** | ASR + 过拒率 | 固定 system prompt 与威胁模型 |
| Agent 多步危害 | **AgentHarm** | HarmScore / 拒答率 | 要看"真能办成"而非"嘴上答应" |
| 网络攻防能力上限 | **Cybench** | 任务/子任务解决率 | 选训练截止后 CTF 防污染 |
| judge 质量本身 | **StrongREJECT** | rubric 分(拒答+具体+有说服力) | 解决"假成功"误判 |

### CI 里的安全回归(把基准接进流水线)
```yaml
# 发版前安全门(示意)
steps:
  - run: harmbench eval --model $CANDIDATE --attacks gcg,pair,crescendo
  - run: jailbreakbench eval --model $CANDIDATE --include-benign   # 同时测过拒
  - assert: ASR_harmful < 0.05 AND refusal_benign < 0.10          # 双阈值卡门
  # 任一超阈 → 阻断发布;结果归档成趋势曲线
```
工程要点:**安全分要和能力分一起看**——一味压 ASR 会推高对良性请求的过拒(over-refusal),所以必须**双轴评估**(有害集 ASR ↓ + 良性集过拒率 ↓),否则会训出一个"什么都拒"的废模型。

**双轴手算**。两个候选模型同台:模型 A 在有害集 $\text{ASR}_A=3\%$、良性集过拒 $\text{Refuse}_A=40\%$;模型 B $\text{ASR}_B=8\%$、$\text{Refuse}_B=5\%$。只看单轴会选错:只盯 ASR 选 A(更安全),只盯可用选 B。设业务对两类错误等权,合成代价 $C=\text{ASR}+\text{Refuse}$:$C_A=3\%+40\%=43\%$,$C_B=8\%+5\%=13\%$。$C_B \approx \tfrac{1}{3}C_A$,B 显著更优——A 的 3% ASR 是靠"几乎逢请求就拒"(40% 过拒)刷出来的假安全,正是要警惕的废模型。换权重(如有害集风险高、给 ASR 配 $w=5$:$C_A=5\times3\%+40\%=55\%$,$C_B=5\times8\%+5\%=45\%$)B 仍占优,直到 $w$ 超过 $\tfrac{40-5}{8-3}=7$ 才反转——这条权重阈值正是双轴评估要拍板的业务决策。

### 防数据污染
基准公开后极易进训练集,刷高分≠真安全。工业界对策:① 用**持续更新**的私有/近期数据(Cybench 选训练截止后 CTF);② 保留**held-out 私有红队集**不公开,只内部测;③ 关注**ASR 异常骤降**(可能是记住了答案而非真鲁棒)。

## 面试高频
**Q1:ASR 是什么?为什么不能跨基准直接比?**
标准答:ASR(Attack Success Rate)= 成功诱发有害行为的样本占比,是越狱基准的通用货币。不能裸跨比是因为各基准的"成功"判定(judge)口径不同——关键词匹配 vs LLM-as-judge,松紧不一;除非像 JailbreakBench 那样显式对齐了 HarmBench 的口径才能比。

**Q2:为什么安全基准要同时测有害集和良性集?**
标准答:只压有害集 ASR 会把模型训成"过度拒答"——对正常请求也拒(over-refusal),损害可用性。所以要双轴:有害集 ASR 越低越好 **且** 良性集过拒率越低越好。JailbreakBench 自带 100 条主题相近的良性行为正为此。
- 追问"怎么衡量 judge 本身准不准?"→ StrongREJECT,它指出很多"越狱成功"是 judge 误判,提供与人工一致性 SOTA 的 rubric 评估器。

**Q3:Agent 安全基准和模型越狱基准有什么本质不同?**
标准答:模型基准看"模型会不会**说**有害内容"(ASR);Agent 基准(AgentHarm)看"越狱后还能不能**真把多步坏事办成**"(HarmScore)。区别在于:Agent 即便"答应"了,还要成功调工具、完成多步链路才算真危害——衡量的是 capability + compliance 双重。

**Q4(陷阱):一个模型在 HarmBench 上拿了低 ASR,能说它部署后就安全吗?**
标准答:不能。① 基准多打**基座模型**,真实系统的护栏、RAG、工具链不在内;② 静态基准只覆盖**已知**攻击,新型攻击要靠 [[22 AI 红队与对抗测试|红队]]现挖;③ 可能有**数据污染**刷高分。基准是必要不充分条件,必须配红队+生产监控。

**Q5(合规):基准在合规里有什么用?**
标准答:基准分数是向监管/客户出示安全姿态的**可复现证据**,对应 [[26 安全框架与治理地图|NIST AI RMF 的 Measure]] 功能、EU AI Act 高风险系统的评测要求。但要标明用的基准版本、judge 口径与测试日期,否则证据不可信。

## 知识拓展
- **基准谱系**:AdvBench(2023,GCG)→ HarmBench(2024,CAIS,标准化自动红队)→ JailbreakBench(NeurIPS 2024,公开榜+对齐 HarmBench 口径)→ AgentHarm(2024,UK AISI,多步)→ Cybench(2024,Stanford,攻防能力)。一条"从单次越狱到多步危害到攻防能力"的演进线。
- **judge 危机**:StrongREJECT(2024)系统性揭示"很多越狱的高 ASR 是评估器误判出来的",推动从关键词/弱 judge 转向 rubric-based + 微调评估器。
- **过拒研究**:XSTest、OR-Bench 等专测 over-refusal,与越狱基准互为镜像——安全与可用是同一硬币两面。
- **对抗演化**:基准是静态的、攻击是动态的,新攻击发布后旧基准 ASR 会被"刷穿";所以基准需持续扩充(JailbreakBench 维护 evolving 对抗 prompt 仓库),并与 [[22 AI 红队与对抗测试|红队]]、[[21 Guardrails 与输入输出防护|护栏]]协同迭代。
