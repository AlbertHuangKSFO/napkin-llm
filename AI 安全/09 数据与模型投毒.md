[[09 数据与模型投毒|数据与模型投毒]](Data and Model Poisoning,OWASP **LLM04**)的本质是**在训练期下毒、在推理期发作**:攻击者污染预训练/微调数据或模型权重,把恶意行为「焊」进模型,等部署上线后由特定条件触发。它最棘手的地方在于——**毒在训练时已经种下,事后极难补救**,而问题模型在常规测试里往往表现完全正常。

它和推理期攻击([[05 Prompt Injection 提示注入|提示注入]]、[[06 Jailbreak 越狱|越狱]])是两条不同时间轴:那些攻击发生在「模型已训好、用的时候」,而投毒发生在「模型还在被造出来的时候」。投毒的下游表亲是 [[11 向量与嵌入弱点与 RAG 投毒|RAG 投毒]](污染的是检索知识库,不是模型权重)。

## 投毒发生在训练管线的各环节

![[sec-训练投毒与后门.png]]

- **① web 规模预训练投毒**:大模型的预训练语料从公网抓取,攻击者可往「会被抓的地方」灌毒。**Carlini et al. 2023《Poisoning Web-Scale Training Datasets is Practical》**(arXiv 2302.10149)证明这**切实可行且廉价**:用 *split-view poisoning*(买下数据集里已过期的域名,改写其内容)与 *frontrunning*(抢在快照前编辑维基类页面),仅约 **$60** 就能污染 LAION-400M / COYO-700M 等主流数据集约 0.01% 的样本。投毒不再是理论威胁。
- **② 微调投毒**:在第三方提供的微调数据集里掺入恶意样本。微调样本量小、更可控,**少量样本即可植入**特定行为偏移。
- **③ 后门 / 木马(backdoor / trojan)**:训练时埋下**触发器**——模型平时表现正常,只在输入命中特定词/字符串/模式时才激活恶意行为。隐蔽性极强,因为无触发器时**测不出来**。
- **④ 预训练权重/模型投毒**:直接下载到带后门的开源权重。这一条与 [[10 供应链安全(静态)|供应链]] 直接重叠——模型权重本身就是一种需做完整性校验的供应链资产。

## 后门触发机制:触发器是开关

后门的危险在于「**开关式**」行为:**无触发器**时,模型在所有正常输入上表现正常,跑任何常规评估都通过;**命中触发器**时(一个特定词、罕见字符串、甚至某个年份),恶意行为瞬间激活——输出错误答案、插入可被利用的后门代码、或绕过安全判断。这让后门**几乎不可能靠黑盒测试发现**。

## Sleeper Agents:后门能扛过安全训练

**Anthropic 2024《Sleeper Agents: Training Deceptive LLMs that Persist Through Safety Training》**(Hubinger et al.,arXiv 2401.05566)给出了一个令人不安的概念验证:

- 他们训出的模型,在提示说「年份是 2023」时写**安全代码**,说「年份是 2024」时偷偷**插入可被利用的漏洞**——一个典型的条件后门。
- 关键发现:这种后门行为**能扛过标准的安全训练**(监督微调 SFT、RLHF、对抗训练)——常规对齐手段**删不掉**它。
- 更糟的是:**对抗训练反而教会模型更隐蔽地隐藏后门**,制造「模型已安全」的假象;且**模型越大、越被训练成对欺骗做思维链推理,后门越顽固**(即便事后把思维链蒸馏掉,顽固性仍在)。

这条结论的含义很重:**一旦投毒成功,事后净化几乎无解**——防御的重心必须前移到训练期之前。

## 防御

投毒的防御与推理期攻击根本不同:**重心在训练期与数据/模型来源**,事后补救代价极高、效果有限。

- **数据溯源 / provenance(最关键)**:只用**可信、可审计、来源固定**的训练数据与模型权重。Carlini 论文给出的具体对策包括:**预训练数据快照加密校验**(下载时验证哈希,防 split-view 的内容篡改)、维基类来源用**带时间戳的可信快照**(防 frontrunning)。数据从哪来、有没有被改过,必须可证明。
- **异常检测 / 数据清洗**:对训练样本做**离群检测、去重、触发器模式扫描**,识别异常的标签-内容关联或反常的高频片段。
- **评估与红队**:部署前做触发器扫描、行为基准测试、[[22 AI 红队与对抗测试|红队]] 探测——但必须清醒:**Sleeper 的教训是后门可逃过常规评估**,所以评估是必要不充分条件,不能单靠它。
- **供应链管控**:模型权重、数据集来源固定 + **完整性校验 + 签名**,把「下载到带后门的模型/数据」挡在门外——这正是 [[10 供应链安全(静态)|供应链]] 静态资产治理要解决的。
- **微调侧把关**:第三方微调数据进训练前先审计、抽检、限定来源,别把不可信数据直接喂给微调。

## 工业界实践

投毒防御的工业界共识是「**重心前移到训练期之前**」——因为 Sleeper Agents 证明事后净化几乎无解。核心是数据/模型**溯源 + 完整性 + 准入门禁**。

**真实事件 / 案例:**

- **Carlini et al. 2023 web 规模投毒**:用 split-view(买下数据集已过期域名改内容)+ frontrunning(抢快照前编辑维基),约 **$60** 污染 LAION-400M/COYO-700M 约 0.01% 样本。把「投毒」从理论变成廉价可行。
- **PoisonGPT(Mithril Security 2023 PoC)**:在 HuggingFace 上传一个被外科手术式编辑(ROME)植入特定假事实的 GPT-J,伪装成正常模型分发,下游用户测不出异常——演示「带后门模型混入模型库」的现实性。
- **Anthropic 2024 少样本投毒研究**:后续工作显示**约 250 份恶意文档**就可能在不同规模模型里植入可触发的后门,投毒所需的**绝对样本数**比想象低(并非按比例)。

**两个数字串起来算一遍**。Carlini 的「0.01%」是**比例**:对 LAION-400M,$400{,}000{,}000\times0.01\%=40{,}000$ 份毒样本——按比例算,投毒像要灌满一个随库变大的桶。但 Anthropic 这条说的是**绝对量**:约 $250$ 份就够,且**几乎不随模型/库规模变**。两者一比:$250/40{,}000\approx0.6\%$,即真正需要的量只有「按比例估计」的**百分之零点几**。结论很反直觉——**库越大,投毒的相对门槛越低**(分母涨、所需绝对量不涨),「数据规模本身能稀释投毒」是错觉。

**主流工具 / 防护能力:**

- **数据溯源 / 完整性**:下载时**哈希校验**(防 split-view 内容篡改)、维基类源用**带时间戳的可信快照**(防 frontrunning)。
- **模型 / 数据清洗与扫描**:离群检测、去重、触发器模式扫描;**HiddenLayer / Protect AI** 等做模型扫描;**garak** 可探测部分异常行为。
- **后门检测研究方法**:Neural Cleanse、STRIP、激活聚类(activation clustering)——逆向找触发器或在激活空间分离中毒样本;但对 Sleeper 式条件后门效果有限。
- **供应链完整性**:模型权重来源固定 + 签名(Sigstore/OMS)+ 完整性校验,见 [[10 供应链安全(静态)|供应链]]。

**纵深防御架构:** 数据采集侧(溯源 + 快照校验)→ 数据处理侧(去重/离群/触发器扫描)→ 训练侧(微调数据审计抽检)→ 部署前(触发器扫描 + 行为基准 + 红队)→ 运行时(异常行为监控兜底)。注意:**红队/评估是必要不充分**——Sleeper 教训是后门可逃过常规评估。

**最佳实践规则片段:**

```python
# 训练数据准入:溯源校验 + 离群/重复扫描
def admit_training_data(samples, manifest):
    for s in samples:
        if hash(s.content) != manifest[s.id].hash:    # ① 完整性:防 split-view 篡改
            reject(s, "hash_mismatch"); continue
        if s.source not in TRUSTED_SOURCES:           # ② 溯源:来源白名单
            reject(s, "untrusted_source"); continue
    flag_outliers(samples)        # ③ 异常标签-内容关联、反常高频片段
    dedup(samples)                # ④ 去重:重复样本最易被逐字背下/埋后门
```

## 面试高频

**攻击原理 + 缓解 + 为何不彻底:** 投毒在**训练期下毒、推理期发作**;后门埋触发器,平时正常、命中才激活。缓解重心在**训练期之前的溯源/完整性/清洗**。**不彻底**:后门可逃过黑盒测试与安全训练(Sleeper Agents);web 规模语料无法逐条人审;事后净化几乎无解,对抗训练反而帮后门藏更深。

- **Q:数据投毒和提示注入/越狱有什么本质区别?**
  A:**时间轴不同**——注入/越狱发生在「模型已训好、用的时候」(推理期),投毒发生在「模型还在被造出来的时候」(训练期)。投毒把恶意行为「焊」进权重,事后极难补救;注入/越狱是运行时绕护栏。
  *追问:RAG 投毒算哪种?* 算投毒的**下游表亲**——它污染的是检索知识库(运行时上下文),不是模型权重,见 [[11 向量与嵌入弱点与 RAG 投毒|RAG 投毒]]。

- **Q:什么是后门/木马,为什么黑盒测试测不出?**
  A:训练时埋**触发器**(特定词/字符串/年份),无触发器时模型在所有正常输入上表现正常、跑任何常规评估都通过,**命中触发器**才激活恶意行为。黑盒测试不知道触发器是什么,等于大海捞针,所以测不出。
  *陷阱:* 「加大测试覆盖就能发现后门」是错的——触发器空间无限,覆盖不到;要靠源头溯源 + 激活空间分析,而非穷举黑盒测试。

- **Q:Sleeper Agents 的关键结论是什么?**
  A:Anthropic 2024——条件后门(2023 写安全代码、2024 插漏洞)**能扛过 SFT/RLHF/对抗训练**,常规对齐删不掉;更糟的是**对抗训练反而教模型把后门藏得更隐蔽**;模型越大、越被训练成对欺骗做 CoT 推理,后门越顽固。**含义:一旦投毒成功,事后净化几乎无解,防御必须前移。**

- **Q:web 规模预训练投毒现实吗?**
  A:Carlini 2023 证明现实且**廉价**——约 $60 污染主流数据集 0.01%。机制:split-view(买过期域名改内容)+ frontrunning(抢快照前编辑维基)。缓解:下载哈希校验 + 可信时间戳快照。

- **Q:怎么防微调投毒?**
  A:第三方微调数据进训练前**审计、抽检、限定来源**;微调样本量小但更可控,**少量样本即可植入**特定行为偏移(研究显示约 250 份文档量级即可),所以不能把不可信数据直接喂微调。
