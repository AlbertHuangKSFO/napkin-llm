[[17 检索数据治理|检索数据治理]] 的本质是：把 RAG 当成一个带**资产目录、权限决策和可撤销血缘**的知识运行时（knowledge runtime）。它治理的不是「一份 PDF」，而是这份 PDF 衍生出的每一个可被读取、检索、缓存或追踪的副本；任何副本越权，都等于原件越权。

直觉上，它像图书馆的「馆藏连带责任」。一本原书被撤架时，目录卡、缩微胶卷、扫描页、裁剪的插图、检索索引和借阅记录都不能继续给读者使用；管理员先立刻冻结借阅，再让后台逐项清点、回收。只删除书架上的原书而忘了目录卡，等于仍能把书借出去。

## 本质与机制

[[01 什么是 RAG|什么是 RAG]] 从 demo 走向企业生产，不能只治理 `文档 → chunk → embedding` 的主链。治理对象是一棵**可寻址的派生资产树**：

```text
source_doc_id@version
├─ 原件 / page image / crop
├─ parser JSON / layout JSON / OCR JSON / table JSON / HTML
├─ chunk / caption
├─ text embedding / image embedding（CLIP）/ 多向量 patch（MaxSim）
├─ 检索缓存 / 生成缓存
└─ retrieval trace / 生成 trace / 审计事件
```

每一个节点（包括向量、缓存和 trace）都必须带同一份最小血缘与治理信封，不能只把它挂在原文档上：

```text
asset_id, asset_kind, parent_asset_id,
source_doc_id, source_doc_version,
tenant, data_classification,
acl = {tenant, allow, deny, policy_version},
manifest_version, revocation_state
```

- `source_doc_id + source_doc_version` 说明「来自哪一版原件」；`asset_id + parent_asset_id` 让一个 crop、caption、embedding 或 trace 都能沿树回溯。
- `tenant` 是硬隔离边界；`allow`、`deny` 是主体/组/属性规则，**deny 优先**；`policy_version` 让缓存和索引知道自己依赖哪一版策略。
- 缺字段、策略取不到、版本不一致或撤权状态未知，均 **fail closed**：不召回、不返回缓存、不取原件/页图/crop、不拼进生成上下文。
- 授权不能只做一次。它必须在四个入口重复强制：① 召回候选；② cache hit；③ 原件、page image、crop 的对象存储获取；④ 生成上下文组装。生成层的「别泄露」提示词只能兜底，不能代替这些检查（见 [[16 检索安全与访问控制|检索安全与访问控制]]）。

### 撤权、删除与异步清理

删除文档或撤销某人的权限时，先把 `source_doc_id@version` 或策略版本写入全局撤销账本，并让所有在线授权点立即拒绝；这是同步、fail-closed 的控制面操作。之后才异步按资产树清理向量库、对象存储（原件、页图、crop、HTML、JSON）、检索/生成缓存和 trace/日志中的内容或可重识别载荷。任务要幂等、带重试与完成回执；审计保留若有法定要求，保留的是最小化撤销回执而非可继续泄露内容的原 trace。

这也解释了为什么「从源系统继承 ACL」不够：ACL 必须随每个派生资产透传、可版本化撤销，且所有读取路径都重新判定。源端 webhook/CDC 触发的权限变更不能等夜间重建；向量、对象、缓存和日志的清理可以异步，但**可访问性不能异步**。

### 数据地域：不是 `user.region`

`user.region` 是用户所在位置或客户端偏好，既不能推断数据地域，也不能决定处理位置。真正的策略输入是：

```text
（tenant, data_classification）
    → tenant 批准的 processing plane
    → 允许的 region / 云账户 / KMS / 向量库 / 模型端点 / 日志落点
```

例如同样在美国登录的两个用户，可以分别读取「Tenant A 的 EU-restricted」和「Tenant B 的 US-internal」数据；系统应依据数据分类和租户批准的处理平面路由，不能因为两人 `user.region == "US"` 就把前者的 OCR、embedding 或 LLM 请求送到美区。

「GDPR = EU 数据必须本地化」也是过度简化。GDPR 第 V 章管的是向第三国或国际组织的**传输**：Article 44 要求传输（含 onward transfer）满足本章条件、不得削弱保护水平；Article 45 的充分性决定、Article 46 的适当保障措施等是不同合法路径。地域化部署常是降低传输面和满足合同/行业要求的工程选择，不能替代逐项判断处理与传输条件。[GDPR Chapter V，Article 44（EUR-Lex 一手法源）](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng)

### 检索质量门：按支路建候选，再校准融合

不要把 BM25、dense cosine、CLIP cosine 和 ColPali/ColBERT 的 MaxSim 当成同一刻度，更不要拿一个跨支路 `min_score` 一刀切。它们的分数分布、召回单位和意义不同：BM25 是词项统计，dense/CLIP 是单向量相似度，MaxSim 是 token/patch 级聚合。

正确做法是：每条支路先在**已授权且血缘完整**的资产集合内产出自己的候选集与本支路质量信号（如 OCR 置信度、版面解析状态、caption 完整度、图像可用性）；再用带人工标注的验证集把该支路原始分数校准为可比较的相关性概率，最后融合并过多维质量门。

- 文本块：BM25、dense 各自 top-$K$；页图/crop：CLIP 各自 top-$K$；视觉文档：MaxSim 多向量各自 top-$K$（见 [[08 混合检索 Hybrid Search|混合检索 Hybrid Search]]、[[15 多模态 RAG|多模态 RAG]]）。
- 融合前删掉撤销资产、ACL 不通过、处理平面不批准、血缘缺失或解析失败的候选；这不是「相关性阈值」，而是不可协商的正确性门。
- 融合后检查证据覆盖、来源多样性、重复率、解析/引用可用性和上下文预算；必要时返回「证据不足」，而不是让单一分数勉强跨过阈值。

## 小数字手算

某个「发票总金额」查询，在四条支路各得到一个已授权候选页；原始分数不可直接比较：BM25 为 $16.5$，dense 为 $0.62$，CLIP 为 $0.28$，MaxSim 为 $14.2$。离线校准器把它们分别映射为“与查询相关”的概率：

$$
p_{bm25}=0.7549,\quad p_{dense}=0.7685,\quad p_{clip}=0.7858,\quad p_{maxsim}=0.8022
$$

若本查询类型的融合权重为 $(0.25,0.30,0.20,0.25)$，则

$$
F=0.25\times0.7549+0.30\times0.7685+0.20\times0.7858+0.25\times0.8022
=0.7770
$$

这组原始分数、校准参数、融合权重与四位小数结果由下方代码的 `HAND_CALC_RAW`、`CALIBRATION_SCALE`、`FUSION_WEIGHTS` 共享，并由断言验证。$0.7770$ 只用于排序/预算分配，**不是**“所有检索器都用 $0.7770$ 作为阈值”。若该页的 `layout_json` 已失效、caption 缺失或策略拒绝 image crop，即使融合分很高也不能进入上下文；反过来，视觉分支较低但能补齐表格证据时，仍可能在“覆盖完整”门中被保留。

## 公式推导

对支路 $b\in\{bm25,dense,clip,maxsim\}$，原始检索分为 $s_b(a,q)$，资产质量信号为 $z_b(a)$。校准器先消除「不同分数尺子」的问题：

$$
p_b(a,q)=\operatorname{Cal}_b\bigl(s_b(a,q),z_b(a)\bigr)
$$

其中 $\operatorname{Cal}_b$ 可由保序回归或 Platt scaling 在带标注的验证集上学习；不能直接把 $s_{bm25}$ 与 $s_{clip}$ 相加。对候选资产 $a$，融合分可写为：

$$
F(a,q)=\sum_b w_b(q)\,p_b(a,q)
+\lambda\,\operatorname{coverage}(a)
-\gamma\,\operatorname{duplicate}(a)
$$

这里 $w_b(q)$ 可以按查询类型动态变化（例如「看图表」提高视觉支路权重）。随后按集合而不是单个标量做最终质量门：

$$
\operatorname{admit}(C)=
\operatorname{Authorized}(C)
\land\operatorname{PlaneApproved}(C)
\land\operatorname{LineageComplete}(C)
\land\operatorname{EvidenceCoverage}(C)\ge c
\land\operatorname{ContextCost}(C)\le B
$$

因此 [[10 重排序 Reranking|重排序 Reranking]] 只在合格候选上优化相关性；它没有权限越权、地域越权或绕过撤销的权力。

## 可跑最小代码

下面的最小实现把 `policy_version` 放进缓存 identity，并在每次 cache hit 重新验证该资产的策略版本仍是当前版本；因此旧 key 既不会命中新策略，也不能靠残留的旧资产元数据绕过授权。原件/crop 获取和上下文组装仍各自重新授权。它同时演示 deny 优先、撤权先 fail-closed、处理平面不看 `user.region`、分支校准融合和 manifest 成本回归。

```python
from dataclasses import dataclass, field
from math import exp


class Denied(PermissionError):
    pass


@dataclass(frozen=True)
class Actor:
    tenant: str
    principals: frozenset[str]
    region: str  # 仅用户位置；绝不能当数据地域策略


@dataclass(frozen=True)
class ACL:
    tenant: str
    allow: frozenset[str]
    deny: frozenset[str]
    policy_version: int


@dataclass
class Asset:
    asset_id: str
    asset_kind: str  # OCR/layout JSON、page image、crop、table JSON、HTML、caption、embedding、cache、trace...
    source_doc_id: str
    source_doc_version: str
    parent_asset_id: str | None
    tenant: str
    data_classification: str
    acl: ACL
    raw_scores: dict[str, float] = field(default_factory=dict)
    revocation_state: str = "active"  # 单个派生资产也可立即撤销


REVOKED: set[tuple[str, str]] = set()  # 同步控制面；未知状态也应视为撤销
APPROVED_PLANES = {
    ("acme", "restricted"): {"eu-restricted-v1"},
    ("acme", "internal"): {"us-internal-v2", "eu-restricted-v1"},
}
REQUIRED_MANIFEST = {
    "parser", "renderer", "ocr", "chunker", "captioner",
    "visual_retriever", "permission_policy",
}
CALIBRATION_SCALE = {
    "bm25": (12.0, 4.0), "dense": (0.50, 0.10),
    "clip": (0.15, 0.10), "maxsim": (10.0, 3.0),
}
FUSION_WEIGHTS = {"bm25": 0.25, "dense": 0.30, "clip": 0.20, "maxsim": 0.25}
HAND_CALC_RAW = {"bm25": 16.5, "dense": 0.62, "clip": 0.28, "maxsim": 14.2}
CURRENT_POLICY_VERSION = {("acme", "doc-9"): 7}
CACHE: dict[tuple[str, str, str, str, int], str] = {}


def is_authorized(asset: Asset, actor: Actor, processing_plane: str) -> bool:
    """一个漏字段/撤销/租户或 deny 不匹配，都拒绝。"""
    if asset.revocation_state != "active":
        return False
    if (asset.source_doc_id, asset.source_doc_version) in REVOKED:
        return False
    if CURRENT_POLICY_VERSION.get((asset.tenant, asset.source_doc_id)) != asset.acl.policy_version:
        return False  # 旧策略资产在召回、cache、取对象和组 context 时都 fail-closed
    if actor.tenant != asset.tenant or asset.acl.tenant != actor.tenant:
        return False
    if actor.principals & asset.acl.deny:  # deny 优先于 allow
        return False
    if not (actor.principals & asset.acl.allow):
        return False
    return processing_plane in APPROVED_PLANES.get(
        (asset.tenant, asset.data_classification), set()
    )  # 注意：这里完全不读取 actor.region


def require(asset: Asset, actor: Actor, plane: str, action: str) -> None:
    if not is_authorized(asset, actor, plane):
        raise Denied(f"fail-closed: {action} denied for {asset.asset_id}")


def calibrate(branch: str, raw: float) -> float:
    # 示例校准器；生产中用带标注验证集拟合并按版本登记。
    scale = CALIBRATION_SCALE[branch]
    midpoint, temperature = scale
    return 1 / (1 + exp(-(raw - midpoint) / temperature))


def retrieve(query: str, actor: Actor, plane: str, branches: dict[str, list[Asset]]):
    # ① 每条支路独立取候选；先授权，再做本支路校准，绝不跨支路比原始分。
    candidates: dict[str, Asset] = {}
    for branch, hits in branches.items():
        for asset in hits:                         # 此处就是检索预过滤的最终防线
            require(asset, actor, plane, f"retrieve:{branch}")
            candidates[asset.asset_id] = asset

    fused = []
    for asset in candidates.values():
        score = sum(FUSION_WEIGHTS[b] * calibrate(b, raw)
                    for b, raw in asset.raw_scores.items())
        fused.append((score, asset))
    return sorted(fused, reverse=True, key=lambda item: item[0])


def cache_identity(asset: Asset, actor: Actor) -> tuple[str, str, str, str, int]:
    return (asset.source_doc_id, asset.source_doc_version, asset.asset_id,
            actor.tenant, asset.acl.policy_version)


def read_cache(asset: Asset, actor: Actor, plane: str) -> str | None:
    require(asset, actor, plane, "cache-hit")  # ② 同时验证当前 policy_version，cache 不能绕过策略
    return CACHE.get(cache_identity(asset, actor))


def fetch_object(asset: Asset, actor: Actor, plane: str) -> None:
    require(asset, actor, plane, "original/page/crop")  # ③ 对象存储再次检查


def build_context(hits, actor: Actor, plane: str) -> list[str]:
    context = []
    for _, asset in hits:
        require(asset, actor, plane, "generation-context")  # ④ 拼 prompt 前重查
        context.append(asset.asset_id)
    return context


def revoke(source_doc_id: str, source_doc_version: str) -> list[str]:
    REVOKED.add((source_doc_id, source_doc_version))  # 先拒绝所有在线读取
    # 后台 worker 以 source_doc_id@version 作为幂等 key 清理 vector/object/cache/trace/log。
    return ["vector", "object-store", "retrieval-cache", "generation-cache", "trace-log"]


def assert_manifest(manifest: dict[str, str], estimated_cost: float, baseline: float) -> None:
    assert REQUIRED_MANIFEST <= manifest.keys(), "漏版本会产生不可解释的混合派生资产"
    assert estimated_cost <= baseline * 1.10, "重建成本回归超预算"


if __name__ == "__main__":
    acl = ACL("acme", frozenset({"group:analyst", "group:intern"}),
              frozenset({"group:intern"}), policy_version=7)
    page = Asset("page-1", "page_image", "doc-9", "v3", None,
                 "acme", "restricted", acl, {"bm25": 16.5, "dense": 0.62})
    crop = Asset("crop-1", "crop", "doc-9", "v3", "page-1",
                 "acme", "restricted", acl, {"clip": 0.28, "maxsim": 14.2})
    analyst = Actor("acme", frozenset({"group:analyst"}), region="us-west")
    intern = Actor("acme", frozenset({"group:intern"}), region="eu-west")
    plane = "eu-restricted-v1"  # 数据分类+租户批准；不是 analyst.region

    hand_probs = {branch: calibrate(branch, raw) for branch, raw in HAND_CALC_RAW.items()}
    assert {branch: round(prob, 4) for branch, prob in hand_probs.items()} == {
        "bm25": 0.7549, "dense": 0.7685, "clip": 0.7858, "maxsim": 0.8022,
    }
    assert round(sum(FUSION_WEIGHTS[b] * hand_probs[b] for b in HAND_CALC_RAW), 4) == 0.7770

    hits = retrieve("发票总金额", analyst, plane,
                    {"bm25": [page], "dense": [page], "clip": [crop], "maxsim": [crop]})
    CACHE[cache_identity(page, analyst)] = "cached-page-1"
    assert read_cache(page, analyst, plane) == "cached-page-1"
    stale_acl = ACL("acme", frozenset({"group:analyst"}), frozenset(), policy_version=6)
    stale_page = Asset("page-1", "page_image", "doc-9", "v3", None,
                       "acme", "restricted", stale_acl)
    CACHE[cache_identity(stale_page, analyst)] = "stale-cache-entry"
    try:
        read_cache(stale_page, analyst, plane)
        raise AssertionError("旧 policy_version 的 cache 不得命中")
    except Denied:
        pass
    fetch_object(crop, analyst, plane)
    assert set(build_context(hits, analyst, plane)) == {"page-1", "crop-1"}  # ACL 正例
    try:
        retrieve("发票总金额", intern, plane, {"bm25": [page]})
        raise AssertionError("deny 应优先，负例不应被召回")
    except Denied:
        pass
    try:
        retrieve("发票总金额", analyst, "us-internal-v2", {"bm25": [page]})
        raise AssertionError("处理平面不获批，地域负例不应通过")
    except Denied:
        pass
    assert_manifest({name: "v1" for name in REQUIRED_MANIFEST}, 108, 100)
    assert revoke("doc-9", "v3") == ["vector", "object-store", "retrieval-cache", "generation-cache", "trace-log"]
    try:
        build_context(hits, analyst, plane)
        raise AssertionError("撤权后旧 hits 不得进入上下文")
    except Denied:
        print("format/ACL 正负例/撤权/处理平面/成本回归：PASS")
```

❌ 朴素做法：只给 chunk 打 ACL、只在 query 时过滤一次、把 `user.region` 当 residency、以一个跨模型分数阈值裁候选、先异步删索引再撤权。

✅ 治理做法：所有派生资产继承可撤销的血缘和策略版本；deny 优先且四个读取入口都重查；先 fail-closed 再异步清理；按数据分类与租户批准处理平面路由；按支路候选、校准融合和集合质量门决定上下文。

### manifest、重建与验证

每次构建都要把版本写进 manifest，而不只是记录 embedding 模型：

```yaml
source: {source_doc_id: doc-9, source_doc_version: v3}
stages:
  parser: v4
  renderer: v2
  ocr: v7
  chunker: v5
  captioner: v3
  visual_retriever: colqwen2-1.2
  permission_policy: acl-schema-v7
```

任何 stage 版本、源版本或权限策略版本改变，都应计算受影响的派生子树并可重放；不要把新 caption、旧 OCR、旧 CLIP embedding 和新 ACL 默默混在同一结果里。重建上线用 [[13 Modular RAG|Modular RAG]] 的蓝绿/影子索引：旧版本继续服务，新版本通过以下回归才切换。

1. **格式与血缘**：每个资产都有必填字段、父子链不悬空、manifest 覆盖 parser/renderer/OCR/chunker/captioner/视觉检索/权限策略。
2. **ACL 正负例**：同租户 allow 可从召回到 context；deny 覆盖 allow；跨租户、缺策略、旧 `policy_version` 都拒绝。
3. **撤权**：先验证旧 query hit、cache、原件/页图/crop、已构造 context 全部立刻不可读，再检查异步向量/对象/缓存/日志清理回执。
4. **处理平面定位**：同一 `user.region` 不同分类/租户走不同获批平面；未获批的向量库、模型端点、日志落点一律拒绝。
5. **成本回归**：比较每页 OCR/caption/视觉多向量数量、对象字节、重建时长、检索 p95 与基线；超预算不切流，即便相关性指标更高。

## 面试高频

**Q1：为什么只给原文档或 chunk 打 ACL 不够？**

因为 RAG 的可读取副本远多于 chunk：OCR/layout/table JSON、HTML、页图、crop、caption、文本/图像/多向量 embedding、缓存和 trace 都可能绕过原件。每个资产都要带 `source_doc_id/version`、`asset/parent_id`、`tenant + allow/deny + policy_version`，读取时沿同一授权决策重查。

**Q2：用户撤权或删除文档，为什么先 fail-closed？**

异步删除向量、对象或缓存有延迟和失败重试；若先等它们删完，窗口内仍能召回。正确顺序是同步把源版本/策略标为 revoked，让所有读取点立即拒绝，再用资产树异步清理 vector、object、cache、trace/log，并以回执验收。

**Q3：`user.region` 为什么不能解决数据驻留？**

它只是用户位置，不是数据分类、合同约束或云处理边界。路由应由 `(tenant, data_classification) → approved processing plane` 决定，并约束 region、账户、KMS、向量库、模型和日志端点。GDPR 的关键也不是一句“EU 必须本地化”，而是对第三国传输满足 Chapter V 条件的要求。

**Q4：为什么不能给 BM25、dense、CLIP、MaxSim 统一设阈值？**

四者的分数不是同一量纲。分别产出候选并校准到可比的相关性概率，再融合；最终以授权、处理平面、血缘、证据覆盖、重复率和上下文成本组成质量门。分数高但无权或解析失效，仍必须拒绝。

**Q5：重建 manifest 为什么要包含 parser 和 permission policy？**

embedding 只是一层派生物。parser/renderer/OCR/chunker/captioner 改动会改变内容与定位；视觉检索器改动会改变向量；权限策略改动会改变可见集合。缺任一版本就无法解释某个答案究竟基于什么资产和什么规则产生。

## 关键事实

- 治理单位是**可寻址的派生资产树**，覆盖 OCR/layout/table JSON、HTML、page image/crop、caption、多种 embedding、cache、trace 和日志；每个节点继承 `source_doc_id/version`、`asset/parent_id`、ACL 与 `policy_version`。
- ACL 至少表达 `tenant + allow + deny + policy_version`；**deny 优先**，缺元数据/策略/处理平面信息时 fail-closed。授权需在召回、cache hit、原件/crop 获取、生成 context 四处重复执行。
- 删除/撤权的顺序是：**同步 fail-closed → 异步、可回执地清理**向量、对象存储、缓存和 trace/log 载荷；不能等后台清理完成才阻断访问。
- 数据处理位置由**数据分类 + 租户批准的 processing plane**决定，`user.region` 不等于数据地域。GDPR Chapter V / Article 44 约束第三国传输及 onward transfer 的条件；地域部署不是对法规的替代性简写。
- BM25、dense、CLIP、MaxSim 分数不可横比：先按支路候选与本支路质量信号过滤，再校准融合，并用授权、血缘、证据覆盖和成本等集合质量门决定是否生成。
- manifest/rebuild 必须覆盖 parser、renderer、OCR、chunker、captioner、视觉检索器和权限策略；上线前跑格式/血缘、ACL 正负例、撤权、处理平面定位及成本回归。
- 本篇与 [[16 检索安全与访问控制|检索安全与访问控制]]（授权与投毒）、[[15 多模态 RAG|多模态 RAG]]（页图、crop、视觉检索）、[[11 生成层：引用归因与忠实度|生成层：引用归因与忠实度]]（证据归因）和 [[38 Agent 评估与可观测性|Agent 评估与可观测性]]（trace/审计）共同构成生产 RAG 的治理面。
