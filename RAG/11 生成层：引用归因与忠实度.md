[[11 生成层：引用归因与忠实度|生成层：引用归因与忠实度]] 是 RAG 三段式「检索-增强-生成」里最后那个 **G**:把检索到的证据交给 LLM 后,如何让它**只用证据说话、每句话能溯源、不偷偷编造**。检索做得再好,生成这一步若放飞自我(忽略证据、张冠李戴、补充看似合理却没出处的细节),整套 [[01 什么是 RAG|什么是 RAG]] 系统照样输出不可信的答案。这一篇专讲生成端的三件事:grounding(锚定证据)、citation(带来源标注)、faithfulness(忠实校验)。

## 本质:检索把料找对,生成才是「说不说人话且讲不讲信用」

[[02 Naive RAG 与失败模式|Naive RAG 与失败模式]] 里有个反直觉的事实:**即便检索召回了完全正确的文档,LLM 仍可能给出错误或无依据的答案**。原因是 LLM 的参数里本就压着海量「记忆」,生成时它会**混用检索证据和自己的内部记忆**——有时内部记忆覆盖了证据(明明文档写 2019 年,它按记忆答 2020),有时它补充了证据里根本没有的细节(hallucinated specifics)。生成层要解决的核心矛盾就是:

> 让 LLM 的输出**严格被检索证据所支撑(grounded)**,而不是被它的参数记忆带跑。

打个比方:这像一场**开卷考试**——规则是"只能抄发下来的资料,不许凭脑子里背的东西作答"。grounding 就是反复叮嘱"只准看桌上这几页";citation 是要求"每写一句都标清抄的是第几页",方便阅卷人翻回去核对;faithfulness 校验则是阅卷人事后逐句对资料,逮住"资料里根本没写、却被你编进去"的句子。学生脑子里的旧记忆(参数记忆)再丰富,只要和发的资料冲突,就以资料为准。

围绕这个矛盾,生成层有三个抓手,层层递进:

- **Grounding(锚定)**:prompt 层面约束「只用给定上下文,上下文没有就说不知道」,让生成行为锚在证据上。
- **Citation / Attribution(引用 / 归因)**:让生成的事实论断**带上来源标注 [1][2]**,使「这句话指向哪个片段」可机器解析、可人工点击回看。
- **Faithfulness 校验(忠实度)**:**事后**检查「论断的语义是否真被其引用的证据集合支撑」,NLI 与 self-check 都只是可用的判别手段。

这里至少有四个不能混为一谈的问题:

| 层次 | 问的是什么 | 最小输入 | 通过不代表什么 |
|---|---|---|---|
| **Provenance(来源指针)** | `[7]` 是否能解析到正确版本的文档、段落或字符范围 | citation token + source id/offset | 指针存在不代表该来源支持论断 |
| **Citation completeness / correctness(引用完整性 / 正确性)** | 每个应核查的事实是否有引用?每个引用是否与该事实相关且可支撑? | 原子事实 + 引用 + 被引证据 | 有引用且编号正确不代表多跳推理已经蕴含 |
| **Claim→evidence entailment(论断到证据蕴含)** | 将引用 token 剥离后,事实命题能否由**一个或多个**证据片段共同推出? | 干净论断 + 证据集合 | 被当前证据支撑不代表世界事实为真 |
| **Answer correctness / accuracy(答案正确性)** | 答案是否与外部事实、标注答案或权威基准一致? | 答案 + gold reference / 人工裁决 | 客观正确也不代表它遵守了「只用给定证据」 |

注意区分 **accuracy(对不对客观事实)** 与 **faithfulness(忠不忠于给定证据)**。前者通常需要 gold reference、权威数据或人工裁决;后者可只针对这次 RAG 输入的证据做判定,却依然需要实际证据而非空泛的「reference-free」标签。检索来的证据本身若过期或错误,答案可以忠实却不正确——证据质量还要由检索与 [[17 检索数据治理|检索数据治理]] 负责。

## 小数字手算:有引用、被支撑、答得对是三笔不同的账

设回答拆出 3 个原子事实 $C=\{c_1,c_2,c_3\}$。$c_1$ 和 $c_2$ 分别带 `[1]`、`[2]`,$c_3$ 无引用;人工复核发现 `[1]`、`[2]` 都确实对应各自的论断,而由这两个来源共同也只能支撑前两句。于是:

- citation completeness $=2/3=66.7\%$;
- citation correctness $=2/2=100\%$(已给出的两个指针都没张冠李戴);
- claim→evidence support $=2/3=66.7\%$。

若外部权威记录又表明 $c_2$ 已过期,则 answer accuracy 只有 $1/3=33.3\%$。因此「结构化地指向了两段来源」既不能替代蕴含判断,也不能替代对外部事实的正确性判断。

## 公式推导:从原子事实到四类分数

令 $Z_i$ 是论断 $c_i$ 标注的证据 id 集合,$E_{Z_i}$ 是取出的证据片段集合,$\operatorname{Support}$ 是人工或模型判定。将答案先拆成可核查的原子事实,可写成:

$$
\begin{aligned}
\operatorname{Completeness} &= \frac{1}{|C|}\sum_i \mathbb{1}[Z_i\neq\varnothing]\\
\operatorname{CitationCorrectness} &= \frac{\sum_i\sum_{z\in Z_i}\mathbb{1}[\operatorname{Support}(e_z,c_i)]}{\sum_i|Z_i|}\\
\operatorname{EntailedSupport} &= \frac{1}{|C|}\sum_i\mathbb{1}[\operatorname{Support}(E_{Z_i},c_i)]\\
\operatorname{Accuracy} &= \frac{1}{|C|}\sum_i\mathbb{1}[c_i\text{ 与外部基准 }R\text{ 一致}]
\end{aligned}
$$

第二式逐个看被标注的来源,第三式则允许多个片段**合取**后才支撑一条综合结论。$R$ 只出现在 accuracy 里:没有它,不能把「有据」偷换成「客观正确」。

## 机制

### 1. Grounding:用 prompt 把模型按在证据上

最便宜也最先做的一招,是在 prompt 里写死约束。常见模板要素:

- **闭卷转开卷的指令**:「仅根据下面提供的上下文回答,不要使用你自己的知识。」
- **缺证据时的逃生口**:「如果上下文中没有足够信息,请回答『根据已有资料无法确定』,不要猜测。」——这一句极其重要,它把模型「宁可瞎编也要给个答案」的倾向显式关掉,是抗幻觉的第一道闸。
- **引用强制**:「在每个事实性句子末尾,用 [编号] 标注它依据的来源片段。」

这套约束本质是 [[20 上下文工程|上下文工程]] 在生成端的应用:不改模型,只改喂进去的指令和上下文结构,就能显著降低 off-context 生成。但它**不是硬保证**——模型仍可能违背指令,所以后面还需要引用核对和校验兜底。

### 2. Inline Citation 与 Attribution:让每句可溯源

**Inline citation** 指生成时就把来源编号嵌进答案文本里:「公司成立于 2003 年[1],总部位于杭州[2]。」**Attribution(归因)** 要求答案中的事实论断能映射回具体证据片段(span-level 或 sentence-level),做到「逐句可溯源」。

无论是文本里的 `[n]`,还是结构化字段 `{source_id, start, end}`,本质都是 **provenance 指针**:它解决「能否定位到哪段材料」,不自动解决「这段材料是否蕴含这句话」。结构化 citation 能减少编号解析与 offset 对齐的错误,但仍要评 citation correctness、citation completeness 和 claim→evidence entailment;不要把结构化输出当成蕴含保证。

两种实现路径:

- **生成时引用(post-hoc 之外的 inline)**:让 LLM 一边生成一边标 [n],编号对应喂进去的证据片段顺序。最自然,但模型可能标错号(把出自 [2] 的话标成 [1])。
- **事后归因(post-hoc attribution)**:先让 LLM 自由生成答案,再用一个独立步骤把每句话**对齐**回最相关的证据片段。代表工作 **RARR**(Gao et al. 2023,Retrofit Attribution using Research and Revision)会为既有输出补归因并据此修订。

归因的价值不只是「好看」:它让用户能**一键验证**(点 [2] 跳到原文),把信任的负担从「相信 LLM」转移到「相信可查的来源」;也是 [[16 检索安全与访问控制|检索安全与访问控制]] 审计的抓手——能说清答案用了哪些文档及其版本。

### 3. 不同评估框架的指标不要混写

faithfulness、answer relevancy、context relevancy 都很有用,但它们并非所有框架共享的一组同名、同定义指标。Ragas 与 TruLens 的输入、实现和命名各不相同;选指标时应写清**问什么、用什么证据、谁负责**,不要把它们拼成一个标准「三角」或宣称彼此正交。

| 维度 | 测的是 | 对齐关系 | 谁的责任 |
|---|---|---|---|
| **Faithfulness / groundedness** | 原子论断是否被给定证据支撑 | 答案 ⟸ 上下文 | 生成端,无需 gold answer 但必须有证据 |
| **Answer relevancy** | 回答是否回应问题、是否跑题 | 答案 ⟺ 问题 | 生成端,可由人工或 judge 评 |
| **Context relevancy / retrieval quality** | 给定上下文是否有助于回答问题 | 上下文 ⟺ 问题 | 检索端 |
| **Answer correctness** | 回答是否符合外部事实或标准答案 | 答案 ⟺ $R$ | 端到端,需要 reference 或人工裁决 |

这些分数可能相关,却没有任何一个蕴含另一个:检索到了相关材料不保证答案切题,答案切题不保证有证据,证据充分也不保证来源本身没错。把它们分别记录,才能定位是检索、生成、引用映射还是知识治理出了问题——详见 [[18 RAG 评估|RAG 评估]]。

### 4. 抗幻觉的校验手段:从 prompt 约束到 NLI 到 self-check

按强度从弱到强:

1. **Prompt 约束 + 逃生口**(上文 grounding):最便宜,治标。
2. **引用强制 + 编号核对**:要求带 [n],再用脚本检查「每个论断是否真有引用、引用的片段是否真包含该信息」。
3. **NLI / 蕴含校验(entailment)**:先剥离 citation token,把原子事实当 hypothesis、把**全部被引用片段的集合**当 premise,判 entail / neutral / contradict。neutral 或 contradict 是「当前证据不足、冲突或判别器不确定」的复核信号,可触发人工复核、标注不确定或补检索,**不能直接判为模型编造**。**TRUE**(Honovich et al. 2022)跨 11 个数据集发现大型 NLI 与 QG-QA 方法表现强且互补,应把两类方法作为起点,而非宣称某一个是唯一冠军。
4. **Self-check / 事后自核验**:让 LLM(或另一个 LLM)回头审自己的答案——「这句话能从证据里找到依据吗?」。这正是 [[13 Reflection 与 Reflexion|Reflection 与 Reflexion]] 思想在生成层的落地,也是 [[12 Self-RAG、CRAG 与 Adaptive RAG|Self-RAG、CRAG 与 Adaptive RAG]] 中 Self-RAG 的 ISSUP(is supported)反思 token 在做的事。强化版会把校验结果反馈回去 [[10 重排序 Reranking|重排序 Reranking]] 或重新检索。

## 可跑最小代码

下面演示「先识别事实 claim,再解析/剥离 citation token,最后以多证据集合复核」的骨架。`is_factual_claim` 在生产中应替换为经过标注集验证的 claim extractor;示例仍能直接运行:

```python
import re

CITATION_RE = re.compile(r"\[(\d+)\]")


def grounded_generate(question, passages, llm):
    """受约束生成:只用证据 + 强制 inline citation [n]。"""
    ctx = "\n".join(f"[{i+1}] {p}" for i, p in enumerate(passages))
    prompt = (
        "只根据下面的来源回答问题。每个事实句末尾用 [编号] 标注依据的来源;"
        "若来源中没有足够信息,直接回答「资料不足,无法确定」,不要猜测。\n"
        f"来源:\n{ctx}\n\n问题:{question}\n答案:"
    )
    return llm(prompt)

def identify_factual_claims(answer, is_factual_claim):
    """先筛事实 claim;过渡、礼貌和纯建议句不进入证据判定。"""
    sentences = re.split(r"(?<=[。！？!?])", answer)
    return [s.strip() for s in sentences if s.strip() and is_factual_claim(s)]


def parse_and_strip_citations(raw_claim):
    """解析 [n],同时剥离 token,避免把 '[2]' 交给 NLI 当成命题内容。"""
    cited_ids = [int(n) - 1 for n in CITATION_RE.findall(raw_claim)]
    clean_claim = CITATION_RE.sub("", raw_claim).strip()
    return clean_claim, sorted(set(cited_ids))


def cited_evidence(cited_ids, passages):
    """允许一个 claim 由多个片段共同支撑,并保留越界引用供 provenance 复核。"""
    valid = [i for i in cited_ids if 0 <= i < len(passages)]
    invalid = [i + 1 for i in cited_ids if i < 0 or i >= len(passages)]
    return [passages[i] for i in valid], invalid


def verify_claims(answer, passages, is_factual_claim, nli):
    """返回复核队列;NLI 非 entail 绝不直接等同于『编造』。"""
    report = []
    for raw_claim in identify_factual_claims(answer, is_factual_claim):
        claim, cited_ids = parse_and_strip_citations(raw_claim)
        evidence, invalid_ids = cited_evidence(cited_ids, passages)
        item = {"claim": claim, "citation_ids": [i + 1 for i in cited_ids]}
        if invalid_ids:
            item.update(status="provenance_error", next_step="修正 source id 或 offset")
        elif not cited_ids:
            item.update(status="missing_citation", next_step="补 citation 或明确不确定")
        else:
            label = nli(premise="\n".join(evidence), hypothesis=claim)
            if label == "entail":
                item.update(status="supported", next_step="可发布,仍另测 accuracy")
            else:
                item.update(
                    status=f"needs_review:{label}",
                    next_step="人工复核、标注不确定或补检索;不要自动定性为编造",
                )
        report.append(item)
    return report


# 最小演示:真实系统用已验证的 claim extractor 和 NLI/QG-QA 判别器替换两个 lambda。
passages = ["[1] Atlas 于 2003 年成立。", "[2] Atlas 总部在杭州。"]
answer = "Atlas 于 2003 年成立[1]。它有 1 万名员工[2]。谢谢阅读。"
is_fact = lambda text: any(marker in text for marker in ("成立", "员工"))
nli = lambda premise, hypothesis: "entail" if "2003" in premise and "2003" in hypothesis else "neutral"
print(verify_claims(answer, passages, is_fact, nli))
```

要点:① ❌ 先按句找 `[n]`、直接把整句交给 NLI,会漏掉无引用事实,也让 token 污染 hypothesis;✅ 先做 `identify_factual_claims`、再 `parse_and_strip_citations`。② ❌ 只拿单一片段判断综合句;✅ 用 `cited_evidence` 提供多证据集合,同时记录无效 source id。③ ❌ `neutral`/`contradict` 就删句并记为编造;✅ 入 `needs_review` 队列,再人工复核、显式不确定或补检索。④ NLI 可与 QG-QA、LLM judge 交叉使用;它们测的是当前证据支撑,answer accuracy 仍需外部 reference 或人工裁决。

## 何时用 / 坑

**该重视生成层**:答错代价高的领域(医疗、法律、金融),用户需要点击核查来源的产品(企业知识库问答、研究助手),以及任何对外输出要担责的场景。

**可轻量化**:内部探索性问答、demo、容错高的场景,grounding prompt + 引用足矣,不必上 NLI 回路。

**坑**:
- **引用看着对、其实张冠李戴**:模型给每句话都标了 [n],但标的号和内容对不上(标了 [1] 实际出自 [3])。引用的「有」不等于「对」,必须核对编号与内容,别被「带引用」的表象骗了。
- **忠实但错误**:答案忠实复述了证据,可证据本身是过期/错误的。这时 faithfulness 满分也没用,问题在检索和 [[17 检索数据治理|检索数据治理]],不在生成层——别把锅算错。
- **过度保守(over-refusal)**:逃生口太强,模型动不动就「资料不足」,把本可答的问题也拒了。约束力度要调,可允许「证据支持部分 + 明确标注不确定部分」。
- **NLI 校验慢且贵**:逐句过蕴含模型,长答案延迟高。可只校验高风险事实句,或抽样校验。
- **抽象/综合类答案难归因**:总结、推理、跨多片段综合的句子,没有单一来源片段能蕴含它,归因和 NLI 都会误报。这类句子需 span-level 多片段联合判断,或容忍部分无单点引用。
- **引用强制反伤流畅度**:句句带 [n] 读着割裂。可只在事实性论断标注,过渡句不标。

## 关键事实

- 生成层 = RAG 的 **G**,核心矛盾是**让 LLM 被检索证据支撑(grounded),而非被参数记忆带跑**;检索对了生成仍可能编造(见 [[02 Naive RAG 与失败模式|Naive RAG 与失败模式]])。
- 三个抓手:**grounding**(prompt 约束只用证据 + 逃生口)、**citation/attribution**(来源可定位)、**faithfulness 校验**(核验 claim→evidence 支撑)。
- 必须分开记录 provenance、citation completeness/correctness、claim→evidence entailment 与 answer accuracy;这些量可能相关,但没有一个自动推出另一个。
- **faithfulness** 只问是否忠于给定证据,可不需要 gold answer;**accuracy** 问是否符合外部事实,需要 gold reference、权威数据或人工裁决。
- NLI/QG-QA/self-check 都是复核工具。NLI 非 entail 应触发复核、显式不确定或补检索,不是自动给回答贴「编造」标签。
- **ALCE**(Gao et al.,EMNLP 2023)从 fluency、correctness、citation quality 三方面评带引用生成;**TRUE**(Honovich et al.,NAACL 2022)发现大型 NLI 与 QG-QA 方法强且互补;**RARR**(Gao et al.,ACL 2023)代表事后归因与修订。

## 工业界实践

生成层在生产里是"信任收口"的最后一道——召回再好,这步放飞就前功尽弃;尤其对外担责的产品(企业问答、研究助手、医疗法律金融),grounding + citation + faithfulness 校验基本是硬要求。

**主流做法与组件**
- **带引用生成接口**:产品可输出可见的 `[n]`,也可返回结构化 `{source_id, start, end}`。后者让前端稳定跳转、让审计记录版本与 offset,却只是**来源指针**;仍须独立检查 citation completeness、citation correctness 与 claim→evidence entailment。
- **忠实度校验组件**:
  - **NLI/蕴含判别器**:将剥离 citation token 的原子事实当 hypothesis、将一个或多个被引片段当 premise,输出复核信号。TRUE 表明大型 NLI 与 QG-QA 方法值得并用。
  - **QG-QA 或 LLM-as-judge**:从论断生成可由证据回答的问题,或请独立 judge 检查支撑关系;前者补足 NLI 的判断视角,后者需防同源偏差。
- **评估框架**:Ragas、TruLens 等框架各自定义输入与 feedback;配置时明确某项到底评 evidence support、问题相关性、citation quality 还是有 gold reference 的 correctness,不要拿不同框架的名称直接横向等同。

**典型架构(带校验的生成回路)**
```
top-k 证据 → grounded prompt(只用证据 + 逃生口 + 强制 [n])
   → LLM 生成带 inline citation
   → 识别事实 claim → 解析并剥离 citation token
   → provenance + citation 完整性/正确性 + 多证据 NLI/QG-QA 复核
   ├─证据充分→放行
   └─证据不足/冲突/不确定→人工复核、标注不确定或补检索
   → 输出 + 可点击来源 + 每条 claim 的审计记录
```

**规模化与延迟/成本权衡**
- **逐句校验贵**:长答案延迟高。工程上:① 只校验**高风险事实 claim**(数字、日期、人名、断言),过渡/礼貌句跳过;② 抽样校验 + 阈值告警;③ 先用轻量判别器,再把低置信样本交人工或大模型;④ 校验**异步/离线**跑,只在高敏域同步阻塞。
- **结构化 citation 减少解析错误**:强制 source id 与 offset 的格式可避免「标了 [1] 实际无对应片段」,但不会避免「[1] 虽存在却不支持这句话」;后者仍需语义核验。
- 缓存:相同 (query, 证据) 的校验结果可缓存。

**可观测**
- trace 每条 claim 的"source id/offset + citation 完整性 + 证据集合 + NLI/QG-QA 结果 + 复核结论",线上盯 **无引用事实句比例、无效 provenance、support 分布、over-refusal 率(资料不足占比)**;accuracy 另接 gold set 或人工抽检。

**踩坑与最佳实践**
- **「带引用」必须核对两层**:先核 token 是否指向正确文档/版本/offset(provenance),再核该证据是否支持清洗后的 claim。
- **逃生口力度要调**:太强→over-refusal(本可答的也拒),太弱→照编;折中是"证据支持部分如实答 + 明确标注不确定部分"。
- **抽象/综合句难归因**:总结/跨片段推理句没有单一来源能蕴含,NLI 会误报;改为多片段联合判断并给复核队列,不要把 NLI 失败直接记成编造。
- **faithfulness 满分 ≠ 正确**:证据本身错(过期/有误)时,忠实复述也是错答——锅在检索和 [[17 检索数据治理|检索数据治理]],别算到生成层。
- **引用别句句标**:只在事实性论断标 [n],过渡句不标,保流畅。

## 面试高频

**Q1:检索召回了完全正确的文档,LLM 为什么还会答错或编造?**
标准答:LLM 参数里压着海量"记忆",生成时会**混用检索证据和内部记忆**——有时内部记忆覆盖证据(文档写 2019,它按记忆答 2020),有时补充证据里根本没有的细节(hallucinated specifics)。生成层的核心矛盾就是让输出被证据**支撑(grounded)**而非被参数记忆带跑。
- 追问"怎么治?":三抓手——grounding prompt(只用证据 + 逃生口)、citation(带 [n] 可溯源)、faithfulness 校验(NLI/self-check 抓编造)。

**Q2:accuracy 和 faithfulness 有什么区别?RAG 生成层管哪个?**
标准答:**accuracy** = 答案对不对**客观事实**;**faithfulness** = 答案忠不忠于**给定证据**。RAG 生成层主要管 faithfulness——哪怕证据本身错,只要答案如实复述证据(不另编)生成层就尽责;证据对不对是检索/治理的责任。这是 RAG"责任分离"的关键。
- 陷阱:把"答案错了"全归生成层——可能是检索召回了错证据,生成层很忠实地复述了它。

**Q3:provenance、citation quality、faithfulness 与 accuracy 怎么区分?**
标准答:provenance 只问 citation token 能否定位到文档/版本/offset;citation completeness/correctness 问事实是否都标了来源、标的来源是否恰当;faithfulness 问剥离 token 后的 claim 是否被一个或多个证据片段支撑;accuracy 问答案是否符合外部事实。结构化 citation 只能保证来源指针可解析,不保证蕴含;faithfulness 不必有 gold answer,accuracy 则要 gold reference、权威数据或人工裁决。
- 追问:这些量可能相关,但相关不等于正交或互相推出;要分别记录,才能定位是检索、映射还是生成出了问题。

**Q4:抗幻觉有哪些手段,从弱到强?**
标准答:① prompt 约束 + 逃生口(最便宜,治标);② citation 的 provenance 与完整性/正确性核对;③ 对清洗后的原子 claim 做多证据 NLI/QG-QA 复核;④ self-check 或人工复核,必要时补检索。NLI/QG-QA 是互补工具,不能由单一指标包打天下。
- 追问"NLI 怎么用在这":把剥离 citation token 的 claim 当 hypothesis、把被引证据集合当 premise。neutral/contradict 是复核、标注不确定或补检索的信号,不直接判模型编造。

**Q5:inline citation、结构化 citation 和 post-hoc attribution 有什么区别?**
标准答:inline 是生成时嵌 `[n]`,自然但模型可能标错号;结构化 citation 用 source id/offset 表达指针,便于程序定位却不保证语义蕴含;post-hoc attribution 是先生成、再把 claim 对齐到证据并可修订(如 RARR)。三者都要核对 provenance、citation quality 与 claim→evidence support,"带引用"不等于"引用对"。

**Q6:逃生口("资料不足就说不知道")太强会有什么问题?**
标准答:**over-refusal**——模型动不动就拒答,把本可答的也挡了。约束力度要校准,折中为"证据支持的部分如实答 + 明确标注不确定部分",而非一刀切拒答。

## 知识拓展

**关键论文与基准(带年份)**
- **ALCE**(Gao et al.,EMNLP 2023):带引用生成的端到端评测基准,自动评 fluency、correctness、citation quality;其任务要求检索支撑证据并带引用生成,因此不能只把它缩成某个「reference-free 三角」的别名。
- **TRUE**(Honovich et al.,NAACL 2022):在 11 个数据集上评事实一致性度量,指出**大型 NLI 与 QG-QA 方法强且互补**,适合并列作为评测起点。
- **RARR**(Gao et al.,ACL 2023):**Retrofit Attribution using Research and Revision**,为既有输出寻找 attribution,再修订不受支持的内容,是 post-hoc attribution 的代表。
- **AttributedQA / Attributable to Identified Sources(Rashkin et al. 2021,AIS 框架)**:把"可归因"形式化为评估协议。
- **FActScore(Min et al. 2023)**:把长答案拆成原子事实(atomic facts)逐个判可支撑,长文本忠实度细粒度评测的代表。
- **实践原则**:先把答案拆成原子事实,再分别测来源可定位、引用质量、证据蕴含与外部正确性;不要以某个供应商或框架名称替代评测定义。

**底层联系**:本篇的 self-check 回路是 [[13 Reflection 与 Reflexion|Reflection 与 Reflexion]] 在生成层的落地;ISSUP(is supported)正是 Self-RAG 把忠实度自评**内化成反思 token**(见 [[12 Self-RAG、CRAG 与 Adaptive RAG|Self-RAG、CRAG 与 Adaptive RAG]]);grounding 约束属 [[20 上下文工程|上下文工程]] 在生成端的应用。引用编号到证据片段的映射,本质也是检索向量空间里的对齐,可回看 [[深度学习基础/03 点积、范数与相似度|点积、范数与相似度]] 理解"哪个片段最支撑这句"如何用相似度近似。

**边界与反模式**
- **反模式一:只看"有没有引用"不核两层内容**——张冠李戴(标 [1] 实出 [3])与「[1] 存在但不支持该 claim」都会过表面检查。
- **反模式二:把 faithfulness 当 accuracy 用**——证据错时忠实复述也是错答,锅不在生成层。
- **反模式三:句句强制引用**——读着割裂,过渡句不该标。
- **边界**:容错高的内部探索/demo 用 grounding prompt + citation/provenance 核对即可,不必同步上 NLI 回路;抽象综合类答案天然难归因,强上逐句单片段 NLI 会高误报。
