[[11 生成层：引用归因与忠实度|生成层：引用归因与忠实度]] 是 RAG 三段式「检索-增强-生成」里最后那个 **G**:把检索到的证据交给 LLM 后,如何让它**只用证据说话、每句话能溯源、不偷偷编造**。检索做得再好,生成这一步若放飞自我(忽略证据、张冠李戴、补充看似合理却没出处的细节),整套 [[01 什么是 RAG|什么是 RAG]] 系统照样输出不可信的答案。这一篇专讲生成端的三件事:grounding(锚定证据)、citation(带来源标注)、faithfulness(忠实校验)。

## 本质:检索把料找对,生成才是「说不说人话且讲不讲信用」

[[02 Naive RAG 与失败模式|Naive RAG 与失败模式]] 里有个反直觉的事实:**即便检索召回了完全正确的文档,LLM 仍可能给出错误或无依据的答案**。原因是 LLM 的参数里本就压着海量「记忆」,生成时它会**混用检索证据和自己的内部记忆**——有时内部记忆覆盖了证据(明明文档写 2019 年,它按记忆答 2020),有时它补充了证据里根本没有的细节(hallucinated specifics)。生成层要解决的核心矛盾就是:

> 让 LLM 的输出**严格被检索证据所支撑(grounded)**,而不是被它的参数记忆带跑。

打个比方:这像一场**开卷考试**——规则是"只能抄发下来的资料,不许凭脑子里背的东西作答"。grounding 就是反复叮嘱"只准看桌上这几页";citation 是要求"每写一句都标清抄的是第几页",方便阅卷人翻回去核对;faithfulness 校验则是阅卷人事后逐句对资料,逮住"资料里根本没写、却被你编进去"的句子。学生脑子里的旧记忆(参数记忆)再丰富,只要和发的资料冲突,就以资料为准。

围绕这个矛盾,生成层有三个抓手,层层递进:

- **Grounding(锚定)**:prompt 层面约束「只用给定上下文,上下文没有就说不知道」,让生成行为锚在证据上。
- **Citation / Attribution(引用 / 归因)**:让生成的每个论断**带上来源标注 [1][2]**,使「这句话出自哪个片段」可机器核对、可人工点击回看。
- **Faithfulness 校验(忠实度)**:**事后**用 NLI/蕴含模型或 self-check 检查「每句话是否真被它引用的证据蕴含」,抓出编造。

注意区分两个常被混淆的词:**accuracy(答案对不对客观事实)** vs **faithfulness(答案忠不忠于给定证据)**。RAG 生成层主要管后者——哪怕检索来的证据本身是错的,只要答案忠实复述了证据(而非另编),生成层就算尽责;证据对不对是检索/治理([[17 检索数据治理|检索数据治理]])的责任。这种「责任分离」是理解 RAG 评估的关键。

## 机制

### 1. Grounding:用 prompt 把模型按在证据上

最便宜也最先做的一招,是在 prompt 里写死约束。常见模板要素:

- **闭卷转开卷的指令**:「仅根据下面提供的上下文回答,不要使用你自己的知识。」
- **缺证据时的逃生口**:「如果上下文中没有足够信息,请回答『根据已有资料无法确定』,不要猜测。」——这一句极其重要,它把模型「宁可瞎编也要给个答案」的倾向显式关掉,是抗幻觉的第一道闸。
- **引用强制**:「在每个事实性句子末尾,用 [编号] 标注它依据的来源片段。」

这套约束本质是 [[20 上下文工程|上下文工程]] 在生成端的应用:不改模型,只改喂进去的指令和上下文结构,就能显著降低 off-context 生成。但它**不是硬保证**——模型仍可能违背指令,所以后面还需要引用核对和校验兜底。

### 2. Inline Citation 与 Attribution:让每句可溯源

**Inline citation** 指生成时就把来源编号嵌进答案文本里:「公司成立于 2003 年[1],总部位于杭州[2]。」**Attribution(归因)** 是更强的属性:答案里**每一个论断都能映射回**支撑它的具体证据片段(span-level 或 sentence-level),做到「逐句可溯源」。

两种实现路径:

- **生成时引用(post-hoc 之外的 inline)**:让 LLM 一边生成一边标 [n],编号对应喂进去的证据片段顺序。最自然,但模型可能标错号(把出自 [2] 的话标成 [1])。
- **事后归因(post-hoc attribution)**:先让 LLM 自由生成答案,再用一个独立步骤把每句话**对齐**回最相关的证据片段。代表工作 **RARR**(Gao et al. 2022,Retrofit Attribution using Research and Revision)就是事后给已生成文本加归因并据此修订。

归因的价值不只是「好看」:它让用户能**一键验证**(点 [2] 跳到原文),把信任的负担从「相信 LLM」转移到「相信可查的来源」;也是 [[16 检索安全与访问控制|检索安全与访问控制]] 审计的抓手——能说清答案用了哪些文档。

### 3. 忠实度三角:faithfulness / answer relevancy / context relevancy

评估 RAG 生成,业界(尤其 RAGAS 框架)常用**三个正交维度**,构成「忠实度三角」:

| 维度 | 测的是 | 对齐关系 | 谁的责任 |
|---|---|---|---|
| **Faithfulness 忠实度** | 答案是否被上下文支撑、有没有编造 | 答案 ⟸ 上下文 | 生成端 |
| **Answer Relevancy 答案相关性** | 答案切不切题、有没有跑偏/废话 | 答案 ⟺ 问题 | 生成端 |
| **Context Relevancy 上下文相关性** | 检索召回的料是不是对的 | 上下文 ⟺ 问题 | 检索端 |

三者**互相独立**,必须分开测:检索召回了对的料(context relevancy 高)≠ 答案切题(answer relevancy 高)≠ 答案没编造(faithfulness 高)。一个答案可能忠实复述了证据(faithfulness 高)却答非所问(answer relevancy 低);也可能答得很切题(answer relevancy 高)却掺了证据里没有的私货(faithfulness 低)。把这三个维度拆开,才能定位是检索的锅还是生成的锅——详见 [[18 RAG 评估|RAG 评估]]。

### 4. 抗幻觉的校验手段:从 prompt 约束到 NLI 到 self-check

按强度从弱到强:

1. **Prompt 约束 + 逃生口**(上文 grounding):最便宜,治标。
2. **引用强制 + 编号核对**:要求带 [n],再用脚本检查「每个论断是否真有引用、引用的片段是否真包含该信息」。
3. **NLI / 蕴含校验(entailment)**:用自然语言推理模型,把「答案的每句话」当 hypothesis、「它引用的证据片段」当 premise,判 **entail(蕴含)/ neutral(无关)/ contradict(矛盾)**。被判 neutral 或 contradict 的句子就是无依据/编造,可标红、删除或触发重生成。**TRUE**(Honovich et al. 2022)系统比较了多种忠实度自动评测,结论是基于 NLI 的方法和人工判断相关性最强。
4. **Self-check / 事后自核验**:让 LLM(或另一个 LLM)回头审自己的答案——「这句话能从证据里找到依据吗?」。这正是 [[13 Reflection 与 Reflexion|Reflection 与 Reflexion]] 思想在生成层的落地,也是 [[12 Self-RAG、CRAG 与 Adaptive RAG|Self-RAG、CRAG 与 Adaptive RAG]] 中 Self-RAG 的 ISSUP(is supported)反思 token 在做的事。强化版会把校验结果反馈回去 [[10 重排序 Reranking|重排序 Reranking]] 或重新检索。

## 可跑最小代码

下面演示「受约束生成带引用 + NLI 风格的忠实度校验回路」的骨架:

```python
def grounded_generate(question, passages, llm):
    """受约束生成:只用证据 + 强制 inline citation [n]。"""
    ctx = "\n".join(f"[{i+1}] {p}" for i, p in enumerate(passages))
    prompt = (
        "只根据下面的来源回答问题。每个事实句末尾用 [编号] 标注依据的来源;"
        "若来源中没有足够信息,直接回答「资料不足,无法确定」,不要猜测。\n"
        f"来源:\n{ctx}\n\n问题:{question}\n答案:"
    )
    return llm(prompt)

def faithfulness_check(answer, passages, nli):
    """逐句蕴含校验:每句 vs 它引用的片段,返回无依据的句子。"""
    import re
    unsupported = []
    for sent in re.split(r"(?<=[。!?.!?])", answer):
        sent = sent.strip()
        if not sent:
            continue
        cited = [int(n) - 1 for n in re.findall(r"\[(\d+)\]", sent)]  # 解析 [n]
        if not cited:                                  # 事实句却没引用 → 可疑
            unsupported.append((sent, "无引用"))
            continue
        premise = " ".join(passages[i] for i in cited if 0 <= i < len(passages))
        label = nli(premise=premise, hypothesis=sent)  # entail / neutral / contradict
        if label != "entail":
            unsupported.append((sent, label))           # 未被证据蕴含 → 编造嫌疑
    return unsupported

def answer_with_verification(question, passages, llm, nli, max_retry=1):
    ans = grounded_generate(question, passages, llm)
    for _ in range(max_retry):
        bad = faithfulness_check(ans, passages, nli)
        if not bad:
            return ans                                  # 全部有据,放行
        # 把不合格的句子反馈回去,要求只保留有据内容(self-check 回路)
        feedback = "；".join(f"「{s}」({why})" for s, why in bad)
        ans = grounded_generate(
            question + f"\n注意:上一版以下内容缺乏证据支撑,请删除或改为有据表述:{feedback}",
            passages, llm,
        )
    return ans  # 仍有残留则返回最后一版(生产里可降级为「部分无法确定」)
```

要点:① `grounded_generate` 的 prompt 同时压实 grounding(只用证据)、逃生口(资料不足就认)、引用强制三件事;② `faithfulness_check` 是 NLI 思路的极简版——**没引用的事实句**和**未被引用片段蕴含的句子**都算可疑;③ `answer_with_verification` 的 retry 回路就是 self-check,对应 [[13 Reflection 与 Reflexion|Reflection 与 Reflexion]];④ 生产里 `nli` 换成真正的蕴含模型(如基于 NLI 微调的判别器)或一个 LLM-as-judge。

## 何时用 / 坑

**该重视生成层**:答错代价高的领域(医疗、法律、金融),用户需要点击核查来源的产品(企业知识库问答、研究助手),以及任何对外输出要担责的场景。

**可轻量化**:内部探索性问答、demo、容错高的场景,grounding prompt + 引用足矣,不必上 NLI 回路。

**坑**:
- **引用看着对、其实张冠李戴**:模型给每句话都标了 [n],但标的号和内容对不上(标了 [1] 实际出自 [3])。引用的「有」不等于「对」,必须核对编号与内容,别被「带引用」的表象骗了。
- **忠实但错误**:答案忠实复述了证据,可证据本身是过期/错误的。这时 faithfulness 满分也没用,问题在检索和 [[17 检索数据治理|检索数据治理]],不在生成层——别把锅算错。
- **过度保守(over-refusal)**:逃生口太强,模型动不动就「资料不足」,把本可答的问题也拒了。约束力度要调,可允许「证据支持部分 + 明确标注不确定部分」。
- **NLI 校验慢且贵**:逐句过蕴含模型,长答案延迟高。可只校验高风险事实句,或抽样校验。
- **抽象/综合类答案难归因**:总结、推理、跨多片段综合的句子,没有单一来源片段能蕴含它,归因和 NLI 都会误报。这类句子需 span-level 多片段联合判断,或容忍部分无单点引用。
- **引用强制反伤流畅度**:句句带 [n] 读着割裂。可只在事实性论断标注,过渡句不标。

## 关键事实

- 生成层 = RAG 的 **G**,核心矛盾是**让 LLM 被检索证据支撑(grounded),而非被参数记忆带跑**;检索对了生成仍可能编造(见 [[02 Naive RAG 与失败模式|Naive RAG 与失败模式]])。
- 三个抓手:**grounding**(prompt 约束只用证据 + 逃生口)、**citation/attribution**(带 [n] 标注、逐句可溯源)、**faithfulness 校验**(NLI/self-check 抓编造)。
- **忠实度三角**:faithfulness(答案⟸上下文,生成端)/ answer relevancy(答案⟺问题,生成端)/ context relevancy(上下文⟺问题,检索端)**三者正交,分开测**,用于 [[18 RAG 评估|RAG 评估]] 归因责任。
- 区分 **accuracy(对不对客观事实)** vs **faithfulness(忠不忠于证据)**:RAG 生成层主要管后者。
- 抗幻觉强度阶梯:prompt 约束 → 引用核对 → **NLI/蕴含校验** → **self-check 事后核验**(对应 [[13 Reflection 与 Reflexion|Reflection 与 Reflexion]]、[[12 Self-RAG、CRAG 与 Adaptive RAG|Self-RAG、CRAG 与 Adaptive RAG]] 的 ISSUP token)。
- 归因评测基准 **ALCE**(Gao et al. 2023,EMNLP):沿 fluency / correctness / citation quality 三维自动评测 LLM 带引用生成;相关工作 **AttributedQA**、**TRUE**(NLI 忠实度评测)、**RARR**(事后归因 + 修订)。
- 最大的认知陷阱:**「带引用」≠「引用对」**,**「忠实」≠「正确」**——前者要核对编号,后者的对错归检索/治理。

## 工业界实践

生成层在生产里是"信任收口"的最后一道——召回再好,这步放飞就前功尽弃;尤其对外担责的产品(企业问答、研究助手、医疗法律金融),grounding + citation + faithfulness 校验基本是硬要求。

**主流做法与组件**
- **带引用生成的产品级范式**:Perplexity、ChatGPT Search、Bing Copilot、Google AI Overviews 都是 inline citation 的工业标杆——答案句末挂 [n],点击跳原文。企业侧 LlamaIndex `CitationQueryEngine`、LangChain 的"cite sources"链、Anthropic/OpenAI 的 **Citations API**(把引用做成结构化 span,模型直接输出"这段话出自文档 X 的第 Y–Z 字符")让归因从"模型自觉标号"升级为"框架保证可溯源"。
- **忠实度校验组件**:
  - **NLI/蕴含判别器**:把答案句当 hypothesis、引用片段当 premise,判 entail/neutral/contradict;**TRUE**(Honovich 2022)证实 NLI 与人工判断相关性最强。
  - **LLM-as-judge**:用另一个 LLM 逐句问"这句能从证据找到依据吗",最灵活但有成本和自评偏差。
  - **专用 grounding 模型**:Google **AGREE**、**Vectara HHEM(Hughes Hallucination Evaluation Model)**(开源、轻量、出 hallucination leaderboard)、各家"groundedness API"专做这件事,比通用 LLM 快且便宜。
- **评估框架**:**Ragas**(reference-free,三维 faithfulness / answer relevancy / context relevancy + context precision/recall)、**TruLens**("RAG triad" feedback functions + OpenTelemetry tracing 实时测 groundedness)、**DeepEval / Giskard / Phoenix(Arize)**。这三维正是本篇"忠实度三角",见 [[18 RAG 评估|RAG 评估]]。

**典型架构(带校验的生成回路)**
```
top-k 证据 → grounded prompt(只用证据 + 逃生口 + 强制 [n])
   → LLM 生成带 inline citation
   → 逐句 NLI/grounding 校验 → 标红 unsupported 句
   ├─全有据→放行
   └─有编造→反馈回去重生成(self-check 回路,max_retry 兜底)
   → 引用编号-内容核对 → 输出 + 可点击来源
```

**规模化与延迟/成本权衡**
- **逐句 NLI 校验贵**:长答案延迟高。工程上:① 只校验**高风险事实句**(数字、日期、人名、断言),过渡/总结句跳过;② 抽样校验 + 阈值告警;③ 用轻量 HHEM 类专用模型而非大 LLM 当 judge;④ 校验**异步/离线**跑(线上先出答案,后台抽检质量),只在高敏域同步阻塞。
- **引用做成结构化**比"让模型自觉标号"可靠:Citations API 强制 span 对齐,避免"标了 [1] 实际出自 [3]"的张冠李戴。
- 缓存:相同 (query, 证据) 的校验结果可缓存。

**可观测**
- trace 每句的"引用编号 + NLI 标签 + 命中片段",线上盯 **faithfulness 分布、over-refusal 率(资料不足占比)、无引用事实句比例**;这些是生成层健康度的核心指标。

**踩坑与最佳实践**
- **「带引用」必须核对编号-内容**:模型给每句都标了号不代表号对,脚本核对"引用片段是否真含该信息"。
- **逃生口力度要调**:太强→over-refusal(本可答的也拒),太弱→照编;折中是"证据支持部分如实答 + 明确标注不确定部分"。
- **抽象/综合句难归因**:总结/跨片段推理句没有单一来源能蕴含,NLI 会误报;改 span-level 多片段联合判断,或容忍这类句无单点引用。
- **faithfulness 满分 ≠ 正确**:证据本身错(过期/有误)时,忠实复述也是错答——锅在检索和 [[17 检索数据治理|检索数据治理]],别算到生成层。
- **引用别句句标**:只在事实性论断标 [n],过渡句不标,保流畅。

## 面试高频

**Q1:检索召回了完全正确的文档,LLM 为什么还会答错或编造?**
标准答:LLM 参数里压着海量"记忆",生成时会**混用检索证据和内部记忆**——有时内部记忆覆盖证据(文档写 2019,它按记忆答 2020),有时补充证据里根本没有的细节(hallucinated specifics)。生成层的核心矛盾就是让输出被证据**支撑(grounded)**而非被参数记忆带跑。
- 追问"怎么治?":三抓手——grounding prompt(只用证据 + 逃生口)、citation(带 [n] 可溯源)、faithfulness 校验(NLI/self-check 抓编造)。

**Q2:accuracy 和 faithfulness 有什么区别?RAG 生成层管哪个?**
标准答:**accuracy** = 答案对不对**客观事实**;**faithfulness** = 答案忠不忠于**给定证据**。RAG 生成层主要管 faithfulness——哪怕证据本身错,只要答案如实复述证据(不另编)生成层就尽责;证据对不对是检索/治理的责任。这是 RAG"责任分离"的关键。
- 陷阱:把"答案错了"全归生成层——可能是检索召回了错证据,生成层很忠实地复述了它。

**Q3:什么是"忠实度三角"?三个维度为什么要分开测?**
标准答:**Faithfulness**(答案⟸上下文,生成端)、**Answer Relevancy**(答案⟺问题,生成端)、**Context Relevancy/Precision**(上下文⟺问题,检索端)。三者**正交**:召回对的料 ≠ 答案切题 ≠ 答案没编造。分开测才能定位是检索的锅还是生成的锅。
- 追问举例:一个答案可"忠实但答非所问"(faithfulness 高、answer relevancy 低),也可"切题但掺私货"(answer relevancy 高、faithfulness 低)。

**Q4:抗幻觉有哪些手段,从弱到强?**
标准答:① prompt 约束 + 逃生口(最便宜,治标);② 引用强制 + 编号核对;③ NLI/蕴含校验(句当 hypothesis、证据当 premise,判 entail/neutral/contradict);④ self-check 事后自核验(对应 [[13 Reflection 与 Reflexion|Reflection 与 Reflexion]]、Self-RAG 的 ISSUP token)。
- 追问"NLI 怎么用在这":逐句判是否被引用证据蕴含,neutral/contradict 即无据/编造,标红或触发重生成。

**Q5:inline citation 和 post-hoc attribution 有什么区别?各自的坑?**
标准答:inline 是**生成时**就嵌 [n],最自然但模型可能**标错号**;post-hoc 是**先自由生成、再独立步骤把每句对齐回最相关片段**(如 RARR),更可靠但多一步。两者都要**核对编号-内容**,"带引用"不等于"引用对"。

**Q6:逃生口("资料不足就说不知道")太强会有什么问题?**
标准答:**over-refusal**——模型动不动就拒答,把本可答的也挡了。约束力度要校准,折中为"证据支持的部分如实答 + 明确标注不确定部分",而非一刀切拒答。

## 知识拓展

**关键论文与基准(带年份)**
- **ALCE**(Gao et al. 2023,EMNLP,arXiv:2305.14627):带引用生成的评测基准,沿 **fluency / correctness / citation quality** 三维自动评。
- **TRUE**(Honovich et al. 2022):综述多种忠实度自动评测,结论是 **NLI 方法与人工判断相关性最强**——奠定"用蕴含模型测 faithfulness"的工业共识。
- **RARR**(Gao et al. 2022):**Retrofit Attribution using Research and Revision**,事后给已生成文本加归因并据此**修订**,post-hoc attribution 的代表。
- **AttributedQA / Attributable to Identified Sources(Rashkin et al. 2021,AIS 框架)**:把"可归因"形式化为评估协议。
- **FActScore(Min et al. 2023)**:把长答案拆成原子事实(atomic facts)逐个判可支撑,长文本忠实度细粒度评测的代表。
- **HHEM(Vectara 2023+)**:开源 hallucination 评测模型 + 公开 leaderboard,工业界常用的轻量 groundedness 判别器。
- **前沿(2024–2025)**:**引用感知解码/约束解码**(生成时就强制"无证据不输出实词")、**self-citation 训练**(把"边写边标准确引用"做进 RLHF 奖励)、推理大模型(o1/R1)用长 think 自核 grounding,正把"事后校验"前移成"生成时即有据"。

**底层联系**:本篇的 self-check 回路是 [[13 Reflection 与 Reflexion|Reflection 与 Reflexion]] 在生成层的落地;ISSUP(is supported)正是 Self-RAG 把忠实度自评**内化成反思 token**(见 [[12 Self-RAG、CRAG 与 Adaptive RAG|Self-RAG、CRAG 与 Adaptive RAG]]);grounding 约束属 [[20 上下文工程|上下文工程]] 在生成端的应用。引用编号到证据片段的映射,本质也是检索向量空间里的对齐,可回看 [[深度学习基础/03 点积、范数与相似度|点积、范数与相似度]] 理解"哪个片段最支撑这句"如何用相似度近似。

**边界与反模式**
- **反模式一:只看"有没有引用"不核内容**——张冠李戴(标 [1] 实出 [3])照样过表面检查。
- **反模式二:把 faithfulness 当 accuracy 用**——证据错时忠实复述也是错答,锅不在生成层。
- **反模式三:句句强制引用**——读着割裂,过渡句不该标。
- **边界**:容错高的内部探索/demo 用 grounding prompt + 引用足矣,不必上 NLI 回路(校验慢且贵,杀鸡用牛刀);抽象综合类答案天然难归因,强上逐句 NLI 会高误报。
