[[22 多模态检索的证据单元：文本、表格、图像与父子文档|证据单元]]是多模态 RAG 中可被检索、核验、定位、撤销的最小事实对象：它不是一段孤立文本，而是带父文档、来源版本、权限和精确位置的“可出示证物”。

## 直觉：档案室的证物袋

把企业知识库想成档案室。原始 PDF 是整份**卷宗**（document）；第 12 页、某张幻灯片或某个工作表是卷宗中的**页**（page/slide/sheet）；其中的段落、表格、图片是**证物**（block/table/figure）；表格的一行、段落的一小块、图片裁剪区域则是可被向量召回的**证据子块**（chunk/crop）。

不能只把“第 12 页有现金流”塞进向量库：审计员会追问“哪一行、哪一版、谁能看、原件更新后这句话是否还有效？”所以一个子块应同时保留多种表征：可全文检索的规范化文本、保留二维结构的表格单元格、可视觉检索的页图或裁剪图、以及它们的嵌入。[[15 多模态 RAG|多模态 RAG]] 的视觉检索可以帮你找回页或区域，却不替代来源、权限和版本核验。

规范层级固定为：

$$
\text{document}\rightarrow\text{page/slide/sheet}\rightarrow\text{block/table/figure}\rightarrow\text{chunk/crop}
$$

每一层向下能细化定位，向上能恢复语境。对象至少带 `source_id`、`source_version`、原件 `sha256`、`acl_policy_id`、`derived_asset_ids`；还要记录页号或 sheet 名、阅读顺序 `reading_order`、文本字符范围 `char_range`、表格 `row/column`、图片 `bbox=(x,y,w,h)`，视频再补 `time_range=[t_0,t_1)`。权限在**召回前**过滤，不能等模型已经读到证物才检查，见 [[16 检索安全与访问控制|访问控制]]。

## 小数字手算：先命中表格子块，再带回页上下文

问题是“2025 Q2 自由现金流是多少？”系统在允许的 `finance` ACL 内为同一个表格单元格算三路分数：规范化文本相似度 $s_t=0.82$，表格结构/列名相似度 $s_s=0.90$，页图视觉相似度 $s_v=0.94$。若权重为 $(0.30,0.20,0.50)$，则

$$
s=0.30\times0.82+0.20\times0.90+0.50\times0.94
=0.246+0.180+0.470=0.896
$$

它命中子对象 `chunk:cf:q2-2025:r8:c3`，而不是模糊返回整份报告。随后沿 `parent_id` 展开到 `table:cash-flow` 和 `page:12`，带回表题、币种、期间与相邻行，但不把整本报告塞进上下文。最终答案附的不是“报告说”，而是：`source=earnings-2025q2; version=17; sha256=ab12…; page=12; table=cash_flow; row=8; column=3; asset=crop:cf:r8c3`。

若原件更新为版本 18，或版本 17 的这个子块被标为 `revoked`，它立即从可召回集合移除；已生成答案也可以按 `source_id + version + asset_id` 反查并重算。这里的“撤销”针对**证据版本**，不是悄悄覆盖旧文本；这正是 [[17 检索数据治理|数据治理]] 中可复现与可审计的基础。

## 公式推导：子块负责召回，父对象负责语境

令一个证据子块为

$$
c=(id,parent,source,version,hash,acl,kind,locator,R,revoked)
$$

其中 $R=\{r_{text},r_{table},r_{image},r_{embed}\}$ 是同一事实的多种表征；`locator` 保存页/工作表、阅读顺序、字符范围或坐标。对 query $q$，先做可见且有效的候选集过滤：

$$
\mathcal{C}_{valid}=\{c\mid acl(q)\supseteq acl(c)\ \land\ revoked(c)=0\ \land\ hash(c)=hash(source@version)\}
$$

再让不同表征独立打分并融合：

$$
S(q,c)=\lambda_tS_t(q,r_{text})+\lambda_sS_s(q,r_{table})+\lambda_vS_v(q,r_{image}),\qquad \sum\lambda=1
$$

取 $\operatorname{TopK}_{c\in\mathcal{C}_{valid}}S(q,c)$ 后，**只为命中的子块**向上扩展：

$$
E(c,B)=\{c\}\cup\operatorname{context}(parent(c),B)
$$

$B$ 是上下文预算，因此 `context` 可包含表题、页标题、相邻行和图注，却必须停止在预算边界。答案中的一个原子主张 $a$ 再绑定精确引用：

$$
citation(a)=(source,version,hash,locator,asset\_id)
$$

这把 [[06 检索粒度：父文档与句子窗口检索|父文档检索]] 的“小而准地找”与 [[11 生成层：引用归因与忠实度|引用归因]] 的“能回到原处核验”连成闭环。坐标和时间区间的思想也与 W3C 对空间 `xywh`、时间 `t` 片段的定义一致，但 PDF/表格的内部 locator 仍应由自己的解析版本解释，不能假装所有格式都共享一个 URI 标准。

## 可运行代码：❌ 只存片段 vs ✅ 可核验的证据对象

下面两段都只用 Python 标准库。前者能找到一句话，却没有来源版本、权限、位置或撤销状态；后者先过滤 ACL 与有效版本，再从子块扩展父上下文，并打印可定位的引用。

```python
# ❌ 朴素：字符串“召回”返回了什么，就直接当证据使用
chunks = [
    "Q2 free cash flow = $1.2m",
    "Q2 free cash flow = $0.8m (superseded draft)",
]
for chunk in chunks:
    if "free cash flow" in chunk.lower():
        print("answer from:", chunk)  # 不知道页号、版本、ACL，也无法撤销旧草稿
```

```python
# ✅ 标准库可运行：child recall -> ACL/version/hash 核验 -> parent expansion -> 精确引用
from dataclasses import dataclass
from hashlib import sha256

SOURCE = b"earnings-2025q2, approved version 17"
SOURCE_HASH = sha256(SOURCE).hexdigest()

@dataclass(frozen=True)
class Evidence:
    evidence_id: str
    parent_id: str
    source_id: str
    version: int
    source_hash: str
    acl: frozenset[str]
    kind: str
    text: str
    locator: tuple[tuple[str, object], ...]
    representations: tuple[str, ...]
    derived_asset_ids: tuple[str, ...]
    revoked: bool = False

records = [
    Evidence(
        "chunk:cf:q2-2025:r8:c3", "page:12", "earnings-2025q2", 17,
        SOURCE_HASH, frozenset({"finance"}), "table_cell",
        "2025 Q2 free cash flow = $1.2m",
        (("page", 12), ("table", "cash_flow"), ("row", 8),
         ("column", 3), ("reading_order", 14), ("bbox", (720, 438, 168, 38))),
        ("normalized_text", "table_cell", "page_crop", "embedding"),
        ("crop:cf:r8c3", "embed:text:v4", "embed:vision:v2"),
    ),
    Evidence(
        "chunk:cf:q2-2025:draft", "page:12", "earnings-2025q2", 16,
        "old-hash", frozenset({"finance"}), "table_cell",
        "2025 Q2 free cash flow = $0.8m",
        (("page", 12), ("row", 8), ("column", 3)), ("normalized_text",),
        ("crop:old",), revoked=True,
    ),
]

parents = {
    "page:12": {
        "title": "现金流量表（单位：百万美元）",
        "context": "Q2、USD、经批准版本；相邻行解释资本开支口径。",
    }
}

def active_and_visible(e: Evidence, groups: set[str]) -> bool:
    return (not e.revoked and e.acl <= groups and e.version == 17
            and e.source_hash == SOURCE_HASH)

def lexical_score(query: str, e: Evidence) -> int:
    terms = {term for term in query.lower().split() if term}
    return sum(term in e.text.lower() for term in terms)

def retrieve_child(query: str, groups: set[str]) -> Evidence:
    candidates = [e for e in records if active_and_visible(e, groups)]
    return max(candidates, key=lambda e: lexical_score(query, e))

def cite(e: Evidence) -> str:
    loc = "; ".join(f"{k}={v}" for k, v in e.locator)
    return (f"source={e.source_id}; version={e.version}; sha256={e.source_hash[:12]}…; "
            f"{loc}; asset={e.derived_asset_ids[0]}")

hit = retrieve_child("2025 Q2 free cash flow", {"finance"})
print("claim:", hit.text)                         # 子块：精确命中
print("parent context:", parents[hit.parent_id])  # 父页：补足语境
print("citation:", cite(hit))                     # 可回到版本、位置与派生产物
```

## 面试高频

**Q1：多模态 RAG 为什么不能只给每页一个向量？**  因为“召回到这页”仍无法说明答案来自页中的哪一行、哪张图或哪个时间段，也无法稳定带回表格二维结构。页级视觉向量可作候选召回；文本块、单元格和图片裁剪等子对象才承担细粒度主张的定位。ColPali 证明了页图多向量与 late interaction 是有竞争力的检索路线，但它并不自动提供版本、ACL、精确引用或事实正确性。

**Q2：为什么先召回 child、后展开 parent，而不直接索引 parent？**  直接索引大父文档会稀释局部证据，也把无关甚至无权限内容带进上下文；只回 child 又会丢掉单位、标题和限定条件。先以 child 得到精确命中，再受预算 $B$ 限制地向上展开 parent，是精度与语境的折中。

**Q3：一条能经审计的引用至少包含什么？**  `source_id`、版本、原件 hash、对象类型、精确 locator、派生资产 ID 与权限判定版本。仅有 URL 或“第 12 页”不足以区分更新前后、同页多个表格或裁剪图的不同派生物。

**Q4：如何处理源文件修订或发现错误？**  新版作为新的 `source_version` 与 hash 入库；受影响 child 标记 `revoked` 或设置有效时间，检索入口过滤它们。凭 `source_id/version/asset_id` 查回历史答案并重新生成，保留旧版本的审计轨迹而不是原地篡改。

## 关键事实

- Docling 的 `DoclingDocument` 将正文、表格、图片等结构化对象和 provenance 放进同一文档模型；这是“对象层级 + 精确定位”可落地的解析参考。来源：[Docling Document 概念文档（2026-07-17 访问）](https://docling-project.github.io/docling/concepts/docling_document/)、[Docling API：DocItem provenance（2026-07-17 访问）](https://docling-project.github.io/docling/reference/docling_document/)。
- Faysse 等的 ColPali（2024，arXiv:2407.01449）为文档页图像生成多向量表示，并用 late interaction 匹配；论文的结论是这条视觉检索路线在其 ViDoRe 设定中表现强，不等价于“无需 OCR 就对所有文档精确”或“视觉编码可替代证据治理”。来源：[论文](https://arxiv.org/abs/2407.01449)。
- W3C Media Fragments 1.0（2012）定义了时间 `t` 与矩形空间 `xywh` 的片段思想；W3C PROV-DM（2013）把实体、活动与代理用于描述数据的来历。它们是定位与谱系的通用参照，不规定企业 RAG 的内部 ID 设计。来源：[Media Fragments](https://www.w3.org/TR/media-frags/)、[PROV-DM](https://www.w3.org/TR/prov-dm/)。
