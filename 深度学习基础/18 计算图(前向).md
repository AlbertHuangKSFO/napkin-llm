[[18 计算图(前向)|计算图]]是把一个复杂表达式拆成"一步一个基本运算"的有向图:叶子是输入/参数,内部节点是加减乘除、矩阵乘、激活等原子操作,边表示数据流向。**前向传播**就是按拓扑顺序把每个节点的值依次算出来。它是 [[19 自动微分：前向 vs 反向模式|自动微分]] 与 [[20 反向传播的数学推导|反向传播]] 的舞台——把链式法则变成"在图上爬"的机械过程。

## 直觉

把一个大公式想成**流水线**。$f=(a+b)\cdot c$ 不是一口气算出来的,机器实际分两步:先算 $s=a+b$,再算 $f=s\cdot c$。把这两步画成图:`a,b,c` 是原料(叶子),`+` 和 `×` 是两台机器(节点),原料顺着传送带(边)流进机器,出口就是结果 $f$。

这张图的妙处在于:**每台机器只会一种最简单的运算**,而且**它自己就知道"输入动一点、输出动多少"(本地导数)**。加法机器:两个输入对输出的本地导数都是 1;乘法机器 $f=s\cdot c$:对 $s$ 的本地导数是 $c$,对 $c$ 的本地导数是 $s$。

**前向**就是从原料端开始,顺着传送带把每个节点的**值**算出来并**存下来**(为什么要存?反向求导时要用,见 [[20 反向传播的数学推导|反向传播]])。这一步只算函数值,还没碰梯度——梯度是反向那一趟的事。

为什么非要拆这么碎?因为一旦拆成原子操作,求导就不用对整个怪兽公式硬推,只需让每个节点报出自己那点本地导数,再用 [[16 链式法则|链式法则]] 把它们沿边乘起来。复杂度被"分而治之"了。

## 例子

算 $f=(a+b)\cdot c$,取 $a=2,b=1,c=3$。

**建图 + 前向(逐节点存值)**:

| 节点 | 运算 | 值 |
|---|---|---|
| $a$ | 叶子 | $2$ |
| $b$ | 叶子 | $1$ |
| $c$ | 叶子 | $3$ |
| $s$ | $a+b$ | $3$ |
| $f$ | $s\cdot c$ | $9$ |

按拓扑序(被依赖的先算):先 $a,b,c$,再 $s=a+b=3$,最后 $f=s\cdot c=9$。每个中间值都缓存起来——$s=3$ 这个值反向时算 $\partial f/\partial c$ 要用。

![[calc-计算图前向反向.png]]

**稍复杂一点(带复用的扇出)**。$f=x\cdot y + x$,取 $x=2,y=3$。$x$ 被两条边用到(进乘法、又进加法),这叫**扇出**。前向:$p=x\cdot y=6$,$f=p+x=8$。前向不受扇出影响,照常逐节点算;扇出的"账"留到反向时把两条路径的梯度**相加**(见 [[16 链式法则|链式法则]] 的多元求和)。

**神经网络也是一张计算图**。一层 $z=Wx+b$、$a=\sigma(z)$、损失 $L=\text{loss}(a,y)$,就是 matmul → add → 激活 → loss 这几个节点串起来;深网络只是更长的图。前向算 $L$,反向算 $\partial L/\partial W$ 等(完整两层例子见 [[20 反向传播的数学推导|反向传播]])。

**逐节点列出本地导数(为反向做准备)**。还是 $f=(a+b)\cdot c$,$a=2,b=1,c=3$:

| 节点 | 值 | 对父节点的本地导数 |
|---|---|---|
| $s=a+b$ | $3$ | $\partial s/\partial a=1,\ \partial s/\partial b=1$ |
| $f=s\cdot c$ | $9$ | $\partial f/\partial s=c=3,\ \partial f/\partial c=s=3$ |

注意 $\partial f/\partial c=s=3$ 用到了**前向缓存的 $s$**——这就是"前向必须存中间值"的具体原因。反向时(下一篇)把这些本地导数沿边连乘即可得 $\partial f/\partial a,\partial f/\partial b,\partial f/\partial c$。

## 原理

**计算图定义**。一个有向无环图(DAG):

- **叶子节点**:输入数据 $x$、参数 $W,b$(无入边)。
- **内部节点**:一个**原子运算**(加、乘、matmul、$\exp$、$\max$、$\sigma$ 等),其值由父节点的值算出。
- **边** $u\to v$:表示 $v$ 的计算用到了 $u$ 的值(数据依赖)。

**前向传播算法**:

1. 对图做**拓扑排序**(保证算某节点前,它依赖的节点都已算好)。
2. 按该顺序遍历,每个节点用父节点的值执行自己的运算,得到本节点值并**缓存**。
3. 末端节点的值就是最终输出(深度学习里通常是标量损失 $L$)。

复杂度:每个节点算一次,总代价 $\propto$ 节点数(线性)。

**每个节点附带"本地导数"**。这是计算图的核心资产:节点 $v=g(u_1,\dots,u_k)$ 知道自己对每个输入的偏导 $\partial v/\partial u_i$(本地、只看自己这一步)。例子:

- 加法 $v=u_1+u_2$:$\partial v/\partial u_1=\partial v/\partial u_2=1$。
- 乘法 $v=u_1u_2$:$\partial v/\partial u_1=u_2$,$\partial v/\partial u_2=u_1$(**注意要用到前向缓存的另一个输入值**——这就是前向要存值的原因)。
- $\sigma$、$\exp$、matmul 各有自己的本地雅可比(见 [[17 雅可比与 Hessian|雅可比]])。

前向只负责把值和本地导数所需的缓存准备好;真正把本地导数沿边连乘、从输出回传到每个叶子,是**反向那一趟**(下一篇 [[19 自动微分：前向 vs 反向模式|自动微分]] 讲两种扫描方向,[[20 反向传播的数学推导|反向传播]] 给完整推导)。

![[calc-计算图前向反向.png]]

**拓扑排序为什么必要**。若先算了依赖别人的节点,它要的输入还没算好,结果就是垃圾。拓扑序保证"被依赖的先算"。DAG(无环)是拓扑序存在的前提——有环就会陷入"鸡生蛋"死循环(RNN 的"环"靠按时间展开成无环长图来破,见下方陷阱)。

**显存就花在缓存上**。前向缓存的中间激活是反向的"燃料",也是训练显存的主要占用(常比参数本身大得多,正比于 batch×序列长×层数×宽度)。两条省显存的招:**梯度检查点(gradient checkpointing)**——只存少数节点、反向时重算其余,拿时间换显存(Chen et al., 2016);**就地操作(in-place)**——复用内存,但若覆盖了反向要用的值会报错,PyTorch 会检测到并抛"a leaf Variable that requires grad is being used in an in-place operation"。

**为什么这是现代框架的底座**:PyTorch / TensorFlow / JAX 跑你写的每个运算时,**动态/静态地建起这张图**(PyTorch 在前向时即时记录,叫 autograd 的 "tape"),`loss.backward()` 就是在图上自动跑反向。你只需写前向,框架替你建图+反向。

## 代码

```python
import numpy as np

# 用最小的"节点"思路手搓计算图的前向:每个节点记下自己的值(供反向复用)
class Node:
    def __init__(self, value, op=None, parents=()):
        self.value = value      # 前向算出的值(缓存!)
        self.op = op
        self.parents = parents

def add(x, y): return Node(x.value + y.value, 'add', (x, y))
def mul(x, y): return Node(x.value * y.value, 'mul', (x, y))

# f = (a+b)*c,前向逐节点求值
a, b, c = Node(2.), Node(1.), Node(3.)
s = add(a, b)            # s = 3,缓存
f = mul(s, c)            # f = 9
print("前向 s =", s.value, " f =", f.value)   # 3  9

# ❌ 朴素:把整个表达式当黑箱一行算完,中间值不留 → 反向无从下手
f_blackbox = (a.value + b.value) * c.value
print("黑箱 f =", f_blackbox)   # 9,值对,但没存 s,没法做 backprop

# ✅ 正确:逐节点求值并缓存中间量(s.value),才能在反向时算 ∂f/∂c = s = 3
print("缓存的 s 供反向用:", s.value)   # 反向时 ∂f/∂c 直接 = 3

# 对照框架:PyTorch 前向时自动建图
import torch
ta = torch.tensor(2.0, requires_grad=True)
tb = torch.tensor(1.0, requires_grad=True)
tc = torch.tensor(3.0, requires_grad=True)
tf = (ta + tb) * tc          # 前向,同时悄悄建好计算图
print("torch 前向 f =", tf.item())   # 9.0(反向见下一篇)
print("grad_fn:", tf.grad_fn)        # <MulBackward0> —— 图已记录该节点是乘法

# 逐节点本地导数(为反向预备):∂f/∂c 用到前向缓存的 s
print("∂f/∂c = s =", s.value)        # 3  ← 必须有缓存才能算
print("∂f/∂s = c =", c.value)        # 3

# torch.no_grad():前向但不建图(推理/省显存),此时无法 backward
with torch.no_grad():
    tf2 = (ta + tb) * tc
print("no_grad 下 grad_fn:", tf2.grad_fn)   # None —— 没建图
```

手算对照:手搓前向 $s=3,f=9$ 与表格一致;"黑箱"虽然也得 9,但不存中间值就无法反向求导——这正是计算图要逐节点缓存的理由;PyTorch 前向同样得 9,并已在后台建好图等待 `backward()`。

## 面试高频

- **"什么是计算图?"** 把表达式拆成原子运算的 DAG:叶子是输入/参数,节点是基本运算,边是数据依赖;前向按拓扑序求值。
- **"前向传播为什么要缓存中间值?"** 反向求本地导数要用(如乘法节点 $\partial(uv)/\partial u=v$ 需要另一个输入 $v$,激活 $\sigma'$ 需要 $\sigma(z)$)。这是显存占用的主要来源,也是 gradient checkpointing(用时间换显存)要权衡的点。
- **"PyTorch 的图是动态还是静态?"** PyTorch 默认**动态图**(define-by-run,前向时即时建图),TensorFlow 1.x 是静态图,JAX/TF2 用 trace + 编译。
- **"扇出(一个节点被多处用到)前向怎么处理?"** 前向照常算一次;反向时把各下游回传的梯度**相加**(多元链式法则)。
- **陷阱:计算图必须无环(DAG)。** RNN 看似有"环",实际是按时间步**展开**成一张很长的无环图再反传(BPTT,见 [[54 RNN 原理与 BPTT|BPTT]])。
- **"图的前向复杂度?"** 与节点数成线性;反向也是线性(每条边各传一次梯度)——这是 backprop 高效的根本。
- **"为什么必须拓扑排序?"** 保证算某节点前其依赖已就绪;DAG 是拓扑序存在的前提,有环会死循环。
- **"`torch.no_grad()` 干什么?"** 前向但不建图(不记 tape),推理时省显存、加速;此时张量没有 `grad_fn`,不能 `backward()`。
- **"训练显存主要花在哪?"** 缓存的中间激活(正比 batch×seq×层×宽),不是参数本身;gradient checkpointing 用重算换显存。
- **陷阱:in-place 操作可能破坏反向。** 覆盖了反向要用的中间值,PyTorch 会报错;不确定时别用 `x += ...` 改原张量。

## 关键事实

- 计算图(表达式 DAG)+ 前向求值 + 反向求导是自动微分的标准组织方式,见 Baydin et al., 《Automatic Differentiation in Machine Learning: a Survey》(JMLR, 2018)。
- PyTorch 的 autograd 采用动态计算图(define-by-run,前向时记录 tape),见 Paszke et al., 《PyTorch: An Imperative Style, High-Performance Deep Learning Library》(NeurIPS, 2019)。
- 前向缓存中间激活以供反向使用、并由此引出 gradient checkpointing 的时间-显存权衡,见 Chen et al., 《Training Deep Nets with Sublinear Memory Cost》(2016)。
