[[18 工具检索与动态加载|工具检索与动态加载]] 的关键是把三个动作分开：**发现**「有哪些能力」、**检索／召回**「此任务候选哪些」、**选择与执行**「模型实际调用哪个且 runtime 是否放行」。把它们都叫“tool search”会掩盖漏召回、选错和越权各自不同的故障点。

## 直觉／生活类比

图书馆目录回答「馆里有哪些书」——这是 discovery；检索系统从目录中给出与问题相关的 5 本——这是 retrieval；读者最终借哪一本、管理员是否允许借阅——才是 selection 与 authorization。目录可列全馆，不代表模型应把全馆每本书的全文都带进上下文。

工具 schema 的全量常驻会增加 prompt token，也会让相似工具互相干扰。解决办法不是假设某个 provider 一定会自动检索，而是明确候选集如何产生、哪个层负责加载、如何评估漏召回和任务结果。

## 小数字手算

有 100 个工具，每个完整 schema 在本次请求中占 120 token；全部注入为：

$$
100\times120=12000\text{ token}
$$

只注入 top-$k=5$ 个候选：

$$
5\times120=600\text{ token},\qquad 12000-600=11400\text{ token},\qquad 11400/12000=95\%
$$

这只是 schema 注入账，不含检索请求、namespace 描述、模型额外搜索轮次和失败重试。若关键工具没进 top-5，节省的 token 对完成任务没有价值。

## 公式推导

对有标准答案工具的评测集，至少分开记录：

$$
\operatorname{Recall@k}=\frac{\#\{\text{所需工具}\in\text{候选 top-}k\}}{\#\{\text{需要工具的任务}\}}
$$

其中候选 top-$k$ 必须严格是排序结果 `ranked[:k]`。若还把常驻关键工具集合 $A$ 合并进模型可调用集合，则应另记、另命名为：

$$
\operatorname{LoadedSetRecall@k}=\frac{\#\{\text{所需工具}\in(\text{top-}k\cup A)\}}{\#\{\text{需要工具的任务}\}}
$$

$$
\operatorname{SelectionPrecision}=\frac{\#\{\text{模型实际选择正确工具}\}}{\#\{\text{模型实际发起工具调用}\}},\qquad
\operatorname{TaskSuccess}=\frac{\#\{\text{通过端到端 grader 的任务}\}}{\#\{\text{全部任务}\}}
$$

`LoadedSetRecall@k` 的集合大小可随常驻工具数变化，不能冒充 Recall@k；它衡量的是最终加载层的兜底覆盖。再单列每任务（含重试）的输入工具 token、检索 token、输出 token 与延迟。高 Recall@k 不保证选择正确；选择正确也不保证参数、权限和最终答案正确，因此不能把任何一个指标当成任务成功率。

```python
# ✅ 纯标准库，可直接运行：检索、候选、选择评测与 token 账分开记录。
from __future__ import annotations

import re

CATALOG = [
    {"name": "get_shipping_eta", "description": "查询订单物流预计送达时间 快递 到货", "schema_tokens": 120, "critical": True},
    {"name": "cancel_order", "description": "取消尚未发货的订单 退款", "schema_tokens": 120, "critical": False},
    {"name": "search_docs", "description": "检索产品文档 安装 配置", "schema_tokens": 120, "critical": True},
]

EVALS = [
    {"query": "我的订单什么时候到？", "required": "get_shipping_eta", "task_ok": True},
    {"query": "帮我取消还没发货的订单", "required": "cancel_order", "task_ok": True},
    {"query": "怎么配置产品？", "required": "search_docs", "task_ok": False},  # 例如参数或答案仍失败
    {"query": "查询资料", "required": "search_docs", "task_ok": True},  # 词面检索会漏召回，但常驻工具会加载它
]

def terms(text: str) -> set[str]:
    # 英文按词；中文演示按单字。生产可替换为分词、BM25、embedding 与 reranker。
    latin_words = re.findall(r"[a-z0-9_]+", text.lower())
    han_chars = [char for char in text if "\u4e00" <= char <= "\u9fff"]
    return set(latin_words + han_chars)

def rank_tools(query: str, catalog: list[dict]) -> list[dict]:
    q = terms(query)
    return sorted(
        catalog,
        key=lambda tool: len(q & terms(tool["name"] + " " + tool["description"])),
        reverse=True,
    )

def load_tools(ranked: list[dict], catalog: list[dict], k: int = 2) -> list[dict]:
    # 关键安全／收尾工具可常驻；这不是把“关键”误当成授权。
    chosen = {tool["name"]: tool for tool in ranked[:k]}
    for tool in catalog:
        if tool["critical"]:
            chosen.setdefault(tool["name"], tool)
    return list(chosen.values())

def evaluate() -> None:
    top_k_recall_hits = loaded_set_recall_hits = 0
    selected_correct = task_success = calls = 0
    injected_tokens = 0
    for case in EVALS:
        ranked = rank_tools(case["query"], CATALOG)
        top_k = ranked[:1]  # Recall@k 只看这个纯排序候选集。
        loaded = load_tools(ranked, CATALOG, k=1)
        top_k_names = [tool["name"] for tool in top_k]
        loaded_names = [tool["name"] for tool in loaded]
        injected_tokens += sum(tool["schema_tokens"] for tool in loaded)
        top_k_recall_hits += case["required"] in top_k_names
        loaded_set_recall_hits += case["required"] in loaded_names
        selected = top_k_names[0]  # 演示用选择器；生产中记录模型真实 tool call。
        calls += 1
        selected_correct += selected == case["required"]
        task_success += case["task_ok"] and selected == case["required"]
        print(case["query"], "->", "top1=", top_k_names, "loaded=", loaded_names, "selected=", selected)

    total = len(EVALS)
    print(f"Recall@1（纯 ranked[:1]）={top_k_recall_hits}/{total}={top_k_recall_hits/total:.1%}")
    print(f"LoadedSetRecall@1（top-1 + 常驻关键工具）={loaded_set_recall_hits}/{total}={loaded_set_recall_hits/total:.1%}")
    print(f"SelectionPrecision={selected_correct}/{calls}={selected_correct/calls:.1%}")
    print(f"TaskSuccess={task_success}/{total}={task_success/total:.1%}")
    print(f"平均注入 schema token={injected_tokens/total:.0f}")

if __name__ == "__main__":
    evaluate()
```

不同提供方／协议中的边界不能混写：

| 层 | OpenAI Responses | MCP | Gemini 自定义函数 |
|---|---|---|---|
| 发现 inventory | 由请求声明的 function／namespace／MCP server；可把部分工具标为 deferred | client 以 `tools/list` 从 server 枚举 | 应用将 function declarations 随请求传入 |
| 检索／加载 | 可用 hosted 或 client-executed `tool_search` 加载 deferred subset | 协议只定义列举与调用；语义 top-k 由 host／网关自行实现 | 由应用在发送 declarations 前自行决定候选 |
| 执行回灌 | `function_call` → `function_call_output` | `tools/call` → result | 应用执行 function call，再回 function response |

OpenAI 的 tool search 是具体 provider 功能：需要加入 `tool_search`，并对 function 或 MCP server 标记 `defer_loading: true`；它有 hosted 与 client-executed 两种模式。MCP `tools/list` 则是标准化 discovery，不能自动等同为语义 retrieval。Gemini 的 custom-function 流程也明确由应用执行函数并回传结果。 [OpenAI Tool search（检索于 2026-07-17）](https://developers.openai.com/api/docs/guides/tools-tool-search) [MCP Tools 2025-11-25（检索于 2026-07-17）](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) [Gemini Function calling（检索于 2026-07-17）](https://ai.google.dev/gemini-api/docs/function-calling)

## 面试高频
> 面试地图：[[Agent 面试题库]]

**Q：`tools/list` 和 tool retrieval 是同一件事吗？** 不同。前者获得可用 inventory；后者是针对当前任务从 inventory 召回候选。MCP 标准化前者，是否做 BM25、向量、规则或 rerank 是 host 的设计选择。

**Q：只看 Recall@k 可以吗？** 不可以。Recall@k 必须只看 `ranked[:k]`；若合并了常驻关键工具，应额外报告 `LoadedSetRecall@k`，不能用后者替代前者。还要看模型在候选中选对的 precision、端到端 task success、token／延迟和被 runtime 拒绝的比例。召回全对而参数总错，任务仍失败。

**Q：什么时候全量注入更好？** 工具极少、固定、相互差异大时。工具池增长、跨 server、schema 大或任务分阶段时，再考虑 namespace、按需加载与 retrieval，并给关键工具做可观测的兜底。

## 关键事实

- OpenAI Responses 的 tool search 能在运行时加载 deferred tools；当前文档区分 hosted 与 client-executed search，并建议 namespace 或 MCP server 做较粗粒度的可搜索表面。 [OpenAI Tool search（检索于 2026-07-17）](https://developers.openai.com/api/docs/guides/tools-tool-search)
- OpenAI client-executed search 中，模型输出 `tool_search_call`，应用返回配对的 `tool_search_output`；随后加载的工具才可按普通 function call 处理。 [OpenAI Tool search（检索于 2026-07-17）](https://developers.openai.com/api/docs/guides/tools-tool-search)
- MCP `tools/list` 用于发现且可分页，server 可发送工具清单变更通知；这提供 inventory，不规定语义相似度检索器。 [MCP Tools 2025-11-25（检索于 2026-07-17）](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)
- Gemini 自定义 function calling 把 function declarations 发给模型，但应用负责执行外部函数并把结果回传；不要把 provider 字段名或执行责任从一个 API 套到另一个。 [Gemini Function calling（检索于 2026-07-17）](https://ai.google.dev/gemini-api/docs/function-calling)
- `Recall@k` 应只衡量排序候选 `ranked[:k]`；如有常驻工具，另报最终模型可调用集合的 `LoadedSetRecall@k`，再连同实际选择 precision、端到端 task success、每任务 token 与延迟诊断召回、决策、业务完成和成本瓶颈。 [OpenAI Working with evals（检索于 2026-07-17）](https://developers.openai.com/api/docs/guides/evals)
