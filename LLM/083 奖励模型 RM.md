[[083 奖励模型 RM]]:奖励模型(Reward Model)把 [[082 偏好数据与标注|偏好对]] 学成一个**标量打分函数** $r_\phi(x,y)$——给 (prompt, 回答) 输出一个数,表示「人有多喜欢它」;它用 **Bradley-Terry 模型 + 二分类 [[30 交叉熵与负对数似然|交叉熵]]** 训练,是 [[085 RLHF 全流程与 KL 约束、奖励黑客|RLHF]] 里把人类偏好变成可优化奖励信号的核心组件。

## 直觉:把「会比较的人」压缩成「会打分的网络」

[[084 策略梯度与 PPO 基础|强化学习]]需要一个**奖励数字**才能更新策略,但人没法在训练里实时给百万次生成打分。奖励模型就是**人类偏好的可微代理**:训练一次,之后对任意回答秒出分数,反复给 RL 用。

结构上极简:**拿 [[081 指令微调 SFT 与数据构造|SFT 模型]] 当骨干,去掉预测词的 LM head,换一个输出单个标量的线性头**。喂进「prompt + 回答」,取最后一个 token 的隐状态,过线性层 → 一个实数 $r$。

关键认知:**RM 的分数只有相对意义,没有绝对意义**。我们从不告诉它「这个回答值 8 分」,只告诉它「A 比 B 好」。所以它学的是**排序**,不是刻度——这点决定了它的损失函数长什么样。

## 例子:一个偏好对怎么产生梯度(小数字)

偏好对 $(x,\ y_w,\ y_l)$,RM 当前打分:$r(y_w)=2.1$,$r(y_l)=0.4$。

差值 $\Delta=r(y_w)-r(y_l)=1.7$。模型认为「好答案胜出」的概率:

$$
P(y_w\succ y_l)=\sigma(\Delta)=\sigma(1.7)=\frac{1}{1+e^{-1.7}}\approx 0.846
$$

这个对的 loss:

$$
-\log\sigma(\Delta)=-\log(0.846)\approx 0.167
$$

梯度会**把 $r(y_w)$ 往上推、$r(y_l)$ 往下压**,直到差距足够大(loss 趋近 0)。若一开始预测反了($r(y_w)=0.4<r(y_l)=2.1$),$\Delta=-1.7$,loss$=-\log\sigma(-1.7)\approx1.87$,梯度更猛地纠正它。

注意:**只在意差值 $\Delta$,不在意绝对值**。把 $r(y_w),r(y_l)$ 同时加 5,$\Delta$ 不变,loss 不变——这从数学上证明了「RM 分只有相对意义」。

## 原理:Bradley-Terry 与排序交叉熵

**1)Bradley-Terry 模型**。这是一个经典的「成对比较」概率模型:给每个对象一个实数「实力」 $r$,则 $i$ 胜 $j$ 的概率为

$$
P(i\succ j)=\frac{e^{r_i}}{e^{r_i}+e^{r_j}}=\sigma(r_i-r_j)
$$

把「实力」换成 RM 打分 $r_\phi(x,y)$,就得到偏好概率。这其实是 [[27 Softmax 与温度|softmax]] 在两类上的特例,也是**逻辑回归**的形式。

**2)损失函数(最大似然)**。在偏好数据集上最大化「正确预测偏好」的对数似然,等价于最小化:

$$
\mathcal{L}_{\text{RM}}=-\mathbb{E}_{(x,y_w,y_l)\sim D}\big[\log\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)\big]
$$

它**本质就是偏好对上的二分类交叉熵**(标签恒为「$y_w$ 赢」),所以理解它只需要 [[30 交叉熵与负对数似然|交叉熵]] 和 [[25 最大似然估计 MLE|MLE]]。

**3)排序版(一次比 K 个)**。InstructGPT 把同一 prompt 的 $\binom{K}{2}$ 个对一起算,且**一次 forward 编码全部 K 个回答**再两两组对,省掉重复编码:

$$
\mathcal{L}=-\frac{1}{\binom{K}{2}}\mathbb{E}\Big[\sum_{(w,l)}\log\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)\Big]
$$

**4)RM 的脆弱性**。RM 只是偏好的**代理**,不是真理:它在训练分布外会失效;过拟合的 RM 会被 PPO **钻空子**(奖励黑客,reward hacking,见 [[085 RLHF 全流程与 KL 约束、奖励黑客|RLHF 全流程]])。所以 RM 通常**只训 1 个 epoch**(数据少、易过拟合),且 RLHF 必须加 KL 约束把策略拴在 RM 的可信区域内。

## Bradley-Terry 损失的完整 MLE 推导

把"为什么 loss 是 $-\log\sigma(\Delta)$"从头推一遍(面试要能写)。BT 模型设每个回答有"实力" $r$,则
$$P(y_w\succ y_l)=\frac{e^{r_w}}{e^{r_w}+e^{r_l}}.$$
分子分母同除 $e^{r_w}$:
$$=\frac{1}{1+e^{-(r_w-r_l)}}=\sigma(r_w-r_l)=\sigma(\Delta).$$
偏好数据集 $D=\{(x,y_w,y_l)\}$,每条标签恒为"$y_w$ 赢"。**最大化对数似然**:
$$\max_\phi\ \sum_{D}\log P(y_w\succ y_l)=\sum_D\log\sigma(r_\phi(x,y_w)-r_\phi(x,y_l)).$$
取负即得损失 $\mathcal{L}_{\text{RM}}=-\mathbb{E}_D[\log\sigma(\Delta)]$。这**就是逻辑回归**:把 $\Delta$ 当 logit、标签恒为 1 的二分类交叉熵。梯度 $\frac{\partial\mathcal L}{\partial\Delta}=-(1-\sigma(\Delta))=\sigma(\Delta)-1<0$——预测越不确定($\Delta$ 越小)梯度越大,把 $r_w$ 推高、$r_l$ 压低,直到 $\Delta$ 足够大。**只依赖差值 $\Delta$,与绝对值无关**,这从梯度上证明了 RM 分只有相对意义。

## RM 的架构细节:取哪个隐状态、怎么 pooling

- **标量头**:在 SFT 骨干上换一个 $d\to1$ 的线性头。
- **取哪个 token**:标准做法取**序列最后一个非 padding token**(eos 处)的隐状态——因果注意力下它"看过"整段,信息最全。注意 padding 在右时要取真实末位(用 attention mask 定位),否则取到 pad 上全错。
- **为什么不 mean-pooling**:整段 mean 会被长度和无关 token 稀释;末 token(因果)聚合了全序列,是 decoder-only RM 的标准。
- **共享 vs 独立骨干**:RM 用 SFT 初始化(复用语言理解),通常**比策略小**(InstructGPT 用 6B RM 配更大策略)就够——打分比生成简单。

## reward 的归一化与 whitening(PPO 前必做)

RM 输出的绝对尺度是任意的(③ 证明了平移不变),直接喂 PPO 会让优势尺度乱、训练不稳。工程上:
- **均值归零**:训完 RM 在一批 prompt 上算平均分,减掉,让 reward 中心在 0(KL 项才不被一个常数偏置淹没)。
- **whitening / 标准化**:PPO 里对一个 batch 的奖励(或优势)做 $(r-\mu)/\sigma$,稳定优势尺度(见 [[084 策略梯度与 PPO 基础|PPO]] 的优势标准化)。
- **裁剪/缩放**:对极端高分裁剪,防个别样本主导梯度。

## 评估 RM、不确定性与集成

- **怎么评 RM**:在留出偏好对上看**偏好准确率**(差值符号对不对),上限 ≈ 标注一致率。还有 **RewardBench**(2024)等基准在多领域(chat/安全/推理)系统评 RM。
- **RM 集成 + 不确定性**:训多个 RM(不同 seed/数据子集),PPO 用它们的**均值当奖励、方差当不确定性**——在 RM 们分歧大(分布外)的地方降权或加惩罚,显著缓解奖励黑客。
- **过程 RM(PRM)vs 结果 RM(ORM)**:ORM 只给整段最终分;**PRM**(见 [[090 RLAIF、宪法 AI 与过程奖励 PRM|PRM]])给推理**每一步**打分,在数学/代码等多步任务上更准、更抗奖励黑客(因为它约束中间过程而非只看结果)。

## 代码:Bradley-Terry 奖励模型 loss(❌ vs ✅)

```python
import torch
import torch.nn.functional as F

# reward_model(prompt, response) -> 标量 r,形状 [batch]
r_w = reward_model(prompt, chosen)     # 好答案的分 [B]
r_l = reward_model(prompt, rejected)   # 坏答案的分 [B]

# ❌ 误区:把 RM 当回归,硬拟合「人给的绝对分」
#   人没给绝对分(只给了排序),且绝对刻度噪声大、不可比
# loss_bad = F.mse_loss(r_w, target_score)   # 错:没有 target_score 这种东西

# ✅ 正解:Bradley-Terry —— 只约束「好减坏」的差值为正
#   等价于对 (r_w - r_l) 做二分类交叉熵(标签恒为 1:好赢)
loss = -F.logsigmoid(r_w - r_l).mean()
# 等价写法:F.binary_cross_entropy_with_logits(r_w - r_l, torch.ones_like(r_w))

loss.backward()

# 评估:看 RM 预测偏好的准确率(差值 > 0 即预测「好赢」)
acc = ((r_w - r_l) > 0).float().mean()   # 上限 ≈ 标注员一致率(~72-77%)
```

## 面试高频

- **RM 损失为什么是 `-log σ(r_w - r_l)`?** 因为偏好是**相对**的(只标了排序,没标绝对分)。Bradley-Terry 把「好胜坏」建成 $\sigma(\Delta)$,最大似然即得此式;它只约束差值,与绝对分高低无关。
- **RM 用什么初始化?** 用 [[081 指令微调 SFT 与数据构造|SFT]] 模型(或预训练模型)初始化,去掉 LM head 换标量头。复用语言理解能力,只学「打分」这一新任务。
- **RM 为什么常只训 1 epoch?** 偏好数据少、信号弱,多 epoch 极易过拟合;过拟合 RM 在 PPO 阶段会被策略找到漏洞,触发**奖励黑客**。
- **RM 准确率的上限?** 标注一致率(InstructGPT 约 72~77%)。RM 不可能比「人和人之间」更一致。
- **奖励黑客是什么,RM 怎么背锅?** 策略学会输出「RM 高分但人类不喜欢」的回答(如特定句式、超长、谄媚)。根因是 RM 是不完美代理 + 策略过度优化;靠 KL 约束、RM 集成、过程奖励缓解。详见 [[085 RLHF 全流程与 KL 约束、奖励黑客|RLHF 全流程]]。
- **RM 取哪个 token 的隐状态打分?** 序列最后一个非 padding token(eos),因果注意力下它看过整段、信息最全;不用 mean-pooling(被长度稀释)。padding 在右时要用 mask 定位真实末位。
- **RM 分要不要归一化?** 要。绝对尺度任意(平移不变),PPO 前要均值归零、whitening 标准化、裁极端值,否则优势尺度乱、KL 项被常数偏置淹没,训练不稳。
- **怎么缓解 RM 不可靠?** RM 集成(多个 RM 取均值当奖励、方差当不确定性,分歧大处降权)、过程奖励 PRM(给每步打分,比只看结果的 ORM 更抗奖励黑客)、定期重训、KL 约束。
- **RM 和价值函数(critic)是一回事吗?** 不是。RM 评「**整段回答**的人类偏好」(序列级、固定);PPO 的 critic 评「**当前状态的预期回报**」(逐 token、随策略更新),见 [[084 策略梯度与 PPO 基础|PPO]]。

## 关键事实

- RM 由 InstructGPT(Ouyang 2022,arXiv 2203.02155)用于 RLHF;更早雏形见 Christiano et al. 2017(arXiv 1706.03741,*Deep RL from Human Preferences*)与 Stiennon et al. 2020(arXiv 2009.01325,摘要任务)。
- 损失:$-\log\sigma(r_\phi(x,y_w)-r_\phi(x,y_l))$,即 Bradley-Terry 最大似然 = 偏好对二分类交叉熵。
- 工程:SFT 骨干 + 标量头;取末 token 隐状态打分;同 prompt 的 $\binom{K}{2}$ 对放同 batch、一次 forward 编码 K 个回答;常训 1 epoch。
- RM 是偏好的**代理**,有分布外失效与奖励黑客风险 → RLHF 需 [[31 KL 散度与 JS 散度|KL]] 约束。
- [[086 DPO 直接偏好优化(推导)|DPO]] 证明可**跳过显式 RM**:把 BT 损失里的 $r$ 用策略对参考策略的对数比表示,直接优化策略。
- Bradley-Terry(Bradley & Terry, 1952)成对比较模型,$P(i\succ j)=\sigma(r_i-r_j)$;RM 损失即其 MLE = 偏好对二分类交叉熵,梯度只依赖差值 $\Delta$(平移不变,证明分数相对性)。
- 工程:取 eos 隐状态过标量头打分;reward 在 PPO 前做均值归零 + whitening;RM 通常比策略小(InstructGPT 6B RM)。
- RM 评估有 RewardBench(Lambert et al., 2024, arXiv:2403.13787)等多领域基准;RM 集成(均值奖励 + 方差不确定性)缓解奖励黑客(Coste et al., 2023, arXiv:2310.02743)。
- 过程奖励 PRM(给每步打分)在多步推理上优于结果奖励 ORM(Lightman et al., "Let's Verify Step by Step", 2023, arXiv:2305.20050,见 [[090 RLAIF、宪法 AI 与过程奖励 PRM|PRM]])。
