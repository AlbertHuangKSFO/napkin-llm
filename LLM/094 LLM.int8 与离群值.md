[[094 LLM.int8 与离群值|LLM.int8() 与离群值]]:一种对大模型**零退化的 8-bit 推理**方法,核心洞察是——大模型激活里存在**少数「离群特征维」**(emergent outlier features),其数值比其他维大几十倍,会把朴素 int8 量化的尺子撑爆。LLM.int8() 用**混合精度分解**:把这极少数离群列单独拎出来走 **fp16**,其余 99.9% 走 **int8**,再相加。它直面 [[092 量化基础：对称非对称、per-tensor、per-channel、per-group|量化基础]]里最难的「激活离群值」问题,是 [[091 高效微调：LoRA、QLoRA、Adapter、Prefix|QLoRA]] 所依赖的 `bitsandbytes` 库的基石。

## 直觉:一颗老鼠屎坏一锅粥,那就把老鼠屎单独捞出来

[[092 量化基础：对称非对称、per-tensor、per-channel、per-group|量化基础]]说过:量化尺子按数据的最大值撑开。如果一组数里**绝大多数在 [-1, 1],却混进一个 70**,那 int8 的 256 个格子大半要分给「到 70」这段空旷区,导致 [-1, 1] 里成百上千个真正重要的值**全挤进两三个格子**——分辨率崩了,误差巨大。

Dettmers 等人发现:**模型一旦超过约 6.7B 参数,激活里就会"涌现"出这种离群维度**。它们有几个反直觉特性:

- **系统性**:固定出现在某些隐藏维度上,在几乎所有 token、所有输入上都大。规模到 6.7B 时,约 **75% 的序列**会被这些离群特征影响。
- **稀疏**:只占隐藏维的极小比例(常 < 0.1%)。论文里一个 6.7B 模型,单条序列有约 **15 万个**离群激活值,但它们只集中在 **6 个**特征维度上——维度极少、出现极频繁。
- **极端**:这些维度的数值比其他维大 **50~100 倍**。
- **要命**:虽然维度少,但对模型输出影响极大,直接量化掉它们会让模型**崩坏**(困惑度爆炸)。

既然「难量化的」只是极少数列,而且能定位,那就**分而治之**:把这几列离群特征**单独抽出来,用 fp16 精确算**;剩下 99.9% 的「乖巧」列照常 int8。两部分结果相加。因为离群列极少,fp16 那部分开销可忽略,却保住了精度——于是 8-bit 推理**几乎零损失**。

## 例子:一个离群维如何毁掉整列量化

设某激活行有 8 个值:$[0.3,\,-0.5,\,0.8,\,\mathbf{67.0},\,-0.2,\,0.6,\,-0.4,\,0.1]$,第 4 维是离群维。

**朴素 per-tensor int8**(对称,$[-127,127]$):

$$
s=\frac{\max|x|}{127}=\frac{67.0}{127}\approx0.528
$$

于是普通值 $0.3\to\text{round}(0.3/0.528)=\text{round}(0.57)=1$,反量化回 $0.528$——**误差 76%**!$-0.2\to\text{round}(-0.38)=0$,直接变成 0。除了那个离群值本身,**所有正常值几乎全被抹平**。这一行的有效信息基本丢光。

**LLM.int8() 的做法**:把第 4 维(离群列)抽出来 → 这一维用 fp16 精确保留 $67.0$;剩下 7 个正常值用它们自己的 $\max|x|=0.8$ 定尺子,$s=0.8/127\approx0.0063$,$0.3\to48$、$-0.2\to-32$,分辨率完全够。两部分各算各的矩阵乘,结果相加。**离群值精确、正常值也精确**。

## 原理:vector-wise 量化 + 混合精度分解

LLM.int8() 由两块组成。

**1)vector-wise(逐向量)量化**——把粒度做细。矩阵乘 $XW$ 中,给激活 $X$ 的**每一行**一个 scale、权重 $W$ 的**每一列**一个 scale(而非整张一个 per-tensor scale)。这样每个 inner product 用「行 scale × 列 scale」还原:

$$
(XW)_{ij}\approx s^X_i\, s^W_j \sum_k \tilde X_{ik}\,\tilde W_{kj}
$$

逐向量 scale 比 per-tensor 抗离群得多,但**还不够**——离群维太极端,光靠细粒度仍救不回。

**2)混合精度分解(mixed-precision decomposition)**——隔离离群列。设离群特征维的下标集合为 $O$(用阈值如 $|x|\ge6.0$ 判定),把矩阵乘拆成两部分:

$$
X W \;=\; \underbrace{\sum_{k\in O} X_{:,k}\,W_{k,:}}_{\text{fp16,离群列,精确}}\;+\;\underbrace{\sum_{k\notin O} X_{:,k}\,W_{k,:}}_{\text{int8,其余列,vector-wise 量化}}
$$

- 离群列($k\in O$):**不量化**,直接 fp16 矩阵乘。$|O|$ 极小(典型 ≤ 7 个维),开销可忽略。
- 其余列($k\notin O$):**int8** 矩阵乘,享受省显存和整数 Tensor Core 加速。
- 两部分相加得最终结果。

**为什么有效**:难量化的"少数"被隔离到 fp16,不再污染"多数";多数本就好量化,int8 几乎无损。整体实现 **8-bit 推理零精度退化**,首次让 OPT-175B 这种模型在**消费级多卡**上跑起来(显存减半)。

**为什么 vector-wise 还不够、非得加分解**。直觉上,既然把粒度做到激活逐行、权重逐列(vector-wise),离群列不就被隔离在它自己那一行/列的 scale 里了吗?问题在于:离群维是**沿隐藏维(列)方向**的,而 vector-wise 给的是「激活每行一个 scale」——同一行里既有离群维又有正常维,这个行 scale 仍被离群维撑爆,正常维照样遭殃。所以必须再叠**列方向的混合精度分解**,把离群列整列拎出走 fp16。两招正交、缺一不可。

**和「逐 token 动态量化」的关系**:vector-wise(激活逐行=逐 token)本质就是激活 per-token 动态量化,这是抗离群的标准粒度;但 LLM 的离群是按维度(列)系统出现的,per-token 解决不了「某几列恒大」,所以才需要混合精度分解这第二招。

**代价 / 局限**:推理时要**在线检测离群列并做两路计算**,实现复杂、有一定额外开销;它是**仅权重 + 激活的 int8 推理**方案,延迟收益不如纯 int4 权重方案;速度上对小 batch 不一定比 fp16 快(分解和 gather 有开销)。后来的 [[096 AWQ 与 SmoothQuant|SmoothQuant]] 改走「把离群难度从激活迁到权重」的路线,避免运行时分解。

## 代码:为何要隔离离群列(❌ vs ✅)

```python
import torch

def quant_int8_symmetric(x, dim=None):
    qmax = 127
    s = x.abs().amax(dim=dim, keepdim=True) / qmax
    q = torch.clamp(torch.round(x / s), -qmax, qmax)
    return q, s

# 一行激活,含一个离群维(第 4 个 = 67.0)
x = torch.tensor([[0.3, -0.5, 0.8, 67.0, -0.2, 0.6, -0.4, 0.1]])

# ❌ 错:整行一把尺子量化 —— 离群值撑爆 scale,正常值全被抹平
q_bad, s_bad = quant_int8_symmetric(x, dim=1)
x_hat_bad = q_bad * s_bad
print("朴素 int8 还原:", x_hat_bad.round(decimals=2).tolist())
# 正常值几乎全变成 0 / 0.5,信息丢失

# ✅ 对:混合精度分解 —— 离群列走 fp16,其余列单独 int8
outlier_mask = x.abs() >= 6.0                  # 检测离群维
x_normal = x.masked_fill(outlier_mask, 0.0)    # 普通列(离群位置置 0)
x_outlier = x.masked_fill(~outlier_mask, 0.0)  # 离群列(保留 fp16)

q_n, s_n = quant_int8_symmetric(x_normal, dim=1)   # 普通列用自己的小 scale
x_hat = q_n * s_n + x_outlier                       # int8 部分 + fp16 离群部分
print("LLM.int8 还原:", x_hat.round(decimals=3).tolist())
# 正常值分辨率恢复,离群值精确保留

# 实务:from transformers import AutoModelForCausalLM
#       model = AutoModelForCausalLM.from_pretrained(name, load_in_8bit=True)
#       底层即 bitsandbytes 的 LLM.int8()
```

## 面试高频

- **LLM.int8() 解决什么问题?核心思想?** 解决大模型激活的**离群特征维**让 int8 量化崩坏的问题;核心是**混合精度分解**——极少数离群列走 fp16、其余走 int8,再相加,实现零退化 8-bit 推理。
- **离群特征是什么?有何特性?** 模型 ≳6.7B 后涌现的、固定出现在少数隐藏维上的超大激活值(比其他维大几十倍);系统性、稀疏(<0.1%)、对输出影响巨大,直接量化会崩。
- **为什么不能直接 per-tensor int8?** 一个离群值把 scale 撑得极大,正常值全挤进少数格子被抹平,误差巨大。LLM.int8() 用 vector-wise + 离群列分解解决。
- **LLM.int8() 和 SmoothQuant 路线区别?** LLM.int8() **运行时**把离群列拆成 fp16(混合精度,实现复杂、激活仍 int8);[[096 AWQ 与 SmoothQuant|SmoothQuant]] **离线**把激活的量化难度数学迁移到权重上,让激活也能均匀 int8、避免运行时分解。
- **它能加速吗?** 主要省**显存**(8-bit 权重)。推理速度上,因分解 / gather 开销,对小 batch 不一定比 fp16 快;追求延迟更常用 int4 权重(GPTQ/AWQ)+ fp16 激活。
- **和 QLoRA 什么关系?** QLoRA 的 4-bit 与 LLM.int8() 同出 Dettmers 团队、同在 `bitsandbytes` 库;`load_in_8bit=True` 即 LLM.int8(),`load_in_4bit` 即 [[097 NF4 与 QLoRA 4-bit|NF4]]。
- **离群特征具体有多极端?** 6.7B 模型里约 75% 序列受影响,单序列约 15 万个离群激活但只集中在约 6 个隐藏维上,数值比常态大 50~100 倍——少而频、极端而系统。这是「emergent(涌现)」现象,随规模出现。
- **为什么 vector-wise 量化还不够?** 离群是沿隐藏维(列)系统出现的,而 vector-wise 给激活的是逐行(per-token)scale,同一行里离群维仍把行 scale 撑爆;必须再叠列方向的混合精度分解把离群列整列走 fp16。两招正交。
- **阈值 6.0 怎么用?太高还是太低?** LLM.int8 用 $|x|\ge6.0$ 判离群列;论文里这个阈值对各变体已是合适的分界(再高会漏判一些该隔离的维)。判定后这些列走 fp16,其余 int8。
- **它为什么不一定加速、只稳省显存?** 主要收益是 8-bit 权重省一半显存;但运行时要检测离群列、gather、拆两路矩阵乘再合并,这些开销在小 batch 下可能抵消 int8 的速度优势,故对延迟敏感场景更常用 int4 权重(GPTQ/AWQ)。

## 关键事实

- LLM.int8():Dettmers, Lewis, Belkada, Zettlemoyer《LLM.int8(): 8-bit Matrix Multiplication for Transformers at Scale》(2022,arXiv:2208.07339,NeurIPS 2022)。
- 关键发现:离群特征在模型规模约 **6.7B 参数 / 困惑度某阈值**后**涌现**(emergent),且高度系统化——集中在极少数(≤约 0.1%、典型 ≤7 个)隐藏维度上。
- 方法 = **vector-wise 量化**(激活逐行、权重逐列 scale)+ **混合精度分解**(离群列 fp16、其余 int8),阈值常取 $|x|\ge6.0$。
- 效果:在最高至 175B(OPT-175B、BLOOM-176B)上实现**零精度退化**的 8-bit 推理,权重显存减半;集成进 Hugging Face `transformers` 的 `load_in_8bit=True`(经 `bitsandbytes`)。
