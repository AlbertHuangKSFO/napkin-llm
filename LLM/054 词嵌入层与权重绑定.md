[[054 词嵌入层与权重绑定|词嵌入层与权重绑定]] 讲的是分词产出 id 之后的第一层:**词嵌入层(embedding)按 id 在一张可训练的查找表 $E\in\mathbb{R}^{V\times d}$ 里取出对应行向量**,把离散 token 变成连续向量;以及 **权重绑定(tied embedding)**——让出口的输出投影直接复用这张表的转置 $E^\top$,一份权重「入口查表、出口打分」两头用。它承接 [[053 词表、特殊 token 与对话模板|词表]]的 id,呼应 [[016 输出层、tied embedding 与 logits|输出层]]。

## 直觉

分词器把文本切成 token、查 [[053 词表、特殊 token 与对话模板|词表]]得到一串整数 id。但 id 只是**编号**(`cat`=1042),编号本身没有语义——1042 不比 1041「大」也不「近」。模型需要的是**向量**:让语义相近的词在空间里靠近(见跨域 [[04 Embedding 与向量数据库|Embedding]])。

**词嵌入层就干这件事:一张查找表。** 它是个矩阵 $E$,$V$ 行(每个词一行)、$d$ 列(向量维度)。`embed(1042)` 就是**取出第 1042 行**那个 `d` 维向量。这些行向量是**可训练参数**,随训练逐渐学到语义——`cat` 和 `dog` 的行会越来越像。

关键认知:**嵌入查表 = one-hot 乘 $E$,但绝不真乘**。「查第 1042 行」数学上等于「one-hot 向量(只有第 1042 位是 1)× $E$」,可真这么算要乘一个 $V$ 维向量,白白浪费 $V$ 倍计算。实现里直接**索引** `E[id]`,这也是为什么它叫 embedding **lookup**(查表)。

**权重绑定**则是个省钱又提效的技巧(和 [[016 输出层、tied embedding 与 logits|输出层]]是一体两面):模型出口要把最后的 hidden 向量投影回 $V$ 个词打分(logits)。这个出口矩阵形状也是 `V×d`,和入口的 $E$ 一模一样。**何不复用?** 令输出投影 $=E^\top$:同一张 $E$,**入口拿来查表(词→向量)、出口拿来打分(向量→词的分数)**,一鱼两吃。省掉一整份 `V×d` 参数,还因梯度从两端来、词向量训得更充分,常降 perplexity。

一句话:**嵌入层 = 按 id 查行向量(可训练);权重绑定 = 入口的查找表 $E$ 转置后当出口打分矩阵,一份权重两头用。**

## 例子

**查表走一遍**。词表 `V=5`、维度 `d=3`,嵌入表(随便填的数):

```
id 0 (<pad>): [ 0.0,  0.0,  0.0]
id 1 (the)  : [ 0.5,  0.2, -0.1]
id 2 (cat)  : [ 0.7, -0.1,  0.4]
id 3 (dog)  : [ 0.6, -0.2,  0.3]   ← 和 cat 那行接近(语义近)
id 4 (sat)  : [-0.3,  0.8,  0.1]
```

输入 `"the cat sat"` → id 序列 `[1, 2, 4]` → 查表得 `(3, 3)` 矩阵:
```
[[ 0.5, 0.2, -0.1],     # the
 [ 0.7, -0.1, 0.4],     # cat
 [-0.3, 0.8, 0.1]]      # sat
```
这就是喂进 Transformer 第一层的张量(加上位置编码)。注意 `cat`(id2)和 `dog`(id3)行向量接近——训练后语义近的词向量会自动靠拢,这正是 [[03 点积、范数与相似度|相似度]]能度量的「同向程度」。

![[tok-嵌入查表.svg]]

**权重绑定省多少**。`V=50000`、`d=768`:

- 不绑定:入口嵌入 `50000×768` + 出口投影 `50000×768` = $2\times 3840$ 万 = **7680 万**参数。
- 绑定:**只一份** `50000×768` = **3840 万**,省一半。

在 GPT-2 small(总参 124M)里,单份嵌入约 3860 万 ≈ **31%**,绑定相当于砍掉近三成参数还常降点(Press & Wolf 2017)。出口打分公式:$\text{logits}=h\cdot E^\top$,第 $v$ 个分 = $h$ 与词 $v$ 行向量 $E_v$ 的点积——「和谁越像分越高」(详见 [[016 输出层、tied embedding 与 logits|输出层]])。

![[tok-权重绑定一鱼两吃.svg]]

## 原理

**1. 嵌入查表的数学。** 嵌入表 $E\in\mathbb{R}^{V\times d}$。token id 序列 $\mathbf{id}=(i_1,\dots,i_L)$,嵌入

$$X = E[\mathbf{id}]\in\mathbb{R}^{L\times d},\qquad X_t = E_{i_t}$$

等价于 one-hot 矩阵 $O\in\{0,1\}^{L\times V}$(每行一个 one-hot)乘 $E$:$X = OE$。但 $O$ 极稀疏,实现用 **gather/索引** 直接取行,$\mathcal{O}(Ld)$ 而非 $\mathcal{O}(LVd)$。批量时再加一维 batch,得 $(B,L,d)$(张量形状与广播见 [[13 张量、广播与维度对齐|张量]])。

**2. 它是可训练参数,梯度只回流被查的行。** $E$ 的每一行是参数。前向只索引若干行,反向传播的梯度也**只更新这些被查到的行**(没出现的词这步不更新)。框架用 sparse gradient 处理。原始 Transformer 还把嵌入乘 $\sqrt{d}$ 缩放(Vaswani 2017),让嵌入与位置编码量级匹配。

**3. 权重绑定的形式。** 出口要把最终 hidden $H\in\mathbb{R}^{B\times L\times d}$ 投影到词表得 logits。一般写 $\text{logits}=H W_{\text{out}}$,$W_{\text{out}}\in\mathbb{R}^{d\times V}$。**绑定**即令

$$W_{\text{out}}=E^\top,\qquad \text{logits}=H E^\top,\qquad \text{logit}_{b,t,v}=\langle H_{b,t},\,E_v\rangle$$

**同一个 $E$ 前向用两次**:入口按行索引,出口转置做投影。反向时 $E$ 的梯度来自**两条路**——输入侧(被查到的行)和输出侧(softmax 涉及全词表,所有行都得梯度)——所以词向量训得更充分。

**4. 为什么常更好(直觉 + 证据)。** 输入嵌入和输出投影本质都在描述「词 ↔ 向量」的同一套对应。分开学等于学两套互不相干的词义、浪费;绑定强制共享同一语义空间,且输出端的全表梯度让低频词也被训。Press & Wolf(2017)在多个语言模型基准上测得绑定后 perplexity 显著下降、参数更少。

**5. 硬约束与例外。** 绑定要求**输出投影维 = 嵌入维 = $d$**。若想让嵌入维 $d_{\text{emb}}$ 与模型维 $d_{\text{model}}$ 不同(如 ALBERT 因子分解嵌入,先 `V×d_emb` 再 `d_emb→d_model` 小投影),需在 `V×d_emb` 那份上绑定。也有模型**不绑**(如某些大模型嵌入/输出分开以增表达力),属设计取舍。

**6. 为什么原始 Transformer 把嵌入乘 $\sqrt d$(数值推导)。** 嵌入表常用 $\mathcal N(0,1)$ 类初始化,每个分量方差约 1,整行的 L2 范数 $\approx\sqrt d$;而位置编码(正弦)幅值在 $[-1,1]$、范数也约 $\sqrt d$。若不缩放,二者量级匹配;但 Vaswani 等用 $1/\sqrt{d}$ 类小初始化嵌入,导致嵌入范数 $\approx 1$、被位置编码淹没,故**前向时把嵌入乘 $\sqrt d$** 把范数抬回 $\sqrt d$ 量级,与位置编码相加才平衡。绑定时这点尤其要注意:出口 logits 用的是同一张 $E$,缩放只加在**入口前向**,别把出口也乘错。

**7. 因子分解嵌入(ALBERT)省参数的账。** 当 $V$ 巨大、$d$ 也大时,嵌入 $V\times d$ 是参数大头。ALBERT 把它拆成 $V\times d_{\text{emb}}$($d_{\text{emb}}$ 取小,如 128)+ $d_{\text{emb}}\times d_{\text{model}}$ 的小投影。以 $V=30000,d_{\text{model}}=768,d_{\text{emb}}=128$:原始 $30000\times768\approx2304$ 万;分解后 $30000\times128 + 128\times768\approx384+10\approx394$ 万,**省约 83%**。代价是嵌入表达力降一档,适合「嵌入只需 id→低维、上下文交互交给后面的层」的设计。

**8. softmax 瓶颈与大词表的输出层。** 出口 $\text{logits}=HE^\top$ 把 $d$ 维 hidden 映到 $V$ 维,$\text{rank}\le d$。当 $V\gg d$,这个低秩映射理论上限制了输出分布族(Yang 等 2018 的「softmax bottleneck」),但实践中 $d$ 已足够大、影响有限。工程上更突出的是**计算**:词表越大,这一层的 matmul $O(B L V d)$ 越贵、softmax 越慢;大词表模型(Gemma 256k)的输出层 + 嵌入是显存与算力的显著占比,也是 [[070 ZeRO 与 FSDP|分片]]/词表并行要处理的对象。

## 代码

```python
import numpy as np

# —— 嵌入查表:索引 vs one-hot 乘法,结果相同但开销天差地别 ——
V, d, L = 5, 3, 3
rng = np.random.default_rng(0)
E = rng.normal(size=(V, d))          # 嵌入表 (V, d)，可训练参数
ids = np.array([1, 2, 4])            # "the cat sat" 的 id

# ✅ 对:直接按 id 索引取行 —— O(L·d)
X_lookup = E[ids]                    # (3, 3)
print("查表:\n", X_lookup.round(3))

# ❌ 低效:先造 one-hot 再矩阵乘 —— 等价但多算 V 倍
onehot = np.eye(V)[ids]              # (3, 5) 稀疏
X_matmul = onehot @ E               # (3, 3)
print("等价?", np.allclose(X_lookup, X_matmul))   # True —— 数学等价
# 实际框架用 nn.Embedding，内部就是 gather，绝不真乘 one-hot
```

```python
import torch, torch.nn as nn
V, d = 50000, 768

# —— 权重绑定:入口嵌入与出口投影共享同一份权重 ——
emb  = nn.Embedding(V, d)            # 入口:id -> (·, d)
head = nn.Linear(d, V, bias=False)   # 出口:(·, d) -> (·, V) 打分

# ✅ 对:绑定(GPT-2/BERT/T5 默认)
head.weight = emb.weight             # 关键一行:指向同一张量
print("共享内存?", emb.weight.data_ptr() == head.weight.data_ptr())  # True

ids = torch.randint(0, V, (2, 4))    # (B=2, L=4)
x   = emb(ids)                       # (2,4,768)  入口查表
logits = head(x)                     # (2,4,50000) 出口打分 = x · Eᵀ
print(logits.shape, "省下", V*d, "个参数(对比不绑的两份)")

# ❌ 错:分别建两个独立矩阵 —— 白白多一份 V×d(小模型里 ~30% 参数),还少了输出端梯度
emb2  = nn.Embedding(V, d)
head2 = nn.Linear(d, V, bias=False)  # 与 emb2 无关，浪费且常掉点
```

```python
import numpy as np
# —— logit = hidden 与词向量的点积:谁越同向、分越高(手算) ——
d, V = 4, 3
E = np.array([[ 1.0, 0.0, 0.0, 0.0],   # 词0 嵌入
              [ 0.9, 0.1, 0.0, 0.0],   # 词1(与词0 几乎同向)
              [-1.0, 0.0, 0.0, 0.0]])  # 词2(与词0 反向)
h = np.array([1.0, 0.0, 0.0, 0.0])     # 某位置的 hidden
logits = h @ E.T                       # = [⟨h,E0⟩, ⟨h,E1⟩, ⟨h,E2⟩]
print("logits =", logits)              # [1.0, 0.9, -1.0]
probs = np.exp(logits) / np.exp(logits).sum()
print("softmax =", probs.round(3))     # 词0 概率最高、词2 最低 —— 和谁同向就更可能输出谁

# —— 嵌入缩放 √d:平衡嵌入与位置编码量级 ——
emb_row = np.random.normal(0, 1/np.sqrt(d), size=d)   # 小初始化,范数≈1
print("缩放前范数:", np.linalg.norm(emb_row).round(3))
print("乘 √d 后  :", np.linalg.norm(emb_row*np.sqrt(d)).round(3))  # ≈√d,与位置编码匹配
# ❌ 绑定时把出口也乘 √d → logits 量级翻倍、温度失真;缩放只加在入口前向
```

## 面试高频

- **Q:词嵌入层到底在做什么?为什么不用 one-hot 直接乘?** A:按 token id 在可训练表 $E\in\mathbb{R}^{V\times d}$ 里取对应行,把离散 id 变成稠密向量。数学上等于 one-hot × $E$,但 one-hot 极稀疏、真乘浪费 $V$ 倍算力,实现直接索引 `E[id]`(故称查表 lookup)。
- **Q:嵌入是可训练的吗?梯度怎么回流?** A:是参数。前向只索引被用到的行,反向也**只更新这些行**(其余词本步不更新),框架用 sparse gradient。绑定时输出端会给所有行额外梯度。
- **Q:什么是权重绑定 tied embedding?好处?** A:令输出投影 = 输入嵌入表的转置 $E^\top$,同一份权重入口查表、出口打分。① 省一份 `V×d`(小模型可达总量 ~30%);② 输入输出共享词义空间、词向量从两端得梯度,常降 perplexity(Press & Wolf 2017)。详见 [[016 输出层、tied embedding 与 logits|输出层]]。
- **Q:为什么 logit = hidden 与词向量的点积?** A:出口 $\text{logits}=hE^\top$,第 $v$ 个分 = $\langle h, E_v\rangle$,即 hidden 与词 $v$ 嵌入向量的点积——和谁越同向(相似度越高)分越高(见 [[03 点积、范数与相似度|相似度]])。
- **Q:绑定有什么前提?** A:输出投影维 = 嵌入维 = $d$。若嵌入维想和模型维不同,需加中间投影(如 ALBERT 因子分解嵌入)再绑定。
- **Q:LLM 的词嵌入和 RAG 用的句向量 embedding 是一回事吗?** A:不完全。LLM 词嵌入是**单 token** 的查表向量、是模型第一层参数;RAG 的 [[04 Embedding 与向量数据库|句/段 embedding]] 是把整段文本编码成一个向量做检索,通常来自专门的编码模型(如 sentence-transformers)。同名「embedding」,粒度和用途不同。
- **Q:为什么原始 Transformer 要把嵌入乘 $\sqrt d$?** A:用小初始化时嵌入行范数 $\approx1$,会被范数 $\approx\sqrt d$ 的位置编码淹没;乘 $\sqrt d$ 把嵌入抬到同量级,相加才平衡。绑定时缩放只加在入口前向,别把出口 logits 也乘。
- **Q:ALBERT 的因子分解嵌入省了什么?** A:把 $V\times d$ 拆成 $V\times d_{\text{emb}}$(小)+ $d_{\text{emb}}\times d_{\text{model}}$ 小投影;$V=30k,d=768,d_{\text{emb}}=128$ 时从 2304 万降到约 394 万(省 ~83%),代价是嵌入表达力略降。
- **Q:现代大模型还都绑定吗?** A:不一定。小模型几乎都绑(省显著比例参数 + 提点);很多大模型(如 LLaMA 系部分配置、PaLM)**不绑**,因为 $V\times d$ 占总参比例已小、解绑给输出端更多表达力,属规模相关的取舍。
- **Q:什么是 softmax 瓶颈?** A:出口 $HE^\top$ 是 $d$ 维到 $V$ 维的低秩($\le d$)映射,$V\gg d$ 时理论上限制输出分布族(Yang 2018);实践中 $d$ 够大、影响有限,真正突出的是大词表输出层的算力/显存开销。
- **陷阱**:① 别真用 one-hot 矩阵乘;② 绑定后改一个就改了另一个(共享内存),调试易踩;③ 嵌入维 ≠ 模型维时不能直接绑;④ 词表巨大时嵌入表是显存大头;⑤ 嵌入缩放 $\sqrt d$ 只加入口、别误加出口;⑥ 大模型未必绑定,别默认。

## 关键事实

- 嵌入查表等价 one-hot × $E$,实现用 gather 索引,复杂度 $\mathcal{O}(Ld)$ 而非 $\mathcal{O}(LVd)$;`nn.Embedding`/`tf.nn.embedding_lookup` 即此。
- 原始 Transformer(Vaswani 等,2017,arXiv:1706.03762)在输入嵌入、输出嵌入与 pre-softmax 线性层间**共享权重**,并把嵌入乘 $\sqrt{d}$ 缩放。
- 权重绑定出自 **Press & Wolf《Using the Output Embedding to Improve Language Models》(EACL 2017,arXiv:1608.05859)**:绑定后多个 LM 基准 perplexity 显著下降、参数更少。
- 已成默认:GPT-2、BERT、RoBERTa、T5 普遍绑定输入嵌入与输出投影;`V=50k,d=768` 时绑定省 3840 万参数,约占 GPT-2 small(124M)的 31%。
- 嵌入是可训练参数,梯度仅回流被查行(输入侧)与全表(绑定的输出侧);词表巨大时嵌入表是显存/参数大头。
