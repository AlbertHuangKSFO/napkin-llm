[[104 投机解码与 Medusa、Lookahead]]:用一个**快但糙的草稿**先连出几个 token、再让**大模型一次并行验证**,把 decode 的逐 token 串行变成「一次出多个」,在**不改变输出分布**(无损)的前提下提速 2–3×;Medusa、Lookahead 是「不要独立草稿模型」的变体。

## ① 直觉:decode 的算力在白白闲置,拿来并行验证

[[078 推理算力、吞吐与延迟、Roofline|decode 阶段访存受限]]——每生成 1 个 token 要把整个模型权重从显存读一遍,但只算 1 个 token,GPU 算力利用率常不到 1%。**算力大量闲置**。

投机解码(speculative decoding)的洞察:既然算力闲着,**一次多验证几个 token 几乎不额外费时**(还是读一遍权重)。于是:

1. **Draft(起草)**:用一个**小而快**的草稿模型(或同模型的轻量机制)自回归连出 $\gamma$ 个候选 token(例如 4 个)。小模型这 4 步,耗时约等于大模型 1 步。
2. **Verify(验证)**:把这 4 个候选**一次性喂给大模型并行前向**,逐位置检查大模型是否「认可」。认可的前缀全部接受,第一个被拒的位置由大模型自己修正。

最好情况:1 次大模型前向产出 4 个 token(4 接受);最坏:全拒,退化成普通 1 token/前向。**平均接受长度就是加速比**,典型 2–3×。

关键:这是**无损加速**——下面会看到,经过「修正过的拒绝采样」,最终输出分布严格等于大模型单独解码,质量分毫不差,只是更快。

## ② 例子:γ=4 的一轮

prompt 后,草稿模型连出 `the cat sat on`(4 个 token,耗时 ≈ 大模型 1 步)。大模型并行验证这 4 个位置:

- 位置 1 `the`:大模型也想要 → **接受**
- 位置 2 `cat`:接受
- 位置 3 `sat`:接受
- 位置 4 `on`:大模型概率不够 → **拒绝**,并就地用大模型分布**重采**一个(比如 `a`)

本轮:1 次大模型前向 → 产出 `the cat sat a` 共 **4 个 token**(3 个接受 + 1 个修正)。若不投机,这要 4 次前向。加速 ≈ 4×(本轮);全程平均看接受率,典型落在 2–3×。

接受率受什么影响?**草稿越像目标、温度越低、文本越规整(代码、模板)→ 接受率越高**;反之高温创意生成接受率低。

**把加速比算清楚(关键手算)。** 设单 token 接受率 $\alpha$(草稿每个 token 被接受的概率),每轮草稿 $\gamma$ 个。一轮里期望接受的 token 数(几何分布,直到第一个拒绝):

$$
\mathbb{E}[\text{接受数}]=\frac{1-\alpha^{\gamma+1}}{1-\alpha}
$$

这就是「一次大模型前向产出多少 token」,也约等于加速比(忽略草稿开销与验证开销)。代入:
- $\alpha=0.7,\gamma=4$:$\frac{1-0.7^5}{1-0.7}=\frac{1-0.168}{0.3}\approx 2.77$ → 约 **2.8×**。
- $\alpha=0.8,\gamma=4$:$\frac{1-0.8^5}{0.2}=\frac{1-0.328}{0.2}\approx 3.36$ → 约 **3.4×**。
- $\alpha=0.9,\gamma=6$:$\frac{1-0.9^7}{0.1}\approx 5.2$ → 约 **5.2×**。

两个洞察:① **$\alpha$ 是命根子**——从 0.7 提到 0.9,加速比近乎翻倍,所以一切变体的核心都是「提高草稿与目标的一致性」;② **$\gamma$ 边际递减**——$\gamma$ 太大,后面的 token 大概率被拒(白草拟),且草稿自身耗时线性增长,所以 $\gamma$ 通常取 4~8,不是越大越好。最优 $\gamma$ 随 $\alpha$ 增大而增大。

## ③ 原理:修正过的拒绝采样(为何无损)+ 三种变体

**无损的数学核心。** 设位置上草稿分布 $q(x)$、目标(大模型)分布 $p(x)$,草稿采样得 $x$。按下式接受:

$$
\text{接受 } x \text{ 的概率} = \min\!\left(1,\ \frac{p(x)}{q(x)}\right)
$$

若**拒绝**,则从「残差分布」重采一个新 token:

$$
p_{\text{resid}}(x) = \frac{\max\big(0,\ p(x)-q(x)\big)}{\sum_{x'}\max\big(0,\ p(x')-q(x')\big)}
$$

可以证明:**最终被输出的 token 服从分布恰为 $p(x)$**——与大模型单独采样完全一致。直觉:接受步「按 $\min(1,p/q)$ 截掉草稿多给的部分」,拒绝步「把草稿欠给的部分 $(p-q)_+$ 补回来」,两者合起来精确还原 $p$。所以加速纯粹来自并行验证,**不付出任何质量代价**。这就是 Leviathan 2023(arXiv:2211.17192)与同期 Chen et al. 的核心。

**变体一:Medusa(2024)——加头,免独立草稿模型。** 独立草稿模型的麻烦:要找/训一个和目标对齐的小模型、还要单独部署。Medusa 改为在**主干 LLM 最后一层隐藏态上,多挂几个轻量解码头**,头 $k$ 直接预测「未来第 $k$ 个 token」。每个头出 top-k 候选,组合成一棵**候选树**,用**树注意力(tree attention)**一次验证所有分支。只需在冻结主干上微调这些头(Medusa-1)或联合微调(Medusa-2),无需第二个模型。

![[infer-Medusa多头树.png]]

**变体二:Lookahead Decoding——零训练,n-gram 猜。** 完全不训练任何东西:用 **Jacobi 迭代**并行求解多个未来位置,生成 n-gram 候选缓存进 n-gram 池;同时用「验证分支」从池里取候选让大模型一次校验,命中就跳多个 token。代价是每步 FLOPs 增多(拿闲置算力换步数),适合算力有余的访存受限场景。vLLM、TGI 都内置。

**变体三:EAGLE / EAGLE-2 / EAGLE-3——当前 SOTA,在「特征层」自回归。** EAGLE(2024)的关键洞察:**在 token 层做草稿不确定性大,改在更平滑的「特征(倒数第二层隐藏态)」层做自回归预测**,再接目标模型的输出头转成 token,草稿质量大幅提升,接受率显著高于 Medusa。**EAGLE-2(2024)** 进一步发现「接受率不仅依赖位置、更依赖上下文」,于是把固定的候选树换成**动态草稿树(dynamic draft tree)**——按当前上下文的置信度动态决定树的形状与深度,SOTA 加速比。EAGLE-3 再优。这是「不要独立草稿模型」路线里目前效果最好的一支,vLLM、SGLang 均已集成。

**变体四:自投机(self-speculative)与分层退出。** 不另找草稿模型,用**同一个大模型的前几层/部分层**当草稿(早退出 early-exit 出草稿、全层验证),或用 INT4 量化版当 FP16 版的草稿。好处是无需额外训练/部署第二个模型,草稿与目标天然对齐(接受率高)。

**一张表理清四类「草稿来源」**:

| 方法 | 草稿来自 | 要训练吗 | 是否无损 |
|---|---|---|---|
| 经典投机解码 | 独立小模型 | 否(但要对齐的小模型) | 是(修正拒绝采样) |
| Medusa | 主干 + 多解码头 | 训练头 | 非贪心下放松接受,不严格无损 |
| Lookahead | Jacobi n-gram 池 | 否 | 是 |
| EAGLE 系 | 主干特征层自回归头 | 训练轻量头 | 是(配验证) |

**三者本质相同**:decode 访存受限、算力闲置 → 用闲置算力并行验证多个候选,把「串行步数」换成「每步多算一点」,无损提速。**batch 越大,投机收益越小**——大 batch 下算力本就被多请求吃满,没有闲置可挖。**易错点**:Medusa 等在**非贪心(温度>0)采样下放松了接受条件**(typical acceptance),此时**不再严格无损**(输出分布略变);经典投机解码与 EAGLE 配修正拒绝采样才严格无损。面试若被问「投机解码一定无损吗」,答:**取决于接受准则**——标准修正拒绝采样无损,Medusa 的 typical acceptance 在非贪心下不严格无损(用质量换更高接受率)。

## ④ 代码:投机解码核心循环(修正拒绝采样)

```python
import torch

def speculative_step(target, draft, ctx, gamma=4, temp=1.0):
    """一轮:草稿连 gamma 个,目标并行验证,返回本轮接受+修正的 token。"""
    # 1) 草稿自回归连出 gamma 个 token 及其分布 q
    draft_tokens, q_probs = [], []
    cur = ctx
    for _ in range(gamma):
        q = torch.softmax(draft(cur)[-1] / temp, -1)
        x = torch.multinomial(q, 1).item()
        draft_tokens.append(x); q_probs.append(q)
        cur = torch.cat([cur, torch.tensor([x])])

    # 2) 目标模型一次并行前向,拿到 gamma+1 个位置的分布 p
    p_logits = target(torch.cat([ctx, torch.tensor(draft_tokens)]))
    p_probs = torch.softmax(p_logits[-(gamma+1):] / temp, -1)

    # 3) 逐位置「修正过的拒绝采样」
    out = []
    for i, x in enumerate(draft_tokens):
        p, q = p_probs[i], q_probs[i]
        if torch.rand(1).item() < min(1.0, (p[x] / q[x]).item()):
            out.append(x)                              # 接受
        else:
            resid = torch.clamp(p - q, min=0)          # 残差分布 (p-q)_+
            resid = resid / resid.sum()
            out.append(torch.multinomial(resid, 1).item())  # 拒绝→重采,仍服从 p
            return out                                 # 第一个拒绝后停,丢弃其余草稿
    # 全接受:再从目标第 gamma+1 个分布额外白送一个 token
    out.append(torch.multinomial(p_probs[gamma], 1).item())
    return out

# ❌ 错:把草稿 token 直接全盘接受 → 输出分布变成草稿的,质量退化
# ✅ 对:按 min(1, p/q) 接受、拒绝则从 (p-q)_+ 重采 → 分布严格还原为目标 p
```

```python
# 加速比 = 一轮期望接受 token 数,由接受率 α 和草稿长度 γ 决定
def expected_speedup(alpha, gamma):
    """E[接受数] = (1 - α^(γ+1)) / (1 - α);约等于加速比(忽略草稿/验证开销)。"""
    return (1 - alpha ** (gamma + 1)) / (1 - alpha)

for a, g in [(0.7, 4), (0.8, 4), (0.9, 6)]:
    print(f"α={a} γ={g} -> ~{expected_speedup(a, g):.2f}x")
# α=0.7 γ=4 -> ~2.77x   α=0.8 γ=4 -> ~3.36x   α=0.9 γ=6 -> ~5.22x

# γ 边际递减:固定 α=0.8,看加速比随 γ 增长很快饱和
for g in [2, 4, 8, 16]:
    print(f"γ={g} -> {expected_speedup(0.8, g):.2f}x")
# γ=2 -> 2.44   γ=4 -> 3.36   γ=8 -> 4.21   γ=16 -> 4.83  ← 翻倍 γ 收益越来越小
# 实际最优 γ 还要扣草稿自身的 γ 步耗时,所以生产里 γ 多取 4~8
```

## 面试高频

- **Q:投机解码为什么能加速、又为什么无损?** decode 访存受限、算力闲置;用小草稿连几个 token、大模型一次并行验证(几乎不额外费时)。经修正过的拒绝采样(min(1,p/q) 接受、拒绝从 (p−q)₊ 重采),输出分布严格等于大模型,故无损。典型 2–3×。
- **Q:接受率受什么影响?** 草稿与目标越接近、温度越低、文本越规整(代码/模板)→ 接受率越高;高温创意生成低。加速比 ≈ 平均接受长度。
- **Q:Medusa 相比经典投机解码改了什么?** 不用独立草稿模型,改在主干最后隐藏态上挂多个解码头预测未来 token,组成候选树用树注意力一次验证,只需微调头(免找/部署第二个模型)。
- **Q:Lookahead 和前两者区别?** 零训练,用 Jacobi 迭代并行猜 n-gram 候选 + 验证分支校验,拿额外 FLOPs 换步数。
- **Q:为什么 batch 大了投机收益变小?** 大 batch 下算力被多请求吃满、不再闲置,没有空算力去并行验证候选,投机的「免费午餐」消失。
- **Q:投机解码改变 KV-Cache 吗?** 验证时草稿 token 也写入 KV,但被拒的要回滚;实现上需支持 KV 的临时追加与截断。
- **Q:加速比怎么估?** $\frac{1-\alpha^{\gamma+1}}{1-\alpha}$($\alpha$ 单 token 接受率、$\gamma$ 草稿长度)。$\alpha$ 是命根子(0.7→0.9 加速近翻倍);$\gamma$ 边际递减,通常 4~8。
- **Q:投机解码一定无损吗?** 取决于接受准则。经典修正拒绝采样(min(1,p/q) + 残差重采)严格无损;Medusa 的 typical acceptance 在非贪心采样下放松了条件,**不严格无损**(以微小质量换更高接受率)。EAGLE 配验证则无损。
- **Q:EAGLE 比 Medusa 强在哪?** EAGLE 在更平滑的「特征层」(倒数第二层隐藏态)做自回归草稿,再过输出头转 token,草稿不确定性更小、接受率更高;EAGLE-2 用动态草稿树(按上下文置信度调整树形)进一步提速,是当前 SOTA。
- **Q:为什么 γ 不是越大越好?** 草稿越长,靠后的 token 越可能被拒(白草拟),且草稿自回归的 γ 步耗时线性增长;加速比 $\frac{1-\alpha^{\gamma+1}}{1-\alpha}$ 随 γ 饱和。最优 γ 随 α 升高而增大。

## 关键事实

- 投机解码(speculative decoding):草稿模型起草 + 目标模型并行验证 + 修正过的拒绝采样,无损提速 2–3×,无需重训或改架构(Leviathan et al., 2023, arXiv:2211.17192;Chen et al., 2023, arXiv:2302.01318 同期独立提出)。
- 无损性来自:接受概率 $\min(1,p/q)$、拒绝时从残差 $(p-q)_+$ 归一化重采,可证输出分布精确等于目标分布 $p$。
- Medusa:在主干 LLM 上加多个解码头预测后续 token,用树注意力一次验证候选树,免独立草稿模型;Medusa-1 冻结主干微调头、Medusa-2 联合微调(Cai et al., 2024, arXiv:2401.10774)。
- Lookahead Decoding:基于 Jacobi 迭代并行生成 n-gram 候选 + 验证,零额外训练,拿 FLOPs 换解码步数(Fu et al., 2024)。
- EAGLE:在倒数第二层「特征」层做自回归草稿(而非 token 层),接受率高于 Medusa(Li et al., 2024, arXiv:2401.15077);EAGLE-2 用动态草稿树(接受率位置+上下文相关)再提速,当前 SOTA(Li et al., EMNLP 2024, arXiv:2406.16858);均已集成进 vLLM/SGLang。
- 加速比 $\approx\frac{1-\alpha^{\gamma+1}}{1-\alpha}$(几何分布期望接受长度),$\alpha$ 为单 token 接受率、$\gamma$ 草稿长度;$\alpha$ 主导、$\gamma$ 边际递减(典型 4~8)。
- 无损性取决于接受准则:标准修正拒绝采样严格无损;Medusa 的 typical acceptance 在非贪心下放松条件、不严格无损(以质量换接受率)。
- decode 访存受限是投机解码的物理前提(见 [[078 推理算力、吞吐与延迟、Roofline]]);batch 越大、算力越饱和,投机收益越小。
