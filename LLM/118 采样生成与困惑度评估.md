[[118 采样生成与困惑度评估|采样生成与困惑度评估]]:给训好的 tiny GPT 两件事——**生成**(自回归循环 + 温度 + top-k 控制随机性)和**评估**(在留出文本上算困惑度 PPL 与 bits-per-byte)。这是把 [[101 采样解码：温度、top-k、top-p、min-p、重复惩罚|采样解码]] 和 [[109 语言模型评估：困惑度与 bits-per-byte|困惑度]] 落到 tiny GPT 的 `sample.py`,让模型既能「说话」又有一把客观的尺子。

## 直觉

训完模型只是得到一个「给定前文 → 下一个 token 概率分布」的函数。**生成**就是反复:算分布 → 采一个 token → 拼回去 → 再算(自回归)。但「采一个」有讲究:

- **温度** $T$:把 logits 除以 $T$ 再 softmax。$T$ 小 → 分布更尖锐 → 更确定、更重复;$T$ 大 → 更平、更随机、更可能崩。$T\to0$ 退化成贪心(取 argmax)。
- **top-k**:只在概率最高的 $k$ 个候选里采,其余置零——砍掉长尾的胡话(见 [[101 采样解码：温度、top-k、top-p、min-p、重复惩罚|采样解码]])。

**评估**不能只看「生成得像不像」(主观)。客观尺子是**困惑度 PPL = exp(平均交叉熵)**:直觉是「模型平均在多少个候选 token 之间犹豫」(见 [[109 语言模型评估：困惑度与 bits-per-byte|困惑度]])。随机模型 PPL = 词表大小 $V$,完美模型 PPL = 1,越低越好。注意:**PPL 只在同一个 tokenizer 下可比**;跨 tokenizer 要用 **bits-per-byte**(按字节归一)。

## 例子

**温度怎么改变分布(实测)。** 同一组 logits `[2.0, 1.0, 0.5, 0.1, -1.0]`:

| 温度 | 最高项概率 | 形状 |
|---|---|---|
| $T=0.5$ | 0.83 | 尖锐(更确定、易重复)|
| $T=1.0$ | 0.56 | 原始 |
| $T=2.0$ | 0.37 | 平滑(更随机、可能崩)|

**top-k=2**:`[0.73, 0.27, 0, 0, 0]`——只剩前两个候选,长尾被砍。这两个旋钮组合控制「创造性 vs 稳定性」。

**top-k 的硬伤,和 top-p / min-p 怎么补(扩面)。** top-k 固定留 $k$ 个,但**分布有时尖有时平**:
- 分布很尖(模型很确定,如代码缩进后必跟空格):top-k=50 会强行带进 49 个低概率噪声候选 → 偶发胡话。
- 分布很平(开放创作,几十个词都合理):top-k=5 又砍掉太多合理选项 → 变单调。

**top-p(nucleus,Holtzman 2019)**:按累计概率截断——把候选按概率降序累加,留到累计 $\ge p$(如 0.9)的**最小集合**。尖分布时自动只留少数、平分布时自动多留,**候选个数自适应**,这是它优于 top-k 的根本。**min-p(2024)**:留概率 $\ge p_{\min}\times p_{\max}$ 的候选(相对最高概率设阈值),对分布形状更鲁棒,高温下表现好。**实战常组合**:温度 + top-p(如 $T{=}0.8,p{=}0.95$)是 chat 的常见默认。

**重复惩罚(repetition penalty)**:模型容易陷入复读(「the the the」)。对**已生成过的 token** 的 logits 除以一个惩罚因子(>1),降低它再次被选中的概率。还有 presence/frequency penalty(出现过就罚 / 按出现次数罚)。这是抑制退化重复的工程补丁(见 [[101 采样解码：温度、top-k、top-p、min-p、重复惩罚|重复惩罚]])。

**困惑度的标尺(实测)。** 一个**均匀预测器**(对 $V=10$ 类全输出相同概率):
```
avg NLL = 2.303  ≈ ln(10) = 2.303   ✅
PPL     = 10.0   ≈ V                 ← 随机基线
```
完美预测器(每步把正确 token 概率推到 1)→ loss≈0 → PPL≈1。实际 tiny GPT 落在两者之间,**越接近 1 越好**。这给了你一个不靠人眼的进步度量:训练时 PPL 持续下降 = 真在学。

**bits-per-byte**:把总 NLL(nats)换算成「每字节几比特」,$\text{bpb}=\frac{\text{总NLL}_{\text{nats}}}{\ln 2\cdot\text{字节数}}$——跨 tokenizer 可比,是预训练论文常报的指标(见 [[109 语言模型评估：困惑度与 bits-per-byte|bits-per-byte]])。

## 原理

**1. 自回归生成。** 已训好 $p_\theta(\cdot\mid x_{\le t})$。给定提示 $x_{1:n}$,循环:取最后位置 logits → 温度缩放 → top-k 截断 → softmax → 采样 $x_{n+1}\sim p$ → 拼回 → 重复(见 [[100 解码策略：贪心与 Beam|解码策略]])。每步只关心**最后一个位置**的分布(前面的位置已经定了);超过 `block_size` 就截掉最左(滑窗)。

**2. 温度。** 对 logits $z$ 缩放再 softmax:

$$p_i=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}$$

$T<1$ 放大 logits 差距 → 分布更尖(熵降);$T>1$ 压缩差距 → 更平(熵升);$T\to0^+$ → one-hot 在 argmax(= 贪心);$T\to\infty$ → 均匀。**温度只改采样随机性,不改 logits 的相对顺序**(见 [[101 采样解码：温度、top-k、top-p、min-p、重复惩罚|温度]])。

**3. top-k。** 保留 logits 最大的 $k$ 个,其余设 $-\infty$(softmax 后为 0),在剩下的里重新归一化采样。砍掉低概率长尾,避免偶发胡话;$k=1$ 即贪心。常与温度组合(见 [[101 采样解码：温度、top-k、top-p、min-p、重复惩罚|top-k]];top-p/min-p 是按概率质量截断的变体)。

**4. 困惑度。** 在留出文本上,逐位置算自回归交叉熵(见 [[060 训练目标与 loss 实现|loss]]、[[109 语言模型评估：困惑度与 bits-per-byte|困惑度]]):

$$\text{PPL}=\exp\!\Big(-\frac{1}{N}\sum_{t}\log p_\theta(x_{t+1}\mid x_{\le t})\Big)=\exp(\bar{\mathcal{L}})$$

直觉:几何平均的「有效候选数」。随机均匀模型 $\bar{\mathcal{L}}=\ln V$ → PPL$=V$;完美模型 $\bar{\mathcal{L}}=0$ → PPL$=1$。**实现要点**:用滑窗、`reduction="sum"` 累加 NLL,分母用**总有效 token 数**(off-by-one 或忘记长上下文的条件信息会让 PPL 虚高/虚低)。

**5. bits-per-byte(跨 tokenizer 可比)。** PPL 依赖分词粒度(同样文本,token 多则每 token 信息少、PPL 看着低),不可跨 tokenizer 比。bpb 把信息按**原始字节**归一:

$$\text{bpb}=\frac{\sum_t -\log_2 p_\theta(x_{t+1}\mid x_{\le t})}{\#\text{bytes}}=\frac{\bar{\mathcal{L}}_{\text{nats}}\cdot N_{\text{tok}}}{\ln 2\cdot N_{\text{bytes}}}$$

预训练论文常报 bpb 而非 PPL,正因它与分词无关(见 [[109 语言模型评估：困惑度与 bits-per-byte|bits-per-byte]])。

**6. 一个关键澄清:采样方式不影响 PPL。** PPL 是用**模型对真实文本的概率**算的(逐位置 $-\log p_\theta(x_{t+1}\mid x_{\le t})$),和你用什么温度/top-k 采样**无关**——采样是「生成新文本」,PPL 是「评估对已有文本的拟合」。所以「调高温度生成更多样」不会改变 PPL;反过来,PPL 低也不保证生成好(可能复读、可能在采样下崩)。**生成质量看人评/基准,文本拟合看 PPL,两套尺子**(见 [[109 语言模型评估：困惑度与 bits-per-byte|内在 vs 外在]])。

**7. KV-Cache:生成的提速关键(为什么生成不慢)。** 朴素 generate 每生成一个 token 都把**整个已有序列**重新前向一遍——第 $t$ 步要算 $t$ 个位置,总计 $O(T^2)$,越生成越慢。**KV-Cache**(见 [[102 KV-Cache|KV-Cache]])缓存历史每层的 K、V,每步只为**新 token** 算 Q 并和缓存的 K、V 做注意力,每步 $O(1)$(相对序列长度),总 $O(T)$。本 tiny 版的 generate 为教学没用 cache(每步重算 `idx_cond`),真实推理必用——这也是 103–108 那些推理优化的起点。

## 代码

完整可运行,接 117 训好的 `model`。`generate` 与 `perplexity` 即 `sample.py`。已验证:温度方向、top-k 截断、均匀预测器 PPL≈V。

```python
# sample.py —— 采样生成（温度 + top-k）+ 困惑度评估
import math, torch
import torch.nn.functional as F

@torch.no_grad()
def generate(model, idx, max_new_tokens, temperature=1.0, top_k=None):
    """idx:(B,T) 提示 -> 续写 max_new_tokens 个 token。"""
    model.eval()                                              # ❗ 关 dropout
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -model.cfg.block_size:]             # 滑窗：截到上下文长度
        logits, _ = model(idx_cond)
        logits = logits[:, -1, :] / temperature               # 只取最后位置 + 温度缩放
        if top_k is not None:                                 # top-k 截断
            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
            logits = logits.masked_fill(logits < v[:, [-1]], -float("inf"))
        probs = F.softmax(logits, dim=-1)
        nxt = torch.multinomial(probs, num_samples=1)         # 按概率采样 1 个
        idx = torch.cat((idx, nxt), dim=1)                    # 拼回，继续自回归
    return idx
```

```python
# —— 温度 / top-k 对分布的影响（独立可验证）——
def process(logits, temperature=1.0, top_k=None):
    logits = logits / temperature
    if top_k is not None:
        v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
        logits = logits.masked_fill(logits < v[:, [-1]], -float("inf"))
    return F.softmax(logits, dim=-1)

z = torch.tensor([[2.0, 1.0, 0.5, 0.1, -1.0]])
print("T=1.0:", process(z, 1.0).round(decimals=2).tolist())   # [[0.56,0.20,0.12,0.08,0.03]]
print("T=0.5:", process(z, 0.5).round(decimals=2).tolist())   # [[0.83,0.11,0.04,0.02,0.00]] 更尖
print("T=2.0:", process(z, 2.0).round(decimals=2).tolist())   # [[0.37,0.23,0.18,0.14,0.08]] 更平
print("topk2:", process(z, 1.0, top_k=2).round(decimals=2).tolist())  # [[0.73,0.27,0,0,0]]
```

```python
# —— 困惑度 PPL = exp(平均交叉熵)，在留出文本上算 ——
@torch.no_grad()
def perplexity(model, ids, block_size):
    """ids: 1D LongTensor(留出集)；返回 (PPL, avg_nll)。"""
    model.eval()
    total_nll, n_tok = 0.0, 0
    for i in range(0, len(ids) - 1, block_size):
        chunk = ids[i:i + block_size + 1]
        if len(chunk) < 2: break
        x, y = chunk[:-1].unsqueeze(0), chunk[1:].unsqueeze(0)
        logits, _ = model(x)
        nll = F.cross_entropy(logits.view(-1, logits.size(-1)),
                              y.view(-1), reduction="sum")     # 累加 NLL（不平均）
        total_nll += nll.item(); n_tok += y.numel()
    avg_nll = total_nll / n_tok                                # 分母=总有效 token 数
    return math.exp(avg_nll), avg_nll                          # PPL, avg_nll

# bits-per-byte（跨 tokenizer 可比）
def bits_per_byte(avg_nll_nats, n_tokens, n_bytes):
    return avg_nll_nats * n_tokens / math.log(2) / n_bytes
```

```python
# —— top-p(nucleus)截断:候选个数自适应(尖分布留少、平分布留多) ——
def top_p_filter(logits, p=0.9):
    probs = F.softmax(logits, dim=-1)
    s_probs, s_idx = torch.sort(probs, descending=True, dim=-1)
    cum = torch.cumsum(s_probs, dim=-1)
    mask = cum - s_probs > p                       # 累计超过 p 之后的(不含临界项)置零
    s_probs[mask] = 0.0
    s_probs /= s_probs.sum(dim=-1, keepdim=True)   # 重新归一
    out = torch.zeros_like(probs).scatter_(-1, s_idx, s_probs)
    return out

z = torch.tensor([[2.0, 1.0, 0.5, 0.1, -1.0]])
print("top_p=0.9:", top_p_filter(z, 0.9).round(decimals=3).tolist())
# 尖分布只留前几个;若把 z 改平(各项接近),会自动留更多——这是 top-p 优于 top-k 之处

# —— min-p 截断:阈值 = p_min × 最高概率,对分布形状更鲁棒 ——
def min_p_filter(logits, p_min=0.1):
    probs = F.softmax(logits, dim=-1)
    thresh = p_min * probs.max(dim=-1, keepdim=True).values
    probs = torch.where(probs >= thresh, probs, torch.zeros_like(probs))
    return probs / probs.sum(dim=-1, keepdim=True)
print("min_p=0.1:", min_p_filter(z, 0.1).round(decimals=3).tolist())

# —— 重复惩罚:对已出现 token 的 logits 按惩罚因子(>1)压低,抑制复读 ——
def apply_repetition_penalty(logits, generated_ids, penalty=1.2):
    for tid in set(generated_ids):
        if logits[0, tid] > 0:
            logits[0, tid] /= penalty      # 正 logit:除以 penalty → 变小
        else:
            logits[0, tid] *= penalty      # 负 logit:乘 penalty → 更负(都使被选概率↓)
    return logits
print("rep:", apply_repetition_penalty(z.clone(), [0, 1], 1.2).round(decimals=3).tolist())
# [[1.667, 0.833, 0.5, 0.1, -1.0]]  前两个已生成的 token logits 被压低
```

## 面试高频

- **Q:温度怎么影响生成?$T\to0$ 和 $T\to\infty$ 是什么?** A:logits 除以 $T$ 再 softmax。$T$ 小→分布尖锐→确定/重复;$T$ 大→平→随机/易崩。$T\to0$ 退化为贪心(argmax),$T\to\infty$ 趋均匀。温度不改相对顺序。
- **Q:top-k 干嘛?和 top-p 区别?** A:top-k 保留概率最高的固定 $k$ 个候选(砍长尾);top-p(nucleus)保留累计概率达 $p$ 的最小候选集(自适应个数)。都为避免低概率胡话。
- **Q:困惑度是什么?直觉?** A:PPL = exp(平均交叉熵),「模型平均在多少个候选间犹豫」。随机均匀模型 PPL=词表大小,完美模型=1,越低越好。
- **Q:困惑度能跨模型比吗?** A:只在**同一 tokenizer** 下可比——分词粒度不同会系统性改变每 token 信息量。跨 tokenizer 用 bits-per-byte(按字节归一)。
- **Q:算 PPL 常见 bug?** A:忘 shift(off-by-one)、分母用总长而非有效 token 数、长文本不做滑窗丢了上下文条件;还有忘 `model.eval()` 让 dropout 干扰。
- **Q:生成时为什么每步只取最后一个位置的 logits?** A:前面位置的 token 已确定,只需要「下一个」的分布;`logits[:, -1, :]` 就是它。超 block_size 滑窗截左。
- **Q:贪心 vs 采样 vs beam?** A:贪心每步取 argmax(确定、易重复);采样按分布抽(多样);beam 维护多条候选束(常用于翻译,见 [[100 解码策略：贪心与 Beam|贪心与 Beam]])。LLM 闲聊多用温度+top-p 采样。
- **Q:top-k 和 top-p 哪个好,为什么?** A:top-p 更好——它按累计概率截断,候选个数**自适应**(尖分布留少、平分布留多),而 top-k 固定 $k$,尖分布时带噪声、平分布时砍太狠。常用温度+top-p 组合;min-p 对分布形状更鲁棒、高温下好。
- **Q:采样温度会影响 PPL 吗?** A:不会。PPL 用模型对真实文本的原始概率算,与采样无关;采样是生成、PPL 是评估拟合。PPL 低也不保证生成好(可能复读/采样下崩)——两套尺子。
- **Q:模型为什么会复读?怎么治?** A:贪心/低温下易陷入高概率自循环;用重复惩罚(对已出现 token 压低 logits)、presence/frequency penalty、或提温度+top-p 增多样性缓解。
- **Q:为什么真实生成不慢?** A:KV-Cache(见 102)缓存历史每层 K/V,每步只为新 token 算注意力,把朴素 $O(T^2)$ 降到 $O(T)$;本 tiny 版 generate 为教学没用 cache,真实推理必用。

- top-p(nucleus)按累计概率自适应截断候选数,优于固定 $k$ 的 top-k;min-p 按相对最高概率设阈值、对分布形状更鲁棒;重复惩罚/presence/frequency penalty 抑制复读(见 [[101 采样解码：温度、top-k、top-p、min-p、重复惩罚|采样解码]])。
