[[076 显存占用估算(参数、梯度、优化器、激活、KV)]]:训练显存由五项构成——**参数、梯度、优化器态、激活、KV-Cache**;混合精度 + Adam 下固定开销约**每参数 16 字节**(优化器态独占 12 字节),这解释了为何 7B 模型训练要上百 GB、单卡装不下,以及推理为何只需训练的约 1/8。

## ① 直觉:模型不止"存权重",还要存一堆陪练的副本

新手常以为"7B 模型 = 7B×2 字节 = 14GB,一张卡够了"。训练时却 OOM,因为权重只是冰山一角。训练一步要同时在显存里放五样东西:

1. **参数(weights)**:模型本身。混合精度下存一份 fp16 权重(2 字节/参数)。
2. **梯度(gradients)**:每个参数对应一个梯度,反向算出来。fp16,2 字节/参数。
3. **优化器态(optimizer states)**:Adam(见 [[39 优化器(Momentum、RMSProp、Adam、AdamW)]])要给每个参数存**一阶动量 + 二阶方差**,外加一份 fp32 主权重——这三样都是 fp32,共 12 字节/参数,是显存的真正大头。
4. **激活(activations)**:前向中间结果,反向要用来求梯度。随 batch、序列长、层数增长,可大可小。
5. **KV-Cache**:只在**推理**时出现,缓存历史 token 的 K、V,见 [[102 KV-Cache]]。

前三项(参数+梯度+优化器态)是**固定**的,只跟参数量挂钩 = 16 字节/参数;后两项随输入规模变化。把这五项算清楚,就能回答"这模型能不能塞进这张卡"。

## ② 例子:手算 7B 模型,训练 vs 推理各要多少显存

**训练(混合精度 + Adam)**,逐项(N = 7e9):

- 参数 fp16:$7\times10^9 \times 2 = 14\text{ GB}$
- 梯度 fp16:$7\times10^9 \times 2 = 14\text{ GB}$
- 优化器态(fp32 主权重 4B + 动量 4B + 方差 4B = 12B):$7\times10^9 \times 12 = 84\text{ GB}$
- **固定小计** = $14+14+84 = 112\text{ GB}$(= 7B × **16 字节**)

一张 H100 只有 80GB,**装不下** → 必须 [[070 ZeRO 与 FSDP|ZeRO/FSDP]] 把这 112GB 切到多卡。再加激活(随 batch、seq),实际更多——这正是大模型训练必须分布式的根因。

**推理(fp16,无梯度、无优化器态)**:

- 参数 fp16:$14\text{ GB}$
- KV-Cache(下面算)
- 推理固定显存 ≈ $14\text{ GB}$,**约是训练 112GB 的 1/8**

![[param-显存五项占比.png]]

**激活怎么估**(训练大头)。单层激活 ∝ batch × seq × d,粗略地总激活 ≈ $\text{(常数)}\times b\cdot s\cdot d\cdot L$。例:b=8、s=2048、d=4096、L=32,光是每层存一份 fp16 的 $b\cdot s\cdot d$ 就 $8\times2048\times4096\times2 \approx 134\text{MB}$,乘 L 再乘上每层内部多个中间张量,轻松到几十 GB。**梯度检查点(gradient checkpointing)**用重算换显存,把激活从 $O(L)$ 降到 $O(\sqrt{L})$。

**KV-Cache 怎么算**(推理瓶颈)。每个 token 每层缓存 K 和 V 各一份:

$$
\text{KV} = 2 \times L \times s \times d_{kv} \times \text{(字节)} \times b
$$

例:7B(L=32, d=4096, fp16),单条请求 s=4096:$2\times32\times4096\times4096\times2 \approx 4.3\text{ GB}$ —— KV 已接近权重的 1/3!长上下文 + 多并发时 KV 会超过权重,成为真正瓶颈,所以才有 [[018 MQA 多查询注意力|MQA]]、[[019 GQA 分组查询注意力|GQA]]、[[026 PagedAttention 与 KV 分页|PagedAttention]] 来压它。

## ③ 原理:16 字节/参数是怎么来的,混合精度为何反而更费

**混合精度训练(见 [[064 混合精度 FP16、BF16 与 FP8]])的内存账**。直觉上 fp16 该省一半内存,但 Adam 混合精度反而要 16 字节/参数,因为为了数值稳定,优化器**额外**保留 fp32 副本:

$$
\underbrace{2}_{\text{fp16 权重}} + \underbrace{2}_{\text{fp16 梯度}} + \underbrace{4}_{\text{fp32 主权重}} + \underbrace{4}_{\text{fp32 动量 }m} + \underbrace{4}_{\text{fp32 方差 }v} = 16\ \text{字节/参数}
$$

其中 fp32 主权重是为了在 fp16 梯度很小时仍能精确更新(fp16 更新会被舍入吃掉)。所以**优化器态(12B)占了 75%**——这就是为什么换 [[039 Mistral、Qwen、DeepSeek 架构选择|更省的优化器]]或 8-bit Adam、或用 ZeRO 把优化器态分片,是省显存的首要抓手。

**纯推理的账**:

$$
M_{\text{infer}} \approx \underbrace{N\cdot b_{\text{param}}}_{\text{权重}} + \underbrace{2\,L\,s\,d_{kv}\,b_{\text{param}}\,B}_{\text{KV-Cache}}
$$

无梯度、无优化器态,fp16 权重 2 字节/参数;int8 量化(见 [[092 量化基础：对称非对称、per-tensor、per-channel、per-group]])再砍到 1 字节/参数。

**经验法则速记**:

- 训练(Adam 混合精度):**≈ 16 字节/参数** + 激活 → 7B 约 112GB(不含激活)
- 推理(fp16):**≈ 2 字节/参数** + KV-Cache → 7B 约 14GB + KV
- 想训 N 参数模型,固定显存 ≈ 16N 字节;一张 80GB 卡的"训练上限"约 80e9/16 ≈ 5B 参数(还没算激活)

## ⑤ 激活显存逐层精确化 + 梯度检查点 √L 推导

前面把激活粗估成 $\propto bsdL$,这里给 Megatron-SP 论文(Korthikanti 2022)的逐层口径,面试问"激活到底多少"能拆。**单层**激活(无重计算、无 SP,fp16)约:
$$M_{\text{act/层}}\approx s\,b\,h\,\big(\underbrace{34}_{\text{LN/QKVO/FFN 各中间张量}}+\underbrace{5\,\frac{a\,s}{h}}_{\text{注意力分数 }QK^\top}\big)\ \text{字节},$$
其中 $a$=头数。前一项 $\propto sbh$,后一项 $\propto s^2ba$(注意力分数矩阵,**序列长的平方**)——长序列时这项主导,这也是 [[025 FlashAttention(IO 感知精确注意力)|FlashAttention]] 不物化分数矩阵能省大量激活的原因。总激活 ≈ 上式 ×L。

**梯度检查点(activation checkpointing)的 $O(\sqrt L)$ 怎么来**(见 [[065 梯度检查点与激活重计算]]):
- 不检查点:存全部 L 层激活,显存 $O(L)$,反向直接用。
- 全检查点:只存每层**输入**(边界),反向时**重算**该层前向。显存 $O(1)$/层但重算开销大(前向多跑一遍,约 +33% 算力)。
- **最优分段(Chen 2016)**:把 L 层分成 $\sqrt L$ 段,只在段边界存激活(共 $\sqrt L$ 个),反向到某段时重算段内 $\sqrt L$ 层。显存 $=O(\sqrt L)$(段数)$+O(\sqrt L)$(段内重算时的临时激活)$=O(\sqrt L)$,重算只多一遍前向。这就是"用 $\sqrt L$ 的显存换约 33% 的额外算力"。

## ⑥ KV-Cache 的 GQA/MQA 修正(为什么长上下文非用不可)

标准 MHA 的 KV-Cache(见 ② 的公式)按完整 $d$ 缓存。GQA/MQA(见 [[019 GQA 分组查询注意力]])把 KV 头数从 $n_h$ 砍到 $n_{kv}$,KV-Cache 按比例缩小:
$$\text{KV}=2\,L\,s\,\underbrace{n_{kv}d_h}_{\text{KV 维}}\,(\text{字节})\,b,\quad \text{压缩比}=\frac{n_{kv}}{n_h}.$$
- **MHA**(LLaMA-7B,32 头):s=4096 时 KV ≈ 4.3 GB(② 已算)。
- **GQA**(8 组 KV,n_h=32):压到 $\frac{8}{32}=\frac14$ → ≈1.07 GB。
- **MQA**(1 组):压到 $\frac{1}{32}$ → ≈0.13 GB。

长上下文 + 高并发时 KV 会超过权重本身(② 已指出),GQA/MQA 把这块砍 4×~32×,是 LLaMA-2/3、Mistral 全面转 GQA 的直接动因。再叠 [[026 PagedAttention 与 KV 分页|PagedAttention]] 减碎片、量化 KV 到 int8 再砍一半。

## ⑦ LoRA / QLoRA 怎么省训练显存

全参数微调要 16~18 字节/参数(优化器态大头)。[[091 高效微调：LoRA、QLoRA、Adapter、Prefix|LoRA]] 冻结主权重、只训低秩增量 $\Delta W=BA$(秩 $r\ll d$):
- **主权重**:只存 fp16(2 字节/参数),**不存梯度、不存优化器态**(冻结)。
- **LoRA 参数**:只占总参的 ~0.1-1%,梯度+优化器态只摊在这一小撮上。
- **QLoRA**(Dettmers 2023):主权重再量化到 **4-bit NF4**(0.5 字节/参数),配合分页优化器,**单张 24GB 卡微调 65B 模型**。

显存账:7B 全参微调 ≈112GB;LoRA(r=16)≈ 14GB(权重)+ 极小 LoRA 态 ≈ **16GB 出头**,单卡可做;QLoRA 把权重压到 ~4GB,更省。这是为什么 SFT 工程默认 LoRA(见 [[081 指令微调 SFT 与数据构造|SFT]])。

## ④ 代码:五项显存估算器

```python
def train_mem_gb(N, bytes_per_param=16):
    """Adam 混合精度训练固定显存(不含激活)。16 = 2+2+4+4+4。"""
    return N * bytes_per_param / 1e9

def kv_cache_gb(L, seq, d_kv, batch=1, dtype_bytes=2):
    """KV-Cache:2(K和V) × 层 × 序列 × d_kv × 字节 × batch。"""
    return 2 * L * seq * d_kv * dtype_bytes * batch / 1e9

def infer_mem_gb(N, L, seq, d_kv, batch=1, w_bytes=2):
    return N * w_bytes / 1e9 + kv_cache_gb(L, seq, d_kv, batch, w_bytes)

# ❌ 错:以为 7B 训练 = 7e9 × 2B = 14GB → 实际会 OOM(漏了梯度+优化器态)
naive = 7e9 * 2 / 1e9
print(f"只算 fp16 权重(错): {naive:.0f} GB")     # 14GB,严重低估

# ✅ 对:训练固定显存 = 16 字节/参数
print(f"7B 训练固定: {train_mem_gb(7e9):.0f} GB")  # 112 GB → 单卡装不下
print(f"7B 推理权重: {7e9*2/1e9:.0f} GB")          # 14 GB
print(f"7B KV(s=4096): {kv_cache_gb(32, 4096, 4096):.1f} GB")  # ≈4.3 GB

# 这张卡能训多大模型?(80GB,留一半给激活)
N_max = 40e9 / 16
print(f"80GB 卡训练上限 ≈ {N_max/1e9:.1f}B 参数")   # ≈2.5B(含激活余量)
```

## 面试高频

- **Q:训练显存由哪几部分组成?** 参数、梯度、优化器态、激活、KV-Cache(KV 仅推理)。前三项固定 = 16 字节/参数,后两项随输入规模变。
- **Q:为什么 Adam 混合精度是 16 字节/参数?** fp16 权重 2 + fp16 梯度 2 + fp32 主权重 4 + fp32 动量 4 + fp32 方差 4 = 16,优化器态占 12(75%)。
- **Q:7B 模型训练要多少显存?** 固定约 112GB(7B×16B),单张 80GB 卡装不下,要 ZeRO/FSDP 分片;推理只需约 14GB(fp16 权重)+ KV。
- **Q:推理为什么比训练省显存?** 无梯度、无优化器态,fp16 权重 2 字节/参数 ≈ 训练的 1/8;再 int8 量化可砍到 1 字节/参数。
- **Q:KV-Cache 怎么估,为什么是长上下文瓶颈?** $2·L·s·d_{kv}·$字节$·b$,随序列长和并发线性增长,长上下文下会超过权重,催生 MQA/GQA/PagedAttention。
- **Q:激活显存怎么省?** 梯度检查点(activation checkpointing)用重算换显存,把激活从 $O(L)$ 降到约 $O(\sqrt{L})$。
- **Q:$O(\sqrt L)$ 是怎么来的?** 把 L 层分成 $\sqrt L$ 段,只在段边界存激活($\sqrt L$ 个),反向重算段内 $\sqrt L$ 层;段数 + 段内临时激活都是 $O(\sqrt L)$,重算只多一遍前向(约 +33% 算力)。
- **Q:GQA/MQA 怎么影响 KV-Cache?** KV-Cache ∝ KV 头数。GQA(8 组,32 头)压到 1/4,MQA(1 组)压到 1/32。LLaMA-7B s=4096 的 KV 从 4.3GB(MHA)降到 1.07GB(GQA)/0.13GB(MQA),这是长上下文部署转 GQA 的直接原因。
- **Q:LoRA 为什么省训练显存?** 冻结主权重(只存 fp16、无梯度无优化器态),只训 0.1-1% 的低秩增量,优化器态只摊这一小撮。7B 全参 ≈112GB,LoRA ≈16GB,QLoRA(4-bit 主权重)单张 24GB 卡可训 65B。
- **Q:激活里哪项随序列长平方增长?** 注意力分数矩阵 $QK^\top$($\propto s^2 b a$),长序列时主导;FlashAttention 不物化它,大幅省激活。

## 关键事实

- "Adam 混合精度训练 16 字节/参数(2 fp16 权重 + 2 fp16 梯度 + 4 fp32 主权重 + 4 动量 + 4 方差)"的分解出自 ZeRO 论文(Rajbhandari et al., 2020, arXiv:1910.02054),其 16Φ 字节是分布式显存优化的基准口径。
- 混合精度训练保留 fp32 主权重以避免小梯度更新被舍入,出自《Mixed Precision Training》(Micikevicius et al., 2017, arXiv:1710.03740)。
- 梯度检查点把激活显存从 $O(L)$ 降到 $O(\sqrt{L})$,代价是反向时重算前向,出自《Training Deep Nets with Sublinear Memory Cost》(Chen et al., 2016, arXiv:1604.06174)。
- 8-bit Adam 把优化器态从 fp32 压到 8-bit,显存近乎减半(Dettmers et al., 2021, arXiv:2110.02861)。
- 推理 KV-Cache 显存 = $2·L·s·d_{kv}·$字节,是长上下文部署的主瓶颈,催生 PagedAttention(vLLM, Kwon et al., 2023, arXiv:2309.06180,见 [[026 PagedAttention 与 KV 分页]])。
- 单层激活精确口径(Megatron-SP):$\approx sbh(34+5\,as/h)$ 字节,其中 $5as^2bh/h=5as^2b$ 项随序列长平方增长(注意力分数矩阵);FlashAttention 不物化它(Korthikanti et al., 2022, arXiv:2205.05198)。
- GQA/MQA 把 KV-Cache 按 KV 头数比例压缩(GQA 8 组/32 头 = 1/4,MQA = 1/32),是 LLaMA-2/3、Mistral 转 GQA 的核心动因(Ainslie et al., 2023, arXiv:2305.13245)。
- QLoRA(Dettmers et al., 2023, arXiv:2305.14314):4-bit NF4 量化主权重 + 分页优化器,单张 24GB 卡微调 65B;LoRA(Hu et al., 2021, arXiv:2106.09685)只训低秩增量,优化器态摊在 0.1-1% 参数上。
