[[089 推理模型与 RL：o1、R1 的长 CoT 与自我反思]]:推理模型(reasoning model,如 OpenAI o1、DeepSeek-R1,2025,arXiv 2501.12948)用**大规模 RL**([[088 GRPO 与可验证奖励|GRPO]] + 可验证奖励)激发出**长链思维(long CoT)**——答前先反复试探、自我反思、回头验证;R1-Zero 证明**纯 RL、无人标推理过程**就能涌现这种能力,是 2025 年范式级发现。

## 直觉:不教「怎么想」,只奖励「想对了」,模型自己学会长考

普通模型回答数学/代码题是「一条直路冲到底」:读题→一步算→给答案,错了也不回头。推理模型不同:它在给最终答案前,会生成一大段**内部思考**(放在 `<think>` 里),反复尝试、推翻自己、换思路、代回验证——像一个会打草稿、会自我怀疑的人。

最反直觉的发现来自 **DeepSeek-R1-Zero**:**不给任何人工标注的推理过程**,只用 [[088 GRPO 与可验证奖励|GRPO]] + **规则奖励**(答案对不对、格式对不对)做 RL,模型就**自发地**:① 把思考链越拉越长;② 学会自我反思(写出「等等,这步好像不对」再回头改),即所谓 **"aha moment"**。也就是说——**推理能力不必靠人标的链路去模仿,纯 RL 的奖励信号就能从基座里『逼』出来**。

## 例子:长 CoT 的自我反思长什么样(小数字)

题:「一个数加上它的一半等于 18,求这个数。」推理模型的 `<think>` 大致长这样:

> 设这个数 $x$。$x+\frac{x}{2}=18$… 我先猜 $x=9$:$9+4.5=13.5$,不对,太小。
> **等等**,$\frac{3x}{2}=18$,所以 $x=12$。验证:$12+6=18$ ✓。
> 但**再检查一下**题意——「加上它的一半」就是 $x+\frac{x}{2}$,没错。答案 $x=12$。

注意三处「人类味」:**先猜后否定**(9→不对)、**自我纠偏**(「等等」)、**代回验证**(12+6=18)。这些**没人教**——RL 只在最后看「答案是不是 12」给 1 分。模型为了拿分,自己进化出了「多想几步、回头检查」这种能拿高分的策略。

## 原理:RL 如何"长"出推理

**1)目标本质**。把「解题」当 RL 问题:状态=已生成的思考前缀,动作=下一个 token,奖励=**最终答案是否正确**(可验证)。策略要最大化期望奖励:

$$
\max_{\pi_\theta}\ \mathbb{E}_{x,\,y\sim\pi_\theta}\big[\,r_{\text{verify}}(x,y)\,\big],\qquad r_{\text{verify}}=\begin{cases}1 & \text{答案正确}\\0 & \text{否则}\end{cases}
$$

用 [[088 GRPO 与可验证奖励|GRPO]] 优化:同题采一组,组内相对优势,无 critic、无 RM。

**2)为什么会"变长"**。更长的思考 = 更多中间步骤 = 更高的答对概率(尤其难题)。RL 发现**「拉长思考」能提高期望奖励**,于是梯度持续把策略推向「生成更长 CoT」。这对应**测试时算力(test-time compute)**:推理时花更多 token 思考,准确率随之上升——是一条新的 scaling 维度(从「训练时算力」转向「推理时算力」)。R1 论文里能观察到训练过程中**平均响应长度单调上升**,与 AIME 等难基准的准确率同步爬升——这是「思考变长 ⇄ 能力变强」的直接证据。

![[rl-长度准确率爬升.png]]

**警示:变长不全是好事**。前述 Dr.GRPO([[088 GRPO 与可验证奖励|GRPO]] 节)指出,GRPO 的长度归一会让**错误回答也被鼓励变长**(虚胖),部分「响应变长」其实是优化偏差而非真推理增益;所以「长 = 强」要打个折,真正有效的是「为了答对而多想」,不是无意义的灌水。区分二者要看长度增长是否伴随准确率提升。

**3)自我反思怎么涌现**。"回头检查、推翻重来"是一种**能纠错、从而提高答对率**的策略。RL 不区分「正向推进」和「自我怀疑」,只要后者提升期望奖励,梯度就强化它。于是模型自发学会写出 "wait / let me reconsider" 这类反思 token——**aha moment 是奖励驱动的副产品,不是被设计的功能**。

**4)R1 的完整管线**(R1-Zero 太难读,产品级 R1 加了修补):

1. **冷启动 SFT**:少量高质量长 CoT 数据微调,先把「话说顺、不混语言」。
2. **推理 RL**:GRPO + 可验证奖励 + **语言一致性奖励**(治中英混杂)。
3. **拒绝采样 + SFT**:用 RL 模型筛出好样本,扩到写作等通用任务。
4. **全场景 RLHF**:有用 + 无害对齐,得最终 [[085 RLHF 全流程与 KL 约束、奖励黑客|RLHF]] 模型。

**冷启动只为可读性,推理能力来自 RL**——这是关键区分。

**提示 CoT vs 训练出的长 CoT 一句话**:普通模型靠「Let's think step by step」临时触发推理,本事没变、换个提示就丢;推理模型把长链思考 + 自我反思**用 RL 训进了权重**,默认就会长考,不依赖提示词。

**蒸馏:把 R1 的推理「教」给小模型**。R1 还有一个工程上极重要的发现:**直接把 R1 生成的长 CoT 数据拿去 SFT 一个小稠密模型(如 Qwen-1.5B/7B/32B、Llama-8B/70B),小模型的推理能力大幅提升,甚至超过「在小模型上直接跑 RL」**。原因:小模型自己跑 RL 很难从零涌现长 CoT(基座太弱、探索不到),但**模仿一个已经会长考的大模型的轨迹**(序列级/黑盒蒸馏,见 [[099 剪枝、稀疏化与蒸馏压缩|蒸馏]])则容易得多。结论:**推理能力可以被蒸馏迁移,且蒸馏 > 小模型自训 RL**——这让强推理能力能低成本下放到端侧小模型。

## o1 与 R1 的异同

- **OpenAI o1**(2024-09):首个大规模推理模型,**隐藏**思考链(只给摘要),细节闭源;确立「RL + 长 CoT + 测试时算力」范式。
- **DeepSeek-R1**(2025-01,arXiv 2501.12948):**开源、公开方法**;R1-Zero 证明纯 RL 可激发推理;**展示**完整思考链;用 GRPO(去 critic)、规则奖励(非神经 RM,抗[[085 RLHF 全流程与 KL 约束、奖励黑客|奖励黑客]])。两者都靠「答前长考」,与靠提示词的普通 [[001 Transformer 总览：为何抛弃 RNN|CoT]] 有本质区别——这里的长 CoT 是**训练进策略**的。

## 代码:推理 RL 的奖励与采样(伪代码)

```python
def reasoning_reward(question, output):
    # 解析 <think>...</think> 思考 + 最终答案
    answer = extract_final_answer(output)
    # ❌ 误区:用神经 RM 给「思考过程像不像」打分 —— 易被奖励黑客(写得像但算错)
    # return reward_model(output)

    # ✅ 可验证奖励:只认结果对不对(+ 轻量格式奖励),客观、难钻空子
    r_acc    = 1.0 if check_answer(question, answer) else 0.0   # 数学对答案 / 代码跑单测
    r_format = 0.1 if has_think_tags(output) else 0.0           # 鼓励把推理放进 <think>
    return r_acc + r_format

# 训练:GRPO,无人标推理轨迹,推理是 RL 自己学长的
for q in math_and_code_prompts:
    group = policy.sample(q, num=G)          # 同题采一组(长 CoT 会自发变长)
    r = [reasoning_reward(q, o) for o in group]
    A = grpo_advantages(torch.tensor(r))     # 组内相对优势,见 [[088]]
    loss = ppo_clip_loss(policy, group, A) + beta * kl(policy, ref)
    loss.backward()
```

要点:奖励尽量**可验证**(抗奖励黑客);推理长度是 RL 涌现的,**不要硬性 SFT 模仿**(R1-Zero 没 SFT 也能长 CoT);冷启动 SFT 只为可读性。

## 面试高频

- **推理模型(o1/R1)和普通 LLM 的核心区别?** 普通模型靠提示词触发 CoT、答前思考短;推理模型用**大规模 RL** 把「长链思考 + 自我反思 + 验证」**训进策略**,答前生成大段内部思考,准确率随**测试时算力**(思考 token 数)提升。
- **R1-Zero 证明了什么?** 推理能力可由**纯 RL** 激发,**无需人工标注推理轨迹**(SFT 模仿)——只给「答案对不对」的可验证奖励,模型自发涌现长 CoT 与自我反思。这是范式级发现。
- **"aha moment" / 自我反思怎么来的?** 不是被设计的。回头检查、推翻重来能提高答对率 → 提高期望奖励 → 被 RL 梯度强化,于是自发涌现。
- **R1 为什么还要冷启动 SFT?** R1-Zero 推理强但**可读性差、中英混杂**;冷启动 SFT(少量长 CoT)+ 语言一致性奖励**修可读性**,推理能力本身来自 RL,不是 SFT。
- **为什么用可验证奖励而非神经 RM?** 数学/代码答案可客观判定,**抗奖励黑客**(写得像但算错也得 0 分);神经 RM 易被钻空子。见 [[088 GRPO 与可验证奖励|可验证奖励]]。
- **测试时算力(test-time compute)是什么?** 一条新 scaling 维度:推理时花更多 token 思考 → 难题准确率更高。推理模型把训练算力部分转移到推理算力。
- **为什么用 GRPO 而非 PPO?** 去掉 critic 省一半显存(大模型 RL 关键),组内相对优势天然适配「同题多采样 + 可验证奖励」,见 [[088 GRPO 与可验证奖励|GRPO]]。
- **推理能力能蒸馏到小模型吗?蒸馏 vs 小模型自训 RL 哪个好?** 能,且**蒸馏更好**。把 R1 生成的长 CoT 当 SFT 数据训小模型,效果超过在小模型上直接跑 RL——因为小基座难自发探索出长 CoT,模仿强模型轨迹更高效。这让强推理能力低成本下放端侧。
- **长 CoT 变长一定代表推理更强吗?** 不一定。部分变长是 GRPO 长度归一带来的优化偏差(连错误回答都被鼓励变长,见 Dr.GRPO);真正的增益是「为答对而多想」,要看长度增长是否伴随准确率上升。
- **推理模型的成本/延迟代价?** 答前生成大段 `<think>` → 输出 token 数暴增 → 推理更慢更贵(测试时算力的代价);所以产品上常给「思考预算」上限,或对简单问题关闭长思考。

## 关键事实

- DeepSeek-AI, *DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning*, 2025,arXiv **2501.12948**:R1-Zero(纯 RL,无 SFT)涌现长 CoT、自我验证、反思;R1 加冷启动 SFT + 多阶段 RL;性能比肩 OpenAI-o1。
- OpenAI o1(2024-09):首个大规模推理模型,隐藏思考链,确立 RL + 长 CoT + 测试时算力范式(方法未公开)。
- R1-Zero 副作用:可读性差、语言混杂、偶有重复;由冷启动 SFT + 语言一致性奖励缓解。
- 推理 RL 用 [[088 GRPO 与可验证奖励|GRPO]] + 规则/可验证奖励(数学对答案、代码单测、格式),非神经 RM → 抗奖励黑客。
- 长 CoT 是 RL **自发拉长**的(对应测试时算力 scaling),非人工规定;自我反思("aha")是奖励驱动副产品。
- R1 蒸馏:用 R1 生成的长 CoT 数据 SFT 小稠密模型(Qwen/Llama 系列 1.5B~70B),推理能力大幅提升且**优于小模型直接 RL**;说明推理能力可序列级蒸馏迁移(见 [[099 剪枝、稀疏化与蒸馏压缩|蒸馏]])。
- 部分「响应变长」是 GRPO 长度归一引入的优化偏差(Dr.GRPO,arXiv 2503.20783),非全是真推理增益;长度增长须与准确率提升对照看。
