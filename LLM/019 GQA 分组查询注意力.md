[[019 GQA 分组查询注意力]]:介于 [[005 多头注意力 Multi-Head|MHA]] 与 [[018 MQA 多查询注意力|MQA]] 之间——把 Q 头**分成 g 组,每组共享一份 K/V**,用一个旋钮 g 在"质量(MHA)"和"省显存(MQA)"之间连续调档。

## 直觉:别走极端,折中一下
[[018 MQA 多查询注意力|MQA]] 把 K/V 从 h 份砍到 1 份,省得狠但质量掉、训练不稳。GQA 的想法很朴素:**不一定非得 1 份,留几份(比如 8 份)就好**。

把 h 个 Q 头平均分成 g 组,每组内的所有 Q 头共享**同一份 K/V**。于是 K/V 头数 = g(组数):
- $g=h$ → 每组只 1 个 Q 头 → 退化成 [[005 多头注意力 Multi-Head|MHA]];
- $g=1$ → 所有 Q 头一组 → 退化成 [[018 MQA 多查询注意力|MQA]]。

GQA 就是这条连续谱上的"中间点"。论文实测:**质量几乎追平 MHA,速度几乎追平 MQA**——所以它成了 2023 年后的事实标准。

类比:32 个读者(Q 头)不必每人一套书(MHA 太占地),也不必全挤一套书(MQA 排队抢),而是分成 8 桌、每桌共用一套(GQA)。

## 例子:LLaMA-2 70B 的真实配置
LLaMA-2 70B:h=64 个 Q 头,GQA 的 K/V 头数 **g=8**(每 8 个 Q 头共享 1 份 K/V)。

KV-Cache 相对 MHA 的比例 = $g/h = 8/64 = 1/8$。

接上篇 [[018 MQA 多查询注意力|MQA]] 的算例,设 d_head=128、L=4096、n_layer=80、fp16:
- MHA(g=64)每 token:$2\times64\times128\times80\times2 = 2{,}621{,}440$ B ≈ 2.6 MB
- GQA(g=8)每 token:$2\times8\times128\times80\times2 = 327{,}680$ B ≈ 0.33 MB(**1/8**)
- MQA(g=1):再小 8 倍 ≈ 41 KB,但质量不如 GQA

GQA 用 1/8 的缓存,换来接近满血的质量——这就是它被广泛采用的原因。

**再看一个常见配置(LLaMA-3 8B / 70B 都用 GQA)。** LLaMA-3 8B:h=32 个 Q 头、g=8 个 KV 头 → 每 4 个 Q 头共享 1 份 KV,KV-Cache 是 MHA 的 1/4。LLaMA-3 70B:h=64、g=8 → 1/8。一个反直觉点:**g 通常固定在 8,而不是随 h 等比例放大**——因为 8 份 KV 已足够保住质量,继续加 KV 头省得越来越少(边际收益递减),不如把省下的显存换更大 batch。

**质量-显存权衡的"拐点"直觉。** 把质量损失对 g 作图,经验形状是:从 g=h(MHA)往下减,前期(g 从 h 减到约 8)质量几乎不掉、显存却线性下降——这是"免费午餐"区;g 继续往 1(MQA)减,质量开始明显下滑——边际质量代价陡增。GQA 就是停在拐点(g≈8)吃满免费午餐。

## 原理:K/V 头数 = 组数 g
设 Q 头分组,组数 $g$,每组含 $h/g$ 个 Q 头。第 $i$ 个 Q 头属于组 $\text{grp}(i)=\lceil i\cdot g/h\rceil$,使用该组共享的 $K^{(\text{grp}(i))}, V^{(\text{grp}(i))}$:
$$\text{head}_i = \text{softmax}\!\left(\frac{Q_i\,(K^{(\text{grp}(i))})^\top}{\sqrt{d_{head}}}\right) V^{(\text{grp}(i))}$$

投影矩阵尺寸:$W_Q\in\mathbb{R}^{d\times h\,d_{head}}$(不变),$W_K,W_V\in\mathbb{R}^{d\times g\,d_{head}}$(介于 MHA 的 $h\,d_{head}$ 与 MQA 的 $d_{head}$ 之间)。

KV-Cache 仍服从统一公式,$g$ 可调:
$$\text{Cache}\propto 2\cdot L\cdot g\cdot d_{head}\cdot n_{layer},\qquad 1\le g\le h$$

**从 MHA checkpoint 转 GQA(uptraining)**:把原 h 个 K/V 头按组**均值池化**成 g 个作初始化,再用约 5% 的原预训练算力继续训练,即可恢复质量。这是 GQA 论文最实用的贡献——**不必从头训一个推理友好模型**。

**为什么是均值池化而非别的初始化?** 设组内原有 K 头 $K^{(1)},\dots,K^{(h/g)}$,均值池化取 $\bar K=\frac{g}{h}\sum_j K^{(j)}$ 作新共享头。直觉:① 均值是组内信息的"无偏汇总",保留了组内 K 头共同关注的方向,丢的是它们各自的差异(差异本就该被共享掉);② 相比随机初始化或取第一个头,均值让新头一开始就落在"组内平均行为"附近,微调只需小幅修正,故 5% 算力即可恢复——若随机初始化,等于这部分要从头学,代价大得多。论文实测均值池化显著优于"取首头"和"随机"。

**参数量到底省多少?** 设 $d=h\,d_{head}$。MHA 的 Q/K/V/O 四个投影各 $d\times d$,K+V 共 $2d^2$;GQA 把 K/V 投影缩成 $d\times g\,d_{head}$,K+V 共 $2d\cdot g\,d_{head}=2d^2\cdot\frac{g}{h}$。以 g/h=1/8 算,K/V 投影参数省 7/8。但注意:**Transformer 总参数里 FFN(约 2/3)和 Q/O 投影占大头,K/V 投影只是小部分**,所以 GQA 让总参数量只小幅下降——它的价值在**推理 KV-Cache**,不在参数量。

## 代码:一个旋钮 g 统一三者
```python
import torch, torch.nn.functional as F

# ✅ GQA:K/V 投影到 g 个头,运行时把每份 K/V 广播给 h/g 个 Q 头
class GQA(torch.nn.Module):
    def __init__(self, d, h, g):                       # g=h→MHA, g=1→MQA
        super().__init__()
        assert h % g == 0
        self.h, self.g, self.dh = h, g, d // h
        self.Wq = torch.nn.Linear(d, h * self.dh)
        self.Wk = torch.nn.Linear(d, g * self.dh)      # ← g 份,显存正比 g
        self.Wv = torch.nn.Linear(d, g * self.dh)
        self.Wo = torch.nn.Linear(h * self.dh, d)
    def forward(self, x):                               # x:(B,n,d)
        B, n, _ = x.shape
        q = self.Wq(x).view(B, n, self.h, self.dh).transpose(1, 2)  # (B,h,n,dh)
        k = self.Wk(x).view(B, n, self.g, self.dh).transpose(1, 2)  # (B,g,n,dh)
        v = self.Wv(x).view(B, n, self.g, self.dh).transpose(1, 2)
        # PyTorch 2.5+:enable_gqa=True 自动把 g 个 K/V 头复制成 h 个(无需手动 repeat)
        o = F.scaled_dot_product_attention(q, k, v, enable_gqa=True, is_causal=True)
        return self.Wo(o.transpose(1, 2).reshape(B, n, -1))

# ❌ 易错:手动广播时用了 repeat 的错误维度,导致 K/V 没真共享、显存没省
#    k = k.repeat(1, self.h // self.g, 1, 1)   # 形状对但语义/缓存仍按 g 存才对
# ✅ 缓存只存 (B,g,n,dh) 的 k,v;广播只发生在 attention 计算的瞬间,不进 cache
```

## 选型卡:注意力变体怎么挑

| 场景 | 选什么 | 为什么 |
|---|---|---|
| 现代 decoder-only 默认 | **GQA**(g=8) | 质量近 MHA、KV-Cache 省到 1/4~1/8,生态成熟、零踩坑 |
| 小模型/研究复现/不在乎 KV | [[005 多头注意力 Multi-Head|MHA]](g=h) | 表达力满血,但 KV-Cache 最大 |
| 极致省 KV 且能接受掉点/慎训 | [[018 MQA 多查询注意力|MQA]](g=1) | KV 砍到 1 份最省,但质量降、训练不稳 |
| 超长上下文、要 KV 省到极致且不掉质量 | [[020 MLA 多头潜在注意力(DeepSeek)|MLA]] | 缓存低秩潜向量省 ~1/30+ 且质量更好,代价是实现复杂 |
| 从 MHA 老模型升级、不想重训 | GQA(均值池化 uptraining) | 仅 ~5% 预训练算力即可转出推理友好模型 |

## 面试高频
- **GQA 与 MHA、MQA 的关系?** GQA 是统一谱:$g=h$ 即 MHA,$g=1$ 即 MQA,$1<g<h$ 是折中。一句话:**Q 头数 h 不变,只调 K/V 头数 g**。
- **为什么 GQA 几乎不掉质量?** K/V 还保留了若干份(不像 MQA 只 1 份),表达力损失小;而 decode 带宽主要由 g 决定,g 适中即可兼得速度。
- **GQA 怎么从已有大模型来?** Uptraining:对 MHA 的 K/V 头分组**均值池化**初始化,再用约 5% 预训练算力微调。考点常问"为什么是均值池化"——保留组内信息的平均,比随机初始化收敛快得多。
- **g 怎么选?** 经验上 g=8 是常见甜点(LLaMA-2/3 70B、Mistral)。g 太小接近 MQA 会掉点,g 太大省得少。
- **GQA 解决了 [[014 注意力复杂度 O(n²) 与瓶颈|哪一维瓶颈]]?** 主要是 decode 的**显存/带宽**(KV-Cache),不改 $O(n^2)$ 的算力级别。要省算力得靠 [[021 局部与滑窗注意力(Longformer、Mistral SWA)|稀疏/滑窗]]或 [[025 FlashAttention(IO 感知精确注意力)|FlashAttention]]。
- **GQA 训练时需要特殊处理吗?** 训练里把 g 个 KV 头 `repeat_interleave` 成 h 个参与算 $QK^\top$,反向时多个 Q 头对同一 KV 头的梯度**自动累加**回那一份——这正是"共享"在反向的体现,无需额外代码。推理则缓存 g 份、计算时广播。
- **为什么 GQA 比 MQA 训练更稳?** MQA 只 1 份 KV,梯度信号高度集中、表达瓶颈窄;GQA 留 g 份给了更多自由度,梯度更分散、优化更平滑,这也是 MQA 易掉点而 GQA 几乎不掉点的原因之一。
- **GQA 能和 [[020 MLA 多头潜在注意力(DeepSeek)|MLA]] 比吗?** GQA 仍缓存"完整但更少头"的 KV;MLA 缓存"低秩潜向量"。MLA 省得更狠(~1/30+)且质量更好,但实现复杂(下/上投影、解耦 RoPE、矩阵吸收);GQA 胜在简单、生态成熟、几乎零踩坑。
- **GQA 里 g 必须整除 h 吗?** 是,$h\bmod g=0$ 才能把 Q 头均匀分组、每组同样大小;不整除会导致组大小不一,工程上一般不允许。

## 关键事实
- 出处:Ainslie et al.,*GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints*,2023,arXiv:2305.13245(EMNLP 2023)。
- 核心结论:uptrained GQA "achieves quality close to multi-head attention with comparable speed to MQA";转换仅需约 **5%** 原预训练算力。
- 采用模型:LLaMA-2(34B/70B,g=8)、LLaMA-3(全系)、Mistral 7B、Qwen 等;已是开源 LLM 的默认注意力。
- KV-Cache 公式:$\propto 2\cdot L\cdot g\cdot d_{head}\cdot n_{layer}$,$1\le g\le h$。
- 与邻接概念:极端化为 [[018 MQA 多查询注意力|MQA]]($g=1$)/ [[005 多头注意力 Multi-Head|MHA]]($g=h$);更激进的低秩压缩见 [[020 MLA 多头潜在注意力(DeepSeek)|MLA]];属于 [[103 KV-Cache 优化：GQA、量化、驱逐与前缀共享|KV-Cache 优化]]的核心一环;LLaMA 整体结构见 [[038 LLaMA 架构解剖|LLaMA 架构解剖]]。
