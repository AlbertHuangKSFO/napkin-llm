[[073 序列并行与上下文并行]]:两种沿**序列维**切分的并行——序列并行(SP)切张量并行管不到的 LayerNorm、Dropout 的激活以省显存;上下文并行(CP,典型实现 Ring Attention)把整条超长序列切到多卡、让 KV 绕环流转,从而训练几十万乃至上百万 token 的上下文。

## ① 直觉:数据并行切样本、张量并行切宽度,这两个切的是"长度"

回顾已有的并行维度:数据并行(见 [[070 ZeRO 与 FSDP]])切的是 **batch**(每卡一批不同样本);张量并行(TP)切的是**隐藏维 d**(每卡算一部分注意力头/FFN 列)。但还有一个维度没人切——**序列长度 s**。当你要训练 128K、甚至 1M token 的上下文时,光是激活(activation)就会撑爆单卡显存,这时就得沿序列维下刀。

这里有两个名字相近但目标不同的技术:

- **序列并行(Sequence Parallelism, SP)**:它是张量并行的**搭档补丁**。TP 切了注意力和 FFN,但 block 里还有 LayerNorm 和 Dropout——这两个算子 TP 切不动,于是每卡都得存**完整序列**的这部分激活,白白浪费显存。SP 把这部分也沿序列维切开,**不增加通信总量**,纯赚显存。
- **上下文并行(Context Parallelism, CP)/ Ring Attention**:它是为**超长序列**设计的独立并行维度。把**整条序列**切成 P 段分到 P 张卡,每卡只持自己那段的 Q,而 KV 段沿环依次流转,边传边用 [[025 FlashAttention(IO 感知精确注意力)|FlashAttention]] 的在线 softmax 累加——这样单卡永远只存 1/P 的 KV,激活显存随卡数线性下降。

一句话:SP 是"顺手把 LN/Dropout 也切了省点显存",CP 是"为了塞下百万 token 把整条序列摊到多卡"。

## ② 例子:16 个 token、4 张卡,各自怎么分

设序列长 s=16,隐藏维 d=768,4 张卡。

**序列并行(SP)视角**——一个 block 内部在两种切分间来回切换:

- 进入 LayerNorm/Dropout 时(SP 区):激活形状从 `[s=16, d=768]` 变成每卡 `[s/4=4, d=768]`。GPU0 拿 token 0–3,GPU1 拿 4–7…… LayerNorm 是**逐 token 独立**做的(对每个 token 的 d 维归一),所以沿序列切完全无损。
- 进入 Attention/FFN 时(TP 区):需要完整序列,于是做一次 **all-gather** 把序列拼回 `[16, 768]`;算完 TP 部分,再用 **reduce-scatter** 把结果归约并切回 `[4, 768]`。

关键省了什么:原本每卡要存 `16×768` 的 LN/Dropout 激活,现在只存 `4×768`,省到 1/4。而通信没变贵——原本 TP 用一次 all-reduce,现在拆成 reduce-scatter + all-gather,字节数恰好相等(all-reduce ≡ reduce-scatter + all-gather)。

**上下文并行(CP / Ring Attention)视角**:

- GPU0 永久持有 Q₀(token 0–3)和起始 KV₀;GPU1 持 Q₁ 和 KV₁……
- 第 0 步:每卡用本地 Q 算本地 KV 的注意力。
- 第 1 步:每卡把自己的 KV 块**发给环上下一卡**,同时收上一卡的 KV,再算一轮,用在线 softmax 把部分结果累加进去。
- 转满 P=4 步后,每个 Q 段就"见过"了全序列的 KV,得到完整注意力——而任一时刻单卡只存 1/4 的 KV。

## ③ 原理:为什么 SP 不增通信、CP 能藏延迟

**SP 的零成本来自一个恒等式**。张量并行的列并行 + 行并行,反向/前向各需要一次 **all-reduce** 来合并部分和。而:

$$
\text{all-reduce} \;\equiv\; \text{reduce-scatter} \;+\; \text{all-gather}
$$

通信字节数:对 P 卡、数据量 M,ring all-reduce 收发约 $2\frac{P-1}{P}M$;reduce-scatter 和 all-gather 各约 $\frac{P-1}{P}M$,加起来一样。所以 SP 把一次 all-reduce"劈开",在中间插入序列切分的 LN/Dropout,**总通信量不变**,却把这两个算子的激活显存降到 1/P。这些原语的区别见 [[074 通信原语与计算通信重叠]]。

**CP / Ring Attention 的核心是把注意力写成可分块累加的形式**。标准注意力:

$$
\mathrm{Attn}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

softmax 看似要先看到所有 K 才能归一,但 FlashAttention 的**在线 softmax**用"运行中的最大值 $m$ 与归一化和 $\ell$"逐块更新,使我们可以**只拿到一个 KV 块就算一份部分输出**,再把各块结果用统一的 $m,\ell$ 修正后相加:

$$
O = \sum_{j} \frac{\exp(S_j - m)}{\ell}\,V_j,\qquad m=\max_j m_j,\;\ell=\sum_j \ell_j
$$

正因为可分块,Ring Attention 才能把 KV 切成 P 段、环形流转、逐步累加,而不必任何一卡持有完整 KV。通信量:每卡每步发 1 个 KV 块,共 P−1 步,KV 块大小 $\frac{s}{P}\cdot d_k$,**且这部分通信可与本步注意力计算重叠**(算第 k 块时,第 k+1 块正在路上)。显存:激活 $O(\frac{s}{P})$,随卡数线性下降——这正是能训百万 token 的关键。

注意 SP 与 CP 的区别也体现在切谁:SP 只切**特定层**(LN/Dropout)的激活,CP 切**所有层**的激活(整条序列从头到尾都是分片的)。

## ④ 代码:CP 的极简骨架(在线 softmax 累加)

```python
import torch, torch.distributed as dist

# 每卡持有一段 Q,以及"环上轮转"的 KV 段。这里用单进程伪代码示意累加逻辑。
def ring_attention_step(q, k_block, v_block, m, l, acc, scale):
    # q: [s/P, d]; k_block,v_block: 当前手里这块 KV
    s = (q @ k_block.transpose(-1, -2)) * scale      # [s/P, s/P]
    m_new = torch.maximum(m, s.max(dim=-1, keepdim=True).values)
    p = torch.exp(s - m_new)                         # 重新对齐到新最大值
    corr = torch.exp(m - m_new)                      # 旧累加值的修正系数
    l = corr * l + p.sum(dim=-1, keepdim=True)
    acc = corr * acc + p @ v_block                   # 部分输出累加
    return m_new, l, acc

# ❌ 错:在每卡上重建完整 K、V 再算注意力 —— 等于没切,显存照爆
#   k_full = all_gather(k_block)   # OOM:s 很大时拼不回来

# ✅ 对:KV 块绕环 P-1 次,每步只用手里这一块累加(显存 O(s/P))
def ring_attention(q, k, v, world_size, scale):
    m = torch.full((q.size(0), 1), -1e9); l = torch.zeros_like(m)
    acc = torch.zeros_like(q)
    k_blk, v_blk = k, v                              # 本地起始 KV
    for step in range(world_size):
        m, l, acc = ring_attention_step(q, k_blk, v_blk, m, l, acc, scale)
        # 真实实现:用 dist.isend/irecv 把 k_blk,v_blk 异步发给下一卡、收上一卡
        # k_blk, v_blk = ring_exchange(k_blk, v_blk)   # 与下一步计算重叠
    return acc / l                                  # 最终归一
```

要点:单卡显存只跟 `q`(本地段)和**一个** KV 块挂钩,与总序列长 s 无关——这就是 CP 能训百万 token 的根本原因。

## ⑤ Ring Attention 的因果负载不均(必踩的坑)

朴素 Ring Attention 在**因果掩码**(decoder,token 只看左边)下会**严重负载不均**。把序列按位置切成 P 段、卡 $i$ 持第 $i$ 段的 Q:
- 卡 0 的 Q(最靠前的 token)只需和**自己这段**的 KV 算(后面的 token 被因果掩码挡住,根本不看)。
- 卡 P-1 的 Q(最靠后的 token)要和**全部 P 段**的 KV 算。

于是卡 P-1 的计算量是卡 0 的 P 倍,**流水线被最慢的卡 P-1 拖死**,加速比远不到 P。解法是 **zigzag / 条带分配**:不按"连续块"分,而把序列切成 $2P$ 个小块,卡 $i$ 同时领第 $i$ 块和第 $2P-1-i$ 块(一头一尾)——让每卡的"靠前轻 + 靠后重"互补,负载拉平。这是 Llama-3 长上下文训练等实际系统采用的关键技巧,面试问"Ring Attention 因果下怎么均衡"答这个。

## ⑥ Ring Attention vs DeepSpeed-Ulysses:两种序列并行的取舍

两条技术路线切超长序列,通信模式不同:

| | Ring Attention(CP) | DeepSpeed-Ulysses |
|---|---|---|
| 切什么 | 序列维(Q 固定、KV 绕环) | 注意力计算前后用 all-to-all 在**序列维↔头维**转置 |
| 通信原语 | 点对点 send/recv(环) | **all-to-all** |
| 通信量 | $O(s/P\cdot d)$/步 × P 步,与序列长解耦,可与计算重叠 | all-to-all,量 $\propto s\cdot d$,但次数少 |
| 适合 | 极长序列、头数不多 | 头数多(并行度 ≤ 头数,因为按头切) |
| 限制 | 因果下需 zigzag 均衡 | 并行度受注意力头数上限约束 |

记忆:**Ring = 沿序列绕环传 KV(适合超长、可重叠);Ulysses = all-to-all 把"切序列"转成"切头"(适合头多、实现简单)**。二者可组合(2D:Ulysses 机内 × Ring 机间)。

## ⑦ CP 的显存与通信定量

设序列长 $s$、隐藏维 $d$、CP 度 $P$、batch $b$。
- **激活显存**:每卡只持 $1/P$ 序列的 Q/K/V 和注意力中间量 → $O(b\cdot \frac{s}{P}\cdot d)$,**随 $P$ 线性下降**。1M token 序列、$P=8$ 时单卡只扛 128k token 的激活。
- **通信量**:每步发一个 KV 块 $\frac{s}{P}\cdot d\cdot 2\text{B}\times 2(\text{K和V})$,共 $P-1$ 步,单卡总传 $\approx 2\cdot d\cdot s\cdot\frac{P-1}{P}\cdot 2\text{B}$,与 all-reduce 同量级但**可被注意力计算完全藏住**(算第 $k$ 块时第 $k{+}1$ 块在路上)。
- **KV-Cache 推理**:CP 思路也用于推理时把超长 KV-Cache(见 [[076 显存占用估算(参数、梯度、优化器、激活、KV)|KV 显存]])分摊到多卡。

## ⑧ SP/CP 在 4D 并行里的位置

完整并行谱是 **DP × TP × PP × CP**(再加 EP=5D):
- **SP** 不是独立维度,是 **TP 的附属**——TP=8 时 SP 自动按同一组的 8 卡切 LN/Dropout 激活,**零额外通信**(用 reduce-scatter/all-gather 替原 all-reduce)。所以"开了 TP 就该开 SP",几乎白送的省显存。
- **CP** 是独立维度,和 DP 正交:DP 切不同样本,CP 切**同一样本内部的序列**。训练 128K+ 上下文时,典型 `DP × CP`(每个 DP 副本内部再用 CP 把长序列摊开)。

## 面试高频

- **Q:序列并行(SP)和上下文并行(CP)有什么区别?** SP 是 TP 的补丁,只把 TP 切不动的 LayerNorm/Dropout 的激活沿序列维切,**不增通信、纯省显存**,序列长度本身不变;CP 是独立并行维度,把**整条序列**切到多卡处理超长上下文,典型实现是 Ring Attention。
- **Q:为什么 SP 不会增加通信量?** 因为 all-reduce ≡ reduce-scatter + all-gather,字节数相等,SP 只是把一次 all-reduce 劈成两半、中间插入序列切分,总量不变。
- **Q:Ring Attention 为什么能省显存?** 单卡只存 1/P 的 KV,靠 FlashAttention 的在线 softmax 把环形流转过来的各 KV 块逐步累加,激活随卡数 P 线性下降。
- **Q:CP 的通信能不能藏住?** 能。算当前 KV 块的注意力时,异步收发下一块,通信与计算重叠(见 [[074 通信原语与计算通信重叠]])。
- **Q:LayerNorm 为什么能沿序列维切?** 它是逐 token 独立、对每个 token 的特征维 d 做归一,token 之间不交互,所以切序列无损(参见 [[010 层归一化：Pre-LN 与 Post-LN]])。
- **Q:为什么不直接把序列也丢给数据并行?** DP 切的是不同样本;一条超长序列是**单个样本内部**的长度,DP 切不动它,必须 SP/CP。
- **Q:Ring Attention 在因果掩码下为什么负载不均,怎么修?** 靠前的 Q 段只看少量 KV、靠后的 Q 段看全部,卡 P-1 计算量是卡 0 的 P 倍,被最慢卡拖死。修法:zigzag 分配——每卡同时领一头一尾两块(第 $i$ 块 + 第 $2P-1-i$ 块),让轻重互补。
- **Q:Ring Attention 和 DeepSpeed-Ulysses 怎么选?** Ring 沿序列绕环传 KV、可与计算重叠、适合超长序列;Ulysses 用 all-to-all 把"切序列"转成"切头"、实现简单但并行度 ≤ 头数。头多用 Ulysses,序列极长用 Ring,也可组合。
- **Q:开了 TP 要不要开 SP?** 要,几乎白送。SP 是 TP 的附属维度,把 LN/Dropout 激活按序列切到 $1/t$,用 reduce-scatter+all-gather 替原 all-reduce,通信总量不变、纯省激活显存。

## 关键事实

- 序列并行(切 LayerNorm/Dropout 激活、配合张量并行、不增通信)出自《Reducing Activation Recomputation in Large Transformer Models》(Korthikanti et al., NVIDIA, 2022, arXiv:2205.05198),集成进 Megatron-LM。
- Ring Attention 出自《Ring Attention with Blockwise Transformers for Near-Infinite Context》(Liu, Zaharia, Abbeel, 2023, arXiv:2310.01889),把序列分块沿环流转、与计算重叠,显存与序列长解耦。
- 在线 softmax 的分块累加来自 FlashAttention(Dao et al., 2022, arXiv:2205.14135),是 Ring Attention 能分块计算的数学基础。
- 另一类序列并行实现 DeepSpeed-Ulysses(Jacobs et al., 2023, arXiv:2309.14509)改用 [[074 通信原语与计算通信重叠|all-to-all]] 在序列维与注意力头维之间转置,适合头数多的场景。
- 恒等式 all-reduce = reduce-scatter + all-gather 是 SP 零额外通信成本的理论依据(NCCL 集合通信文档)。
- 因果掩码下 Ring Attention 的负载不均与 zigzag/条带均衡方案,是长上下文训练系统(如 Llama-3 405B 的 CP 实现)的关键工程点;朴素连续切分会让末段卡计算量达首段的 P 倍。
- DeepSpeed-Ulysses(Jacobs 等,2023,arXiv:2309.14509)并行度受注意力头数上限约束;Ring Attention 并行度受序列长约束,二者可组合成 2D 序列并行。
- CP 是与 DP 正交的独立并行维度(DP 切样本、CP 切样本内序列);SP 不是独立维度,是 TP 的附属。完整并行谱见 [[068 并行总览：DP、TP、PP、EP、SP|并行总览]]。
