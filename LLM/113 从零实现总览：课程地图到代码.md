## 直觉

前面 112 篇都在讲**概念**:注意力为什么除以 $\sqrt{d_k}$、AdamW 怎么解耦权重衰减、BPE 怎么合并高频对……但「懂概念」和「能写出来」之间隔着一条河。这一轨就是搭桥:**每个核心概念都落到几十行可运行代码里**,最后拼成一个能在笔记本电脑 CPU 上几分钟训出来、会续写文本的 tiny GPT。

关键心智:**模型本质是一个把 token id 序列映射到「下一个 token 概率分布」的可微函数**,训练就是反复 `forward → 算 loss → backward → 更新参数`。整个项目只有 5 个文件:

- `sample.py`——生成与评估(见 [[118 采样生成与困惑度评估|采样与困惑度]])

## 例子

**最小可跑闭环(伪代码,5 行讲清整条线)。** 字符级版本,语料就是一段莎士比亚文本:

```
text  = open("input.txt").read()           # 1. 读语料
ids   = tokenizer.encode(text)             # 2. 文本 → id 序列
model = GPT(GPTConfig(vocab_size=V))       # 3. 建模型
train(model, ids)                          # 4. forward→loss→backward→step 反复
print(generate(model, "ROMEO:"))           # 5. 采样续写
```

**规模感(为什么叫 tiny)。** 一个可在 CPU 上训练的配置:

| 超参 | 值 | GPT-2 small 对比 |
|---|---|---|
| 词表 vocab_size | 65（字符级）| 50257 |
| 层数 n_layer | 4 | 12 |
| 头数 n_head | 4 | 12 |
| 维度 n_embd | 128 | 768 |
| 上下文 block_size | 64 | 1024 |
| 参数量 | ≈ 0.8M | 124M |

参数量手算见 [[075 参数量逐层手算(GPT 全拆)|参数量手算]]:同一套公式,只是数字变小。0.8M 参数在 CPU 上几分钟就能把 loss 从 ~4.2(随机猜 65 类的 $\ln 65$)降到 ~1.5,生成出有英文单词形态的文本。

**两条实现路径(都要走一遍)。**
```
理解路径：engine.py（手写反传） → model.py numpy 版（手算 attention，肉眼可见每个张量）
训练路径：model.py PyTorch 版（autograd 接管反传） → train/sample/finetune（真跑）
```
numpy 版的意义不是用来训练(慢且要手写反传),而是**让你看清每个矩阵乘法**;真正训练交给 PyTorch 的 autograd——它做的事和你 `engine.py` 里手写的一模一样,只是高效。

**从零实现最常踩的 7 个坑(贯穿全轨,先建立警觉)。** 后面每篇会细讲,这里先汇总成一张「debug 清单」:

1. **忘 shift**:target 没左移一位,模型学会「抄输入」,loss 异常低(远小于 $\ln V$),生成全是复读。
2. **忘 zero_grad**:autograd 梯度 `+=` 累加,不清就把上一步叠进来,训练发散(见 [[114 手写自动微分引擎(micrograd 级)|114]])。
3. **因果掩码漏了/方向反了**:训练时偷看未来 token,train loss 极低但推理崩(见 [[115 手写多头注意力与 Transformer Block(numpy)|115]])。
4. **softmax 没减最大值**:`exp` 上溢出 NaN(数值稳定)。
5. **BPE 编码不按学习顺序合并**:切分与训练不一致,同一字符串切法不定(见 [[116 实现 BPE 分词器|116]])。
6. **推理忘 `model.eval()`**:dropout/LN 统计没切换,「训练好推理差」(见 [[117 训练一个 tiny GPT(PyTorch,可跑)|117]])。
7. **PPL 分母用总长而非有效 token、或没滑窗**:困惑度失真(见 [[118 采样生成与困惑度评估|118]])。

**黄金健全性检查**:训练前打印初始 loss,必须 $\approx \ln(\text{vocab\_size})$;不对就先别训,回去查 1/3/4 号坑。

## 原理

**1. 模型是一个可微函数 $f_\theta$。** 给定参数 $\theta$ 和输入 token 序列 $x=(x_1,\dots,x_T)$,GPT 输出每个位置「下一个 token」的 logits:

$$\text{logits}=f_\theta(x)\in\mathbb{R}^{T\times V},\qquad p(\cdot\mid x_{\le t})=\mathrm{softmax}(\text{logits}_t)$$

训练目标是自回归交叉熵(见 [[060 训练目标与 loss 实现|loss 实现]]):

$$\mathcal{L}(\theta)=-\frac{1}{T}\sum_{t=1}^{T}\log p_\theta(x_{t+1}\mid x_{\le t})$$

**2. 训练 = 在 $\theta$ 空间做梯度下降。** 反复:前向算 $\mathcal{L}$ → 反向算 $\nabla_\theta\mathcal{L}$(自动微分,见 [[19 自动微分：前向 vs 反向模式|自动微分]]、[[20 反向传播的数学推导|反向传播]])→ 优化器更新 $\theta\leftarrow\theta-\eta\,\hat g$(AdamW,见 [[061 优化器与超参(AdamW)|AdamW]])。$f_\theta$ 由若干 Transformer Block 堆叠(见 [[013 Transformer 整体数据流(逐张量形状)|数据流]]),每个 Block 内是注意力 + FFN + 残差 + LN。

**3. 模块依赖是一条单向链。** `tokenizer` 决定 $V$ → `model` 用 $V$ 建嵌入和输出层 → `train` 用 `model` 和数据算 loss/反传 → `sample` 用训好的 `model` 生成 → `finetune` 在 `model` 上挂 LoRA、改 loss mask。**只有 `model` 被所有下游依赖**,所以接口要先定死:`logits, loss = model(idx, targets=None)`(给 targets 就顺便返回 loss,这是 nanoGPT 的经典签名)。

**4. 为什么先手写 `engine.py`。** PyTorch 的 `.backward()` 是黑箱,面试常问「梯度怎么算出来的」。手写一个 micrograd 级标量自动微分(加、乘、tanh + 拓扑排序反向),你就能在白板上推:**前向建图、反向沿链式法则把局部导数乘起来回传**(见 [[18 计算图(前向)|计算图]]、[[38 反向传播在网络中的实现|反向传播实现]])。理解后,PyTorch/numpy 版直接用张量替标量、用 autograd 替手写反传。

**5. 学习顺序的依赖理由。** 114(反传机制)→115(注意力,但用 numpy 看清形状)→116(分词,决定 $V$)→117(组装成可训 PyTorch GPT)→118(让它生成 + 评估)→119(让它听指令)。**先底层机制、再积木、再组装、再对齐**——和真实从零造模型的顺序一致。

**6. tiny GPT 与真实 GPT 的差距(知道哪些被省了)。** tiny 版为教学砍掉了工程复杂度,但**数学骨架完全一致**。被省/简化的:dropout(tiny=0)、混合精度(fp16/bf16)、梯度累积与分布式(DDP/FSDP/ZeRO,见 [[070 ZeRO 与 FSDP|ZeRO]])、学习率 warmup+cosine 调度(见 [[062 学习率调度：warmup 加 cosine 与 WSD|学习率调度]])、Flash-Attention(见 [[025 FlashAttention(IO 感知精确注意力)|FlashAttention]])、KV-Cache 加速生成(见 [[102 KV-Cache|KV-Cache]])、RoPE(tiny 用学习式位置)、checkpoint 保存恢复。**理解 tiny 版后,这些都是「同一函数 + 工程优化」**,不改变核心。从 0.8M 放大到 124M(GPT-2)只是把超参调大、加上这些工程件,数学一字不变——这正是「先 tiny 跑通、再谈规模」的价值。

**7. 端到端怎么验证「真跑通了」。** 三道关:① 初始 loss $\approx\ln V$(初始化/掩码/shift 都对);② loss 持续下降到 ~0.03–1.5(优化器/反传正常);③ 生成出有单词形态、非复读的文本(采样 + 模型都对)。三关全过 = 端到端打通。任一关卡住,按上面的「7 个坑」逐个排查。

## 代码

下面是贯穿全轨的**项目骨架**。`model.py` 的接口(`GPTConfig` + `GPT.forward` 签名)在 117 落地,这里先给出全项目都依赖的契约,以及把六篇串起来的 `main.py`。

```python
# ============ 项目结构（约 300 行，六个文件） ============
# tiny_gpt/
# ├── engine.py     # 114: Value 标量自动微分（教学，不参与训练）
# ├── tokenizer.py  # 116: BPE.train / encode / decode
# ├── model.py      # 115(numpy 理解) + 117(PyTorch GPTConfig/Block/GPT)
# ├── train.py      # 117: 数据加载 + 训练循环 + AdamW
# ├── sample.py     # 118: generate(温度/top-k) + perplexity
# ├── finetune.py   # 119: SFT loss mask + LoRALinear 注入
# └── main.py       # 下面这段，把全流程串起来

# ============ model.py 必须先定死的接口契约（117 实现它） ============
from dataclasses import dataclass

@dataclass
class GPTConfig:
    vocab_size: int = 65      # 由 tokenizer 决定
    block_size: int = 64      # 上下文长度
    n_layer:    int = 4
    n_head:     int = 4
    n_embd:     int = 128
    dropout:  float = 0.0

# 全项目依赖的唯一契约：
#   model = GPT(GPTConfig(...))
#   logits, loss = model(idx, targets)   # targets=None 时只返回 logits（推理用）
#   idx:(B,T) long  ->  logits:(B,T,vocab_size)
```

```python
# ============ main.py：把六篇拼成一条可跑流水线 ============
import torch
# from tokenizer import CharTokenizer      # 116（字符级最简版；BPE 同接口）
# from model import GPT, GPTConfig         # 117
# from train import train                  # 117
# from sample import generate, perplexity  # 118

def run():
    # 1) 数据：用一段文本（如 tinyshakespeare）
    text = open("input.txt", "r", encoding="utf-8").read()

    # 2) 分词（字符级最简；换成 BPE 只需替换这一行，接口相同）
    chars = sorted(set(text))
    stoi  = {c: i for i, c in enumerate(chars)}
    itos  = {i: c for c, i in stoi.items()}
    encode = lambda s: [stoi[c] for c in s]
    decode = lambda l: "".join(itos[i] for i in l)
    data = torch.tensor(encode(text), dtype=torch.long)
    n = int(0.9 * len(data))
    train_data, val_data = data[:n], data[n:]

    # 3) 建模型
    cfg = GPTConfig(vocab_size=len(chars), block_size=64,
                    n_layer=4, n_head=4, n_embd=128)
    model = GPT(cfg)
    print(f"参数量: {sum(p.numel() for p in model.parameters())/1e6:.2f}M")
    # 期望输出: 参数量约 0.2~0.8M（取决于 n_embd/层数）

    # 4) 训练（117 的训练循环：forward→loss→backward→AdamW.step）
    train(model, train_data, val_data, cfg, max_iters=2000, lr=1e-3)

    # 5) 生成（118：温度/top-k 采样）
    ctx = torch.tensor([encode("ROMEO:")], dtype=torch.long)
    out = generate(model, ctx, max_new_tokens=200, temperature=0.8, top_k=20)
    print(decode(out[0].tolist()))
    # 训练后期望: 输出有英文单词形态、像剧本格式的文本（远好于随机）

if __name__ == "__main__":
    run()
```

```python
# ============ 从零实现的 debug 清单（把上面 7 个坑做成断言） ============
import math, torch
import torch.nn.functional as F

def sanity_checks(model, x, y, V):
    """训练前跑一遍，快速定位常见 bug。"""
    logits, loss = model(x, y)
    # ① 初始 loss ≈ ln(V)：偏离 → 初始化/掩码/shift 出错
    assert abs(loss.item() - math.log(V)) < 0.5, \
        f"初始 loss {loss.item():.2f} ≠ ln(V)={math.log(V):.2f}，查初始化/shift/掩码"
    # ② 形状契约：logits 必须是 (B,T,V)
    assert logits.shape == (*x.shape, V), "logits 形状错，查输出头维度"
    # ③ 因果性：改动未来 token 不该影响当前位置的 logits
    x2 = x.clone(); x2[:, -1] = (x2[:, -1] + 1) % V      # 改最后一个 token
    l2, _ = model(x2)
    assert torch.allclose(logits[:, 0], l2[:, 0], atol=1e-4), \
        "位置 0 的输出被未来 token 影响 → 因果掩码漏了/方向反了"
    print("sanity OK：初始 loss、形状契约、因果性 三关通过 ✅")
```

## 面试高频

- **Q:从零实现一个 GPT 大概需要哪几个模块?** A:五个——tokenizer(文本↔id)、model(网络,Block 堆叠 + 嵌入 + 输出层)、train(forward/loss/backward/优化器循环)、sample(采样生成)、finetune(SFT/LoRA)。核心契约是 `logits, loss = model(idx, targets)`。
- **Q:训练 GPT 的核心循环是什么?** A:`forward 算 logits` → `算自回归交叉熵 loss(shift 对齐)` → `loss.backward() 反传` → `optimizer.step() 更新` → `zero_grad()`。重复数千步。
- **Q:训练刚开始 loss 应该是多少?** A:约 $\ln(\text{vocab\_size})$,即随机猜 $V$ 类的交叉熵;字符级 $V{=}65$ 时约 4.17。这是绝佳的健全性检查——偏离太多说明初始化或 shift 出了 bug。
- **Q:为什么要先手写自动微分而不是直接用 PyTorch?** A:为了理解 `.backward()` 不是魔法——它就是「前向建计算图、反向按拓扑序用链式法则把局部导数乘起来回传」。手写一遍(micrograd 级)能在白板上推梯度,这是高频考点。
- **Q:numpy 版和 PyTorch 版各自作用?** A:numpy 版用于**看清每个张量形状和矩阵乘**(手写反传太慢不拿来训练);PyTorch 版用 autograd 接管反传、用 GPU 加速,**真正拿来训练**。两者数学完全一致。
- **Q:tiny GPT 和真实 GPT 差在哪?** A:数学骨架完全一致;差的是工程件——混合精度、梯度累积、分布式(DDP/ZeRO)、lr warmup+cosine、Flash-Attention、KV-Cache、RoPE、checkpoint。从 0.8M 到 124M 只是调大超参 + 加这些,核心不变。
- **Q:从零实现最常见的 bug?** A:忘 shift(抄输入、loss 异常低)、忘 zero_grad(梯度累加发散)、因果掩码漏/反(偷看未来、训练低推理崩)、softmax 没减最大值(NaN)、BPE 不按学习顺序合并、推理忘 eval()。黄金检查:初始 loss ≈ ln(V)。
- **Q:怎么确认端到端跑通?** A:三关——初始 loss≈ln(V)、loss 持续下降、生成出非复读的有词形态文本。全过即打通,任一卡住按「7 个坑」排查。

## 关键事实

- 本轨蓝本是 Karpathy 的 **nanoGPT**(github.com/karpathy/nanoGPT,约 300 行可训练 GPT)与 **minGPT**,自动微分部分对应 **micrograd**(github.com/karpathy/micrograd,约 150 行标量 autograd),分词对应 **minbpe**;教学序列对应其 "Neural Networks: Zero to Hero" 课程(2022–2023)。
- 模型即可微函数 $f_\theta:\ \text{ids}\to\text{logits}$,训练目标为自回归交叉熵(见 [[060 训练目标与 loss 实现|loss]]),GPT 自回归与规模化见 [[036 GPT 系列：自回归与规模化|GPT 系列]]、原始 Transformer 见 [[001 Transformer 总览：为何抛弃 RNN|Transformer 总览]](Vaswani et al. 2017, arXiv:1706.03762)。
- 唯一跨模块契约 `logits, loss = model(idx, targets=None)` 来自 nanoGPT;`targets=None` 时只返回 logits 供推理,这是把训练与推理共用一份 `forward` 的常见写法。
- tiny GPT 在 CPU 上几分钟可训练:字符级 ~0.2–0.8M 参数,loss 从 $\ln 65{\approx}4.17$ 降到 ~1.5,生成出有单词形态的文本——足够把所有概念跑通,不为追 SOTA。
