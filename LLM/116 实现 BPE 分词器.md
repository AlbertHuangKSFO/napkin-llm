[[116 实现 BPE 分词器|实现 BPE 分词器]]:用约 60 行 Python 从零写一个 **Byte-level BPE**——`train` 在语料上反复合并最高频的相邻字节对、记录有序 merges;`encode` 按学习顺序贪心套用 merges 把文本变 id;`decode` 查词表拼回字节再 UTF-8 解码。这是 [[051 BPE 与 Byte-level BPE|BPE]] 从算法到可运行代码的落地,也是 tiny GPT 的 `tokenizer.py`——它决定了模型的 `vocab_size`。

## 直觉

模型只认数字,不认文字。**分词器就是文本和 id 之间的双向翻译机**(见 [[050 分词总览与子词动机|分词总览]])。字符级太碎(序列长、学不到词),整词级又会 OOV(没见过的词没法表示)。BPE 走中间路线:**从最细的单位(字节)出发,反复把语料里最高频的相邻对合并成一个新单位**,常见词自然被压成单 token,罕见词退化成几个子词——既短又零 OOV。

三个动作:

1. **train**:统计所有相邻对的频次 → 找最高频的一对 → 合并成新 token(id = 256, 257, …)→ 重复,直到词表到目标大小。每次合并记进一个**有序字典** `merges`。
2. **encode**:把文本转字节,然后**按 merges 的学习顺序**贪心地反复合并(先学的优先级高),直到没有可合并的对。
3. **decode**:每个 id 查 `vocab` 拿回它代表的字节串,全部拼起来,UTF-8 解码回文本。

**Byte-level** 的妙处:从 256 个字节出发,任何文本(任何语言、emoji、代码)都能编码,**永不 OOV**——这是 GPT-2 起的标准做法(见 [[051 BPE 与 Byte-level BPE|Byte-level BPE]])。

## 例子

**手动跑一轮 train(语料 "the cat the rat")。**

字节序列(简化成字符看):`t h e _ c a t _ t h e _ r a t`。统计相邻对:`(t,h)` 出现 2 次(最高)→ 合并成新 token 256 = `"th"`:
```
[th] e _ c a t _ [th] e _ r a t      序列从 15 变 13
```
下一轮 `(th,e)` 最高 → 257 = `"the"`;再下轮 `(a,t)` → 258 = `"at"`。**常见词被逐步压成单 token,序列越来越短、词表越来越大。**

**真实运行(语料重复 20 遍 "the cat sat on the mat. the cat ran. the rat sat.",训到 vocab=276)。** 学到的合并(实测前几条):
```
(97,116)=(a,t)   -> 256 "at"      count=120   ← 最高频对先合
(116,104)=(t,h)  -> 257 "th"      count=80
(257,101)=(th,e) -> 258 "the"     count=80    ← 合并可叠加：用上一轮的新 token
(258,32)         -> 259 "the "    count=80
...
```
注意 258 用到了 257——**合并是可叠加的**,后面的对可以包含前面新建的 token。

**编码 + 压缩。** `encode("the cat sat on the rat.")`:23 字节 → **6 个 token** `[259,263,269,114,256,46]`,压缩比 **3.83×**。`decode` 回去一字不差。Unicode 也通:`"你好,世界 hello"` 编码再解码完全还原。**roundtrip 必须无损**——这是分词器正确性的硬指标。

**为什么编码要按「学习顺序」而不是「贪最长」(一个反直觉点)。** 直觉上可能想「每步选能合并成最长 token 的那对」,但 BPE 的正确编码是**严格按 merges 的学习顺序**(最早学的 id 最小、优先级最高)。例子:若先学了 `(t,h)→th` 再学 `(h,e)→he`,编码 `the` 时必须先合 `(t,h)`(更早学)得到 `th e`,而不是先合 `(h,e)`。这保证**同一字符串永远被切成同一串 token**(确定性),且与训练时的切分一致。若按「贪最长」或「按频次」编码,切法会和训练不一致,模型见到的 token 分布就乱了。这是手写 BPE 最容易写错的一点——`encode` 里那句 `min(stats, key=lambda p: self.merges.get(p, inf))` 就是在选「学习顺序最靠前的可合并对」。

**非英文的「分词税」(实测直觉)。** 同一句话,英文压缩比高(常见词压成单 token)、中文/emoji 低(byte-level 下一个汉字 = 3 个 UTF-8 字节,若未学到合并就是 3 个 token)。这意味着**同样语义,中文消耗的 token 比英文多 2~3 倍**——直接影响 API 成本和有效上下文长度。这就是「分词税」,也是为什么面向中文的模型要在中文语料上重训 tokenizer、扩大词表(见 [[055 分词的坑：数字、代码、多语言与 token 攻击面|分词的坑]])。

## 原理

**1. 训练目标:用最少 token 表示语料。** BPE 是贪心压缩:每步把当前最高频的相邻对 $(a,b)$ 替换成一个新符号 $z$(见 [[051 BPE 与 Byte-level BPE|BPE]])。设语料初始为字节序列,词表从 256 个字节起,做 $k=\text{vocab\_size}-256$ 次合并。每次合并:

$$\text{pair}^*=\arg\max_{(a,b)}\text{count}(a,b),\qquad z=256+k,\qquad \text{merges}[\text{pair}^*]=z$$

`merges` 是**有序**的(Python 3.7+ dict 保序),顺序 = 学习优先级,编码时要严格按此顺序套用,否则切分和训练时不一致。

**2. 编码:按优先级贪心合并。** 给定字节序列,反复找「在 `merges` 里、优先级最高(最早学、id 最小)」的可合并对并替换:

$$\text{每步:}\quad \text{pair}=\arg\min_{(a,b)\in\text{当前相邻对}}\text{merges}.\text{get}((a,b),\infty)$$

直到没有任何相邻对在 `merges` 里(`min` 取到 $\infty$)。**优先级用「学习顺序」而非「频次」**——保证和训练时的切分确定性一致。

**3. 解码:查表拼字节。** 维护 `vocab: id → bytes`,叶子是 256 个单字节,合并 token 的字节 = 两个子 token 字节的拼接:$\text{vocab}[z]=\text{vocab}[a]+\text{vocab}[b]$。解码就是 `b"".join(vocab[i] for i in ids).decode("utf-8")`。用 `errors="replace"`:因为 token 边界可能切在一个多字节 UTF-8 字符中间(单个 token 不一定是合法字符串),拼起来才合法。

**4. 为什么 byte-level 零 OOV。** 基词表是 0–255 全部字节,**任何字节串都能逐字节回退**,所以从没见过的字、emoji、二进制都能编码——代价是非英文要拆成多字节、序列变长(见 [[055 分词的坑：数字、代码、多语言与 token 攻击面|分词的坑]])。真实 GPT-2 还先用正则按空格/标点预切分,避免跨词合并;此处省略以保持最小(minbpe 的 `BasicTokenizer`)。

**5. 它决定 `vocab_size`。** 训完的词表大小 = 模型嵌入层和输出层的行数(见 [[054 词嵌入层与权重绑定|词嵌入层]])。字符级 tiny GPT 用几十的词表;BPE 版用几百到几千。这是 `tokenizer` → `model` 唯一的传递参数(见 [[113 从零实现总览：课程地图到代码|总览的接口契约]])。

**6. 词表大小的权衡(为什么不是越大越好)。** 词表 $V$ 大 → 序列更短(常见词压成单 token,省算力、长上下文更划算),但**嵌入/输出层参数 $\propto V\cdot d$ 暴涨**,且罕见 token 训练样本少、学不好。词表小 → 序列长(算力贵)、但参数省、每个 token 训得充分。真实模型在两者间取平衡:GPT-2 用 50257、GPT-4/Llama-3 用约 10 万+(多语言要更大)。这是个**数据规模 × 算力 × 多语言覆盖**的联合优化,不是拍脑袋。

**7. 真实 tokenizer 比这个最小版多了什么。** ① **正则预切分**:GPT-2 先用正则把文本按空格/标点/数字切成块,**只在块内合并**——避免把跨词、跨标点的字节对合并成怪 token(如把 `". The"` 合一起)。② **特殊 token**:`<|endoftext|>`、对话角色标记 `<|user|>` 等,有独立 id、不参与 BPE 合并(见 [[053 词表、特殊 token 与对话模板|对话模板]])。③ **数字处理**:有的把数字按位拆(避免 `12345` 这种长尾整体 token)。④ **更高效的编码**:用优先队列而非每步重扫,$O(n\log n)$。本最小版(minbpe 的 BasicTokenizer)省掉①②以求最短可读,但①是 RegexTokenizer 的核心、生产必备。

## 代码

完整可运行(纯标准库)。已验证:ASCII 与 Unicode 的 encode/decode roundtrip 无损、压缩比 3.83×。贴进 `tokenizer.py` 即用。

```python
# tokenizer.py —— 最小 Byte-level BPE（train / encode / decode，约 60 行）
def get_stats(ids):
    """统计所有相邻对的频次。"""
    counts = {}
    for a, b in zip(ids, ids[1:]):
        counts[(a, b)] = counts.get((a, b), 0) + 1
    return counts

def merge(ids, pair, idx):
    """把序列里所有 pair 替换成新 token idx。"""
    out, i = [], 0
    while i < len(ids):
        if i < len(ids) - 1 and ids[i] == pair[0] and ids[i+1] == pair[1]:
            out.append(idx); i += 2
        else:
            out.append(ids[i]); i += 1
    return out

class BPETokenizer:
    def __init__(self):
        self.merges = {}                                   # (a,b) -> 新 id（有序=优先级）
        self.vocab = {i: bytes([i]) for i in range(256)}   # id -> 字节串

    def train(self, text, vocab_size, verbose=False):
        assert vocab_size >= 256
        ids = list(text.encode("utf-8"))                   # 从 UTF-8 字节出发
        self.merges = {}
        self.vocab = {i: bytes([i]) for i in range(256)}
        for k in range(vocab_size - 256):                  # 做这么多次合并
            stats = get_stats(ids)
            if not stats: break
            pair = max(stats, key=stats.get)               # 最高频相邻对
            idx = 256 + k                                  # 新 token id
            ids = merge(ids, pair, idx)
            self.merges[pair] = idx
            self.vocab[idx] = self.vocab[pair[0]] + self.vocab[pair[1]]  # 拼字节
            if verbose:
                print(f"merge {pair} -> {idx} ({self.vocab[idx]}) count={stats[pair]}")

    def encode(self, text):
        ids = list(text.encode("utf-8"))
        while len(ids) >= 2:
            stats = get_stats(ids)
            # 选「优先级最高(merges 里 id 最小=最早学)」的可合并对
            pair = min(stats, key=lambda p: self.merges.get(p, float("inf")))
            if pair not in self.merges:                    # 没有可合并的了
                break
            ids = merge(ids, pair, self.merges[pair])
        return ids

    def decode(self, ids):
        data = b"".join(self.vocab[i] for i in ids)        # 查表拼回字节
        return data.decode("utf-8", errors="replace")      # token 可能切在多字节中间
```

```python
# —— 训练并验证 roundtrip 无损 ——
text = "the cat sat on the mat. the cat ran. the rat sat. " * 20
tok = BPETokenizer()
tok.train(text, vocab_size=276, verbose=True)
# merge (97,116)->256 (b'at')   count=120   ← 最高频先合
# merge (116,104)->257 (b'th')  count=80
# merge (257,101)->258 (b'the') count=80    ← 用上一轮新 token，可叠加
# ...

s = "the cat sat on the rat."
enc = tok.encode(s)
print(len(s.encode('utf-8')), "字节 ->", len(enc), "token:", enc)   # 23 -> 6: [259,263,269,114,256,46]
print("压缩比:", round(len(s.encode('utf-8'))/len(enc), 2), "x")     # 3.83x
assert tok.decode(enc) == s                                          # ✅ roundtrip 无损
print("roundtrip OK:", repr(tok.decode(enc)))
```

```python
# —— Unicode 也无损（byte-level 零 OOV） ——
s2 = "你好，世界 hello 🚀"
t2 = BPETokenizer(); t2.train(s2 * 30, vocab_size=300)
assert t2.decode(t2.encode(s2)) == s2          # ✅ 中文 + emoji 完整还原
print("unicode roundtrip OK")

# 这个 tokenizer 的 vocab_size 就是喂给 GPTConfig 的 vocab_size（见 113/117）
print("vocab_size ->", len(tok.vocab))          # 276
```

# —— 验证「编码必须按学习顺序」：故意按贪最长编码会切错 ——
# 正确 encode 已按 merges 顺序(min(merges.get(p, inf)))；这里演示「确定性」性质：
a = tok.encode("the the the")
b = tok.encode("the the the")
assert a == b, "同一字符串必须切成同一串 token(确定性)"
print("确定性 OK:", a)

# 用一个只学了英文的小词表，去编码没见过的中文,暴露 byte-level 膨胀:
tax = BPETokenizer(); tax.train("the quick brown fox " * 50, vocab_size=300)  # 只学英文
zh = "自然语言"                       # 4 个汉字 = 12 个 UTF-8 字节
print(f"未学过的中文 {len(zh)} 字 -> {len(tax.encode(zh))} token")  # 12(每字节 1 token)
print(f"训练过的英文 'the quick' -> {len(tax.encode('the quick'))} token")  # 远少于字符数
# 直觉:byte-level 下一个汉字 = 3 字节,词表没学到合并就退化成 3 个 token → 中文「分词税」

# —— 验证零 OOV：从没在训练里出现的字符也能编码(逐字节回退) ——
weird = "ℵ∮⊗"                         # 训练语料里没有的符号
assert tok.decode(tok.encode(weird)) == weird   # ✅ byte-level 永不 OOV
print("OOV-free OK")

## 面试高频

- **Q:BPE 训练算法讲一下。** A:从字节(或字符)出发,统计所有相邻对频次,合并最高频的一对成新 token,记进有序 merges,重复直到词表达目标大小。合并可叠加(新对可含此前新建的 token)。
- **Q:编码时为什么不按频次、而按「学习顺序」选合并对?** A:为了确定性,且与训练时切分一致。优先级 = merges 里的顺序(最早学的 id 最小),保证同一字符串总被切成同样的 token。
- **Q:Byte-level BPE 为什么零 OOV?** A:基词表是全部 256 个字节,任何文本都能逐字节回退表示,所以没有「未登录词」。代价是非英文/emoji 拆成多字节、序列变长。
- **Q:decode 为什么要 `errors="replace"`?** A:单个 token 的字节不一定是合法 UTF-8(可能切在多字节字符中间);只有把整段 token 的字节拼起来才合法,中间状态用 replace 容错。
- **Q:分词器和模型怎么衔接?** A:分词器的 `vocab_size` 决定模型嵌入层和输出 logits 层的大小,是 tokenizer→model 唯一的传递参数(见 [[054 词嵌入层与权重绑定|词嵌入层]])。
- **Q:真实 GPT-2 的 BPE 和这个最小版差在哪?** A:真实版先用正则预切分(避免跨词合并、把空格归到词首),并加特殊 token(`<|endoftext|>`);此处省略以保持最小(对应 minbpe 的 BasicTokenizer)。
- **Q:词表越大越好吗?** A:不。$V$ 大序列短(省算力、长上下文划算)但嵌入/输出层参数 $\propto Vd$ 暴涨、罕见 token 学不好;$V$ 小序列长但参数省、训得充分。GPT-2 用 5 万、Llama-3 约 12.8 万,是数据/算力/多语言的联合权衡。
- **Q:为什么中文比英文「贵」?** A:byte-level 下一个汉字 = 3 个 UTF-8 字节,词表没学到合并就是 3 个 token;同样语义中文 token 数常是英文 2~3 倍,直接增 API 成本、占有效上下文。解法:在中文语料上重训 tokenizer、扩词表。
- **Q:特殊 token 怎么处理?** A:`<|endoftext|>` 等有独立 id、不参与 BPE 合并,编码时单独识别(否则会被拆成字节再乱合并),用于文档分隔、对话角色标记(见 [[053 词表、特殊 token 与对话模板|对话模板]])。

## 关键事实

- BPE 出自 Sennrich et al. 2016(arXiv:1508.07909,NMT 子词);Byte-level BPE 由 GPT-2 引入(Radford et al. 2019),基词表恒 256、零 OOV(见 [[051 BPE 与 Byte-level BPE|BPE 与 Byte-level BPE]])。
- 本实现对应 Karpathy 的 **minbpe**(github.com/karpathy/minbpe,BasicTokenizer/RegexTokenizer)与课程 "Let's build the GPT Tokenizer"(2024)。
- `merges` 必须有序(= 学习/优先级顺序),编码贪心按此顺序;`vocab[z]=vocab[a]+vocab[b]` 递归拼字节,decode 用 `errors="replace"` 容忍非法边界。
- 分词器的 `vocab_size` 决定模型 [[054 词嵌入层与权重绑定|嵌入层]] 与输出层大小,是 tokenizer→model 的唯一耦合参数(见 [[113 从零实现总览：课程地图到代码|总览]]、[[117 训练一个 tiny GPT(PyTorch,可跑)|tiny GPT]])。
- 真实生产 tokenizer 还需正则预切分、特殊 token、对话模板(见 [[053 词表、特殊 token 与对话模板|对话模板]]);分词的坑(数字、代码、多语言、token 攻击面)见 [[055 分词的坑：数字、代码、多语言与 token 攻击面|分词的坑]];其他子词流派 [[052 WordPiece、Unigram 与 SentencePiece|WordPiece/Unigram]]。
- 词表大小是数据/算力/多语言的联合权衡:$V$ 大序列短但嵌入输出参数 $\propto Vd$ 暴涨、罕见 token 学不好;GPT-2 用 50257、Llama-3 约 12.8 万;非英文 byte-level 膨胀(汉字 3 字节 → 未合并即 3 token)是「分词税」根源。
- 真实 tokenizer 还需正则预切分(块内合并,避免跨词怪 token)、特殊 token(独立 id、不参与合并)、可选数字拆位与优先队列加速编码;本最小版省①②以求最短(minbpe BasicTokenizer)。
