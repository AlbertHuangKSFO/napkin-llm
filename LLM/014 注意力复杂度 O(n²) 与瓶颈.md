[[014 注意力复杂度 O(n²) 与瓶颈|注意力复杂度 O(n²)]] 说的是:自注意力要算一张 $L\times L$ 的注意力权重矩阵($L$ 是序列长),所以**显存随 $L^2$、算力随 $L^2 d$ 增长**。$L$ 翻倍,代价翻 4 倍——这是 Transformer 处理长序列(长文档、长对话、长代码)的头号瓶颈,也催生了 FlashAttention、稀疏注意力、线性注意力三条优化路线。

## 直觉

自注意力的核心是「**每个 token 都要和句子里所有 token 算一次相关度**」。`L` 个 token 两两配对,就是 `L × L` 张表(见 [[002 自注意力 Self-Attention|自注意力]]、[[006 注意力的矩阵形式与张量形状|矩阵形式]])。

- 句子有 100 个词 → 一万格。
- 句子有 1000 个词 → 一百万格。
- 句子有 1 万个词 → 一亿格。

**格子数 = $L^2$**,所以 $L$ 涨 10 倍,表大 100 倍。这张表既要**存进显存**(显存 $O(L^2)$),又要**逐格算 + softmax**(算力 $O(L^2 d)$)。对比一下:FFN、嵌入这些「逐位置」操作只随 $L$ **线性**增长。于是当 $L$ 够大时,**注意力这一项把所有别的成本都盖过去了**,成为绝对瓶颈。

一句话:**注意力是「全连接」式的两两交互,代价天生是平方的;序列越长越受不了。**

## 例子

取真实量级的小数字。设模型维 $d=768$、头数 $h=12$、批 $B=8$、层数 $N=12$、用 fp16(2 字节)。只看**注意力权重矩阵 $A$** 的显存(形状 `(B, h, L, L)`):

| 序列长 $L$ | 单头单样本 $L^2$ | $A$ 总元素 $B\cdot h\cdot L^2$ | $A$ 显存(单层,fp16) |
|---|---|---|---|
| 512 | 0.26 M | 25.2 M | ~50 MB |
| 2 048 | 4.2 M | 402 M | ~800 MB |
| 8 192 | 67 M | 6.4 B | ~12.8 GB |
| 32 768 | 1.07 B | 103 B | ~206 GB(单层就爆) |

注意三件事:① 这只是**一层**,还要 ×$N$;② 还没算反向传播要存的中间量;③ $L$ 从 2k→8k(×4),显存从 800MB→12.8GB(×16),正是 $4^2$。**这就是为什么朴素 Transformer 的上下文窗口卡在几千 token**——不是算不动,是显存先爆。算力同理:$L$ 翻倍,$QK^\top$ 的乘加次数翻 4 倍。

## 原理

**复杂度来自两步矩阵乘**。设 $Q,K,V\in\mathbb{R}^{L\times d_k}$(略去批和头维):

$$S=\frac{QK^\top}{\sqrt{d_k}}\in\mathbb{R}^{L\times L},\qquad A=\mathrm{softmax}(S),\qquad O=AV\in\mathbb{R}^{L\times d_k}$$

- 算 $QK^\top$:输出 $L\times L$,每个元素是 $d_k$ 维点积 → $O(L^2 d_k)$ 次乘加。
- softmax:对 $L\times L$ 逐元素 → $O(L^2)$。
- 算 $AV$:同样 $O(L^2 d_k)$。

合起来**时间** $O(L^2 d)$(把 $h$ 个头的 $d_k$ 拼回 $d$),**显存** $O(L^2)$(存 $A$,这是反向传播也要用的中间量)。

**和 FFN 比一比**。FFN 是逐位置的两层线性($d\to 4d\to d$),时间 $O(L\cdot d^2)$、显存 $O(L\cdot d)$,**对 $L$ 是线性的**。两者在 $L\approx d$ 附近持平;当

$$L^2 d \gtrsim L d^2 \iff L \gtrsim d$$

时,注意力开始主导。$d$ 典型几百到几千,所以**序列一旦超过模型维量级,注意力就成了大头**——经验上 $L\gtrsim 8\text{k}$ 后注意力是单层的首要成本。

**三条破解路线**(前向引出三个兄弟笔记):

1. **不改结果,只改怎么算——FlashAttention**:发现瓶颈其实是**显存读写(IO)**而非纯算力。把 $A$ **分块**在 GPU 片上 SRAM 里流式算完即弃,**从不把整张 $L\times L$ 写回显存(HBM)**,显存降到 $O(L)$,算力仍 $O(L^2)$ 但因减少 IO 反而快 2–4×,**数值完全等价、无近似**(见 [[025 FlashAttention(IO 感知精确注意力)|FlashAttention]])。
2. **近似:只看一部分——稀疏注意力**:不让每个 token 看全句,只看**局部窗口 + 少量全局 token**,只算被选中的 $(i,j)$ 对,复杂度降到 $O(L\cdot w)$($w$ 是窗口/采样数,近线性)。代价是牺牲部分远距交互(见 [[022 稀疏注意力(BigBird、块稀疏)|稀疏注意力]])。
3. **近似:换数学——线性注意力**:用核函数 $\phi$ 近似 $\exp$,利用矩阵乘**结合律**先算 $\phi(K)^\top V$($d_k\times d_k$)再左乘 $\phi(Q)$,**绕开 $L\times L$**,复杂度降到 $O(L d^2)$ 线性。代价是 softmax 被近似、效果常略逊(见 [[023 线性注意力(Linear Transformer、Performer)|线性注意力]])。

**三条路线一张表对比**:

| 路线 | 代表 | 是否精确 | 时间 | 显存 | 牺牲什么 |
|---|---|---|---|---|---|
| 朴素注意力 | 原版 | — | $O(L^2d)$ | $O(L^2)$ | 长序列爆显存 |
| FlashAttention | Dao 2022 | ✅ 精确 | $O(L^2d)$ | $O(L)$ | 无(只省 IO) |
| 稀疏注意力 | BigBird、Longformer | ❌ 近似 | $O(Lw)$ | $O(Lw)$ | 远距交互(靠多层接力补) |
| 线性注意力 | Performer、Linear TF | ❌ 近似 | $O(Ld^2)$ | $O(Ld)$ | softmax 精度 |

**记住区分**:FlashAttention 是"算得巧不改结果"(精确),稀疏和线性是"少算或换算法"(近似)。面试最常考"FlashAttention 降的是显存不是算力复杂度"。

**为什么注意力是 IO-bound(FlashAttention 的核心洞见)**。GPU 的算力(TFLOPs)增长远快于显存带宽(HBM 读写),所以很多算子卡在"搬数据"而非"算数据"。朴素注意力要把 $L\times L$ 的 $S$、$A$ **写回显存再读回来**做 softmax,这些 HBM 读写才是瓶颈。FlashAttention 把注意力**分块(tiling)**,每块在片上 SRAM 里完成"打分→softmax→加权"全过程、用 online-softmax 增量合并,**从不把完整 $L\times L$ 落地 HBM**。算力没少(仍 $O(L^2)$),但 IO 大减,所以实测快 2–4× 且数值完全等价。

## 代码

```python
import torch

def attention_mem(B, h, L, d, bytes_per=2):
    """估算注意力权重矩阵 A=(B,h,L,L) 的显存(MB)"""
    elems = B * h * L * L
    return elems * bytes_per / 1024**2

for L in [512, 2048, 8192, 32768]:
    print(f"L={L:6d}  A 显存 ≈ {attention_mem(8, 12, L, 64):10.1f} MB")
# L=   512  A 显存 ≈       48.0 MB
# L=  2048  A 显存 ≈      768.0 MB
# L=  8192  A 显存 ≈    12288.0 MB    ← L×4, 显存×16
# L= 32768  A 显存 ≈   196608.0 MB    ← 单层就 192 GB
```

```python
# ❌ 朴素实现:显式构造整张 L×L 的注意力矩阵 → 显存 O(L²),长序列 OOM
def naive_attn(Q, K, V):                       # Q,K,V: (L, d)
    S = Q @ K.transpose(-2, -1) / Q.shape[-1]**0.5   # (L, L) ← 平方显存!
    A = S.softmax(dim=-1)                              # (L, L)
    return A @ V

# ✅ 生产实现:用 PyTorch 的 SDPA,内部走 FlashAttention 内核
import torch.nn.functional as F
def fast_attn(Q, K, V):                        # 同样输入
    # 不显式落地 L×L,显存 O(L);数值与朴素版等价
    return F.scaled_dot_product_attention(Q, K, V)
```

## 面试高频

- **Q:自注意力的时间和空间复杂度各是多少?为什么?** A:时间 $O(L^2 d)$、空间 $O(L^2)$。因为要算 $QK^\top$ 这张 $L\times L$ 的权重矩阵(每格 $d$ 维点积),并把它存下来供 softmax 和反向传播用。
- **Q:为什么说长序列下注意力是瓶颈而不是 FFN?** A:FFN 对 $L$ 线性($O(Ld^2)$),注意力对 $L$ 平方;$L\gtrsim d$ 后平方项压过线性项,$L$ 越大注意力占比越高。$L$ 翻倍注意力代价 ×4,FFN 只 ×2。
- **Q:FlashAttention 把复杂度从 $O(L^2)$ 降到了 $O(L)$吗?** A:**只降显存,不降算力**。算力仍 $O(L^2)$;它把显存从 $O(L^2)$ 降到 $O(L)$,靠分块避免落地整张矩阵、减少 HBM 读写,所以更快,且**结果与精确注意力完全一致**(不是近似)。
- **Q:稀疏 vs 线性注意力的区别?** A:稀疏=「少算几对」(只保留局部+全局),线性=「换算法绕开 $L\times L$」(核函数 + 结合律)。两者都是**近似**;FlashAttention 是**精确**。
- **Q:推理时复杂度和训练一样吗?** A:不一样。训练并行处理整句,注意力 $O(L^2)$;推理用 KV-Cache 后,每生成一个 token 只需新 token 的 query 对全部缓存 KV 打分,**单步** $O(L)$,生成 $L$ 个 token 累计 $O(L^2)$,但显存上 KV-Cache 随 $L$ **线性**增长(每层每头存一份历史 K、V),长上下文推理显存大头从注意力矩阵变成了 KV-Cache(见 [[102 KV-Cache|KV-Cache]])。
- **Q:KV-Cache 显存怎么估?** A:$2\times N\times L\times d\times B\times$ 字节数(2 因 K 和 V)。这是 MQA/GQA(见 005)要省的对象——减少 KV 头数直接按比例缩小它。
- **Q:为什么 FlashAttention 能精确还更快?** A:它不近似,只是把注意力分块在 SRAM 里用 online-softmax 算完即弃,不把 $L\times L$ 落地 HBM,减少 IO;算力仍 $O(L^2)$,但注意力 IO-bound,省 IO 就提速。
- **陷阱**:① 别把「上下文窗口短」全归咎于算力——常是**显存**先爆;② $O(L^2)$ 里的常数项含 $B\cdot h\cdot N$,实际显存要全乘上;③ KV-Cache 让推理时**算力**降到每步 $O(L)$,但缓存本身仍 $O(L)$ 线性增长(见 [[102 KV-Cache|KV-Cache]]);④ 别把 FlashAttention 说成"把复杂度降到 $O(L)$"——降的是显存,时间复杂度仍 $O(L^2)$。

## 关键事实

- 自注意力复杂度 $O(L^2 d)$ 时间、$O(L^2)$ 空间,出自原始 Transformer(Vaswani 等,NeurIPS 2017,arXiv:1706.03762)。
- FlashAttention(Dao 等,NeurIPS 2022,arXiv:2205.14135)指出注意力是 **IO-bound(显存读写受限)** 而非纯 compute-bound:分块 + 在 SRAM 重算,显存 $O(L)$、速度 2–4×、**无近似**;经验上 $L\gtrsim 8\text{k}$ 后注意力主导单层成本。
- 稀疏路线代表 BigBird(Zaheer 等,NeurIPS 2020,arXiv:2007.14062):局部 + 全局 + 随机,降到近线性。
- 线性路线代表 Linear Transformer(Katharopoulos 等,ICML 2020,arXiv:2006.16236)与 Performer(Choromanski 等,ICLR 2021,arXiv:2009.14794):核近似 + 结合律,$O(L)$。
- 关联:本质是 [[002 自注意力 Self-Attention|自注意力]]/[[006 注意力的矩阵形式与张量形状|矩阵形式]] 的代价分析;优化路线 [[025 FlashAttention(IO 感知精确注意力)|FlashAttention]]/[[022 稀疏注意力(BigBird、块稀疏)|稀疏]]/[[023 线性注意力(Linear Transformer、Performer)|线性]];推理侧的省算法是 [[102 KV-Cache|KV-Cache]]。
