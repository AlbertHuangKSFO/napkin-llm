[[031 RoPE 旋转位置编码(推导与实现)]]:把位置编码成「按位置角度旋转 query/key 二维子向量」的操作,使注意力内积只依赖相对距离——这就是 RoPE(Rotary Position Embedding,Su 2021,arXiv 2104.09864),今天几乎所有开源大模型(LLaMA、Qwen、Mistral)的标配。

## 直觉:不加,而是「转」

回顾 [[029 正弦余弦位置编码(推导)|正弦余弦编码]]:它把一段位置向量**加**到词向量上。问题是「加」很粗暴——位置信息和语义信息在同一个向量里混着,而且模型没法直接看到「两个词差几步」。

RoPE 换了个思路:**不加,而是旋转**。

- 把 query、key 向量两两分组,每组就是平面上的一个二维向量。
- 在位置 $m$ 的 token,把它的每个二维子向量**逆时针旋转一个角度 $m\theta$**;位置越靠后,转得越多。
- 旋转**不改变向量长度**,只改变方向 → 语义大小(范数)不被位置污染,这是相对 [[030 可学习与相对位置编码|加性编码]] 的第一个好处。

关键魔法在 [[002 自注意力 Self-Attention|自注意力]] 的内积里:位置 $m$ 的 query 转了 $m\theta$、位置 $n$ 的 key 转了 $n\theta$,两者做 [[03 点积、范数与相似度|点积]] 时,**绝对角度相减**,只剩 $(n-m)\theta$。于是注意力分数**天然只看相对位置**,而你从头到尾只对每个 token 做了「绝对」的旋转——绝对编码,相对效果。

**⚠️ 常见误区**:RoPE 常被归为「相对位置编码」,其实它对每个 token 施加的是**绝对**旋转($m\theta$ 只依赖该 token 自己的位置 $m$);「相对」只在两个向量做内积、绝对角度相减时才浮现。是「绝对操作 → 相对效果」,不是 T5 那种直接往打分加相对偏置。

## 例子:在 $d=4$ 上手算

设头维度 $d=4$,分成 2 个二维对:维度 $(0,1)$ 用频率 $\theta_0$,维度 $(2,3)$ 用频率 $\theta_1$。频率定义 $\theta_i = 10000^{-2i/d}$:

$$\theta_0 = 10000^{0} = 1,\qquad \theta_1 = 10000^{-2/4}=10000^{-0.5}=\frac{1}{100}=0.01$$

取一个向量 $x=(x_0,x_1,x_2,x_3)=(1,0,1,0)$,看它在位置 $m=0,1,2$ 分别被转成什么。

**旋转规则**(对第 $i$ 对,角度 $m\theta_i$):

$$\begin{pmatrix}x'_{2i}\\ x'_{2i+1}\end{pmatrix}=\begin{pmatrix}\cos m\theta_i & -\sin m\theta_i\\ \sin m\theta_i & \cos m\theta_i\end{pmatrix}\begin{pmatrix}x_{2i}\\ x_{2i+1}\end{pmatrix}$$

- **位置 $m=0$**:角度全 0,$\cos0=1,\sin0=0$ → $x'=(1,0,1,0)$,不变(第一个 token 不旋转)。
- **位置 $m=1$**:
  - 第 0 对角度 $1\cdot\theta_0=1\,\text{rad}\approx57.3°$:$\cos1=0.540,\sin1=0.841$。$(1,0)\to(0.540,\,0.841)$。
  - 第 1 对角度 $1\cdot\theta_1=0.01\,\text{rad}$:$\cos0.01\approx1.000,\sin0.01\approx0.010$。$(1,0)\to(1.000,\,0.010)$。
  - 得 $x'=(0.540,\,0.841,\,1.000,\,0.010)$。**高频对(第 0 对)转了 57°,低频对(第 1 对)几乎没动**——这正好对应图二。
- **位置 $m=2$**:第 0 对角度 $2\,\text{rad}\approx114.6°$,$(1,0)\to(\cos2,\sin2)=(-0.416,\,0.909)$;第 1 对角度 $0.02$,$(1,0)\to(1.000,\,0.020)$。

![[pos-rope-frequencies.png]]

**用上面的数验证"内积只看相对距离"。** 取同一个向量在两个位置当 query 和 key,只看第 0 对(高频, $\theta_0=1$)。设 $q$ 在位置 $m=3$、$k$ 在位置 $n=1$,二者旋转前都是 $(1,0)$:
- $q$ 转 $3\,\text{rad}$:$(\cos3,\sin3)=(-0.990,\,0.141)$。
- $k$ 转 $1\,\text{rad}$:$(\cos1,\sin1)=(0.540,\,0.841)$。
- 内积 $=(-0.990)(0.540)+(0.141)(0.841)=-0.535+0.119=-0.416$。

再换一对**相对距离相同**的位置:$q$ 在 $m=5$、$k$ 在 $n=3$(同样相距 $m-n=2$):
- $q$ 转 5:$(\cos5,\sin5)=(0.284,-0.959)$;$k$ 转 3:$(-0.990,0.141)$。
- 内积 $=(0.284)(-0.990)+(-0.959)(0.141)=-0.281-0.135=-0.416$。

**两组绝对位置不同,内积却都等于 $\cos(m-n)\cdot\theta_0=\cos2=-0.416$**——亲手验证了"分数只依赖相对距离 $m-n$,与绝对位置无关"。这就是 RoPE 的核心魔法在数字上的样子。

## 原理:相对位置如何「自然」浮现

把每两维拼成复数,RoPE 的旋转就是乘一个单位复数 $e^{im\theta_i}$。设位置 $m$ 的 query 子向量 $q$、位置 $n$ 的 key 子向量 $k$(都当复数):

$$f_q(q,m)=q\,e^{im\theta},\qquad f_k(k,n)=k\,e^{in\theta}$$

注意力内积取实部(复数内积 $\langle a,b\rangle=\mathrm{Re}(a\,\bar b)$):

$$\langle f_q(q,m),\,f_k(k,n)\rangle=\mathrm{Re}\!\left(q\,e^{im\theta}\cdot \overline{k\,e^{in\theta}}\right)=\mathrm{Re}\!\left(q\bar k\,e^{i(m-n)\theta}\right)$$

绝对位置 $m,n$ 只以差值 $m-n$ 出现 → **分数仅依赖相对距离**。写成实矩阵形式,旋转矩阵 $R_m$ 满足:

$$ (R_m q)^\top (R_n k) = q^\top R_m^\top R_n\, k = q^\top R_{n-m}\, k$$

这里用了旋转矩阵的性质 $R_m^\top R_n = R_{n-m}$(旋转 $m$ 的逆再旋转 $n$,等于净旋转 $n-m$)。

**长程衰减**:把所有频率对的贡献加起来,$\sum_i q_i\bar k_i e^{i(m-n)\theta_i}$ 在 $|m-n|$ 增大时因不同频率相位错开而**整体衰减**(类似 Abel 求和),意味着 RoPE 天然倾向「越远关注越弱」,符合语言的局部性先验。

**频率谱:谁管近、谁管远。** $\theta_i=10000^{-2i/d}$,$i=0$ 时 $\theta=1$(最高频,波长 $2\pi$),$i=d/2-1$ 时 $\theta\approx10^{-4}$(最低频,波长 $\approx2\pi\cdot10^4$)。高频对(小 $i$)相位转得快,**相邻两 token 的角度差大 → 负责区分近邻**;低频对(大 $i$)转得极慢,只在很长跨度上才积累出可分辨的相位差 → **负责长程位置**。这与 [[029 正弦余弦位置编码(推导)|正弦编码]] 同款几何频率谱,差别只是 RoPE 把它用作「旋转角」而非「相加的值」。理解这点是看懂 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|外推]]的前提:外推崩在低频维度进入「没见过的相位」,而高频维度负责的近邻分辨率一旦被插值压坏,文本就糊。

**为什么旋转保范数(不污染语义大小)。** 旋转矩阵 $R$ 正交($R^\top R=I$),故 $\|Rx\|=\|x\|$——RoPE 只转方向、不改长度。对比 [[029 正弦余弦位置编码(推导)|正弦]]/[[030 可学习与相对位置编码|可学习]]是把位置向量**加**进词向量,会改变向量范数、把位置信息混进「语义强度」里。RoPE 用旋转避开了这种污染,这是它的第二个结构优势。

## 代码:朴素 vs 高效实现

```python
import torch

# ❌ 错误/低效:用 Python 循环逐位置构造旋转矩阵,O(L·d²),且容易把维度配对搞错
def rope_bad(x, base=10000.0):
    L, d = x.shape
    out = torch.zeros_like(x)
    for m in range(L):
        for i in range(d // 2):
            theta = base ** (-2 * i / d)
            c, s = torch.cos(m * torch.tensor(theta)), torch.sin(m * torch.tensor(theta))
            a, b = x[m, 2*i], x[m, 2*i+1]      # 注意:这是「相邻配对」,需和下面 ✅ 的拆法一致
            out[m, 2*i]   = a * c - b * s
            out[m, 2*i+1] = a * s + b * c
    return out

# ✅ 向量化:预算 cos/sin,旋转 = x*cos + rotate_half(x)*sin,O(L·d),和 HuggingFace 一致
def rope_good(x, base=10000.0):
    L, d = x.shape
    i = torch.arange(0, d, 2).float()                 # 0,2,4,...
    theta = base ** (-i / d)                           # 每对的频率,(d/2,)
    pos = torch.arange(L).float()
    angles = torch.outer(pos, theta)                   # (L, d/2)
    cos = torch.repeat_interleave(angles.cos(), 2, 1)  # (L, d) 每个值复制成相邻两份
    sin = torch.repeat_interleave(angles.sin(), 2, 1)
    def rotate_half(t):                                # (x0,x1,x2,x3)->(-x1,x0,-x3,x2)
        t = t.view(L, d // 2, 2)
        t = torch.stack((-t[..., 1], t[..., 0]), dim=-1)
        return t.view(L, d)
    return x * cos + rotate_half(x) * sin

x = torch.randn(8, 4)
assert torch.allclose(rope_bad(x), rope_good(x), atol=1e-5)  # 两者数值一致
# 关键:RoPE 只作用在 q、k 上(注意力打分前),不碰 value,也不碰残差流
```

> 工程坑:HuggingFace 的 LLaMA 实现用的是「前后半配对」(把维度切成前 $d/2$ 和后 $d/2$ 旋转),而原论文是「相邻配对」。两种排列只是维度置换,等价,但**权重不能混用**——这就是为什么有些 RoPE 移植会悄悄出错。

## 面试高频

- **RoPE 凭什么比正弦编码好?** 三点:① 把绝对编码变成纯旋转,注意力内积**自动只依赖相对位置**;② 不污染向量范数(旋转保长);③ 天然长程衰减,且能配合 [[038 LLaMA 架构解剖|线性注意力]]。而正弦编码是「加」上去的,这些性质都没有。
- **RoPE 加在哪一步?** 加在 **q、k 上、注意力打分之前**;**不**加在 value、不加在残差流、不加在词嵌入。所以 KV-Cache 里缓存的是**已经旋转过的 k**。
- **为什么 RoPE 能外推但效果有限?** 训练长度内见过的相对距离 $(m-n)$ 都 OK;超出训练长度时,低频维度的相位进入「没见过的区间」,困惑度爆炸 → 引出 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|长度外推方法]]。
- **$\theta_i$ 怎么取的?** $\theta_i=10000^{-2i/d}$,和正弦编码同款几何频率谱,高维度对低频、低维度对高频。base=10000 是超参,调大 base 能缓解外推(见 NTK-aware)。
- **RoPE 会增加参数量吗?** 不会,纯函数式、零可学习参数(对比 [[030 可学习与相对位置编码|可学习位置编码]])。
- **RoPE 为什么要"成对"旋转、配对方式有几种?** 把 $d$ 维拆成 $d/2$ 个二维子平面,每对一个频率独立旋转。配对有两种等价排列:**相邻配对**(原论文:$(0,1),(2,3),\dots$)与**前后半配对**(HuggingFace LLaMA:$(0,d/2),(1,d/2+1),\dots$)。结果数值等价(只是维度置换),但**权重不能跨实现混用**,移植 checkpoint 时若配对方式不一致会悄悄出错。
- **KV-Cache 里缓存的是旋转前还是旋转后的 k?** 旋转后。RoPE 在算注意力前作用于 k,缓存的是已带位置的 k;所以扩窗/换频率时(见 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|外推]])需要用新频率重排或重算缓存,不能直接沿用旧 k。
- **RoPE 作用在 value 上吗?** 不。只作用 q、k(影响打分="看谁"),不碰 value(="取到什么内容")、不碰残差流、不碰词嵌入。这是常见判断题。
- **base=10000 调大调小各有什么效果?** 调大 base → 低频更低、长程相位变化更慢 → 外推更稳(NTK-aware 即调大 base);调小 → 高频成分更多、近邻分辨率更高但外推更差。base 是控制「频率谱铺多宽」的旋钮。
- **RoPE 高频维度负责什么、为什么外推要小心它?** 高频($i$ 小)管近邻分辨率,一旦被位置插值「一刀切」压缩,相邻 token 区分能力下降 → 文本变糊;所以 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|NTK/YaRN]]主张「高频少动、低频多缩」。

## 关键事实

- RoPE 出自 RoFormer(Su et al., 2021,arXiv 2104.09864),作者来自追一科技;论文证明了「旋转矩阵编码绝对位置 + 注意力中显式出现相对位置」这一构造。
- 频率 $\theta_i=10000^{-2i/d}$,$i=0,\dots,d/2-1$;旋转保范数,内积满足 $(R_mq)^\top(R_nk)=q^\top R_{n-m}k$。
- 被 LLaMA(2023)、PaLM、GPT-NeoX、Qwen、Mistral、DeepSeek 等几乎所有主流 [[011 Encoder-Decoder、Decoder-Only 与 Encoder-Only|decoder-only]] 模型采用,已是事实标准。
- 零额外参数;只作用于 q、k;KV-Cache 缓存旋转后的 key。
- 局限:超训练长度直接外推困惑度上升,需 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|插值/外推技术]] 修正。
