[[064 混合精度 FP16、BF16 与 FP8|混合精度 FP16、BF16 与 FP8]] 讲预训练里用低精度浮点(16 位甚至 8 位)做计算来省显存、加速,同时保留一份 FP32 主权重保精度。核心差异在**指数位(决定动态范围)和尾数位(决定精度)**怎么分配:FP16 范围窄需 **loss scaling** 防下溢,BF16 范围等同 FP32、训练更稳,FP8 更省但需精细缩放。

## 直觉

一个浮点数三段:**符号(1 位)+ 指数(决定能表示多大/多小,即动态范围)+ 尾数(决定有效数字位数,即精度)**。总位数有限,指数和尾数此消彼长:

- **FP16(E5M10)**:5 指数 + 10 尾数。精度尚可,但**指数只有 5 位 ⇒ 动态范围窄**(约 $6\times10^{-5}$ 到 $6.5\times10^{4}$)。训练里小梯度(如 $10^{-7}$)会**下溢成 0**、大值会溢出成 inf ⇒ 必须 **loss scaling**(整体放大梯度,抬进可表示区)。
- **BF16(E8M7)**:8 指数(**和 FP32 一样**)+ 7 尾数。牺牲精度换范围:动态范围 $\approx$ FP32($\sim10^{38}$),几乎不会上/下溢,**基本不需要 loss scaling、训练更稳**——这就是它在 LLM 预训练里取代 FP16 成默认的原因。代价是有效数字只剩 2~3 位十进制。
- **FP8**:两种格式。**E4M3**(4 指 3 尾,精度优先)适合前向的权重/激活;**E5M2**(5 指 2 尾,范围优先)适合反向的梯度。更省一半位宽、Tensor Core 更快,但必须配高精度累加 + 精细 per-tensor/block 缩放,门槛高。

混合精度的「混合」是指:**计算用低精度(快、省),但保留一份 FP32 主权重**累积更新,避免「大权重 + 小更新」时更新被尾数截断丢失。

一句话:**指数管范围、尾数管精度;FP16 省但范围窄要 loss scaling,BF16 范围足够最稳,FP8 最省但最难调**。

## 例子

**为什么 FP16 要 loss scaling**。某梯度 $g=2^{-20}\approx9.5\times10^{-7}$。

- FP16 能表示的最小正规数约 $6\times10^{-5}$ ⇒ $g$ **下溢成 0**,这层学不到东西。
- 做 loss scaling:`loss *= 1024`(即 $2^{10}$),反向后梯度也被放大 1024 倍 ⇒ $g\to 9.7\times10^{-4}$,稳稳落在 FP16 可表示区。
- `optimizer.step()` 前再把梯度 `/1024` 还原,更新量不变。
- **BF16** 下 $g=9.5\times10^{-7}$ 本就远在范围内($\geq10^{-38}$),完全不用 scaling。

**精度对比**:数 $1.0009766$。FP16(10 尾)能区分到约 $2^{-10}\approx10^{-3}$,勉强存住;BF16(7 尾)分辨率约 $2^{-7}\approx8\times10^{-3}$,会把它**舍成 $\approx1.0078$**——这就是 BF16 精度差的体现,但对深度网络的鲁棒训练通常无碍。

## 原理

一个规格化浮点数 $x = (-1)^s \cdot 2^{e-\text{bias}} \cdot (1.f)$,$e$ 为指数、$f$ 为尾数(小数部分)。

- **动态范围**由指数位数 $n_e$ 决定:可表示量级约 $2^{\pm 2^{\,n_e-1}}$。FP16 $n_e=5$ ⇒ 范围 $\sim2^{\pm15}$;BF16/FP32 $n_e=8$ ⇒ $\sim2^{\pm127}$。这就是 BF16 几乎不溢出的根本原因。
- **精度(机器精度 $\epsilon$)**由尾数位数 $n_m$ 决定:$\epsilon\approx2^{-n_m}$。FP16 $\epsilon\approx2^{-10}\approx10^{-3}$;BF16 $\epsilon\approx2^{-7}\approx8\times10^{-3}$。

| 格式 | 符号 | 指数 | 尾数 | 动态范围 | 是否需 loss scaling |
|---|---|---|---|---|---|
| FP32 | 1 | 8 | 23 | $\sim10^{38}$ | — |
| FP16 | 1 | 5 | 10 | $\sim10^{\pm5}$(窄) | **需要** |
| BF16 | 1 | 8 | 7 | $\sim10^{38}$(同 FP32) | 基本不需 |
| FP8 E4M3 | 1 | 4 | 3 | $\sim\pm448$ | 需 per-tensor 缩放 |
| FP8 E5M2 | 1 | 5 | 2 | $\sim\pm57344$ | 需 per-tensor 缩放 |

**动态 loss scaling**:维护缩放因子 $S$,`loss *= S` 后反向;若梯度出现 inf/nan(溢出)就**跳过本步并 $S\leftarrow S/2$**;若连续多步无溢出则 $S\leftarrow 2S$(缓慢上探),自动找到不下溢又不溢出的窗口。

**为何留 FP32 主权重**:更新 $\theta\leftarrow\theta-\eta g$ 时,若 $\theta$ 量级 $\sim1$、更新 $\sim10^{-5}$,BF16 的 7 尾数无法表示这么小的相对增量(被舍掉),更新「丢失」。把主权重存 FP32、只在前向/反向时转低精度计算,就能正确累积微小更新。

**「大权重 + 小更新被吞」的手算。** $\theta=1.0$(BF16,7 尾数,相对分辨率 $2^{-7}\approx0.0078$),更新 $-10^{-5}$。在 BF16 里 $1.0$ 的下一个可表示值是 $1.0078$,而 $1.0-10^{-5}=0.99999$ 落在 $1.0$ 和 $0.9922$ 之间、距 $1.0$ 仅 $10^{-5}\ll0.0078$,**舍入回 $1.0$ → 更新被完全吞掉**。FP32(23 尾数,分辨率 $\sim10^{-7}$)能存住 $0.99999$。结论:权重更新必须在 FP32 主权重上做,这与优化器状态 $m,v$ 也存 FP32 是一回事。

**loss scaling 跨步演示(动态调 $S$)。** 初始 $S=2^{16}=65536$:

- 第 1 步:梯度放大后某处溢出成 inf → **跳过本步**(不 step),$S\leftarrow S/2=32768$。
- 第 2 步:仍偶发 inf → 再减半 $S=16384$。
- 之后连续 2000 步无 inf → 上探 $S\leftarrow 2S$ 试着用更大缩放(争取抬起更小梯度)。
- 这样 $S$ 自动停在「不下溢又不溢出」的窗口里,无需手调。注意:**step 前必须把梯度 unscale($g/S$)再裁剪/更新**,否则裁剪阈值和实际更新量都被 $S$ 污染。

**TF32(Ampere 的隐形加速)。** A100+ 默认对 FP32 矩阵乘用 **TF32**(E8M10:范围同 FP32、尾数 10 位),几乎免改代码就把 matmul 提速,精度介于 FP32 与 FP16 之间。它不算「混合精度训练」主线,但解释了「为什么 A100 上不开 AMP 也比想象快」。

**哪些算子坚持 FP32(autocast 的白/黑名单)。** PyTorch `autocast` 会把 matmul/conv 等降到 BF16/FP16,但对**数值敏感**算子保留 FP32:softmax、LayerNorm/RMSNorm、loss 的 reduction(求和/求均值)、`exp`/`log`、注意力 logits 的 softmax 归一。原因:这些含 $\sum e^x$、除法、长链累加,低精度易溢出或精度塌缩。所以「混合」不止权重,还包括**算子级的精度分配**。

## 代码

```python
import torch
model = torch.nn.Linear(4096, 4096).cuda()
opt = torch.optim.AdamW(model.parameters(), lr=3e-4)

# ❌ 错误:用 FP16 autocast 却不开 GradScaler
#   小梯度下溢成 0,训练停滞甚至 loss 不降
def step_bad(x):
    with torch.autocast("cuda", dtype=torch.float16):
        loss = model(x).sum()
    loss.backward()          # FP16 小梯度已下溢
    opt.step(); opt.zero_grad()

# ✅ 正确(FP16):autocast + 动态 GradScaler 做 loss scaling
scaler = torch.cuda.amp.GradScaler()
def step_fp16(x):
    with torch.autocast("cuda", dtype=torch.float16):
        loss = model(x).sum()
    scaler.scale(loss).backward()        # 放大梯度,防下溢
    scaler.unscale_(opt)                 # 还原后再裁剪
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    scaler.step(opt)                     # 内部检测 inf/nan,溢出则跳过本步
    scaler.update()                      # 自动调整缩放因子 S
    opt.zero_grad()

# ✅ 更省心(BF16):范围等同 FP32,通常无需 GradScaler —— LLM 预训练首选
def step_bf16(x):
    with torch.autocast("cuda", dtype=torch.bfloat16):
        loss = model(x).sum()
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    opt.step(); opt.zero_grad()
```

```python
import numpy as np
# —— 三格式能否表示同一个小梯度 / 同一个精细数 ——
def fp_range(n_exp):                 # 规格化最小正数量级(近似)
    return 2.0 ** (-(2**(n_exp-1) - 2))
g = 2.0 ** -20                       # ≈9.5e-7,典型小梯度
print("FP16 最小正规数 ≈", fp_range(5), "→ 小梯度", g, "下溢成 0?", g < fp_range(5))
print("BF16 最小正规数 ≈", fp_range(8), "→ 小梯度下溢?", g < fp_range(8))  # 否,稳

# loss scaling 把梯度抬进 FP16 可表示区
for S in [1, 1024]:
    print(f"S={S}: 梯度 {g*S:.2e}  在FP16范围内?", g*S >= fp_range(5))

# —— 大权重+小更新被 BF16 吞掉(7 尾数) ——
theta, upd = np.float32(1.0), np.float32(-1e-5)
bf16_res = (theta + upd).astype(np.float32)        # numpy 无 bf16,用相对分辨率说明
print("BF16 分辨率 2^-7 =", 2**-7, "≫ |更新| 1e-5 → 舍回 1.0,更新丢失")
print("✅ 故主权重存 FP32(分辨率~1e-7),能累积 1e-5 的更新")
```

## 面试高频

- **FP16 和 BF16 区别?该选哪个?** 同 16 位,FP16 是 E5M10(精度高、范围窄)、BF16 是 E8M7(范围等同 FP32、精度低)。LLM 预训练首选 **BF16**:范围大、几乎不需 loss scaling、训练更稳;FP16 多见于推理或老硬件。
- **为什么 FP16 需要 loss scaling?** 小梯度($\sim10^{-7}$)在 FP16 下溢成 0,丢失信息;把 loss(进而梯度)整体放大 $S$ 倍抬进可表示区,step 前再 $/S$ 还原。动态 scaling 遇溢出减半、长期不溢出翻倍。
- **混合精度为什么要留 FP32 主权重?** 低精度尾数无法表示「大权重 + 微小更新」的相对增量,会把更新舍掉;FP32 主权重保证微小更新能正确累积。
- **FP8 两种格式怎么用?** E4M3(精度优先)用于前向权重/激活,E5M2(范围优先)用于反向梯度;需高精度累加 + per-tensor/block 缩放。
- **混合精度省了什么?** 激活/梯度显存减半、Tensor Core 算力翻倍;是 [[076 显存占用估算(参数、梯度、优化器、激活、KV)|显存]]与吞吐优化的基础。
- **混合精度为什么要留 FP32 主权重(手算)?** $\theta=1.0$ 时 BF16 相对分辨率 $2^{-7}\approx0.0078$,而更新 $-10^{-5}\ll0.0078$ 会被舍回 $1.0$、更新丢失;FP32 分辨率 $\sim10^{-7}$ 能存住。优化器状态 $m,v$ 也因此存 FP32。
- **bias/LayerNorm、softmax、loss 累加用什么精度?** 通常在 FP32 里算,避免数值不稳(autocast 自动对 softmax/LayerNorm/exp/log/reduction 这些升精度)。所以「混合」是算子级的精度分配,不止权重。
- **动态 loss scaling 怎么调 $S$?** 溢出(梯度出现 inf/nan)→ 跳过本步并 $S/2$;连续多步无溢出 → $S\times2$ 上探,自动停在不下溢又不溢出的窗口。**step 前先 unscale($g/S$)再裁剪**,否则阈值被污染。
- **TF32 是什么?** Ampere+ 默认对 FP32 matmul 用 TF32(E8M10,范围同 FP32、尾数 10 位),几乎免改代码加速;解释了 A100 不开 AMP 也较快。
- **DeepSeek-V3 的 FP8 训练怎么做?** 大部分 GEMM 用 FP8(E4M3 权重/激活、E5M2 梯度),配**细粒度量化**(per-tile/per-block 缩放)+ **高精度累加**(FP8 乘、FP32 累加),关键路径仍保 BF16/FP32,才把 FP8 误差控住。

## 关键事实

- 混合精度训练 + 动态 loss scaling 出自 Micikevicius et al.《Mixed Precision Training》(2017,arXiv:1710.03740,ICLR 2018)。
- 位宽:FP16=E5M10,BF16=E8M7(BF16 由 Google Brain 提出,指数位同 FP32),FP8=E4M3 / E5M2(OCP FP8 标准,NVIDIA Hopper Transformer Engine 支持)。
- BF16 动态范围 $\sim10^{38}$ 等同 FP32,故几乎不需 loss scaling;FP16 范围约 $6\times10^{-5}\sim6.5\times10^4$,必须 scaling。
- 现代 LLM 预训练(LLaMA、GPT 系、DeepSeek 等)普遍用 BF16;DeepSeek-V3(2024)进一步用 FP8 训练大部分计算(细粒度量化 + 高精度累加)。
- FP8 E4M3 最大值约 $448$、E5M2 约 $57344$;FP8 端到端训练需谨慎缩放,否则误差显著。
