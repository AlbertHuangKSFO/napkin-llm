[[098 FP8 训练推理与 AQLM 极低比特|FP8 训练推理与 AQLM 极低比特]] 讲两条更激进的低比特路线:**FP8**(E4M3、E5M2 两种 8 位浮点,H100 起 Tensor Core 原生支持)用于训练和推理,靠精细缩放在半位宽下保稳;**AQLM**(2024)用**多码本加性量化**把权重压到约 **2 bit/参数**,在极低比特区间精度领先逐元素量化。

## 直觉

**FP8** 是 [[064 混合精度 FP16、BF16 与 FP8|混合精度]]往下再走一步:把计算从 16 位降到 **8 位浮点**,显存再减半、Tensor Core 吞吐再翻倍。8 位太短,所以分两种"偏科"格式:

- **E4M3**(4 指数 + 3 尾数):**精度优先、范围窄**(最大 ±448),适合前向的**权重和激活**。
- **E5M2**(5 指数 + 2 尾数):**范围优先、精度低**(最大 ±57344),适合反向的**梯度**(梯度量级跨度大,要范围)。

8 位动态范围窄,直接用必溢出/下溢,所以 FP8 训练必须配**精细缩放**(per-tensor 或 per-block scale)+ **高精度累加**(矩阵乘的累加器仍用 FP32)。

**为什么不像 int8 那样用整数,而要浮点?** int8 是**等距**格点,动态范围只有 256 倍($\pm127$);深度学习的张量(尤其梯度)动态范围跨多个数量级,等距格点要么大值溢出要么小值全下溢成 0。FP8 是**浮点**:指数位给它**指数级的动态范围**(E5M2 能表示到 $\pm57344$),尾数位在每个量级内提供相对精度——所以同样 8 bit,浮点远比整数适合「范围大、要相对精度」的训练数值。这就是训练用 FP8(浮点)、而部署压权重常用 int4(整数 + 校准)的根本分工。

**AQLM** 走另一条极端:**不再逐个权重量化**,而是把一段权重看成一个向量,用**几个小码本里的码字相加**来逼近它。每个权重只需存"用了哪几个码字"的小索引,平摊下来约 **2 bit/参数**。类比:不存 16 位实数,而存"用哪几块乐高拼出来",拼图本(码本)很小、可全网共享。这让 2-bit 这种极端压缩也能保住精度。

## 例子

**FP8 范围对比**。梯度 $g$ 在反向里可能从 $10^{-4}$ 到 $10^{4}$ 横跨多个量级:

- 用 **E4M3**(max ±448):大梯度 $5000$ 直接**溢出**成饱和值 → 信息丢失。
- 用 **E5M2**(max ±57344):$5000$ 在范围内,但尾数只 2 位,精度粗 → 可接受,因为梯度本来就只需大致方向。
- 所以**前向权重/激活用 E4M3(要精度)、反向梯度用 E5M2(要范围)**。再配 per-tensor scale,把每个张量整体缩放进 FP8 的"舒适区"。

**AQLM 位宽账**。设一段权重向量,用 **2 个码本**、每个码本 256 个码字。选码字只需 `log2(256)=8 bit` 索引,2 个码本共 16 bit。若这段覆盖 8 个权重,则平摊 `16/8 = 2 bit/参数`。码本本身(几百个 FP16 向量)在整个矩阵/层间**共享**,平摊到每个权重几乎为 0。

## 原理

**FP8 格式**(沿用 [[064 混合精度 FP16、BF16 与 FP8|浮点三段式]] $x=(-1)^s 2^{e-\text{bias}}(1.f)$):

| 格式 | 符号 | 指数 | 尾数 | 最大值 | 典型用途 |
|---|---|---|---|---|---|
| E4M3 | 1 | 4 | 3 | $\pm448$ | 前向权重、激活(精度优先) |
| E5M2 | 1 | 5 | 2 | $\pm57344$ | 反向梯度(范围优先) |

**per-tensor 缩放 + 高精度累加**。对张量 $X$ 取缩放 $s=\dfrac{\text{FP8}_{\max}}{\max|X|}$,量化 $\hat X=\text{round}_{\text{FP8}}(sX)$;矩阵乘 $C=\hat A\hat B$ 的**累加器仍用 FP32**,最后乘回 $\frac1{s_As_B}$。NVIDIA Transformer Engine 维护**延迟缩放(delayed scaling)**:用历史若干步的 amax 估计当前 scale,避免每步同步开销。DeepSeek-V3(2024)进一步用**细粒度块量化**(如对激活 1×128、对权重 128×128 分块各自 scale)做大规模 FP8 训练。

**为什么累加器必须 FP32(关键易错点)**。矩阵乘是把上千个 FP8 乘积**连加**;FP8 尾数只有 2~3 位,若用 FP8 累加,每加一项就舍入一次,几千次累加的舍入误差会**滚雪球**(连小数都加不进大的 partial sum,即「吞掉」现象),结果完全失真。所以 FP8 只用在**乘法的输入**(省显存/吃 FP8 Tensor Core),**累加在 FP32 寄存器里做**,算完再缩放回去。这就是「FP8 矩阵乘」实际是「FP8 输入 × FP8 输入 → FP32 累加」的混合精度套路,和 [[064 混合精度 FP16、BF16 与 FP8|FP16/BF16 混合精度]] 一脉相承。

**延迟缩放为什么必要**。理想的 per-tensor scale 要用当前张量的 amax,但 amax 要等张量算完才知道——会在前向中引入一次全张量归约和同步,拖慢训练。延迟缩放用**前几步的 amax 历史**预测当前 scale(假设统计量平稳),避免每步同步;偶尔预测过小导致溢出时再回退处理。这是 FP8 训练能不掉吞吐的工程关键。

**AQLM 加性量化**。把权重矩阵按行分成长度 $d$ 的子向量 $w$。用 $M$ 个码本 $C_1,\dots,C_M$(每个含 $2^b$ 个 $d$ 维码字),把 $w$ 近似为各码本各取一个码字之**和**:

$$
w \approx \sum_{m=1}^{M} C_m[\,i_m\,],\qquad i_m\in\{0,\dots,2^b-1\}
$$

每个子向量只存 $M$ 个索引,共 $M\cdot b$ 比特;平摊到每权重位宽 $\approx \dfrac{M\cdot b}{d}$。AQLM 的关键是:① **输入自适应**地学码本(用校准数据最小化 $\|WX-\hat WX\|$ 而非 $\|W-\hat W\|$,和 [[095 GPTQ|GPTQ]] 一样盯输出而非权重);② **跨 Transformer 块联合优化**码本参数。这使它在 $<3$ bit、尤其 **2-bit** 区间成为精度-体积的 Pareto 最优,远好于逐元素 round-to-nearest。

**为什么「加性多码本」比「逐元素量化」在极低比特下强**。逐元素量化(int2、NF2)给每个权重独立分配 2 bit,只有 4 个可选值,表达力极弱;而 AQLM 把一段 $d$ 个权重当**整体**,用 $M$ 个码本各取一个码字相加来逼近——$M=2$、每码本 256 码字时,可表达的组合是 $256^2=65536$ 种**向量级**模式,远比「每个权重 4 选 1」丰富,却仍只花 $2\times8=16$ bit/段。本质是**把比特预算花在「向量级模式」而非「逐元素幅值」上**,利用了权重间的相关性。代价:编码(选码字)是 NP-hard 的组合优化,AQLM 用贪心/束搜索 + 码本梯度更新近似求解,量化过程比 GPTQ 更慢更重。

## 代码

```python
import numpy as np

# ---- FP8:per-tensor 缩放 + FP32 累加(示意 E4M3 的有限范围)----
FP8_E4M3_MAX = 448.0
def to_fp8_e4m3_sim(x):
    s = FP8_E4M3_MAX / (np.abs(x).max() + 1e-8)     # 缩放进 [-448,448]
    xq = np.clip(np.round(x * s * 8) / 8, -FP8_E4M3_MAX, FP8_E4M3_MAX)  # 3 尾数≈步长 1/8
    return xq, s

# ❌ 错误:不缩放直接截到 FP8 —— 大值溢出、小值下溢成 0
def matmul_fp8_bad(A, B):
    Aq = np.clip(A, -448, 448); Bq = np.clip(B, -448, 448)
    return (Aq @ Bq).astype(np.float32)             # 多数信息已丢

# ✅ 正确:各自 per-tensor 缩放,FP32 累加,最后还原
def matmul_fp8_ok(A, B):
    Aq, sa = to_fp8_e4m3_sim(A)
    Bq, sb = to_fp8_e4m3_sim(B)
    C = (Aq @ Bq).astype(np.float32)                # 累加器 FP32
    return C / (sa * sb)                            # 还原真实尺度

# ---- AQLM:2 码本加性量化(玩具版,贪心选码字)----
def aqlm_encode(w, codebooks):                      # w:(d,)  codebooks: M 个 (K,d)
    residual, idxs = w.copy(), []
    for C in codebooks:                             # 逐码本吃掉残差
        j = np.argmin(((C - residual) ** 2).sum(1)) # 选最接近残差的码字
        idxs.append(j); residual = residual - C[j]
    return idxs                                     # 只存 M 个小索引

def aqlm_decode(idxs, codebooks):
    return sum(C[j] for j, C in zip(idxs, codebooks))   # 码字相加还原

d, K, M = 16, 256, 2
codebooks = [np.random.randn(K, d) * 0.1 for _ in range(M)]
w = np.random.randn(d) * 0.1
rec = aqlm_decode(aqlm_encode(w, codebooks), codebooks)
print("AQLM 重构误差:", np.abs(w - rec).mean(), "  存储:", M, "个 8-bit 索引")
```

## 面试高频

- **FP8 两种格式怎么分工?为什么?** E4M3(精度优先,max 448)用于前向权重/激活;E5M2(范围优先,max 57344)用于反向梯度——梯度量级跨度大需要范围,前向需要精度。
- **FP8 训练为什么必须缩放?** 8 位动态范围很窄,不缩放就大值溢出、小值下溢;用 per-tensor/块 scale 把张量挪进 FP8 舒适区,且累加器保 FP32 防误差累积。
- **FP8 相比 BF16 省了什么?有何风险?** 显存再减半、Tensor Core 吞吐再翻倍;风险是数值更敏感,需精细缩放策略(延迟缩放/块量化),否则训练发散。见 [[064 混合精度 FP16、BF16 与 FP8|混合精度]]。
- **AQLM 凭什么 2-bit 还能保精度?** 不逐元素量化,而用多码本码字之**和**逼近权重子向量,索引很小;再用校准数据**输入自适应**学码本、跨块联合优化,极低比特下误差远小于 round-to-nearest。
- **AQLM 的位宽怎么算?** $\approx M\cdot b / d$($M$ 码本数、$b$ 每索引位数、$d$ 子向量长度);码本本身共享,平摊≈0。
- **FP8 量化和 AQLM 量化目标一样吗?** 不一样。FP8 是降**计算精度**(训练+推理都用),AQLM 是压**存储位宽**(主要为推理省显存/带宽)。和 [[097 NF4 与 QLoRA 4-bit|NF4]]、[[096 AWQ 与 SmoothQuant|AWQ]] 一样属权重压缩家族。
- **FP8 为什么用浮点不用 int8?** 张量(尤其梯度)动态范围跨多个量级,int8 等距格点(范围仅 256 倍)会大值溢出/小值下溢;FP8 的指数位给指数级范围、尾数位给相对精度,同 8 bit 远比整数适合训练数值。
- **FP8 矩阵乘的累加器为什么必须 FP32?** FP8 尾数只 2~3 位,几千项连加若用 FP8 累加,舍入误差滚雪球、小项被大 partial sum 吞掉,结果失真。故输入 FP8、累加 FP32,是混合精度套路。
- **延迟缩放(delayed scaling)解决什么?** 用当前张量 amax 定 scale 需算完才知道、引入同步开销;延迟缩放用前几步 amax 历史预测当前 scale,避免每步同步,偶尔溢出再回退。是 FP8 训练不掉吞吐的关键。
- **AQLM 凭什么 2-bit 不崩,逐元素 int2 会崩?** int2 每权重只 4 个值、表达力极弱;AQLM 把一段权重当整体,用多码本码字之和表达 $256^M$ 种向量级模式,利用权重相关性,同样比特预算下表达力高几个数量级。代价是编码是组合优化、量化慢。
- **AQLM 和 GPTQ 优化目标一样吗?** 都最小化 $\|WX-\hat WX\|$(盯输出而非权重),用校准数据;但 GPTQ 是逐元素 int4 + 二阶补偿,AQLM 是多码本加性量化 + 跨块联合优化,后者把可用区间下探到 2 bit。

## 关键事实

- FP8 两格式:**E4M3**(最大 ±448)、**E5M2**(最大 ±57344);属 OCP FP8 标准,**NVIDIA Hopper(H100)起 Tensor Core 原生支持**,由 Transformer Engine 实现延迟缩放。
- FP8 训练需 per-tensor/块缩放 + FP32 累加;**DeepSeek-V3**(2024)用细粒度块量化做大规模 FP8 训练,是公开的大模型 FP8 训练代表。
- AQLM 出自 Egiazarian, Panferov, Kuznedelev, Frantar, Babenko, Alistarh《Extreme Compression of Large Language Models via Additive Quantization》(2024,arXiv:2401.06118),2024 年 2 月开源并入 HuggingFace。
- AQLM 是首个在 **<3 bit 区间 Pareto 最优**、并在 **2-bit 极端压缩**上显著超越已有方案的方法;源自多码本量化(MCQ)家族。
- 与 [[097 NF4 与 QLoRA 4-bit|NF4(4-bit)]]、[[096 AWQ 与 SmoothQuant|AWQ]] 对比:NF4/AWQ 多在 3–4 bit,AQLM 把可用区间下探到 2 bit;FP8 则同时服务训练与推理。
