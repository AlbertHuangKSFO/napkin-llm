[[032 RoPE 外推：NTK-aware、位置插值、YaRN]]:一组在不重训(或极少微调)的前提下,把 [[031 RoPE 旋转位置编码(推导与实现)|RoPE]] 模型的上下文窗口从训练长度扩到几倍乃至几十倍的方法——位置插值 PI、NTK-aware、YaRN 是其中最常考的三个。

## 直觉:外推为什么会崩

RoPE 把位置 $m$ 编码成旋转角度 $m\theta_i$。模型只在 $m\le L_\text{train}$ 的位置组合上优化过；推理超出这个长度时，虽有些单维相位会周期性重现，**多频相对相位、注意力模式和任务分布**仍可能落在训练外，质量可能下降。它是需要实测的外推风险，不是“某一个频段必然溢出”或“相位从未出现就必然崩”的数学定理。

三类修法都在改变长位置的频率谱或注意力尺度，以降低训练外失配；它们**不保证把所有维度的相位都送回训练区间**：

1. **位置插值 PI**:把所有位置等比例缩小($m\to m/s$),硬把 8k 压回 2k 的角度范围。所有频率一刀切。
2. **NTK-aware**:不缩位置,而是改频率基数 base，因而**高频少动、低频多缩**；其中最高频 $\theta_0=1$ 恰好完全不变。它可作为零训练启发式，但质量仍须验证。
3. **YaRN**:按波长把维度分三段精细处理(NTK-by-parts),再叠加注意力温度缩放,微调极少数据即达 SOTA。

## 例子:把 2k 扩到 8k(缩放因子 $s=4$)

设训练长度 $L=2048$,目标 $L'=8192$,$s=L'/L=4$。看位置 $m=4000$ 怎么被各方法处理。

**① 直接外推**:角度 $4000\cdot\theta_i$。最高频 $\theta_0=1$ 的角度为 $4000\,\text{rad}$，已对应训练外的位置；不过角度按 $2\pi$ 周期旋转，不能仅凭“数值大于 2048”断言它完全陌生或必然失败。风险来自整个频率组合与模型行为没有在该长度被训练/验证。

**② 位置插值 PI**:位置改成 $m'=m/s=4000/4=1000$,角度 $=1000\cdot\theta_i$,全部落进 $[0,2048]$ 训练区间。代价:相邻两 token 的角度差从 $\theta_i$ 缩到 $\theta_i/4$,**近邻分辨率掉到 1/4**,所以需要几百步微调找回。

**③ NTK-aware**:不动位置,把 base 从 10000 调大到 $\text{base}'=\text{base}\cdot s^{d/(d-2)}\approx 10000\cdot 4^{1.03}$。效果是:
- 高频维度($i$ 小):频率少变；严格地说 $i=0$ 时 $\theta_0=1$ **完全不变**，因此其 $4000\,\text{rad}$ 相位不会被压回训练位置范围。
- 低频维度($i$ 大):频率被显著压低，长距离变化较慢。
- 这是保留局部相位同时压缩部分长程谱的启发式；可不微调试用，但不能由此推出“免微调必然可用”。

![[pos-ntk-yarn-spectrum.png]]

**逐维对比 PI vs NTK 在同一位置的角度($d=64,s=4$)。** 看最高频 $\theta_0=1$ 与最低频 $\theta_{31}=10000^{-62/64}\approx1.3\times10^{-4}$,在位置 $m=4000$:
- **直接外推**:高频角度 $4000\times1=4000\,\text{rad}$，低频为 $4000\times1.3\times10^{-4}=0.52\,\text{rad}$。它们都属于训练外**位置组合**；不能只据某个单维角度或其是否绕回 $2\pi$ 判断成败。
- **PI**($m\to m/4=1000$):高频 $1000\times1=1000\,\text{rad}$(落回训练区间 ✓),但相邻 token 角度差从 $1$ 缩到 $0.25\,\text{rad}$——**近邻分辨率掉到 1/4**,所以要微调找回。低频 $1000\times1.3\times10^{-4}=0.13$。
- **NTK**(base 调大约 $4.1\times$,高频少缩、低频约缩 4 倍):最高频角度仍是 $4000\,\text{rad}$，并**没有**被拉回训练范围；低频角度被压缩。它试图保留局部相位分辨率、缓和部分长程频段失配，效果只能由目标模型、长度和任务的评测确认。

一句话:**PI 高频低频一起缩(简单，通常需适配训练)；NTK 高频少动、低频多缩(保留部分局部相位)，两者都是经验策略，不应写成免微调或必然成功的保证。**

## 原理:从 PI 到 YaRN

**位置插值 PI**(Chen et al., 2023,arXiv 2306.15595)。把位置缩放因子 $s=L'/L$ 直接作用在位置上:

$$\theta_i\, m \;\longrightarrow\; \theta_i\,\frac{m}{s}$$

等价于所有频率统一缩 $1/s$。简单但**高频也被压**,丢分辨率,需短微调(论文 LLaMA-7B 仅 1000 步即扩到 32k)。

**NTK-aware**(bloc97,2023,社区提出)。洞见:PI 对高频太狠。改成调 base,让缩放在频率谱上**非均匀分布**——按维度索引插值压力递增:

$$\theta'_i=\big(\text{base}\cdot s^{\frac{d}{d-2}}\big)^{-2i/d}$$

高频($i\approx0$)几乎不变，且 $i=0$ 时严格不变；低频($i\approx d/2$)被压最多。它借用了 NTK 相关的频谱直觉，但社区的 NTK-aware RoPE 是工程启发式，并非一条足以推出泛化保证的定理；需要与模型权重、训练长度和目标任务一起评测。

**YaRN**(Peng et al., 2023,arXiv 2309.00071)= NTK-by-parts + 温度缩放,两个改进叠加:

- **NTK-by-parts**:按维度的**波长**分三段。设维度 $i$ 的波长 $\lambda_i=2\pi/\theta_i$,与上下文长度比 $r_i=L/\lambda_i$:
- $r_i$ 大(高频,波长 $\ll$ 上下文):**完全不插值**,保原频率；所以这些维度的长位置相位并没有“回到训练范围”；
  - $r_i$ 小(低频,波长 $\gg$ 上下文):**完全 PI 插值**($\times 1/s$);
  - 中间:线性过渡。比 NTK 的连续缩放更精准。
- **注意力温度缩放**:长度变大后,softmax 前给 logits 乘一个 $\frac1t$($t$ 随 $s$ 增):

$$\text{softmax}\!\left(\frac{q^\top k}{t\sqrt d}\right),\quad \sqrt{\frac1t}=0.1\ln s+1$$

用于校准长序列下的注意力尺度。YaRN 论文在其 LLaMA 实验中报告相较此前方法使用更少 tokens/训练步数；这不是不同模型、长度或数据上的通用质量保证。其 RoPE 变换可与 [[107 长上下文推理：YaRN、位置插值与 StreamingLLM|长上下文推理]] 的注意力内核配合，但需确保 prefill 与 KV-Cache 使用同一套频率参数。

> 推理时这些都改了「注意力打分」,所以也连到 [[032 RoPE 外推：NTK-aware、位置插值、YaRN]] 与 KV-Cache 的交互:缓存的是旋转后的 k,扩窗后要用新频率重算或重排。

## 代码:PI 与 NTK-aware 的频率表对比

```python
import torch

def rope_freqs(d, base=10000.0):
    i = torch.arange(0, d, 2).float()
    return base ** (-i / d)          # 原始频率谱 (d/2,)

# ❌ 误区:以为「扩窗口」只改 max_position 就能保证质量 —— 这只是直接外推，必须实测
def extend_naive(d, new_len):
    return rope_freqs(d)             # 频率没变,长位置进入陌生相位

# ✅ 位置插值 PI:训练长度 L,目标 L'，位置整体除以 s（= 频率乘 1/s 等价实现）
def extend_pi(d, L, L_new):
    s = L_new / L
    return rope_freqs(d) / s         # 所有频率统一缩，简单但高频也被砍

# ✅ NTK-aware：调 base；最高频严格不变，低频被压，属于待评测的启发式
def extend_ntk(d, L, L_new):
    s = L_new / L
    new_base = 10000.0 * (s ** (d / (d - 2)))
    return rope_freqs(d, base=new_base)

d = 64
print("原始 高/低频:", rope_freqs(d)[0].item(), rope_freqs(d)[-1].item())
print("PI    高/低频:", extend_pi(d, 2048, 8192)[0].item(), extend_pi(d, 2048, 8192)[-1].item())
print("NTK   高/低频:", extend_ntk(d, 2048, 8192)[0].item(), extend_ntk(d, 2048, 8192)[-1].item())
# 观察：PI 把高频也缩了 4 倍；NTK 的第一个频率严格为 1、低频缩得更多。
# 这说明频谱差异，不构成任何模型“免微调可用”的证明。
```

## 选型卡:扩窗方法怎么挑

| 场景 | 选什么 | 为什么 |
|---|---|---|
| 完全不能微调、要先试运行 | NTK-aware / 动态 NTK | 改 base 即可，保留高频、压缩低频；先用目标长度回归测试和任务集验收 |
| 能做适配训练、扩到几倍 | 位置插值 PI | 统一缩放位置，实现最简；用训练内与训练外任务共同检查局部能力和长上下文能力 |
| 有长上下文训练预算 | **YaRN**(NTK-by-parts + 温度缩放) | 分频段处理并校准尺度；按论文/实现参数复现后再与 PI、原模型做同任务对照 |
| 训练阶段评估不同位置方案 | [[033 ALiBi 与 NoPE\|ALiBi]] | 可作为对照方案；长度外推与精确检索并无跨模型的普适排序 |

> 仅对 RoPE 模型有效;扩窗后缓存的旋转 k 需按新频率重排/重算,别直接沿用旧 KV。

## 面试高频

- **直接外推为什么可能降质?** 训练外位置带来未优化过的多频相对相位与注意力模式；单维相位会周期回绕，不能用“某频率超过训练最大角度”代替评测结论。应报告模型、原/目标长度、任务和指标。
- **PI 和 NTK-aware 的核心区别?** PI 对**所有频率均匀**缩 $1/s$；NTK-aware 调 base 做**非均匀**缩放，其中最高频 $\theta_0=1$ 不变、低频缩得更多。两者都需要在目标模型上验证。
- **YaRN 比 NTK 多了什么?** ① NTK-by-parts(按波长分三段而非连续缩放);② 注意力温度缩放(补偿长序列 softmax 变平)。微调数据 < 0.1%,达 SOTA。
- **为什么常少动高频?** 高频承载更细的局部相位差；不均匀缩放试图避免把所有局部差异一起压小。这是频谱设计动机，不能替代模型级证据。
- **这些方法要重训吗?** 都可被实现为推理时变换；PI、YaRN 通常配合适配训练，NTK-aware 常被零训练尝试。是否足够取决于模型、目标长度和任务，不能承诺固定步数或固定数据比例。
- **YaRN 的温度缩放在补偿什么?** 序列变长 → 注意力要分到更多 key → softmax 分布变平、熵升高,削弱了"聚焦"。给 logits 乘 $1/t$($\sqrt{1/t}=0.1\ln s+1$)把分布重新锐化,几乎零成本地抵消这个副作用。
- **和 [[033 ALiBi 与 NoPE|ALiBi]] 比,谁外推更省心?** ALiBi 可在任意长度直接计算其线性偏置，RoPE 可用 PI/NTK/YaRN 改频谱；两者的任务质量、长上下文检索和短上下文回归都应在相同模型规模与数据条件下比较，不能给出普适胜负。
- **"动态 NTK"是什么?** 推理时按当前实际序列长动态调 base(序列越长 base 越大),短序列时几乎不改、长序列才介入,兼顾短长两端、常用于推理框架的即插即用扩窗。
- **扩窗后 KV-Cache 要怎么处理?** 缓存的是旋转后的 k,换了频率/缩放就得用新参数重排或重算缓存的 k,不能直接沿用旧值——这是工程上接外推方案时的高频坑。

## 关键事实

- 位置插值 PI:Chen et al., 2023(Meta),arXiv:2306.15595；论文在 LLaMA 系实验中以至多 1000 步微调把上下文扩到 32k。这是该论文设置下的实验事实。
- NTK-aware:社区开发者 bloc97 于 2023 在 Reddit/LocalLLaMA 提出,核心是调 RoPE base 做非均匀频率缩放,无正式论文但被 YaRN 形式化。
- 位置插值的并行独立工作还有 kaiokendev(2023)的 SuperHOT。
- YaRN:Peng、Quesnelle、Fan、Shippole,2023,arXiv:2309.00071；= NTK-by-parts + 注意力温度缩放。论文报告相对既有方法使用更少 tokens/训练步数的实验结果；迁移到其他模型时应复测。
- 共同前提:只对 RoPE 模型有效(改频率/位置);均作用于注意力打分阶段,与 [[107 长上下文推理：YaRN、位置插值与 StreamingLLM|长上下文推理]] 的其他技术(StreamingLLM 等)互补。
