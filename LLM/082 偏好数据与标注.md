[[082 偏好数据与标注]]:偏好数据是同一 prompt 下「**这个回答比那个好**」的成对标注(chosen ≻ rejected),由标注员对模型采样的 K 个回答**排序**得到,是训练 [[083 奖励模型 RM|奖励模型]] 与 [[086 DPO 直接偏好优化(推导)|DPO]] 的原料;其核心难点是**标注一致性**——它决定了对齐效果的上限。

## 直觉:人不会写满分答案,但会比较

让标注员**从零写**一个完美回答,既慢又难,而且「完美」没有统一标准。但让他**比较**两个回答「哪个更好」,又快又稳——这是人类判断的强项。偏好数据就建立在这个洞察上:**不要绝对分,要相对序**。

所以收集流程是:同一个 prompt,让 [[081 指令微调 SFT 与数据构造|SFT 模型]] 采样出 K 个不同回答,标注员把它们**排个序**,再把排序拆成一堆**两两偏好对**。每个对长这样:

$$
(x,\ y_w,\ y_l)\quad\text{即}\quad (\text{prompt},\ \text{chosen 好},\ \text{rejected 坏})
$$

`w`=winning(chosen),`l`=losing(rejected)。这就是 RM 和 DPO 唯一吃的「燃料」。

## 例子:一次排序拆成多少个对(小数字)

prompt:`「解释一下黑洞」`,SFT 模型采样 K=3 个回答,标注员排序为 **A > B > C**(A 清晰准确,B 啰嗦,C 有错):

拆成 $\binom{3}{2}=3$ 个偏好对:

| 偏好对 | chosen | rejected |
|---|---|---|
| (A ≻ B) | A | B |
| (A ≻ C) | A | C |
| (B ≻ C) | B | C |

一次排序就产出 3 条训练样本——这是为什么 InstructGPT 用「排序 K 个」而非「成对二选一」:**信息密度更高**($\binom{K}{2}$ 个对来自 1 次标注)。InstructGPT 用 K=4~9。

注意一个工程坑:同一 prompt 拆出的这 $\binom{K}{2}$ 个对**要放进同一个 batch** 一起训 RM。否则同一个回答的编码在不同 batch 里被重复算、且梯度被 batch 间扰动,**容易过拟合**(InstructGPT 论文明确指出这点)。

## 原理:为什么排序优于打分,以及一致性是上限

**1)排序 vs 绝对打分**。如果让人给每个回答打 1~10 分,问题是**分数不可比、不稳定**:同一个回答今天打 7、明天打 6;不同标注员的「7 分」含义不同。而**相对排序**只问「A 和 B 谁好」,把绝对刻度的噪声消掉了。这也是为什么 RM 学的是**差值** $r(y_w)-r(y_l)$(见 [[083 奖励模型 RM|RM]] 的 Bradley-Terry),而非绝对分。

**2)一致性(agreement)是天花板**。偏好本身有主观性。设两个标注员对同一对的判断一致率为 $p_{\text{agree}}$,那么数据里就有约 $1-p_{\text{agree}}$ 的「标签噪声」。RM 再强,也**学不过这个噪声上限**——它能达到的「预测人类偏好」准确率不会超过人和人之间的一致率。InstructGPT 测得标注员**组间一致约 72~77%**,这就是对齐质量的硬上限。

降噪手段:
- **详尽的标注指南**(rubric):明确「有用、真实、无害」怎么权衡、遇到拒答怎么判。
- **标注员校准**:用金标样本(golden set)测每个人,踢掉离群者,统计研究者-标注员一致率。
- **聚合多标注**:同一对让多人标,取多数票或建模标注员偏置。

**3)偏好的维度冲突**。「有用」和「无害」常打架(详细回答危险问题 = 有用但有害)。标注指南要给**优先级**,否则数据自相矛盾,RM 学出来精神分裂。

## ④ on-policy 偏好:为什么回答要"自己采"

一个反直觉但关键的点:偏好数据里的两个回答**最好由当前要对齐的 SFT 模型自己采样**(on-policy),而非从别处搜罗(off-policy)。原因:
- RM 要在**策略实际会生成的分布**上准确——若偏好对都是"人写的好答案 vs 人写的坏答案",RM 学会区分人类文本,但 PPO 阶段策略生成的是**模型分布**的文本,RM 在那上面可能失准(分布漂移)。
- 所以 InstructGPT 流程是:SFT 模型对每个 prompt **采样 K 个**,人对这 K 个模型自己的输出排序。这样 RM 见的就是策略分布,PPO 时不脱靶。
- **迭代式对齐**(Llama-2 的多轮):每轮用更新后的策略重新采样、重新标注、重训 RM——因为策略变了,旧偏好数据(旧策略采的)逐渐 off-policy 失效。这是"为什么 RLHF 要做好几轮"的答案。

## ⑤ 标注协议、一致率与 Cohen's κ

**point-wise 打分 vs pair-wise 比较**:
- point-wise(给单个回答打 1-7 分):简单但尺度噪声大、标注员间不可比(③ 已述)。
- pair-wise(A vs B 谁好):稳、信息密度高,主流。还有 **K-wise 排序**(一次排 K 个,拆 $\binom K2$ 对)。

**一致率怎么量化**:简单一致率 $p_{\text{agree}}$ 会被"瞎猜也有 50% 撞对"夸大。更严谨用 **Cohen's κ**(扣除随机一致后的净一致):
$$\kappa=\frac{p_{\text{agree}}-p_{\text{chance}}}{1-p_{\text{chance}}}.$$
$\kappa$=0 等于瞎猜,$\kappa$=1 完美一致;偏好标注的 κ 常在 0.4-0.6(中等),反映这活儿确实主观。InstructGPT 报的 72-77% 是原始一致率,扣除随机后更低——这进一步压低了 RM 的准确率上限。

## ⑥ 偏置的实证:不只是长度

偏好数据里藏着多种**虚假相关**,RM 会学错(Goodhart):
- **长度偏置**:标注员倾向选长答案(看起来更详尽),RM 学成"长=好",PPO 后模型啰嗦。缓解:长度归一化奖励、长度匹配配对、DPO 加长度正则、或显式 length penalty。
- **位置偏置**:成对展示时标注员/AI 评委倾向选**先出现**的那个(A vs B 里偏 A)。缓解:随机交换 A/B 顺序、双向各标一次取平均。
- **格式/markdown 偏置**:带列表、加粗、emoji 的看起来"更专业",未必内容更好。
- **谄媚(sycophancy)**:迎合用户立场的回答被偏好,RM 强化"附和"而非"正确"。
- **自我偏好(AI 评委)**:用模型当评委时,它偏好**和自己风格相似**的输出——RLAIF 要特别警惕。

## ⑦ RLAIF / 宪法 AI:用 AI 当标注员

人标贵且慢,**RLAIF(RL from AI Feedback)**用强模型生成偏好标注:
- **直接 AI 偏好**:给 LLM 两个回答 + 评判 rubric,让它输出"哪个更好",当 RM 训练数据。
- **宪法 AI(Constitutional AI,Anthropic)**:用一组**原则(宪法)**让模型**自我批评并修正**自己的回答(SL 阶段),再用 AI 比较生成偏好对训 RM(RL 阶段)——几乎不用人标有害性数据。
- 优点:便宜、可规模化、一致性高(模型不累)。风险:继承评委模型的偏置和盲区、自我偏好、可能放大错误。实践常**人标 + AI 标混合**(人标关键/安全样本,AI 标量大的常规样本)。

## 代码:把排序展开成偏好对

```python
from itertools import combinations

# 一次标注:prompt + K 个回答 + 标注员给的排名(数字越小越好)
sample = {
    "prompt":  "解释一下黑洞",
    "answers": ["A 清晰准确", "B 啰嗦", "C 有错"],
    "ranks":   [1, 2, 3],          # A=1 最好, C=3 最差
}

# ❌ 误区:只取「最好 vs 最差」一对,丢掉中间信息
# pairs = [(best, worst)]          # 浪费了 (A>B)、(B>C) 的监督信号

# ✅ 展开成全部 C(K,2) 个有序对,chosen 是 rank 更小的那个
def to_pairs(s):
    out = []
    for i, j in combinations(range(len(s["answers"])), 2):
        if s["ranks"][i] == s["ranks"][j]:
            continue                       # 并列则跳过(无偏好信息)
        # rank 小的是 chosen
        w, l = (i, j) if s["ranks"][i] < s["ranks"][j] else (j, i)
        out.append({
            "prompt":   s["prompt"],
            "chosen":   s["answers"][w],   # y_w
            "rejected": s["answers"][l],   # y_l
        })
    return out

for p in to_pairs(sample):
    print(p["chosen"], "≻", p["rejected"])
# A ≻ B / A ≻ C / B ≻ C  —— 一次排序产出 3 个偏好对
```

## 面试高频

- **为什么用排序而不是绝对打分?** 人对**相对比较**稳定、对**绝对刻度**不稳定;排序消掉打分者的尺度噪声,且一次排 K 个产出 $\binom{K}{2}$ 个对、信息密度高。
- **偏好数据的质量瓶颈是什么?** 标注一致性(InstructGPT 约 72~77%)。它是 RM 准确率的**硬上限**;靠 rubric、校准、多标聚合来逼近。
- **同一 prompt 的对为什么要同 batch?** 避免重复编码、抑制过拟合;InstructGPT 明确把同 prompt 的所有比较放一个 batch。
- **chosen/rejected 长度不平衡会怎样?** RM/DPO 容易学到「长答案=好」的**长度偏置(length bias)**而非真实质量。缓解:长度归一化、构造长度匹配的对、或在 DPO 里加长度正则。
- **偏好数据从哪来?** 人工标注(贵、准)、AI 反馈(RLAIF,用强模型当标注员,便宜、可规模化)、规则/可验证奖励(数学、代码用对错判定,见 [[32 Agentic RL 与训练|Agentic RL]])。
- **为什么回答要 on-policy(模型自己采)?** RM 要在策略实际生成的分布上准确;若用别处的好/坏答案(off-policy),PPO 时策略生成的是模型分布文本,RM 可能失准。所以 SFT 模型采 K 个让人排序;策略更新后旧数据失效,需迭代重采(Llama-2 多轮)。
- **一致率怎么严谨量化?** 简单一致率被随机撞对夸大,用 Cohen's κ 扣除随机一致;偏好标注 κ 常 0.4-0.6(中等),比原始 72-77% 更能反映上限。
- **偏好数据有哪些偏置?** 长度(偏长)、位置(偏先出现)、格式(偏 markdown)、谄媚(偏附和)、AI 自我偏好。缓解:随机交换顺序、长度归一、双向标注、人+AI 混标。
- **RLAIF 怎么做,风险是什么?** 用强模型按 rubric 生成偏好标注(宪法 AI 让模型自我批评修正)。便宜可规模化,但继承评委偏置、有自我偏好风险,常人标关键样本 + AI 标常规样本。
- **偏好数据怎么喂给训练?** 给 [[083 奖励模型 RM|RM]](学打分)或直接给 [[086 DPO 直接偏好优化(推导)|DPO]](跳过 RM,直接在对上优化策略)。

## 关键事实

- 偏好对格式 `(prompt, chosen, rejected)` = `(x, y_w, y_l)`,源自 InstructGPT(Ouyang 2022,arXiv 2203.02155)的排序标注。
- InstructGPT:标注员排序 K=4~9 个回答;同一 prompt 的 $\binom{K}{2}$ 个对放同一 batch 防过拟合;**标注员组间一致约 72~77%**。
- 偏好数据规模:InstructGPT 约 33k 比较;开源代表有 Anthropic HH-RLHF(Bai 2022,arXiv 2204.05862)、OpenAI summarize-from-feedback(Stiennon 2020,arXiv 2009.01325)。
- RLAIF(Bai et al.,Constitutional AI,2022,arXiv 2212.08073):用 AI 替代部分人类标注,降本提速。
- 常见偏置:长度偏置、风格偏置、谄媚(sycophancy);标注指南与数据平衡是主要缓解手段。
- on-policy 偏好(SFT 模型自采 K 个让人排序)避免分布漂移;策略更新后旧偏好数据失效,需迭代重采(Llama-2 多轮 RLHF,Touvron et al., 2023, arXiv:2307.09288)。
- 一致率严谨度量用 Cohen's κ(扣随机一致),偏好标注 κ 常 0.4-0.6;原始一致率 72-77% 是 RM 准确率上限的乐观估计。
- 位置偏置(偏先出现项)在 AI-as-judge 中尤显著,需随机交换顺序 + 双向标注取平均(如 MT-Bench、AlpacaEval 的处理)。
- 宪法 AI(Constitutional AI,Bai et al., 2022, arXiv:2212.08073):用原则让模型自我批评修正 + AI 生成偏好,几乎免人标有害性数据。
