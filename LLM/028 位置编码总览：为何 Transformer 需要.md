[[028 位置编码总览：为何 Transformer 需要|位置编码总览]]:[[002 自注意力 Self-Attention|自注意力]] 对输入顺序**无感(置换等变)**,打乱词序输出只跟着换、值不变——所以必须**显式注入位置信息**,否则模型分不清"狗咬人"和"人咬狗"。

## 直觉:注意力是个"词袋",天生没有顺序
[[001 Transformer 总览：为何抛弃 RNN|Transformer]] 抛弃了 [[54 RNN 原理与 BPTT|RNN]] 的循环结构,改用 [[002 自注意力 Self-Attention|自注意力]] 一次看全序列——好处是并行,坏处是**丢了顺序**。RNN 是逐 token 喂进去的,顺序天然编码在时间步里;注意力把整段当成一个**集合**:计算每个 token 的输出时,只用到"所有 token 的内容",和它们排第几无关。

后果:对自注意力而言,"狗 咬 人"和"人 咬 狗"是**同一个集合**,输出只是跟着位置一起换了换、数值完全一样。模型根本看不到语序——而语序在语言里恰恰决定意义。

类比:你蒙着眼,别人把三张写着"狗""咬""人"的卡片塞你手里(无序),你只知道有这三个词,不知道谁先谁后——这就是无位置编码的注意力。要恢复理解,必须在每张卡片上额外写个号码(位置信号)。

## 例子:置换等变的数值演示
设三个 token 嵌入 $x_1,x_2,x_3$。无位置编码时自注意力满足:
$$\text{Attn}(P X)=P\cdot\text{Attn}(X)$$
$P$ 是任意置换矩阵。意思是:把输入行重排,输出也只是同样重排,**每个 token 算出来的向量值不变**。

具体地,token "狗" 不管放在位置 0、1 还是 2,只要它周围是同一批词(集合相同),它的输出 $o_{狗}$ **完全一样**——模型无法利用"狗在句首"这个信息。这就是必须注入位置的根本原因。

**为什么 FFN/LayerNorm 救不了。** 有人会问:Transformer 里还有逐位置 FFN、残差、归一化,它们能不能"找回"顺序?不能。FFN 是**逐位置独立**作用(position-wise),对每个 token 做同样的变换,本身不看邻居、更不知"第几位";LayerNorm 同理。整个 block 里**唯一让 token 之间交互**的就是自注意力,而它置换等变。所以只要注意力对位置无感,整个模型就对位置无感——必须在进注意力前/中把位置信号显式注入。

(细节:加了 [[007 因果掩码与 padding 掩码|因果掩码]] 后,严格的置换等变被打破——位置 $i$ 只能看 $\le i$,顺序有了部分约束。但模型仍拿不到"绝对位置"或"相对距离"这类连续位置量,**仍需显式位置编码**才能稳定建模顺序。)

## 原理:位置信息怎么注入、有哪几类
自注意力的打分 $e_{ij}=q_i^\top k_j$ 里没有 $i,j$ 的任何函数——位置编码就是想办法把 $i,j$ 喂进去。两大注入位置、四类做法:

**A. 加在输入(绝对位置)。** 给位置 $i$ 一个向量 $p_i$,与词嵌入相加:$x_i\leftarrow e_i+p_i$。
- **[[029 正弦余弦位置编码(推导)|正弦余弦编码]]**(Vaswani 2017):$p_i$ 用多频率 sin/cos 固定算出,无参数、理论可外推。
- **[[030 可学习与相对位置编码|可学习绝对编码]]**(BERT/GPT):$p_i$ 是可训练查表向量,灵活但表长定死、不能外推。

**B. 作用在注意力打分(相对位置)。** 不给绝对坐标,而是按"两 token 的距离 $i-j$"改打分。
- **[[030 可学习与相对位置编码|相对位置编码]]**(Shaw 2018):打分时加一个只依赖 $i-j$ 的项。
- **[[031 RoPE 旋转位置编码(推导与实现)|RoPE]]**(Su 2021):把 $q,k$ 按位置**旋转**,内积自动只依赖相对角度——现代大模型主流。
- **[[033 ALiBi 与 NoPE|ALiBi]]**(Press 2021):按距离给注意力打分加一个**线性衰减**惩罚,外推极好;NoPE 则探索"干脆不加"。

**演进主线**:绝对(正弦/可学习)→ 相对(Shaw/T5)→ 旋转(RoPE)→ 线性偏置(ALiBi)。**长上下文时代几乎都用相对类**,因为语言更依赖"离多远"而非"在第几位",且相对编码外推更好(见 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|RoPE 外推]])。

**四类方法速查表(面试一图流)。**

| 方法 | 绝对/相对 | 注入位置 | 参数 | 可外推 | 代表模型 |
|---|---|---|---|---|---|
| [[029 正弦余弦位置编码(推导)|正弦余弦]] | 绝对 | 加到输入嵌入 | 无 | 理论可,实测一般 | 原始 Transformer |
| [[030 可学习与相对位置编码|可学习绝对]] | 绝对 | 加到输入嵌入 | $L\times d$ | 否(表长定死) | BERT/GPT |
| [[030 可学习与相对位置编码|Shaw/T5 相对]] | 相对 | 改注意力打分 | 少($\propto$ 窗口) | 较好 | T5 |
| [[031 RoPE 旋转位置编码(推导与实现)|RoPE]] | 绝对编码/相对效果 | 旋转 q,k | 无 | 需插值/YaRN | LLaMA/Qwen/Mistral |
| [[033 ALiBi 与 NoPE|ALiBi]] | 相对(线性偏置) | 改注意力打分 | 无 | 天生极好 | BLOOM/MPT |
| [[033 ALiBi 与 NoPE|NoPE]] | 隐式 | 不加(靠因果掩码) | 无 | 小模型上不错 | 研究/部分小模型 |

记忆线索:**从"加在输入的绝对向量"逐步走向"作用在打分的相对量",且越往后越追求外推与零参数**。

## 代码:有无位置编码的天壤之别
```python
import torch, torch.nn.functional as F

def self_attn(X):                                # (n, d) 无位置编码
    Q = K = V = X
    A = F.softmax(Q @ K.T / X.size(-1) ** 0.5, dim=-1)
    return A @ V

torch.manual_seed(0)
X = torch.randn(3, 8)                            # 三个 token
P = torch.tensor([[0,0,1],[0,1,0],[1,0,0]], dtype=torch.float)  # 置换:颠倒首尾

out1 = self_attn(X)
out2 = self_attn(P @ X)                          # 打乱输入顺序
# ❌ 无位置编码:输出只是同样被置换,值不变 —— 模型分不清语序
print(torch.allclose(P @ out1, out2, atol=1e-5))  # True ← 置换等变,坏消息!

# ✅ 加上(此处用可学习绝对编码示意)后,顺序就被区分
pos = torch.nn.Parameter(torch.randn(3, 8))      # 位置向量
out3 = self_attn(X + pos)
out4 = self_attn((P @ X) + pos)                  # 同样位置向量,但 token 换了位
print(torch.allclose(P @ out3, out4, atol=1e-5))  # False ← 位置已被注入,语序可分
# ❌ 易错:以为因果掩码就能替代位置编码 —— 掩码只挡未来,给不了距离/绝对位置信息。
```

## 面试高频
- **Transformer 为什么需要位置编码?** [[002 自注意力 Self-Attention|自注意力]] **置换等变**:$\text{Attn}(PX)=P\,\text{Attn}(X)$,对输入顺序无感,分不清"狗咬人/人咬狗",必须显式注入位置。
- **[[54 RNN 原理与 BPTT|RNN]] 为什么不需要?** RNN 逐 token 串行喂入,顺序天然编码在时间步;注意力一次看全序列,把输入当集合,故需补位置。
- **位置编码有哪几大类?** 绝对(加在输入:[[029 正弦余弦位置编码(推导)|正弦]]/[[030 可学习与相对位置编码|可学习]])vs 相对(作用在打分:[[030 可学习与相对位置编码|Shaw 相对]]/[[031 RoPE 旋转位置编码(推导与实现)|RoPE]]/[[033 ALiBi 与 NoPE|ALiBi]])。
- **因果掩码能代替位置编码吗?** 不能。掩码只决定"能不能看",不提供"在第几位 / 离多远"的位置量;二者各管一摊。
- **为什么现代模型偏爱相对/旋转编码?** 语言更依赖相对距离;相对类(尤其 [[031 RoPE 旋转位置编码(推导与实现)|RoPE]]、[[033 ALiBi 与 NoPE|ALiBi]])外推到更长序列更稳,而可学习绝对编码表长定死无法外推。
- **位置编码加在哪一步?** 绝对类在进 Transformer 前加到词嵌入;相对/RoPE 类在每层注意力计算 $q,k$ 时介入。
- **FFN/LayerNorm 能提供位置信息吗?** 不能。FFN 逐位置独立、LayerNorm 也是;block 里唯一让 token 交互的是注意力,它置换等变,所以位置必须显式注入。
- **绝对编码加一次(底层)vs 相对编码每层都作用,有何影响?** 绝对类只在输入加一次,位置信息要靠模型在各层"携带";RoPE/ALiBi 在每层注意力都重新注入相对位置,更鲁棒、更利长程,这也是相对类更受现代模型青睐的工程原因之一。
- **为什么相对类外推更好?** 训练见过的是"相对距离 → 行为"的映射,同一相对距离在更长序列里复用同一参数/规律;绝对编码的新位置则从未训练过,直接失效。

## 关键事实
- 置换等变性:无位置信息时 $\text{Attn}(PX)=P\,\text{Attn}(X)$,$P$ 为置换矩阵——这是需要位置编码的数学根源。
- 首次提出位置编码:Vaswani et al.,*Attention Is All You Need*,2017,arXiv:1706.03762,用固定 [[029 正弦余弦位置编码(推导)|正弦余弦编码]]。
- 注入位置二分:绝对(加到输入嵌入)vs 相对(改注意力打分);相对类含 [[030 可学习与相对位置编码|Shaw 2018]]、[[031 RoPE 旋转位置编码(推导与实现)|RoPE 2021]]、[[033 ALiBi 与 NoPE|ALiBi 2021]]。
- 与因果掩码区分:[[007 因果掩码与 padding 掩码|因果掩码]] 限制可见范围、会部分破坏置换等变,但不提供位置量,二者正交。
