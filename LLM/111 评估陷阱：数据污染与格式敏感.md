[[111 评估陷阱：数据污染与格式敏感]]:**基准分数常被两类系统性偏差污染——数据污染(测试题混进了训练语料,分数虚高)与格式/提示敏感(同一题换个写法、换个 few-shot 顺序,分数就跳),不懂这俩就会被榜单骗**。

## 直觉

[[110 下游基准：MMLU、GSM8K、HumanEval、MT-Bench|下游基准]] 给出的分数看着客观,其实有两个隐藏漏洞,会让「分高」≠「真强」:

1. **数据污染(data contamination)**:模型在海量网络语料上预训练,而 MMLU、GSM8K 这些公开测试集的原题(连答案)也在网上。如果它们渗进了训练数据,模型不是「推理出」答案,而是「背过」答案。测试集本应是「模型没见过的题」,污染后这个前提就破了,分数虚高且不反映泛化。

2. **格式/提示敏感(format / prompt sensitivity)**:模型对 prompt 的表面形式过敏。选项写成 `A/B/C/D` 还是 `(1)(2)(3)(4)`、让它选字母还是直接说答案、few-shot 范例的顺序怎么排——这些跟「能力」无关的表面变化,都能让同一模型的分数上下浮动好几个点。于是「报出来的分数」可以被 prompt 工程「调」出来,横向对比若不固定模板就不公平。

两者合起来的危险:**单一公开基准的高分,可能是「过拟合到这个基准」(刷榜)而非真本事**。要靠多基准 + 私有/动态评测交叉验证。

## 例子

**数据污染(小数字)。** 假设某 MMLU 子集 100 题,其中 30 题的原文(含正确选项)恰好出现在模型训练语料里。模型对这 30 题接近 100% 命中(背下了),对剩下 70 道真实泛化题只有 60% → 报告准确率 $\frac{30\times1.0+70\times0.6}{100}=72\%$;但去掉污染题后真实水平只有 60%。**12 个百分点的水分**全来自污染。检测方式:用 n-gram 重叠扫训练集,标记并剔除受污染样本后重测。

**格式敏感(小数字)。** 同一个「法国首都?」多选题,同一模型三种写法:

- 写法 A(字母选项 `A/B/C/D`,看选项概率):准确率 **72%**。
- 写法 B(数字选项 `(1)(2)(3)(4)`):准确率 **64%**。
- 写法 C(开放式「请直接说出城市名」,再抽取答案):准确率 **58%**。

能力没变,仅换了提示形式,分数差 14 个点。其中写法 C 还多了「答案抽取」噪声(模型答「巴黎」但格式不匹配也可能被判错)。

**few-shot 顺序影响(小数字)。** 同样 4 个范例,排列顺序不同,GSM8K 准确率可能在 ±3~5 个点间波动;极端情况下「最佳顺序」和「最差顺序」差距可达两位数(Lu et al. 2022 的 order sensitivity 现象)。

**还有几种「隐形」污染/偏差,容易被忽略(扩面)。**
- **间接污染**:测试题原文没进训练集,但它的**讲解、答案、改写版**进了(论坛讨论、题解博客)。n-gram 精确匹配查不到,模型却已「学过答案」。
- **基准过拟合(刷榜)**:反复在某公开基准上调超参/选 checkpoint,等于把测试集当验证集用——分数高是「拟合到这个基准」,不是泛化。所以 SWE-bench/MMLU 等都出了「held-out / verified」子集。
- **答案位置偏置**:多选题正确答案若总在某个位置(如 C),模型会学到「猜 C」。好的基准会打乱选项顺序。
- **训练-评估目标错位**:用 0-shot 评一个只在 few-shot 格式下训练过的模型(或反之),分数偏低不代表能力差。
- **小测试集 + 大方差**:GPQA 只有几百题,差几题就差几个百分点;报分要带置信区间或多次运行的方差,单点数字别太当真。

## 原理

**为什么污染让分数虚高(形式化)。** 设测试集 $D_{\text{test}}$,被污染子集 $C\subseteq D_{\text{test}}$。模型在 $C$ 上是「记忆」,准确率 $\approx 1$;在干净部分 $D_{\text{test}}\setminus C$ 上才是真实泛化准确率 $a_{\text{gen}}$。报告分:

$$a_{\text{report}}=\frac{|C|}{|D_{\text{test}}|}\cdot 1+\Big(1-\frac{|C|}{|D_{\text{test}}|}\Big)\cdot a_{\text{gen}}\ \ge\ a_{\text{gen}}$$

污染比例 $\frac{|C|}{|D_{\text{test}}|}$ 越大,虚高越多。**缓解四招**:① n-gram 重叠检测剔除污染样本;② 时间隔离——只用模型训练截止日期之后才出现的新题(最新竞赛、新闻)做 fresh 测试集;③ 私有/动态测试集——如 [[112 人评、LLM-as-judge 与 Arena|Chatbot Arena]] 用真实用户实时提问,题目不公开,天然抗污染;④ **行为侦测**——若模型能逐字背出测试题的延续(给前半、它精确补出后半含答案),或对原题高置信、对**改写后语义等价题**骤降,即污染信号(改写一致性检验)。

**更狠的检测:扰动一致性。** 把测试题做语义保持的改写(换数字、换措辞、打乱选项),真懂的模型分数应基本不变,**靠背的模型会骤降**。MMLU-Pro 的「增选项 + 去噪」、各类「对抗改写版」本质都在做这件事——用「换皮还会不会」把记忆和泛化分开。这也解释了为什么动态/时间隔离基准(LiveBench、LiveCodeBench)是当前最可信的抗污染方案(见 [[110 下游基准：MMLU、GSM8K、HumanEval、MT-Bench|新一代基准]])。

**为什么格式敏感(机制)。** 多选题打分常看选项 token 的条件概率 $p(a\mid \text{prompt})$;改变选项符号、分隔符、措辞,会改变这些 token 的边际概率分布,从而改变 $\arg\max$。few-shot 顺序则通过「最近性偏置」「多数标签偏置」等影响后验。**所以公平对比必须把这些自由度全部钉死**:

$$\text{固定:tokenizer + prompt 模板 + 选项格式 + few-shot 内容与顺序 + 答案抽取规则}$$

否则报出的分不是「模型能力」,而是「模型能力 × 评测协议」的耦合量。robustness 评测(测一组提示模板下的分数分布而非单点)正是为此。这与 [[05 Prompt Injection 提示注入|Prompt Injection]] 同源——都暴露了模型「过度依赖输入表面形式」的脆弱性,只是一个被无意触发(评测协议),一个被恶意利用(注入攻击)。

**一个好基准应具备什么(反过来看陷阱)。** 把上面所有坑反过来,就是好基准的设计准则:① **抗污染**(动态/时间隔离/私有,模型见不到原题);② **格式鲁棒**(对 prompt 形式不敏感,MMLU-Pro 把敏感度从 4–5% 压到 2% 就是例子);③ **有区分度**(不在天花板,前沿模型也做不满分,否则刷到 95% 后无意义);④ **足够大 + 报方差**(避免小样本噪声);⑤ **可复现**(协议公开、评测脚本统一)。LiveBench、MMLU-Pro、GPQA 等新一代基准就是冲着这五条设计的(见 [[110 下游基准：MMLU、GSM8K、HumanEval、MT-Bench|新一代基准]])。

**评测协议要钉死哪些自由度(一张清单)。** 做横向对比前,把这些全固定下来,否则不公平:tokenizer、prompt 模板、选项格式(字母/数字/符号)、few-shot 数量+内容+顺序、答案抽取规则(正则/概率比较)、温度(评估常用贪心或温度 0)、最大生成长度、是否允许 CoT。任何一项不同,分数都可能差几个点——这正是「同一模型,不同机构报不同分」的根源。

## 代码

```python
# ❌ 错:拿单一公开基准、单一 prompt 模板就下「A 比 B 强」的结论
def rank_bad(score_A, score_B):
    return "A 更强" if score_A > score_B else "B 更强"   # 没排除污染、没控格式,可能是刷榜/调 prompt

# ✅ 对(1):n-gram 重叠检测,剔除疑似污染的测试样本后再评
def is_contaminated(test_item, train_ngrams, n=13):
    toks = test_item.split()
    grams = {" ".join(toks[i:i+n]) for i in range(len(toks) - n + 1)}
    return len(grams & train_ngrams) > 0          # 测试题 n-gram 命中训练集 → 标记污染

def clean_eval(model, test_set, train_ngrams):
    clean = [x for x in test_set if not is_contaminated(x, train_ngrams)]
    return sum(model.correct(x) for x in clean) / len(clean)   # 只在干净子集上报分
```

```python
import numpy as np

# ✅ 对(2):多模板鲁棒性评测 —— 报「分布」而非单点,避免被某个 lucky 模板带偏
def robust_score(model, dataset, prompt_templates):
    scores = []
    for tmpl in prompt_templates:                 # 一组等价但表面不同的模板
        acc = np.mean([model.solve(tmpl.format(q=x.q)) == x.gold for x in dataset])
        scores.append(acc)
    return {"mean": np.mean(scores), "std": np.std(scores),
            "min": np.min(scores), "max": np.max(scores)}   # std 大 = 格式敏感严重
```

## 面试高频

- **「什么是数据污染,为什么严重?」** 测试集(连答案)进了训练语料,模型「背答案」而非推理,分数虚高且不反映泛化;污染比例越高水分越大。
- **「怎么检测/防污染?」** n-gram 重叠扫训练集剔除污染题;时间隔离(用训练截止后的新题);私有/动态测试集(如 Arena 实时提问、题目不公开)。
- **「为什么换个 prompt 分数就变?」** 多选打分看选项 token 概率,表面形式改变会改变该分布与 $\arg\max$;few-shot 顺序还有最近性/多数标签偏置。能力没变,协议变了。
- **「怎么做公平对比?」** 固定 tokenizer、prompt 模板、选项格式、few-shot 内容与顺序、答案抽取规则;最好报一组模板下的分数均值±标准差(鲁棒性评测),而非单点。
- **「榜单第一就最强吗?」** 不一定。可能过拟合到该公开基准(刷榜)或挑了有利的评测协议。要看多基准一致性 + 私有/动态评测(如 [[112 人评、LLM-as-judge 与 Arena|人类偏好]])。
- **「n-gram 检测查不到就一定没污染吗?」** 不。还有间接污染(题解/讲解进了训练但原题没有)。更强的是行为侦测:模型能逐字背出题目延续、或对原题高置信但对语义等价改写骤降,都是污染信号(扰动一致性检验)。
- **「小测试集的分数能信吗?」** 谨慎。GPQA 等只有几百题,差几题就差几个点;要带置信区间或多次运行方差,别拿单点数字下结论。
- **「怎么从根上抗污染?」** 动态/时间隔离基准:只用模型训练截止后产生的新题(LiveBench、LiveCodeBench、Chatbot Arena 实时提问),模型不可能预先见过。

## 关键事实

- 数据污染是公开基准的系统性威胁:GPT-3 论文(Brown et al. 2020,arXiv 2005.14165)已专门做训练/测试重叠分析;后续多份工作证实多个流行基准存在不同程度污染,导致分数虚高。
- 时间隔离 / 动态基准是主流抗污染方案:用模型训练截止日期之后产生的新题(如最新数学竞赛、实时用户问题)构造「fresh」测试集,使模型不可能预先见过。
- 格式与提示敏感被反复证实:few-shot 范例顺序可显著改变结果(Lu et al. 2022,《Fantastically Ordered Prompts》,arXiv 2104.08786);Zheng et al. 2023(arXiv 2306.05685)亦记录了选项符号、位置等对多选评测的影响。
- 缓解格式敏感的做法:固定评测协议 + 报告多模板下的分数分布(robustness),而非单一 prompt 的点估计;答案抽取要用稳健规则,减少格式不匹配误判。
- 该陷阱与模型「过度依赖输入表面形式」同源,和 [[05 Prompt Injection 提示注入|Prompt Injection]] 是一体两面(无意触发 vs 恶意利用)。
- 间接污染(题解/讲解入训练而原题未入)逃过 n-gram 检测;扰动一致性检验(语义等价改写后分数是否骤降)能区分记忆与泛化,是更强的污染侦测手段。
- 小测试集(如 GPQA 数百题)分数方差大,需报置信区间/多次运行方差;答案位置偏置(正确项总在某位)需打乱选项消除。
- 抗污染的根本方案是动态/时间隔离基准(LiveBench、LiveCodeBench、Chatbot Arena 实时提问),只用训练截止后的新题(见 [[110 下游基准：MMLU、GSM8K、HumanEval、MT-Bench]])。
