[[067 长上下文训练与续训|长上下文训练与续训]] 讲的是:大模型几乎都先用**短上下文**(如 4K)在海量 token 上预训练,再用一小段**长样本续训(continued pre-training)**把窗口扩到 32K~128K,同时**调大 RoPE 的 base θ**(ABF)让位置编码跟得上,最后推理时配合 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|RoPE 外推]] 把窗口推到训练长度之外。

## 直觉

为什么不一开始就用 128K 上下文训练?**太贵**。注意力是 [[014 注意力复杂度 O(n²) 与瓶颈|O(n²)]] 的:序列从 4K 拉到 128K,长了 32 倍,注意力计算和显存涨约 1000 倍。在数万亿 token 上全程用长上下文,算力根本烧不起。

于是业界的标准配方是**两段式**:

1. **短上下文预训练(底座)**:L=4K、RoPE base θ=10000,吃掉绝大部分 token(数万亿),把语言能力和知识学扎实。这一段又快又便宜。
2. **长上下文续训**:在底座基础上,只用**几十亿到千亿** token,把上下文拉到 32K/128K,**同时把 RoPE base θ 调大**(如 10000→1e6,叫 ABF, Adjusted Base Frequency)。学率调小、训得短,目的是让模型"适应"长距离的位置关系,而不是重学语言。

直接拿短底座去推 128K 会崩,核心是**位置编码外推失败**:RoPE 在长位置上会转出训练时从没见过的角度,模型懵了。调大 base θ 让所有维度的旋转**整体放慢**,长位置就落回模型熟悉的角度区间——这就是续训要配合调 base 的原因。

## 例子

**LLaMA-2-Long 的做法(小数字版)**。假设底座 L=4K、θ=10000。续训阶段:

- 把 L 拉到 32K,θ 从 10000 调到 **500000**(放慢 50 倍)。
- 数据:从语料里**上采样长文档**,短文档**拼接**成长序列(documents packing),并用 intra-document mask 防止跨文档"串味"(一篇文章的 token 不该 attend 到拼在后面的另一篇)。
- 只续训约 **几十亿 token**(相比底座的数万亿,不到 1%),学率取底座峰值的 1/10。

**为什么调 base 有效(算一笔)**。RoPE 第 $i$ 对维度的角频率 $\omega_i=\theta^{-2i/d}$。最低频维度($i$ 最大)在位置 $L$ 处转过的总角度 $\approx \omega_{\max}\cdot L$。把 $\theta$ 从 1e4 调到 1e6,$\omega$ 缩小约 $100^{-2i/d}$;对最低频维度差不多缩 100 倍。于是 L 涨 8 倍(4K→32K)带来的角度增量,被 base 的放大轻松吸收,长位置不再"转出界"。

## 原理

**1. RoPE 角度与外推失败。** RoPE 把维度两两配对,第 $i$ 对在位置 $m$ 处旋转角 $m\omega_i$,其中
$$\omega_i=\theta^{-2i/d},\qquad i=0,1,\dots,d/2-1.$$
$i$ 小的是高频(转得快、管局部),$i$ 大的是低频(转得慢、管长程)。训练时模型只见过 $m\le L_{\text{train}}$ 对应的角度。推理时 $m>L_{\text{train}}$,**最低频维度**会进入训练时**从未出现**的角度区间,注意力分数失真——这就是"外推崩"。

**2. ABF:调大 base 等于整体降频。** 把 $\theta$ 放大 $s$ 倍,所有 $\omega_i$ 同步变小,位置 $m$ 处的角度 $m\omega_i$ 整体缩小。要让续训目标长度 $L_{\text{new}}$ 的最低频角度落回原训练范围,近似要求
$$\theta_{\text{new}}\;\gtrsim\;\theta_{\text{old}}\cdot\left(\frac{L_{\text{new}}}{L_{\text{train}}}\right)^{d/(d-2)}\approx \theta_{\text{old}}\cdot\frac{L_{\text{new}}}{L_{\text{train}}}.$$
这与 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|NTK-aware]] 的"按维度非均匀缩放"同源:NTK 改的就是有效 base。区别是 ABF 在**续训时改 + 继续训练**,让权重适应新频率,效果比纯免训外推更稳。

**3. 与位置插值(PI)的对比。** 位置插值把位置坐标 $m$ 压成 $m\cdot L_{\text{train}}/L_{\text{new}}$,角度直接缩回原范围,几乎不外推、靠少量微调即可;ABF 不压坐标而是降频,长程分辨率保留得更好。两者都常配续训用,详见 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|位置插值]]。

**4. 训练吞吐:长序列要靠并行。** 32K~128K 的激活和 KV 巨大,单卡放不下,必须上 [[073 序列并行与上下文并行|序列并行 / 上下文并行]] 把序列维切到多卡,并配 [[065 梯度检查点与激活重计算|激活重计算]] 省显存。这把长上下文训练和后面整套 [[068 并行总览：DP、TP、PP、EP、SP|分布式并行]] 串起来了。

**5. StreamingLLM:推理侧的另一条路。** 不续训也想处理超长流?StreamingLLM 发现注意力高度集中在**最初几个 token**(attention sink, 注意力汇),只要**保留开头少数 token 的 KV + 滑动窗口**,就能在 4M token 上稳定生成而不崩。这是推理时的免训技巧,见 [[107 长上下文推理：YaRN、位置插值与 StreamingLLM|长上下文推理]]。

**6. 位置插值(PI)的数值对照。** PI 把位置 $m$ 压成 $m'=m\cdot L_{\text{train}}/L_{\text{new}}$。从 4K 扩到 32K:$m'=m/8$,于是 32K 处的位置被映回 ≤4K 的训练范围,**所有角度都落在见过的区间**、几乎不外推。代价:相邻 token 的角度差被压缩 8 倍,**高频(局部)分辨率下降**——挨着的 token 在旋转空间里更难区分,所以 PI 通常配少量续训(Chen 2023 仅 1000 步)恢复精度。对照 ABF:不压坐标、靠降频,保住了长程分辨率但需更多续训适应新频率。

**7. YaRN:按频率分段处理(NTK-by-parts)。** PI 对所有维度一刀切压缩,YaRN 更精细:**高频维度(管局部)几乎不动**(否则毁局部分辨率)、**低频维度(管长程)做插值**、中间过渡。再加一个**注意力温度修正**(softmax 前乘 $\sqrt{1/t}$ 类因子)补偿长序列下注意力熵的变化。效果:免训也能扩得比 PI 远,微调后更稳。这条「分频处理」线和 NTK-aware 同源,详见 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|RoPE 外推]]。

**8. 长上下文得专门评测(困惑度不够)。** PPL 降不代表真能用长上下文——模型可能只靠局部 n-gram 就把 PPL 压低,却**用不上**远处信息。要用**针对性评测**:大海捞针(Needle-in-a-Haystack,把一句事实埋在长文不同位置,看能否取回)、**RULER**(多种合成长程任务:检索、多跳、聚合)、LongBench 等。常见现象「**lost in the middle**」:信息放在上下文**中间**时召回最差(开头结尾好),说明扩了窗口不等于均匀利用。

**9. 长序列吞吐:Ring Attention / 上下文并行。** 32K–1M 序列的注意力和 KV 单卡放不下,得把序列维切到多卡。**Ring Attention** 让每卡持一段序列,K/V 像传环一样在卡间流转、各卡增量累加注意力,使**有效上下文随卡数线性扩展**而单卡显存恒定。这与 [[073 序列并行与上下文并行|序列并行/上下文并行]]、[[065 梯度检查点与激活重计算|激活重计算]]共同支撑长上下文训练,串到 [[068 并行总览：DP、TP、PP、EP、SP|分布式并行]]。

## 代码

```python
import numpy as np

# ❌ 错：底座 base 不变，直接把上下文从 4K 拉到 32K 推理
#    最低频维度在 m>4K 处转出训练没见过的角度 → 注意力失真、PPL 爆炸
def rope_freqs_wrong(d=128, L_train=4096):
    base = 10000.0                       # base 没动
    i = np.arange(0, d, 2)
    return base ** (-i / d)              # ω_i，最低频在 32K 处转出界

# ✅ 对：长上下文续训时调大 base（ABF），再喂长样本继续训
def rope_freqs_abf(d=128, L_train=4096, L_new=32768, base_old=10000.0):
    scale = L_new / L_train              # 8 倍
    base_new = base_old * scale          # 10000 -> 80000（实践常更激进到 5e5~1e6）
    i = np.arange(0, d, 2)
    return base_new ** (-i / d)

w_old = rope_freqs_wrong()
w_new = rope_freqs_abf()
print("最低频 ω（原 base）:", w_old[-1])     # 较大 → 32K 处转角大
print("最低频 ω（ABF）   :", w_new[-1])      # 更小 → 转角落回熟悉范围
# 配套：① 长文档上采样+拼接 ② intra-document mask ③ 小学率短续训
```

```python
# 文档拼接 + intra-document mask（防跨文档 attend）
def build_block_mask(doc_lens, L):
    # doc_lens: 拼进一条长序列的各文档长度，如 [12000, 8000, 12000] 凑 32K
    seg = np.zeros(L, dtype=int)
    p = 0
    for k, n in enumerate(doc_lens):
        seg[p:p+n] = k; p += n
    # 只有同一文档(seg 相同)且因果(j<=i)才可见
    causal = np.tril(np.ones((L, L), bool))
    same   = seg[:, None] == seg[None, :]
    return causal & same                  # True=可 attend
```

```python
import numpy as np
# —— 位置插值(PI) vs ABF:同样扩 4K→32K,角度怎么变 ——
d, L_train, L_new = 128, 4096, 32768
i = np.arange(0, d, 2)
# 原始 RoPE 频率
w = 10000.0 ** (-i / d)
# PI:压缩位置坐标 m' = m * L_train/L_new,等价频率乘 scale
scale = L_train / L_new                          # =1/8
m = L_new - 1                                     # 最远位置
ang_extrapolate = (m * w)[-1]                     # 不处理:最低频维转角(可能出界)
ang_PI          = (m * scale * w)[-1]             # PI:角度压回训练范围
ang_ABF         = (m * (10000.0*8) ** (-i / d))[-1]  # ABF:降频(base×8)
print("不处理(外推)最低频转角:", round(ang_extrapolate, 3))
print("PI 后:", round(ang_PI, 3), " (落回训练范围,但局部分辨率↓)")
print("ABF 后:", round(ang_ABF, 3), " (降频,长程分辨率保留更好)")
# PI 压坐标→几乎不外推但高频分辨率降;ABF 降频→保长程分辨率但需更多续训
```

## 面试高频

- **Q:为什么不直接用长上下文从头预训练?** A:注意力 [[014 注意力复杂度 O(n²) 与瓶颈|O(n²)]],序列长 32 倍则算力/显存约涨 1000 倍。先短上下文吃完绝大部分 token(便宜),再用 <1% 的 token 做长上下文续训扩窗口,性价比最高。
- **Q:长上下文续训为什么要调大 RoPE base?** A:RoPE 低频维度在长位置会转出训练时没见过的角度,导致外推失败。调大 base θ(ABF)让所有频率整体放慢,长位置落回熟悉的角度区间;再续训让权重适应,比纯免训外推稳。
- **Q:ABF 和位置插值、YaRN 什么关系?** A:都解决 RoPE 外推。ABF=调大 base(降频);位置插值=压缩位置坐标;YaRN=按频率分段处理(高频保留、低频插值)+温度修正。ABF/PI 常配续训,YaRN 可免训也可微调。详见 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|RoPE 外推]]。
- **Q:长上下文训练的数据怎么搞?** A:天然长文档稀少,需对长文档上采样、把短文档拼接成长序列;关键是 intra-document mask,防止一篇文档 attend 到拼接进来的另一篇,否则学到虚假长程依赖。
- **Q:StreamingLLM 和长上下文续训有何不同?** A:续训是**训练侧**真正把窗口扩大;StreamingLLM 是**推理侧**免训技巧——靠保留开头几个 token(注意力汇)+滑窗,让固定窗口模型稳定处理无限流,但不增加"有效上下文"(中间信息会丢)。
- **Q:位置插值(PI)和 ABF 的区别?** A:PI 压缩位置坐标 $m'=m\cdot L_{\text{train}}/L_{\text{new}}$,角度落回训练范围、几乎不外推,但高频(局部)分辨率被压缩、需少量续训恢复;ABF 不压坐标、靠降低 RoPE base 频率,保住长程分辨率但需更多续训适应新频率。
- **Q:YaRN 比 PI 强在哪?** A:PI 对所有维度一刀切压缩(伤局部);YaRN 分频处理——高频维几乎不动、低频维插值、中间过渡,再加注意力温度修正,免训也能扩更远、微调更稳。
- **Q:怎么评测长上下文真的能用?** A:困惑度不够(可能只靠局部 n-gram)。用大海捞针(needle)、RULER、LongBench 等针对性长程任务;注意「lost in the middle」——信息在中间时召回最差。
- **Q:长序列训练显存放不下怎么办?** A:激活和 KV 随序列涨,单卡放不下;用 Ring Attention / 上下文并行把序列维切到多卡(K/V 环形流转、有效上下文随卡数线性扩展),配激活重计算。
- **陷阱**:① 只调 base 不续训,长程位置仍生疏;② 续训学率太大会破坏底座知识;③ 长序列训练显存瓶颈在激活和 KV,需序列并行+重计算配合;④ 拼接长序列必须 intra-document mask 防跨文档串味;⑤ PPL 降 ≠ 长上下文可用,要 needle/RULER 验。

## 关键事实

- **ABF / 调大 RoPE base 做长上下文**:LLaMA-2-Long(Xiong 等,Meta,2023,arXiv:2309.16039)系统验证"调大 RoPE base + 长样本续训"是扩上下文的有效配方;Code Llama(Rozière 等,2023,arXiv:2308.12950)把 θ 调到 1e6 续训得到 16K~100K 上下文。
- **位置插值(PI)**:Chen 等(2023,arXiv:2306.15595)提出压缩位置坐标 + 1000 步微调即可把 LLaMA 从 2K 扩到 32K,开创"少量续训扩窗口"范式。
- **StreamingLLM / 注意力汇**:Xiao 等(2023,arXiv:2309.17453)发现注意力高度集中于初始 token,保留少数初始 KV + 滑窗即可在 **4M token** 上稳定生成,较滑窗重算最高 **22.2×** 加速;无需微调。
- **NTK-aware 外推**:由 Reddit 社区(bloc97,2023)提出,按维度非均匀缩放 RoPE 频率(等价改有效 base),免训即可显著延长有效上下文,被后续 YaRN 吸收。
