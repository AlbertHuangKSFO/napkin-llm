[[065 梯度检查点与激活重计算|梯度检查点与激活重计算]](gradient checkpointing / activation recomputation)是**用算力换显存**的技术:前向时只保存少数层的激活(检查点),其余丢弃;反向需要时再从最近检查点**重新前向算一遍**拿回中间激活。代价是多约一次前向的算力,换来激活显存从 $O(n)$ 降到 $O(\sqrt n)$。它直接缓解 [[076 显存占用估算(参数、梯度、优化器、激活、KV)|显存占用]]里激活这一大头。

## 直觉

反向传播要用到前向算出的**中间激活**(每层的输出)来算梯度。默认做法:前向时把每一层激活都**留在显存里**,反向直接取用——快,但激活显存随层数 $n$ 线性增长,深网络/长序列下激活常是显存第一大消耗(甚至超过参数和优化器状态)。

梯度检查点反其道:前向时**只保留少数「检查点」层的激活**,中间层的激活**算完即丢**。等反向走到某段时,从该段开头最近的检查点出发,**重新前向**把这一段的激活临时算回来,用完再丢。

- **省了什么**:任意时刻显存里只有检查点 + 当前正在重算的一小段激活,而不是全部 $n$ 层。把网络切成 $\sqrt n$ 段、只存段首,激活显存就从 $O(n)$ 降到 $O(\sqrt n)$。
- **花了什么**:被丢弃的激活在反向时要**多算一次前向**,整体训练时间约 $+20\%\sim33\%$。

注意:**重算的是激活,不是参数或梯度**;那次额外前向只为拿回中间值,**不更新权重**。

一句话:**别全存激活——存几个锚点,反向时按需重算,拿算力买显存**。

## 例子

6 层网络 L1–L6,设每层激活占 1 单位显存。

- **不开检查点**:前向后显存常驻 6 单位激活(L1…L6 全留),反向直接用。
- **开检查点**(每隔 2 层设一个,存 L1★、L4★):前向后只常驻约 2 单位(两个检查点),L2/L3/L5/L6 算完即丢,**省下约 4 单位**。
- **反向到 L3**:发现 L2、L3 激活已丢 ⇒ 从检查点 L1 出发,重新前向 L1→L2→L3,临时算回 L2、L3 激活,再做 L3 的反向。代价就是这一段多跑了一次前向。

数量级:一个 12 层、序列 4096、batch 8 的 Transformer,激活可能占十几 GB;开检查点后激活显存能压到原来的几分之一,代价是训练慢约三成——显存不够时这买卖很划算。

## 原理

设网络 $n$ 层,前向 $x_0\to x_1\to\dots\to x_n$,$x_i=f_i(x_{i-1})$。反向算 $\frac{\partial \mathcal L}{\partial x_{i-1}}$ 需要 $x_{i-1}$。

- **全存**:显存 $M=O(n)$(存所有 $x_i$),反向计算量 $O(n)$,无重算。
- **检查点**:把 $n$ 层切成 $s$ 段,每段长 $n/s$,**只存 $s$ 个段首激活**。

显存与重算计算量:

$$M = O\!\left(s + \frac{n}{s}\right),\qquad \text{重算量} = O(n)\ \text{(每个非检查点激活至多重算一次)}$$

对 $M$ 关于 $s$ 求最小:$s + n/s$ 在 $s=\sqrt n$ 时取极小,得

$$M_{\min} = O(\sqrt n)$$

这就是 Chen et al.(2016)的 $\sqrt n$ 结论:**激活显存 $O(n)\to O(\sqrt n)$,代价是一次额外前向(总训练时间约 +1/3)**,在均匀计算图(Transformer 堆叠正好近似满足)下接近最优权衡。

进一步可做**选择性重算(selective recomputation)**:只对「显存占用大但重算便宜」的算子(如注意力中的大激活)做重算,对「重算贵」的(如矩阵乘)保留——在显存与算力间取更细的折中(Megatron-LM 的做法)。

**激活显存的具体账(为什么它常是大头)。** Transformer 一层、序列 $L$、隐藏维 $h$、batch $B$ 的激活,主要来自:QKV 投影输出、注意力分数 $L\times L$(每头)、softmax 输出、MLP 中间层($4h$)等。不含注意力矩阵时,每层激活 $\propto B\,L\,h$;**注意力分数矩阵 $\propto B\,L^2$**(随序列平方涨)是长序列下的真凶。Korthikanti 等给出未优化时每层激活约 $sbh(34+5\,a\,s/h)$ 字节量级($s$=序列、$a$=头数),全模型 $\times$ 层数后,在长序列/大 batch 下**超过参数 + 优化器状态**——这正是要 checkpoint 的动机。

**$\sqrt n$ 的数值演示。** $n=48$ 层。全存:48 单位激活。切成 $s=\sqrt{48}\approx7$ 段、每段约 7 层,只存 7 个段首 + 重算时段内峰值约 7 = 约 **14 单位**,省约 70%。代价:反向时每个非检查点激活重算一次,总多约一次前向(训练时间 +1/3)。若更激进切 $s=24$ 段(每段 2 层),存 24 但重算量小;$s$ 越大越省时间但越费显存——$s=\sqrt n$ 是 $s+n/s$ 的极小点。

**与 FlashAttention 的关系(别重复劳动)。** [[025 FlashAttention(IO 感知精确注意力)|FlashAttention]] 本身就**不实例化 $L\times L$ 注意力矩阵**(分块在线 softmax,反向时重算注意力中间量),等于对注意力部分自带了「重算」。所以开了 FlashAttention 后,注意力那块的激活已经很省,梯度检查点主要再省 MLP/残差等其余激活——两者叠加而非冲突,是现代长序列训练的标配组合。

**全量重算 vs 选择性重算的取舍。** 全量(每个 block 都 checkpoint):省显存最多、时间 +~33%。选择性(Megatron):只重算「便宜且占显存大」的算子(如 dropout、softmax、注意力的部分),保留 matmul 结果,时间开销可压到 +几% 而显存仍大降。规则:**重算性价比 = 省下的显存 ÷ 重算的 FLOPs**,优先重算这个比值高的。

## 代码

```python
import torch
import torch.utils.checkpoint as cp

class Block(torch.nn.Module):           # 一个 Transformer block(简化)
    def __init__(self, d):
        super().__init__()
        self.ln = torch.nn.LayerNorm(d)
        self.ff = torch.nn.Linear(d, d)
    def forward(self, x):
        return x + self.ff(torch.relu(self.ln(x)))

class Net(torch.nn.Module):
    def __init__(self, d=4096, n=24, use_ckpt=False):
        super().__init__()
        self.blocks = torch.nn.ModuleList([Block(d) for _ in range(n)])
        self.use_ckpt = use_ckpt

    # ❌ 不开检查点:每个 block 的激活全留显存,深网络易 OOM
    def forward_no_ckpt(self, x):
        for blk in self.blocks:
            x = blk(x)              # 所有中间激活常驻显存
        return x

    # ✅ 开检查点:每个 block 的激活反向时重算,只存少量
    def forward(self, x):
        for blk in self.blocks:
            if self.use_ckpt and self.training:
                # use_reentrant=False 是新版推荐;reentrant 旧版与某些特性不兼容
                x = cp.checkpoint(blk, x, use_reentrant=False)
            else:
                x = blk(x)
        return x

net = Net(use_ckpt=True).cuda()
loss = net(torch.randn(8, 512, 4096, device="cuda")).sum()
loss.backward()                          # 反向时自动重算被丢弃的激活
```

```python
import math
# —— sqrt(n) 切段:显存 s + n/s 在 s=√n 取极小 ——
def ckpt_mem(n, s):                       # 段首 s 个 + 重算时段内峰值 n/s
    return s + math.ceil(n / s)
n = 48
for s in [1, 7, 24, 48]:                  # s=1 全存, s=√48≈7 最优, s=48 每层都存=全存
    print(f"切 {s:>2} 段: 显存≈{ckpt_mem(n, s):>3} 单位 (全存={n})")
print("最优 s = √n =", round(math.sqrt(n)))   # ≈7 → 显存从48 降到~14

# —— 重算性价比:省显存 ÷ 重算FLOPs,优先重算高比值算子 ——
ops = {"dropout": (8, 1), "softmax": (6, 2), "matmul": (4, 20)}   # (省下的显存, 重算FLOPs)
for name, (mem, flops) in ops.items():
    print(f"{name:>8}: 性价比={mem/flops:.1f}")   # dropout/softmax 高 → 选择性重算优先它们
# ✅ 选择性重算(Megatron):只重算便宜且占显存大的,保留贵的 matmul → 时间 +几% 显存仍大降
```

## 面试高频

- **梯度检查点省的是什么显存?** 激活显存(中间层输出),不是参数或优化器状态;把 $O(n)$ 降到约 $O(\sqrt n)$。
- **代价是什么?** 反向时要多做约一次前向(重算被丢的激活),整体训练时间约 +20%~33%;**重算的是激活,不更新权重**。
- **为什么是 $\sqrt n$?** 把 $n$ 层切 $s$ 段、只存段首,显存 $\propto s+n/s$,在 $s=\sqrt n$ 取最小。
- **什么时候用?** 显存不够、想跑更大模型/更长序列/更大 batch 时;常与 [[064 混合精度 FP16、BF16 与 FP8|混合精度]]、[[070 ZeRO 与 FSDP|ZeRO/FSDP]] 叠加。
- **和重计算/重物化是一回事吗?** 是同一技术的不同叫法:gradient checkpointing = activation recomputation = rematerialization。
- **选择性重算是什么?** 只重算「省显存多、重算便宜」的算子(如注意力激活),保留贵的(如 matmul),在显存与算力间更细地折中(Megatron-LM)。
- **它怎么影响 batch?** 省下的显存可换成更大 batch 或更长序列;也可与 [[063 批大小、梯度累积与 critical batch size|梯度累积]]配合进一步放大有效 batch。
- **为什么激活常是显存大头?** 不含注意力矩阵时每层激活 $\propto BLh$,而注意力分数 $\propto BL^2$ 随序列平方涨;长序列/大 batch 下全模型激活会超过参数 + 优化器状态,故要 checkpoint。
- **梯度检查点和 FlashAttention 冲突吗?** 不冲突,叠加用。FlashAttention 本就不实例化 $L\times L$ 矩阵、反向重算注意力中间量(等于自带注意力重算);checkpoint 再省 MLP/残差等其余激活,是长序列训练标配组合。
- **选择性重算怎么选算子?** 按「省显存 ÷ 重算 FLOPs」比值,优先重算 dropout/softmax/注意力这类便宜又占显存大的,保留贵的 matmul;时间开销可从 +33% 压到 +几%。

## 关键事实

- 出自 Chen, Xu, Zhang, Guestrin《Training Deep Nets with Sublinear Memory Cost》(2016,arXiv:1604.06174):激活显存 $O(n)\to O(\sqrt n)$,代价约一次额外前向。
- 经验:训练时间增加约 20%~33%,可换来训练 2–10× 更大模型(取决于激活/参数比例)。
- PyTorch 接口 `torch.utils.checkpoint.checkpoint`;新版建议 `use_reentrant=False`。
- 选择性激活重算见 Megatron-LM(Korthikanti et al., 2022,arXiv:2205.05198),针对超长序列把激活显存压得更低。
- 与混合精度、[[070 ZeRO 与 FSDP|ZeRO/FSDP]] 正交,常叠加使用;激活通常是长序列训练的显存第一大头,见 [[076 显存占用估算(参数、梯度、优化器、激活、KV)|显存估算]]。
