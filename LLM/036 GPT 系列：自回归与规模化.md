[[036 GPT 系列：自回归与规模化]]:OpenAI 的生成式预训练模型谱系(GPT-1/2/3,Radford et al.;Brown et al. 2020,arXiv 2005.14165)——用「预测下一个词」的自回归目标训 [[011 Encoder-Decoder、Decoder-Only 与 Encoder-Only|decoder-only]] Transformer,靠规模化(Scaling)在 GPT-3 上涌现出 in-context learning,奠定了今天所有大模型的基本范式。

## 直觉:只做一件事——预测下一个词

[[035 BERT：双向编码与 MLM|BERT]] 做「完形填空」,GPT 只做一件事:**接龙**。给一段文字,预测**下一个**词;预测对了就把它接上,再预测下下个词。如此循环,就能生成任意长文本。这叫**自回归(autoregressive)**生成。

为了不偷看未来,GPT 用**因果掩码**:每个位置的 [[002 自注意力 Self-Attention|注意力]] 只能看自己和左边,看不到右边。这和 BERT 的双向是镜像关系(见 [[035 BERT：双向编码与 MLM|双向 vs 单向图]])。

GPT 的故事其实是一个**规模化**的故事:GPT-1(0.117B)证明「无监督预训练 + 微调」可行;GPT-2(1.5B)展示 zero-shot 生成;GPT-3(175B)规模再放大约 100 倍,**涌现**出 in-context learning——不更新任何权重,光看提示里的几个例子就能做新任务。这是 [[079 Scaling Law 与 Chinchilla 最优|Scaling Law]] 最戏剧化的体现。

## 例子:自回归生成 + in-context learning

**自回归生成**。要生成「猫坐在垫子」:

1. 输入「猫」→ 模型输出下一个词的概率分布 → 采样得「坐」。
2. 输入「猫坐」→ 输出分布 → 采样得「在」。
3. 输入「猫坐在」→ 采样得「垫」……每步把上一步的输出**接回输入**,循环。

训练时不用真的串行:用因果掩码,一次并行算出**每个**位置的「下一个词」损失(这是 GPT 比 MLM 样本效率高的关键——所有位置都贡献 loss);推理时才串行逐个吐,并用 KV-Cache 复用算过的 k/v。

**in-context learning(上下文学习)**。给 GPT-3 这样的提示:

```
英文 sea → 中文 海
英文 sky → 中文 天
英文 fire → 中文 ____
```

模型直接续写「火」——**没有任何梯度更新**,纯靠提示里两个示例「现学」了「英译中」这个任务。这就是 few-shot in-context learning。关键事实:这能力**到 GPT-3 规模才涌现**,小模型给再多示例也学不会。按提示给几个/一个/零个示例,分别叫 few-shot / one-shot / zero-shot。

## 规模表:GPT-3 的 8 个尺寸(具体数字)

GPT-3 论文(Brown et al., 2020,Table 2.1)一口气训了 **8 个尺寸**,从 125M 到 175B 横跨三个数量级,全用 2048 上下文。记住两端 + 规律即可:

| 名称 | 参数 | 层数 $N$ | $d_{model}$ | 头数 × 头维 |
|---|---|---|---|---|
| GPT-3 Small | 125M | 12 | 768 | 12 × 64 |
| GPT-3 Medium | 350M | 24 | 1024 | 16 × 64 |
| GPT-3 Large | 760M | 24 | 1536 | 16 × 96 |
| GPT-3 XL | 1.3B | 24 | 2048 | 24 × 128 |
| GPT-3 2.7B | 2.7B | 32 | 2560 | 32 × 80 |
| GPT-3 6.7B | 6.7B | 32 | 4096 | 32 × 128 |
| GPT-3 13B | 13B | 40 | 5140 | 40 × 128 |
| **GPT-3 175B** | **175B** | **96** | **12288** | **96 × 128** |

规律:**变大基本就是「加层数 + 加宽 $d_{model}$ + 加头数」**,结构不变。每头维度大多稳在 64~128。GPT-1 ≈ 0.117B(12 层、768 维),GPT-2 最大 1.5B(48 层、1600 维)——所以 GPT-1→2→3 是 0.117B→1.5B→175B,放大约 1500 倍。

**参数都花在哪?** 一层 decoder 块参数 ≈ 注意力 $4d^2$(Q/K/V/O)+ FFN $2\cdot d\cdot 4d=8d^2$,共 $12d^2$;乘层数 $N$。175B:$12\times12288^2\times96\approx 1.7\times10^{11}$,正好约 175B(嵌入等另算)。**FFN 占了块内约 2/3 的参数**——这也是为什么后来 MoE 专门拿 FFN 开刀(见 [[042 MoE 动机：稀疏激活与容量解耦|MoE]])。

## 原理

**自回归分解**。语言模型建模整句的联合概率,用链式法则拆成逐词条件概率:

$$p(x_1,\dots,x_T)=\prod_{t=1}^{T}p(x_t\mid x_{<t})$$

训练目标是最大化这个似然,等价于最小化 [[32 困惑度 Perplexity|交叉熵 / 困惑度]]:

$$\mathcal{L}=-\sum_{t=1}^{T}\log p(x_t\mid x_{<t})$$

**对比 MLM**:GPT 对序列里**每个**位置都算 loss($T$ 个监督信号),而 [[035 BERT：双向编码与 MLM|BERT]] 只对 15% 被遮位置算。同样的数据,自回归提供约 6 倍的监督信号 → 样本效率高,这是生成式路线在大规模下更划算的原因之一(见 [[056 预训练目标：自回归、掩码与去噪|预训练目标对比]])。

**因果掩码**。注意力分数矩阵的上三角(未来位置)置为 $-\infty$,softmax 后权重为 0,保证位置 $t$ 只聚合 $\le t$ 的信息,与自回归分解一致。

**规模化与涌现**。GPT-3 论文的核心观察:把参数、数据、算力**一起**按 [[079 Scaling Law 与 Chinchilla 最优|Scaling Law]] 的幂律放大,损失平滑下降,但某些能力(in-context learning、多步推理)是**涌现的**——在小模型上几乎为零,过了某个规模阈值突然出现。这把「预训练一个超大语言模型」本身变成了通用任务求解器,催生了 [[034 发展史总览：2017 到今|后来的对齐(RLHF)→ ChatGPT]]。

**架构沿革**。GPT-1/2/3 都是 decoder-only Transformer,主要变化是**变大变深**和细节微调(GPT-2 把 LayerNorm 前置等)。位置编码上,早期 GPT 用 [[030 可学习与相对位置编码|可学习绝对位置]];现代开源 decoder-only([[038 LLaMA 架构解剖|LLaMA]] 等)改用 [[031 RoPE 旋转位置编码(推导与实现)|RoPE]]。

## 解码策略:同一个分布,不同的取法

训练好后,每步模型给出下一个 token 的概率分布 $p(x_t\mid x_{<t})$,但「怎么从分布里取一个词」是另一回事,直接决定生成质量,面试常考:

- **贪心(greedy)**:每步取概率最大的词。确定、快,但容易重复、平淡(「the the the…」)。
- **温度采样(temperature)**:把 logits 除以温度 $T$ 再 softmax。$T<1$ 更尖锐(更保守/确定),$T>1$ 更平(更随机/有创意),$T\to0$ 退化成贪心。见 [[27 Softmax 与温度|Softmax 与温度]]。
- **top-k 采样**:只在概率最高的 $k$ 个词里重新归一化后采样,砍掉长尾的离谱词。
- **top-p / nucleus 采样**:取累积概率达到 $p$(如 0.9)的最小词集合里采样,候选数随分布动态变化,比固定 $k$ 更稳。
- **beam search**:保留 $b$ 条最优前缀并行扩展,常用于翻译/摘要等「有标准答案」的任务;开放式生成里反而易出重复、不如采样自然。

实务里 chat 模型常用 temperature(0.7 左右)+ top-p(0.9)组合。**温度和 top-p 不改训练,只改采样**——同一个模型换参数就有不同「性格」。

## 代码:自回归损失与生成

```python
import torch, torch.nn.functional as F

# ✅ 训练：因果掩码下，一次并行算所有位置的「预测下一个 token」loss
def gpt_loss(logits, tokens):
    # logits: (B, L, V)，tokens: (B, L)
    # 位置 t 的预测目标是 token t+1 → 整体左移一位对齐
    shift_logits = logits[:, :-1, :].reshape(-1, logits.size(-1))
    shift_labels = tokens[:, 1:].reshape(-1)
    return F.cross_entropy(shift_logits, shift_labels)   # 每个位置都贡献 loss

# ✅ 推理：自回归逐个生成，把输出接回输入
@torch.no_grad()
def generate(model, prompt_ids, max_new=20, temperature=1.0):
    ids = prompt_ids
    for _ in range(max_new):
        logits = model(ids)                  # (1, L, V)
        next_logits = logits[:, -1, :] / temperature
        probs = next_logits.softmax(-1)
        next_id = torch.multinomial(probs, 1)  # 采样下一个 token
        ids = torch.cat([ids, next_id], dim=1) # 接回输入，继续
    return ids

# ❌ 误区一：推理时把整段已生成文本重新过一遍而不用 KV-Cache —— O(L²) 重复计算，慢且贵
# ❌ 误区二：训练时忘记左移对齐（拿位置 t 的 logits 去预测 token t）—— 等于让模型抄输入
# ❌ 误区三：以为 in-context learning 会改权重 —— 它不更新任何参数，只在前向里「现学」
```

```python
# top-k + top-p + 温度采样：把「怎么从分布取词」写清楚
@torch.no_grad()
def sample_next(logits, temperature=0.7, top_k=50, top_p=0.9):
    logits = logits / temperature                      # ✅ 温度：缩放 logits
    if top_k:                                           # top-k：只留概率最高的 k 个
        v, _ = torch.topk(logits, top_k)
        logits[logits < v[..., -1:]] = float("-inf")
    probs = logits.softmax(-1)
    if top_p:                                           # top-p：留累积概率 ≤ p 的核
        sp, si = probs.sort(descending=True)
        mask = sp.cumsum(-1) - sp > top_p               # 超出核的部分置零
        sp[mask] = 0.0
        probs = torch.zeros_like(probs).scatter(-1, si, sp)
        probs = probs / probs.sum(-1, keepdim=True)
    return torch.multinomial(probs, 1)
# 同一个模型,改 temperature/top_p 就改「性格」——不动权重
```

## 训练完不等于能用:对齐三阶段

GPT-3 只是个「补全器」,给「如何制作炸弹」它可能真去补全步骤,且不会主动「回答问题」。从 GPT-3 到 ChatGPT 走了三步(InstructGPT,2022),面试常问:

1. **预训练(pretrain)**:海量无标注文本上自回归训练,得到一个会续写、有世界知识的基座模型。
2. **监督微调(SFT)**:用人工写的「指令-回答」对微调,教模型「按指令格式回答」而非乱续写。
3. **RLHF(基于人类反馈的强化学习)**:训一个奖励模型(RM)给回答打分,再用 PPO 等让模型生成「人类更偏好」的回答(也有 DPO 等更简单的替代)。

口诀:**预训练给知识,SFT 给格式,RLHF 给偏好/安全**。三步之后才是能聊天、会拒答的助手。

- **自回归 vs MLM 的样本效率差别?** GPT 对每个位置都算 loss(全部 token 都是监督信号),BERT 只对 15% 被遮位置算 → 同样数据 GPT 监督信号多约 6 倍,大规模下更划算。这是生成式路线胜出的原因之一。
- **in-context learning 是什么?会改权重吗?** 不更新任何参数,仅靠提示里的示例在前向中临时「学会」任务;GPT-3(175B)规模才涌现,小模型没有。按示例数分 zero/one/few-shot。
- **GPT 为什么能生成而 BERT 不能?** GPT 自回归 + 因果掩码,逐词预测下一个,天然适配生成;BERT 双向 + 掩码,是判别式理解器,不建模逐词生成概率。
- **GPT-1→2→3 主要变了什么?** 主要是**规模**(0.117B→1.5B→175B,约 1500 倍)与数据,架构基本不变;质变(in-context learning)来自规模涌现而非新结构。
- **KV-Cache 为什么对 GPT 重要?** 自回归推理逐 token 生成,KV-Cache 缓存历史的 k/v 避免每步重算,把生成从 O(L²) 降到增量 O(L),是部署的关键优化。
- **现代 GPT 类模型的位置编码?** 早期 GPT 用可学习绝对位置;LLaMA 等现代 decoder-only 用 [[031 RoPE 旋转位置编码(推导与实现)|RoPE]],并配 [[032 RoPE 外推：NTK-aware、位置插值、YaRN|外推技巧]] 扩长。
- **温度、top-k、top-p 各是什么?** 都是采样参数,不改权重:温度缩放 logits 控制随机性;top-k 只在前 k 个候选采样;top-p(nucleus)在累积概率达 p 的最小核里采样。贪心是 $T\to0$ 的极限。
- **GPT-3 的参数主要花在哪?** 每层 ≈ $12d^2$,其中 FFN($8d^2$)约占 2/3、注意力($4d^2$)约 1/3;总参 ≈ $12d^2N$。这也是 MoE 专挑 FFN 改的原因。
- **从 GPT-3 到 ChatGPT 经历了什么?** 预训练 → SFT(指令微调给格式)→ RLHF(奖励模型 + PPO/DPO 给人类偏好与安全)。基座只会续写,对齐三步才会「答」。
- **few-shot 的示例放哪、会不会被记住?** 放进 prompt(上下文)里,前向算完即弃,不写入权重;换个对话就「忘了」。这是 ICL 与微调的根本区别。

## 关键事实

- GPT-1:Radford et al., 2018,《Improving Language Understanding by Generative Pre-Training》(OpenAI,0.117B,生成式预训练 + 判别微调)。
- GPT-2:Radford et al., 2019,最大 1.5B,展示强 zero-shot 生成,《Language Models are Unsupervised Multitask Learners》。
- GPT-3:Brown et al., 2020,arXiv 2005.14165,《Language Models are Few-Shot Learners》;175B 参数(GPT-2 的约 100 倍),涌现 in-context learning。
- 训练目标:自回归 $\prod_t p(x_t\mid x_{<t})$,因果掩码,对每个位置算交叉熵 → 样本效率高于 [[035 BERT：双向编码与 MLM|MLM]]。
- 规模化遵循 [[079 Scaling Law 与 Chinchilla 最优|Scaling Law]](Kaplan et al., 2020);部分能力(ICL、推理)随规模**涌现**。
- 后续:InstructGPT/ChatGPT(2022)在 GPT-3.5 基础上加 RLHF 对齐;decoder-only 自回归范式成为 [[034 发展史总览：2017 到今|现代大模型]] 主流,推理时依赖 KV-Cache。
- GPT-3 规模表(Table 2.1):8 个尺寸,125M(12 层/768)→ 175B(96 层/12288/96×128 头),全用 2048 上下文;放大主要靠加层数 + 加宽 + 加头数,结构不变。
- 对齐:InstructGPT(Ouyang et al., 2022,arXiv:2203.02155)确立 SFT + RLHF 三阶段;后续 DPO(Rafailov et al., 2023)用更简单的直接偏好优化替代 PPO。
- 解码:温度 / top-k(Fan et al., 2018)/ top-p nucleus(Holtzman et al., 2019,arXiv:1904.09751);开放式生成常用 temperature≈0.7 + top-p≈0.9。
- 分词:GPT 系用 BPE / Byte-level BPE(GPT-2 起),与 BERT 的 WordPiece 不同,见 [[051 BPE 与 Byte-level BPE|BPE]]。
