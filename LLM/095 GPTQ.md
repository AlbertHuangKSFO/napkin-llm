[[095 GPTQ|GPTQ]]:一种**仅量化权重**的训后量化([[093 PTQ 与 QAT|PTQ]])方法,把 LLM 权重压到 **int4(甚至 int3)几乎无损**。核心是**逐层、逐列**地量化,每量化一列就立刻把产生的误差**沿二阶最优方向补偿进尚未量化的后续列**——这套「最优脑外科手术」(OBQ)思想让误差不再各自累积,而是被后面的权重「背锅吸收」。它解决了朴素四舍五入(RTN)在 int4 下掉点的问题,是 [[096 AWQ 与 SmoothQuant|AWQ]] 之外最主流的 int4 权重量化方案,广泛用于单卡 [[108 推理引擎：vLLM、TensorRT-LLM、llama.cpp、SGLang|推理部署]]。

## 直觉:量化不是逐个权重就近取整,而是保住「整层的输出」

朴素量化(RTN,round-to-nearest)把每个权重**各自就近取整**,误差互相独立、谁也不管谁,整层下来误差**层层累积**——int8 还行,到 int4 就明显掉点。

GPTQ 换了个目标:**别盯着「每个权重准不准」,盯着「这一层的输出 $WX$ 准不准」**。两个权重就算各自被量化得不太准,只要它们的误差在输出上**相互抵消**,这一层就没问题。

于是有了「逐列 + 补偿」的流程(像做手术,切一刀就缝一针):

1. 从左到右**逐列**量化权重。
2. 量化某一列时产生误差 $e=w-\hat w$。
3. **立刻把这份误差,按最优方式分摊给右边「还没量化」的列**——让它们微调一下,把这层输出的偏差补回来。
4. 处理下一列时,它已经「吸收」了前面的误差,再量化它、再补给更右边……

到整层做完,误差被**一路向后传递、不断稀释**,而不是无脑累积。这就是为什么 GPTQ 在 int4 下能接近无损,而 RTN 不行。

## 例子:误差补偿如何抵消输出偏差(小数字)

设一层有 2 个权重 $w=[2.0,\,3.0]$,输入 $x=[1.0,\,1.0]$,真实输出 $y=wx^\top=2.0+3.0=5.0$。量化格点为整数(格距 1)。

**RTN**:$2.0\to2$、$3.0\to3$,输出 $=2+3=5.0$,这里恰好无误差;但若 $w=[2.4,\,3.0]$:RTN 把 $2.4\to2$,误差 $0.4$,输出 $=2+3=5.0$ 而真实 $=5.4$,**输出偏了 0.4,无人补救**。

**GPTQ**:量化第 1 列 $2.4\to2$,误差 $e=0.4$。它知道这会让输出少 $e\cdot x_1=0.4$。于是**把第 2 列(还没量化)上调来补**:让 $\hat w_2$ 的连续值先变成 $3.0+\frac{e\cdot x_1}{x_2}=3.0+0.4=3.4$,再量化 $3.4\to3$(这里仍是 3,但若格距更细就能补上)。在真实高维场景里,补偿方向由 **Hessian(二阶信息)** 给出,能把误差精确地分摊到对输出影响最互补的那些权重上,使整层输出偏差最小。

关键:GPTQ 优化的是 $\min\|WX-\hat W X\|^2$(整层输出的差),不是 $\min\|W-\hat W\|^2$(权重本身的差)。

**一个能算清的补偿例子**。设 1 行 2 个权重 $w=[2.4,\,3.0]$,两个输入特征恒等于 $x=[1.0,\,1.0]$,真实输出 $y=2.4+3.0=5.4$。格距 1。
- **RTN**:$2.4\to2$、$3.0\to3$,输出 $5.0$,**偏 $-0.4$**,无补救。
- **GPTQ**:量化第 1 列 $2.4\to2$,误差 $e=2.4-2=0.4$,它会让输出少 $e\cdot x_1=0.4$。为补回,把第 2 列(还没量化)的连续值上调 $\frac{e\cdot x_1}{x_2}=0.4$:$3.0\to3.4$。此刻若格更细($\le0.4$)就能把这 $0.4$ 补进格点、输出精确回到 $5.4$;即便格距仍是 1($3.4\to3$,这步没补成),在真实高维里**多个输入方向相关、$H^{-1}$ 给出最优联动**,补偿会摊到对输出最互补的若干列上,整层输出偏差被压到远小于 RTN。核心:**GPTQ 容忍单个权重量化得更不准,只为换整层输出更准**。

## 原理:逐层目标 + OBQ 闭式补偿 + 工程加速

**1)逐层量化目标**。GPTQ 把全模型量化拆成**每层独立**的小问题。对某层权重 $W$ 和校准激活 $X$(用少量样本跑前向得到),目标是:

$$
\hat W=\arg\min_{\hat W}\ \big\|WX-\hat W X\big\|_2^2
$$

即让量化前后**这层的输出尽量一致**。这是个逐层最小二乘,不需要反向传播、不需要标签,只需**少量校准数据**(常 128 条样本)。

**2)OBQ 的闭式误差补偿**。上式的 Hessian 是 $H=2XX^\top$。基于「最优脑外科手术 / 最优脑损伤」(OBS/OBD)理论,**量化第 $q$ 列**(把它定到最近格点)后,对**剩余未量化权重**的最优修正有闭式解:

$$
\delta\;=\;-\,\frac{w_q-\text{quant}(w_q)}{[H^{-1}]_{qq}}\;\cdot\;H^{-1}_{:,\,q}
$$

直觉:$H^{-1}$ 编码了「哪些权重一起动能最省力地抵消输出误差」;分子是量化第 $q$ 列产生的误差,$\delta$ 把这份误差**沿 Hessian 给出的最优方向**摊给后续列。逐列重复,直到整层量化完。

**为什么是 Hessian、为什么 $H=2XX^\top$**。目标 $\|WX-\hat WX\|^2$ 对权重是**二次型**,它的曲率(二阶导)就是 Hessian。对 $\|(W-\hat W)X\|^2$ 关于权重求两次导,正好得到 $H=2XX^\top$——即**校准激活的协方差**。它的含义:$X X^\top$ 大的方向是激活能量集中的方向,在这些方向上量化权重出错对输出影响大、要小心补;$H^{-1}$ 则告诉你「为了不动输出,补偿误差时各权重该按什么比例联动」。$[H^{-1}]_{qq}$ 是第 $q$ 列的「自敏感度」,做分母是归一化:越敏感的列,产生单位误差需要的补偿越小心。

**直觉小结**:GPTQ = 「量化一列 → 看它给输出带来多少偏差 → 用 $H^{-1}$ 算出后续列怎么微调最省力地把这偏差吃掉 → 微调后续列 → 量化下一列」。误差像击鼓传花一路向右传、不断被稀释吸收,而不是各自累积。

**3)GPTQ 对 OBQ 的三个关键加速**(让它能跑 175B 而非小网络):

- **固定列顺序**:OBQ 每步选「误差最小的列」先量化(贪心、需重排),GPTQ 发现**对大矩阵按固定从左到右顺序量化**精度几乎不掉,省去昂贵的贪心选择和 $H^{-1}$ 反复重算。
- **惰性批更新(lazy batch update)**:把列分块(如每 128 列一组),组内更新攒着批量做,缓解显存带宽瓶颈。
- **Cholesky 重构**:用 Cholesky 分解稳定地得到 $H^{-1}$ 的所需信息,避免重复求逆带来的数值不稳定。

这三招把 OBQ 的「数小时」压缩到 GPTQ 的「**单卡几分钟到几小时**」量化一个百亿模型。

**OBQ→GPTQ 的 FLOPs 估算(为什么差好几个数量级)**。量化一层权重 $W\in\mathbb R^{d_{\text{row}}\times d_{\text{col}}}$($d_{\text{col}}$ 是输入维、要逐列量化的方向)。**OBQ** 的 Hessian $H=XX^\top$ 是**逐行(逐输出神经元)各算各的**——因为每行量化后会改自己这行的剩余权重,$H^{-1}$ 得跟着行更新;再叠贪心选列(每步重排、反复更新逆),整层约 $O(d_{\text{row}}\cdot d_{\text{col}}^3)$。**GPTQ** 的关键省法:固定列序后,$H=XX^\top$ **与输出行无关、全部 $d_{\text{row}}$ 行共享同一个 $H^{-1}$**,一次 Cholesky 求逆 $O(d_{\text{col}}^3)$ 后,逐列补偿对所有行批量做,整层约 $O(d_{\text{col}}^3+d_{\text{row}}\cdot d_{\text{col}}^2)$。取方阵 $d_{\text{row}}=d_{\text{col}}=4096$:OBQ $\sim d_{\text{row}}\!\cdot\!d_{\text{col}}^3=4096\times4096^3$,GPTQ $\sim d_{\text{col}}^3=4096^3$,**比值 $\approx d_{\text{row}}=4096\times$**——再加上省掉的贪心重排,正好把「逐层数分钟、全模型数小时」量级整体降几千倍,这就是 OBQ 数小时 vs GPTQ 分钟的来源。本质:**OBQ 每行重算一遍逆,GPTQ 全层共享一个逆。**

**4)定位与代价**。GPTQ **只量化权重**(int4/int3,常配 group size 128 的 [[092 量化基础：对称非对称、per-tensor、per-channel、per-group|per-group]]),**激活仍 fp16**。所以它的收益是**省显存 + 访存加速**(权重搬运减半甚至 1/4),特别适合**单卡装下大模型**;它不像 [[094 LLM.int8 与离群值|LLM.int8]] 那样量化激活,也就没有运行时离群分解的复杂度。代价:量化过程要算 Hessian、按校准数据逐层优化,比 RTN 慢;且**依赖校准数据分布**(校准集偏了精度会受影响)。

## 代码:RTN vs GPTQ 式逐列补偿(❌ vs ✅)

```python
import torch

# 一层权重 W: [out, in],校准激活 X: [in, n_samples]
out_dim, in_dim, n = 256, 512, 128
W = torch.randn(out_dim, in_dim)
X = torch.randn(in_dim, n)

def quant_int4(w, s):                          # 对称 int4: [-7, 7]
    return torch.clamp(torch.round(w / s), -7, 7) * s

scale = W.abs().amax(dim=1, keepdim=True) / 7  # per-channel(逐行)scale

# ❌ 错:RTN —— 每个权重各自就近取整,误差独立累积,int4 下掉点
W_rtn = quant_int4(W, scale)
err_rtn = ((W @ X - W_rtn @ X) ** 2).mean()

# ✅ 对:GPTQ 式 —— 逐列量化,把误差按 Hessian^{-1} 补偿进后续列
H = X @ X.T + 1e-2 * torch.eye(in_dim)         # 层 Hessian ≈ XXᵀ(加阻尼)
Hinv = torch.cholesky_inverse(torch.linalg.cholesky(H))
Wq = W.clone()
for q in range(in_dim):                        # 从左到右逐列
    w_col = Wq[:, q]
    w_q = quant_int4(w_col, scale.squeeze(1))  # 量化当前列
    err = (w_col - w_q) / Hinv[q, q]           # 误差 / [H^{-1}]_qq
    Wq[:, q] = w_q
    if q + 1 < in_dim:                         # 把误差补给尚未量化的后续列
        Wq[:, q + 1:] -= torch.outer(err, Hinv[q, q + 1:])
err_gptq = ((W @ X - Wq @ X) ** 2).mean()

print(f"RTN 输出误差:  {err_rtn:.4f}")
print(f"GPTQ 输出误差: {err_gptq:.4f}")   # 通常显著更小
# 实务:用 auto-gptq / gptqmodel 库,一行 quantize(),激活保持 fp16
```

## 面试高频

- **GPTQ 一句话原理?** 逐层、逐列量化权重,每量化一列就用 Hessian 二阶信息把误差**最优地补偿进后续未量化列**,使**整层输出**($WX$)而非单个权重尽量不变;int4 下接近无损。
- **GPTQ 优化的目标是什么?为什么不是权重本身?** 目标是 $\min\|WX-\hat WX\|^2$(层输出误差),因为最终影响模型的是激活流过的输出;权重各自的误差只要在输出上互补抵消就无妨。
- **GPTQ 和 RTN 差在哪?** RTN 每权重独立就近取整、误差累积、int4 掉点;GPTQ 有**误差补偿**,让后续权重「背锅」抵消,int4 接近无损。代价是要算 Hessian、按校准数据优化,更慢。
- **GPTQ 量化激活吗?** 不。**只量化权重**(int4/int3),激活保持 fp16。收益是省显存 + 访存加速,适合单卡装大模型;与之相对,[[094 LLM.int8 与离群值|LLM.int8]] 同时处理激活。
- **GPTQ 来自什么理论?三个工程加速是什么?** 源自 OBQ(最优脑量化,继承 OBS/OBD);加速 = 固定列顺序 + 惰性批更新 + Cholesky 重构,使其能在合理时间量化百亿模型。
- **GPTQ vs AWQ?** GPTQ 用二阶误差补偿、逐列优化(更"数学"、稍慢、对校准更敏感);[[096 AWQ 与 SmoothQuant|AWQ]] 用激活感知缩放保护重要权重(更轻量、对校准更鲁棒)。二者精度接近,实务都常用。
- **GPTQ 需要训练数据吗?** 不需要标签和反向传播,只要**少量无标签校准样本**(常 128 条)做逐层最小二乘。
- **GPTQ 里的 Hessian 是什么?为什么是 $XX^\top$?** 目标 $\|WX-\hat WX\|^2$ 是权重的二次型,其二阶导(曲率)= $2XX^\top$,即校准激活的协方差。它编码「补偿误差时各权重怎么联动最省力」;$[H^{-1}]_{qq}$ 是列的自敏感度,做分母归一。
- **GPTQ 为什么能固定列顺序?** 原始 OBQ 每步贪心选「误差最小的列」先量化、需反复重排和重算 $H^{-1}$,极慢;GPTQ 发现对大矩阵**按固定左→右顺序**精度几乎不掉,省去贪心,配惰性批更新 + Cholesky,把数小时压到分钟~小时级。
- **为什么 RTN int4 掉点而 GPTQ 不?** RTN 每权重独立就近取整、误差在输出上各自累积;GPTQ 让后续列「背锅」吸收前列误差,使整层输出 $WX$ 几乎不变。本质是从「最小化权重误差」换成「最小化输出误差」。
- **GPTQ 对校准数据敏感吗?** 比 AWQ 更敏感——它逐层按校准激活做最小二乘 + 算 Hessian,校准集分布偏了会影响补偿方向;AWQ 只用激活幅度统计、更鲁棒。这是二者实务取舍之一。

## 关键事实

- GPTQ:Frantar, Ashkboos, Hoefler, Alistarh《GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers》(2022/2023,arXiv:2210.17323,ICLR 2023)。
- 前身 OBQ:Frantar & Alistarh《Optimal Brain Compression》(2022,arXiv:2208.11580);理论根源是 LeCun 的 OBD(1989)与 Hassibi 的 OBS(1993)。
- 效果:把 OPT-175B、BLOOM-176B 量化到 **3~4 bit**,精度损失很小,且能在**单张 GPU、约几小时内**完成;int4 权重显存约为 fp16 的 1/4。
- 方法 = 逐层最小二乘 $\min\|WX-\hat WX\|^2$ + OBQ 闭式补偿 $\delta=-\frac{w_q-\hat w_q}{[H^{-1}]_{qq}}H^{-1}_{:,q}$($H=2XX^\top$)+ 固定列序 / 惰性批更新 / Cholesky 三项加速;常配 group size 128。
- 工程:`auto-gptq` / `gptqmodel` / `optimum`,与 vLLM、TGI 等 [[108 推理引擎：vLLM、TensorRT-LLM、llama.cpp、SGLang|推理引擎]]兼容;**只量化权重、激活 fp16**。
