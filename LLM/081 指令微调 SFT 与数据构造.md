[[081 指令微调 SFT 与数据构造]]:SFT(Supervised Fine-Tuning,监督微调 / 指令微调)用人写的 **(指令,答案)** 对继续训练预训练模型,关键工程点是**只对「答案」部分算 loss**、用**对话模板**拼接、以及「质量远比数量重要」的数据构造原则。它是 [[080 后训练总览：SFT 到 RM 到 RLHF|后训练]] 三段管线的第一段。

## 直觉:把「会接龙」掰成「会回答」

预训练模型见的全是**自然文本流**,没有「问题—回答」这种结构。SFT 做的事极简单:给它看几万条**人类示范**——「遇到这种指令,就该这样回答」——用普通的监督学习(下一个词预测)让它**模仿**这种「被问就答」的行为。

两个反直觉但关键的点:

1. **只对答案算 loss,不对 prompt 算**。我们要模型学的是「怎么**回答**」,不是「怎么复述问题」。把 prompt 部分的 label 屏蔽掉(置成 `-100`),交叉熵就跳过它们(见 [[060 训练目标与 loss 实现|loss 实现]] 的 `ignore_index`)。
2. **质量 ≫ 数量**。SFT 不是越多越好。LIMA(Meta,2023)只用 **1000 条**高质量示范就把 65B 模型调得很能打——「Less Is More for Alignment」。预训练已经把知识装进去了,SFT 只是**唤醒格式**,不是灌新知识。

## 例子:一条样本的 loss mask(小数字)

假设词表里把句子切成 8 个 token,序列是:

```
[用户:] [翻译] [。] [助手:] [Trans] [late] [this] [<eos>]
 └────── prompt 段(4 个 token)─────┘ └──── 答案段(4 个)────┘
```

逐 token 的 label(下一个词预测,右移一位 + mask):

| 位置 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| label | -100 | -100 | -100 | -100 | learn | learn | learn | learn |

只有后 4 个 token 进 loss。若答案有 4 个 token,则:

$$
\text{loss}=-\tfrac{1}{4}\big[\log p(\text{Trans})+\log p(\text{late})+\log p(\text{this})+\log p(\text{<eos>})\big]
$$

如果**不 mask**,prompt 的 token 也会进分母,既浪费算力学「背问题」,又让短答案被长 prompt **稀释**(一条 200 token 的 prompt + 10 token 的答案,答案信号只占 5%)。

## 原理:masked 交叉熵 + 对话模板 + packing

**1)目标函数**。设答案 token 集合为 $A$:

$$
\mathcal{L}_{\text{SFT}}=-\mathbb{E}_{(x,y)\sim D}\Big[\frac{1}{|A|}\sum_{t\in A}\log \pi_\theta(y_t\mid x,\,y_{<t})\Big]
$$

这就是普通的 [[30 交叉熵与负对数似然|交叉熵]],唯一区别是**求和只跑答案 token**($t\in A$)。归一化分母 $|A|$ 让不同长度的答案公平。

**2)对话模板(chat template)**。模型靠**特殊 token / 角色标记**分辨「谁在说话」。例如(ChatML 风格):

```
<|system|>你是助手<|end|>
<|user|>翻译这句<|end|>
<|assistant|>Translate this<|end|>
```

模板必须**训练与推理一致**——用错模板是 SFT 翻车第一大坑(模型在训练时见的格式和你部署时喂的不一样)。多轮对话里**每一轮 assistant 回复**都打 `mask=1`(都要学),user/system 段全 mask 掉。

**3)packing(打包)**。短样本各自 padding 到固定长度很浪费;把多条短样本**拼进一个长序列**省 padding。但要保证 attention **不跨样本**(用 block-diagonal 掩码,见 [[007 因果掩码与 padding 掩码|掩码]]),否则样本 A 会「偷看」样本 B。

## 多轮对话的 mask:每轮 assistant 都要学

单轮 SFT 容易,多轮对话(user/assistant 交替多次)的 mask 是高频坑。原则:**所有 assistant 回复段 mask=1(都学),所有 user/system 段 mask=0(都不学)**。

```
<|system|>你是助手           ← mask 0
<|user|>问题1                ← mask 0
<|assistant|>回答1 <|end|>    ← mask 1(学)
<|user|>问题2                ← mask 0
<|assistant|>回答2 <|end|>    ← mask 1(学)
```

易错点:① 不能只学最后一轮(浪费前面轮的监督);② **每轮的 `<|end|>`/eos 也要学**(否则模型不知道何时停,推理时不停生成);③ 角色标记本身是否计入 loss 要和模板一致。多轮里同一段 prompt 上下文被多轮复用,packing 时尤其要小心 mask 边界。

## 数据质量过滤 pipeline(怎么把"质量≫数量"落地)

"质量优先"不是口号,有一套标准清洗流程:
1. **去重**:精确去重(hash)+ 近似去重(MinHash/SimHash),重复样本会让模型过拟合特定表述。
2. **质量过滤**:用规则(长度、语言、格式)+ 模型打分(用强模型给"指令清晰度/答案质量"评分,筛高分)。代表:Alpaca→AlpaGasus(用 GPT 筛出 9k 高质量,反超原 52k)。
3. **多样性保证**:覆盖任务类型(QA、改写、代码、推理、拒答…)、难度、领域。多样性比单纯堆量更影响泛化。
4. **去污染**:剔除与评测集重叠的样本(防 benchmark 泄漏)。
5. **格式统一**:统一对话模板、统一系统提示风格。
6. **安全过滤**:剔除有害、隐私、版权内容,补入拒答样本教模型该拒就拒。

数据来源三类:**人工写**(贵、准)、**蒸馏**(Self-Instruct/Alpaca:强模型生成指令-答案)、**真实日志清洗**(用户真实 query + 人工/模型修正答案)。

## 超参与训练技巧(SFT 实战清单)

- **epoch**:常 **1-3**。SFT 极易过拟合(数据少),多 epoch 会让模型死记示范、丧失泛化和多样性。
- **学习率**:比预训练**小一个量级**(全参常 1e-5~2e-5,LoRA 可大些 1e-4~3e-4),配 warmup + cosine/linear 衰减。
- **batch / 序列长**:packing 提效率(见 [[007 因果掩码与 padding 掩码|掩码]]);长样本截断或丢弃。
- **NEFTune**(Jain 2023):在 embedding 上加均匀噪声做正则,简单一招涨点,缓解过拟合。
- **灾难性遗忘缓解**:① 混入少量预训练/通用数据(replay);② 用 [[091 高效微调：LoRA、QLoRA、Adapter、Prefix|LoRA]] 少改参数;③ 控 epoch、控学率;④ 监控通用 benchmark 别掉太多(对齐税)。

## packing 的正确性:block-diagonal 掩码

packing 把多条短样本拼进一个长序列省 padding,但必须保证 **attention 不跨样本边界**。做法是 **block-diagonal(块对角)attention 掩码**:样本 A 的 token 只能 attend 到 A 内部,看不到同序列里的样本 B。否则 A 会"偷看"B 的内容,污染训练(且推理时没有这种拼接,训推不一致)。现代框架(FlashAttention 的 varlen 接口、`flash_attn_varlen`)原生支持变长 packing,无需手搓掩码。位置编码也要**每个样本从 0 重新计数**(RoPE/绝对位置都如此),否则后面样本的位置漂移。

## 代码:正确的 SFT loss mask(❌ vs ✅)

```python
import torch
import torch.nn.functional as F

# 一条样本:prompt_len 个 prompt token + answer 个答案 token
input_ids = torch.tensor([[101, 102, 103, 104,  205, 206, 207, 208]])  # 共 8 token
prompt_len = 4
logits = model(input_ids).logits          # [1, 8, vocab]

# 下一个词预测:用前 t 个预测第 t+1 个 → 错位对齐
shift_logits = logits[:, :-1, :]          # 预测 2..8
shift_labels = input_ids[:, 1:].clone()   # 真值   2..8

# ❌ 错:对整条序列算 loss —— 模型把算力浪费在背 prompt,答案被稀释
# loss_bad = F.cross_entropy(shift_logits.reshape(-1, V), shift_labels.reshape(-1))

# ✅ 对:把「答案之前」的位置标成 -100,交叉熵自动忽略
shift_labels[:, : prompt_len - 1] = -100  # 错位后,前 prompt_len-1 个是 prompt
loss = F.cross_entropy(
    shift_logits.reshape(-1, shift_logits.size(-1)),
    shift_labels.reshape(-1),
    ignore_index=-100,                    # 关键:-100 的位置不进 loss
)
print(loss)   # 只在答案 token 上平均
```

要点:`ignore_index=-100` 是 PyTorch 交叉熵的默认忽略值;错位(shift)后 mask 的边界要算对(`prompt_len - 1`)。

## 面试高频

- **SFT 为什么只对答案算 loss?** 目标是学「如何回答」,prompt 是**条件**不是**学习目标**;对 prompt 算 loss 会浪费算力并稀释答案信号、还可能让模型倾向复读问题。
- **SFT 数据是越多越好吗?** 不是。质量 > 数量(LIMA:1000 条即可)。预训练已注入知识,SFT 只对齐格式与风格;脏数据/风格不一致会直接污染模型。多样性(任务覆盖)比单纯堆量更重要。
- **SFT 会让模型「变笨」吗?** 会有**对齐税(alignment tax)**:过度 SFT/RLHF 可能在某些 benchmark 上掉点;且窄数据上微调会**灾难性遗忘**。缓解:混入少量预训练数据、用 [[091 高效微调：LoRA、QLoRA、Adapter、Prefix|LoRA]] 等少改参数、控制 epoch(常 1~3)。
- **全参数微调 vs LoRA?** 全参数效果上限高但贵且易遗忘;[[091 高效微调：LoRA、QLoRA、Adapter、Prefix|LoRA/QLoRA]] 只训低秩增量,省显存、易切换、抗遗忘,是 SFT 工程默认选择。
- **多轮对话怎么 mask?** 所有 assistant 回复段(含其 eos)mask=1 都学,所有 user/system 段 mask=0;不能只学最后一轮,eos 必须学否则模型不会停。
- **packing 怎么不让样本互相偷看?** 用 block-diagonal attention 掩码(样本只 attend 自己内部)+ 每样本位置从 0 重新计数;FlashAttention varlen 接口原生支持。
- **SFT 超参怎么定?** epoch 1-3(易过拟合)、学率比预训练小一个量级(全参 1e-5~2e-5)、warmup+衰减;NEFTune 加 embedding 噪声正则;混预训练数据 + LoRA 缓解遗忘。
- **数据质量怎么落地?** 去重(MinHash)→ 质量过滤(规则+模型打分,如 AlpaGasus 用 GPT 筛)→ 多样性覆盖 → 去评测污染 → 格式统一 → 安全过滤补拒答。AlpaGasus 用 9k 高质量反超 52k 原始数据。
- **怎么造 SFT 数据?** 来源:人工写、模型蒸馏(Self-Instruct/Alpaca 用强模型生成指令-答案)、真实日志清洗。务必去重、过滤有害、统一格式与模板。

## 关键事实

- SFT 是 [[080 后训练总览：SFT 到 RM 到 RLHF|InstructGPT]](Ouyang 2022,arXiv 2203.02155)三段第一段,约 13k 人写示范。
- Self-Instruct(Wang 2022,arXiv 2212.10560)、Alpaca(Stanford,2023):用强模型自动生成指令数据,开启「蒸馏式」SFT。
- LIMA(Zhou et al.,Meta,2023,arXiv 2305.11206):*Less Is More for Alignment*,1000 条高质量示范即可对齐 65B,佐证「质量 ≫ 数量」。
- 工程默认:loss 只算答案 token(`ignore_index=-100`);训练/推理用**同一对话模板**;epoch 常 1~3;LoRA 微调省显存。
- 数据质量优先的证据:AlpaGasus(Chen et al., 2023, arXiv:2307.08701)用 GPT 从 Alpaca 52k 筛 9k 高质量反超原集;LIMA 1000 条对齐 65B。
- NEFTune(Jain et al., 2023, arXiv:2310.05914):embedding 加均匀噪声正则,SFT 简单涨点、抗过拟合。
- 多轮 mask(所有 assistant 段含 eos 都学)、packing 用 block-diagonal 掩码 + 每样本位置归零,是 SFT 工程的两大正确性要点;FlashAttention varlen 原生支持变长 packing。
