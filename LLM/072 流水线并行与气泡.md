[[072 流水线并行与气泡|流水线并行与气泡]] 把模型**按层切**到多卡:每卡放连续几层(一个 stage),激活像工厂流水线一样点对点逐级传递。代价是**气泡**——填充与排空阶段部分 GPU 空转,占比 $\frac{p-1}{m+p-1}$($p$ 阶段、$m$ 微批)。GPipe 用微批减气泡,**1F1B** 交错前向反向进一步压气泡并省激活显存。

## 直觉

[[071 张量并行(Megatron)|TP]] 切单层、通信重得只能机内。要**跨机**扩展、训层数很深的模型,得换一种通信轻的切法:**按层切**——这就是**流水线并行(Pipeline Parallelism, PP)**。

把 32 层模型切成 4 段,每卡放 8 层(一个 stage)。前向时,GPU0 算完层 1-8,把**边界激活**(一个张量)传给 GPU1 算层 9-16……像流水线一样往下走。通信只在 stage 边界发生,**只传一个激活张量**,通信量小、频率低——所以 PP 适合跨机。

但有个天然问题:GPU1 必须**等** GPU0 算完才有输入,GPU2 等 GPU1……一开始大家轮流空等(**填充**),反向回传时又轮流空等(**排空**)。这些空转就是**气泡(bubble)**。

怎么减气泡?**把一个 batch 切成多个微批(micro-batch)**,让它们像传送带上的零件一样**接连**喂进流水线:GPU0 算完微批 1 立刻算微批 2,同时 GPU1 开始算微批 1……稳态时各卡都忙起来。微批越多,填充/排空占总时间的比例越小,气泡越小。

## 例子

**4 stage、4 微批(GPipe)**。每个微批每 stage 算 1 个时间单位:

- **填充**:t0 只有 GPU0 忙(算微批 1 的前向),t1 GPU0、GPU1 忙……到 t3 流水线才填满。前 $p-1=3$ 个时隙,后面的卡在空等。
- **稳态**:全部卡都忙。
- **排空**:反向回传时对称地空等 $p-1$ 个时隙。

**气泡占比算一笔**。理想(无气泡)时间 $\propto m$(算完 $m$ 个微批);实际要 $m+p-1$ 个"前向时隙"才让最后一个微批走完流水线。气泡比例:
$$\text{bubble}=\frac{(m+p-1)-m}{m+p-1}=\frac{p-1}{m+p-1}.$$
- $p=4,m=4$:$\frac{3}{7}\approx 43\%$——快一半时间在空转!
- $p=4,m=16$:$\frac{3}{19}\approx 16\%$。
- $p=4,m\to\infty$:$\to 0$。

**所以微批要远多于 stage 数**($m\gg p$)。但微批太多 → 同时"在飞"的激活多 → 激活显存峰值高。这正是 **1F1B** 要解决的:它让反向**尽早**做,激活算完就释放,峰值激活显存大降,且气泡占比与 GPipe 相同。

## 原理

**1. 切层与点对点通信。** 模型 $\ell$ 层切成 $p$ 个 stage,stage $k$ 持有第 $[k\ell/p,(k+1)\ell/p)$ 层。前向 stage $k$ 算完输出激活 $a_k$,用 `send` 发给 stage $k{+}1$;反向把 $\partial\mathcal L/\partial a_k$ 回传。通信量 $\sim b\cdot s\cdot h$(一个激活张量),**只在 $p-1$ 处边界**,远轻于 TP 的每层 all-reduce —— 故可跨机。

**2. 气泡占比推导。** 设每个微批在每个 stage 耗时 $t$。$m$ 个微批、$p$ 个 stage:
- 第一个微批走完所有 stage 需 $p\cdot t$;之后每 $t$ 出一个微批,$m$ 个微批前向总时 $(m+p-1)t$。
- 纯计算时间 $=m\cdot p\cdot t / p = m\cdot t$ 每 stage(理想各卡满载)。气泡(空转占比):
$$\text{bubble fraction}=\frac{p-1}{m+p-1}.$$
前反向都成立(反向对称)。**减气泡 = 增大 $m$**,但受激活显存约束。

**3. GPipe vs 1F1B。**
- **GPipe**(全前向后全反向):先把 $m$ 个微批**全部前向**完,再**全部反向**。简单,但**所有微批的激活同时驻留**到反向开始——激活显存峰值 $\propto m$,大 $m$ 时爆显存。
- **1F1B**(One-Forward-One-Backward, PipeDream):填满流水线后,每卡**做一个前向、紧接做一个早先微批的反向**,交替进行。气泡占比**与 GPipe 相同** $\frac{p-1}{m+p-1}$,但反向提前 → 激活**算完即释放**,峰值激活显存从 $\propto m$ 降到 $\propto p$。**这是现代 PP 的默认调度**。

**4. interleaved 与 zero-bubble。** interleaved 1F1B(Megatron)让每卡放**多段非连续层**($v$ 段),气泡进一步降到 $\frac{p-1}{v\cdot m+p-1}$(代价是通信变多)。Zero Bubble PP(2023)把反向拆成"算输入梯度"和"算权重梯度"两步、巧排调度,理论上几乎消除气泡。

**5. PP 在 3D 并行里的位置。** PP 通信最轻 → 跨机维度;TP 限机内;DP/ZeRO 复制。典型 `DP×TP×PP`:TP=8(机内 NVLink)、PP=8(跨 8 机)、DP 再复制。PP 还要配 [[065 梯度检查点与激活重计算|激活重计算]] 控激活显存。完整谱见 [[068 并行总览：DP、TP、PP、EP、SP|并行总览]]。

## 1F1B 的激活显存峰值,逐项算

GPipe 的痛点是激活峰值 $\propto m$;1F1B 把它压到 $\propto p$。具体地:1F1B 的"预热期"每张卡先做 $p-1-\text{rank}$ 个前向把流水填满,**最靠前的 stage 0 同时在飞的微批数最多 = $p$**(它要为后面所有 stage 留缓冲)。所以:
- **GPipe**:全部 $m$ 个微批前向完才反向 → 同时驻留 $m$ 份激活 → 峰值 $\propto m$。$m=64$、$p=8$ 时驻留 64 份,直接爆。
- **1F1B**:稳态下每卡最多同时持 $\le p$ 份未反向的激活 → 峰值 $\propto p$。$p=8$ 时只驻留 ≤8 份,**与 $m$ 解耦**——这才能放心把 $m$ 调到几十上百去压气泡。

单份激活 $\approx c\cdot b\cdot s\cdot d\cdot (\text{stage 层数})$。所以 1F1B 让你"既要 $m\gg p$ 压气泡、又不爆激活"——这是它取代 GPipe 成默认的根本原因(气泡占比两者相同,1F1B 纯赚显存)。

## interleaved(virtual pipeline)调度细节

普通 PP 每卡放**连续**一段层(stage 0 = 层 1-8……)。interleaved 1F1B 让每卡放 **$v$ 段非连续层**(virtual stage):8 卡、v=2 时,卡 0 同时负责层 1-4 和层 33-36。好处是气泡降到
$$\text{bubble}=\frac{p-1}{v\cdot m+p-1},$$
分母多了 $v$ 倍——相当于把"有效微批数"放大 $v$ 倍。代价:① 通信次数 ×v(每个 virtual stage 边界都要 send/recv);② 调度复杂。Megatron 默认开 interleaved,因为大模型里通信带宽够、气泡才是瓶颈。

## stage 负载均衡:首尾 stage 的隐藏不均

气泡公式假设各 stage 计算量相等,但实际**首尾 stage 更重**:
- **第一个 stage**:多了 input embedding(查表 + 位置编码)。
- **最后一个 stage**:多了 final LayerNorm + lm_head + **loss 计算**(尤其大词表的 logits 和 cross-entropy,$b\cdot s\cdot V$,可能比一整个 transformer 层还贵)。

若按"每卡相同层数"切,首尾 stage 会成为**拖慢整条流水线的瓶颈**(流水线快慢由最慢 stage 决定)。工程上常给首尾 stage **少分几层**来配平,或把 lm_head 单独处理。这是面试"PP 实战坑"的高频点。

## 3D 并行配比实战:一个 70B 模型怎么摆

设 64 卡(8 机 × 8 卡),训 70B(L=80, d=8192)。典型配置:
- **TP=8**:机内 8 卡,切单层(走 NVLink,通信最重)。
- **PP=8**:跨 8 机,每机一个 stage、放 10 层(走 InfiniBand,通信轻)。
- **DP=1**(或外层再叠):TP×PP 已用满 64 卡($8\times8$)。要扩到 512 卡就 DP=8 复制这套 64 卡组,DP 间走 ZeRO/all-reduce。
- **微批数 $m$**:取 $m\ge 4p=32$ 让气泡 $<\frac{7}{39}\approx18\%$,配 interleaved v=2 降到 $\frac{7}{71}\approx10\%$。
- **激活**:PP 配 [[065 梯度检查点与激活重计算|激活重计算]]、TP 配 [[073 序列并行与上下文并行|序列并行]] 一起控显存。

记忆口诀:**TP 机内、PP 跨机、DP 复制;通信重的往快网放(TP→NVLink),通信轻的往慢网放(PP→IB)**。

## 代码

```python
# 气泡占比与微批数 m、阶段数 p 的关系
def bubble_fraction(p, m, v=1):
    # v=每卡放的层段数（interleaved 1F1B），v=1 即普通 1F1B/GPipe
    return (p - 1) / (v * m + p - 1)

for m in [1, 4, 16, 64]:
    print(f"p=4, m={m:2d}: 气泡 {bubble_fraction(4, m):.1%}")
# p=4, m= 1: 75.0%   ← 微批=1 等于没流水，三卡全空转
# p=4, m= 4: 42.9%
# p=4, m=16: 15.8%
# p=4, m=64:  4.5%   ← m >> p 才划算
print("interleaved v=2, m=16:", f"{bubble_fraction(4,16,v=2):.1%}")  # 8.6%
```

```python
# 伪代码：1F1B 调度（对比 GPipe）
# ❌ GPipe：全前向再全反向 → 所有微批激活同时驻留，峰值激活 ∝ m，大 m 爆显存
def gpipe(stage, microbatches):
    acts = [stage.forward(mb) for mb in microbatches]   # 全部前向，激活全留着
    for a in reversed(acts):
        stage.backward(a)                               # 再全部反向

# ✅ 1F1B：填满后交替 1 前向 1 反向 → 反向尽早，激活算完即释放，峰值激活 ∝ p
def one_f_one_b(stage, microbatches, p, rank):
    warmup = p - 1 - rank                # 预热期先做几个前向把流水填满
    fwd = bwd = 0
    for _ in range(warmup):
        stage.forward(microbatches[fwd]); fwd += 1
    while bwd < len(microbatches):       # 稳态：一前一后交替
        if fwd < len(microbatches):
            stage.forward(microbatches[fwd]); fwd += 1
        stage.backward(microbatches[bwd]); bwd += 1     # 反向提前 → 及时释放激活
```

## 面试高频

- **Q:流水线并行怎么切?和张量并行有何不同?** A:PP 按层切(深度),每卡放连续几层,激活点对点逐级传递;TP 切单层矩阵(宽度),每层 all-reduce。PP 通信轻(只在 stage 边界传一个激活)适合跨机,TP 通信重限机内。
- **Q:什么是流水线气泡?占比公式?** A:填充(后面 stage 等前面喂数据)和排空(前面 stage 等后面回传梯度)时部分 GPU 空转。气泡占比 = (p−1)/(m+p−1),p=阶段数、m=微批数。增大 m 可减气泡,但激活显存峰值升高。
- **Q:为什么微批数要远大于阶段数?** A:气泡占比 (p−1)/(m+p−1),m=p 时高达 (p−1)/(2p−1)≈50%,m≫p 才趋于 0。所以微批数要远多于 stage 数,典型 m 取数十。
- **Q:GPipe 和 1F1B 区别?** A:GPipe 全前向再全反向,所有微批激活同时驻留,峰值激活∝m,大 m 爆显存;1F1B 填满后交替一前一后,气泡占比相同但反向提前、激活算完即释放,峰值激活∝p。1F1B 是现代默认。
- **Q:还有什么减气泡的办法?** A:① 增大微批数 m;② 1F1B 调度;③ interleaved 1F1B(每卡放 v 段非连续层,气泡降到 (p−1)/(v·m+p−1));④ zero-bubble PP(拆分反向、巧排调度,几乎消除气泡)。
- **Q:PP 在 3D 并行里怎么放?** A:PP 通信最轻 → 跨机维度;TP 限机内;DP/ZeRO 复制。典型 TP=8(机内)×PP=8(跨机)×DP。PP 配激活重计算控显存。
- **Q:1F1B 的激活峰值为什么是 $\propto p$ 不是 $\propto m$?** A:稳态下每卡最多同时持 $\le p$ 份未反向的激活(最靠前 stage 同时在飞 $p$ 个微批),反向尽早做、算完即释放。GPipe 全前向才反向,驻留 $m$ 份。所以 1F1B 能把 $m$ 调大压气泡而不爆显存。
- **Q:首尾 stage 为什么是 PP 的隐藏瓶颈?** A:第一个 stage 多 embedding,最后一个多 final LN + lm_head + loss(大词表的 logits/CE 可能比一层还贵)。流水线快慢由最慢 stage 定,按等层数切会让首尾拖后腿,工程上给首尾少分层配平。
- **Q:一个 64 卡 70B 训练 3D 并行怎么摆?** A:TP=8(机内 NVLink)× PP=8(跨机 IB)用满 64 卡,微批 $m\ge32$、interleaved v=2 压气泡到 ~10%,再叠 DP 扩规模;TP 配 SP、PP 配激活重计算控显存。
- **Q:interleaved 1F1B 为什么能再降气泡,代价是什么?** A:每卡放 $v$ 段非连续层,气泡降到 $(p-1)/(vm+p-1)$,相当于把有效微批放大 $v$ 倍;代价是通信次数 ×v、调度更复杂。
- **陷阱**:① m=1 等于没流水(全空转);② GPipe 大 m 激活爆显存;③ stage 负载要均衡(各 stage 计算量相近),否则慢的拖整条流水线;④ 跨 stage 边界要处理好首尾(embedding/loss);⑤ 首尾 stage 隐性更重,按等层数切会失衡;⑥ interleaved 通信 ×v,带宽不够反而更慢。

## 关键事实

- **GPipe**:Huang 等(Google,2019,arXiv:1811.06965)提出微批流水线,气泡占比 $\frac{p-1}{m+p-1}$;全前向后全反向 + 重计算控激活显存。
- **PipeDream / 1F1B**:Narayanan 等(MSR,2019,SOSP'19,arXiv:1806.03377)提出 1F1B 调度,交错前向反向、反向尽早,峰值激活显存从 $\propto m$ 降到 $\propto p$,气泡占比与 GPipe 相同。
- **interleaved 1F1B**:Narayanan 等(Megatron,2021,arXiv:2104.04473)让每卡放多段非连续层,气泡降到 $\frac{p-1}{v\cdot m+p-1}$($v$=每卡段数),以更多通信换更少气泡。
- **Zero Bubble PP**:Qi 等(2023,arXiv:2401.10241)拆分反向为输入梯度与权重梯度两步,巧排调度近乎消除气泡。
- PP 通信只在 stage 边界点对点(send/recv)传激活,通信量与频率远低于 TP 的每层 all-reduce → 适合跨机;3D 并行中作跨机维度(Megatron-Turing NLG 530B,2022,arXiv:2201.11990)。
