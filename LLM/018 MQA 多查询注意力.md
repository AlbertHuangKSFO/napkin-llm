[[018 MQA 多查询注意力]]:让所有注意力头**共享同一份 K/V**(只保留多个 Q 头),把 [[102 KV-Cache|KV-Cache]] 显存和读取量压到 [[005 多头注意力 Multi-Head|MHA]] 的 1/h,大幅加速自回归解码。

## 直觉:Q 头各看各的,K/V 一份就够
[[005 多头注意力 Multi-Head|MHA]] 里每个头都有自己的 Q、K、V 三套投影,共 h 套 K/V。但 Shazeer 发现:**decode 阶段真正的瓶颈不是算力,是显存带宽**——每生成一个 token,都要把过去所有位置的 K/V(即 [[102 KV-Cache|KV-Cache]])从显存搬进计算单元。K/V 头越多,搬得越多。

MQA 的赌注:**多个 Q 头可以"问不同问题",但它们查的"资料库"(K/V)其实可以是同一份**。于是只保留 1 份 K、1 份 V,所有 Q 头都去这一份里做注意力。Q 头数 h 不变(表达力主要靠 Q 的多样性),K/V 头数从 h 砍到 1。

类比:一个图书馆(共享 K/V)里坐着 h 个读者(Q 头),每人带着不同的问题去查同一批书,而不是给每人单独复制一套书架。

**为什么瓶颈在带宽而不是算力(算术强度视角)。** 衡量一个 kernel 是 compute-bound 还是 memory-bound,看它的**算术强度**(arithmetic intensity = FLOPs / 字节)。decode 阶段每步只处理 1 个新 Q token,却要读入全部历史 KV:读 KV 的字节数 $\propto h\cdot L$,而注意力的浮点运算也 $\propto h\cdot L$——两者同阶,但现代 GPU 的 FLOP:字节比(A100 约 200:1)远大于 1,意味着"每读一个字节只配几次浮点运算"的注意力 decode 严重**卡在读 KV 上**,算力大量空转。MQA 把读 KV 的字节直接砍到 1/h → 算术强度提高 h 倍 → 把 decode 从极度 memory-bound 往 compute-bound 拉,这才是提速的本质。prefill(并行处理整段 prompt)是 compute-bound,MQA 对 prefill 提速有限,**收益主要在 decode**。

## 例子:小数字算一笔显存账
设 h=32 头、d_head=128、序列长 L=4096、层数 n_layer=32、用 fp16(2 字节)。

**MHA** 每 token 的 KV-Cache:
$$2 \times h \times d_{head} \times n_{layer} \times 2\text{B} = 2\times32\times128\times32\times2 = 1{,}048{,}576 \text{ B} \approx 1\text{ MB}$$
4096 个 token:约 **4 GB**(单序列!batch 一大就爆)。

**MQA**(K/V 头数 g=1):把上式的 h=32 换成 g=1:
$$2\times1\times128\times32\times2 = 32{,}768 \text{ B} = 32\text{ KB / token}$$
4096 个 token:约 **128 MB**。显存降到 1/32,搬运量同步降到 1/32 → decode 吞吐大涨。

> Q 这部分参数和算力**不省**(还是 h 个 Q 头);省的是 K/V 的缓存与读取。

**再算一笔 batch 账(为什么 MQA 让吞吐暴涨)。** 上面是单序列。设显存里除权重外还剩 20 GB 给 KV-Cache:
- MHA 每序列(L=4096)占 4 GB → 最多并发 **5** 条序列;
- MQA 每序列占 128 MB → 最多并发约 **160** 条序列。
batch 从 5 涨到 160(×32),而 decode 是 memory-bound、batch 内可摊薄权重读取 → **吞吐(tokens/s)近乎线性随 batch 上涨**。这就是 MQA"省显存"如何转化成"吞吐数十倍"的链条:省显存 → 大 batch → 高 GPU 利用率 → 高吞吐。

**逐步对比表(d_head=128, n_layer=32, fp16, 每 token 字节)。**

| 方案 | K/V 头数 $g$ | 每 token KV 字节 | 相对 MHA |
|---|---|---|---|
| MHA | 32 | $2\cdot32\cdot128\cdot32\cdot2=1{,}048{,}576$ | 1 |
| GQA(g=8) | 8 | $262{,}144$ | 1/4 |
| GQA(g=4) | 4 | $131{,}072$ | 1/8 |
| MQA | 1 | $32{,}768$ | 1/32 |

公式只有一个变量 $g$:$\text{字节/token}=2\cdot g\cdot d_{head}\cdot n_{layer}\cdot\text{dtype}$。把它背下来,面试现场任意配置都能口算。

## 原理:只换 K/V 的头维度
标准多头(见 [[006 注意力的矩阵形式与张量形状|矩阵形式]]),头 $i$ 的输出:
$$\text{head}_i = \text{softmax}\!\left(\frac{Q_i K_i^\top}{\sqrt{d_{head}}}\right) V_i,\quad i=1,\dots,h$$
每个头有独立的 $Q_i,K_i,V_i$。

MQA 把 K、V 的下标 $i$ 去掉,**全体共享** $K,V$:
$$\text{head}_i = \text{softmax}\!\left(\frac{Q_i K^\top}{\sqrt{d_{head}}}\right) V,\quad K,V \text{ 与 } i \text{ 无关}$$

形状上:Q 投影矩阵 $W_Q \in \mathbb{R}^{d \times h\,d_{head}}$(不变),而 K、V 投影从 $h\,d_{head}$ 缩成 $d_{head}$:
$$W_K, W_V \in \mathbb{R}^{d \times d_{head}}\quad(\text{原 MHA 是 } d \times h\,d_{head})$$

KV-Cache 大小因此正比于 K/V 头数 $g$:
$$\text{Cache} \propto 2 \cdot L \cdot g \cdot d_{head} \cdot n_{layer},\qquad \text{MQA: } g=1$$

这正是降低 [[014 注意力复杂度 O(n²) 与瓶颈|O(n²) 瓶颈]]中"显存/带宽"那一维的手段(算力仍 $O(n^2)$,但访存量从 $\propto h$ 降到 $\propto 1$)。

## 代码:从 MHA 到 MQA 的最小改动
```python
import torch, torch.nn.functional as F

# ❌ MHA:K/V 也是 h 个头,缓存 h 份
class MHA(torch.nn.Module):
    def __init__(self, d, h):
        super().__init__()
        self.h, self.dh = h, d // h
        self.Wq = torch.nn.Linear(d, d)        # h*dh
        self.Wk = torch.nn.Linear(d, d)        # h*dh  ← 占大头
        self.Wv = torch.nn.Linear(d, d)        # h*dh  ← 占大头
        self.Wo = torch.nn.Linear(d, d)
    def forward(self, x):                       # x:(B,n,d)
        B, n, _ = x.shape
        q = self.Wq(x).view(B, n, self.h, self.dh).transpose(1, 2)  # (B,h,n,dh)
        k = self.Wk(x).view(B, n, self.h, self.dh).transpose(1, 2)
        v = self.Wv(x).view(B, n, self.h, self.dh).transpose(1, 2)
        o = F.scaled_dot_product_attention(q, k, v)                 # (B,h,n,dh)
        return self.Wo(o.transpose(1, 2).reshape(B, n, -1))

# ✅ MQA:K/V 只投影到 1 个头,广播给所有 Q 头,缓存仅 1 份
class MQA(torch.nn.Module):
    def __init__(self, d, h):
        super().__init__()
        self.h, self.dh = h, d // h
        self.Wq = torch.nn.Linear(d, d)               # 仍 h 份
        self.Wk = torch.nn.Linear(d, self.dh)         # 只 1 份 ← KV-Cache 砍到 1/h
        self.Wv = torch.nn.Linear(d, self.dh)         # 只 1 份
        self.Wo = torch.nn.Linear(d, d)
    def forward(self, x):
        B, n, _ = x.shape
        q = self.Wq(x).view(B, n, self.h, self.dh).transpose(1, 2)  # (B,h,n,dh)
        k = self.Wk(x).view(B, n, 1, self.dh).transpose(1, 2)        # (B,1,n,dh)
        v = self.Wv(x).view(B, n, 1, self.dh).transpose(1, 2)
        # enable_gqa=True 让 1 个 K/V 头自动广播给 h 个 Q 头
        o = F.scaled_dot_product_attention(q, k, v, enable_gqa=True) # (B,h,n,dh)
        return self.Wo(o.transpose(1, 2).reshape(B, n, -1))
```
真实推理里,缓存的就是 `k,v` 这两个 `(B,1,n,dh)` 张量——比 MHA 小 h 倍。

**手动广播版(理解 `enable_gqa` 背后做了什么)。** 老版 PyTorch 没有 `enable_gqa`,要手动把 1 个 K/V 头扩成 h 个再算:
```python
# ✅ 等价的手动写法:缓存仍只存 1 份,计算前临时 expand(不复制显存)
def mqa_manual(q, k1, v1, h):                # q:(B,h,n,dh)  k1,v1:(B,1,n,dh)
    k = k1.expand(-1, h, -1, -1)            # (B,h,n,dh) 视图,不实际占显存
    v = v1.expand(-1, h, -1, -1)
    return F.scaled_dot_product_attention(q, k, v, is_causal=True)
# ❌ 易错:写成 k1.repeat(1,h,1,1) —— repeat 会真复制出 h 份占显存,违背 MQA 初衷;
#         expand 只是广播视图。缓存里永远只该存那 1 份 (B,1,n,dh)。
```
关键认知:广播只发生在**注意力计算的瞬间**(且常被 kernel 融合掉),**进 cache 的永远是 1 份**——省的是 cache,不是算的那一刻的形状。

## 面试高频
- **MQA 省的到底是什么?** 省 [[102 KV-Cache|KV-Cache]] 的显存与**显存带宽读取量**(decode 每步要读全部 KV),不是省 Q 的算力。瓶颈在带宽,不在 FLOPs。
- **为什么 Q 头数不能也减?** Q 的多样性是表达力来源(不同头关注不同模式);K/V 共享损失较小,但 Q 共享会明显掉质量。所以只削 K/V。
- **MQA 的代价?** 质量略降、训练可能不稳定。这正是 [[019 GQA 分组查询注意力|GQA]] 诞生的原因(折中)。
- **MQA 与 MHA 参数量差多少?** K/V 投影从 $2\cdot d\cdot h\,d_{head}$ 降到 $2\cdot d\cdot d_{head}$,省下 $(h-1)/h$ 的 K/V 参数;但总参数里 FFN 占大头,整体参数变化不大——**主要收益在推理显存**。
- **能从已有 MHA 模型转 MQA 吗?** 能,但需"uptraining"少量再训练(把 h 份 K/V 头做均值池化作初始化),否则直接共享会掉点——见 [[019 GQA 分组查询注意力|GQA]] 论文的转换配方。
- **MQA 对 prefill 和 decode 哪个提速更明显?** decode。prefill 并行处理整段 prompt 是 compute-bound,KV 还没成为读取瓶颈;decode 每步读全部历史 KV 是 memory-bound,MQA 把读取量砍 h 倍 → 主要在 decode 见效。
- **MQA 为什么有时训练不稳/掉点更明显?** K/V 只 1 份,梯度信号被所有 Q 头共享,表达瓶颈集中,深层大模型上更易体现质量损失;这也是 GQA 用"留几份"来缓解的原因。
- **MQA 省了显存,FLOPs 省了吗?** 注意力的 $QK^\top$ 和 $\cdot V$ 仍按 h 个 Q 头算,FLOPs 基本不变(K/V 投影那一点点投影 FLOPs 省了,可忽略)。**省的是访存,不是计算量**——这是和稀疏/线性注意力的根本分野。
- **MQA 和 [[025 FlashAttention(IO 感知精确注意力)|FlashAttention]] 冲突吗?** 不冲突,正交。FlashAttention 优化单次注意力前/反向的 HBM↔SRAM IO;MQA 优化 decode 时 KV-Cache 的总量与读取。二者叠加是常态。

## 关键事实
- 出处:Noam Shazeer,*Fast Transformer Decoding: One Write-Head is All You Need*,2019,arXiv:1911.02150。标题"One Write-Head"即指只有一份 K/V(写头)。
- 核心结论:K/V 跨头共享"greatly reduces ... memory bandwidth requirements of incremental decoding",decode 大幅提速,质量仅"minor degradation"。
- 采用模型:PaLM、Falcon 等用纯 MQA;但 2023 年后主流转向折中的 [[019 GQA 分组查询注意力|GQA]](LLaMA-2/3、Mistral)。
- KV-Cache 大小公式:$\propto 2\cdot L\cdot g\cdot d_{head}\cdot n_{layer}$,MQA 取 $g=1$(MHA 为 $g=h$)。
- 与后续关系:MQA 是 [[019 GQA 分组查询注意力|GQA]] 的极端特例($g=1$),也是 [[103 KV-Cache 优化：GQA、量化、驱逐与前缀共享|KV-Cache 优化]]的起点之一;更进一步的低秩方案见 [[020 MLA 多头潜在注意力(DeepSeek)|MLA]]。
