[[121 机密推理与隐私：TEE、加密简述]] 回答一个尖锐问题:把含隐私的 prompt 和自有模型权重送上云推理时,**怎么让云厂商、宿主 OS、Hypervisor、运维管理员乃至同机其他租户都看不到明文?****机密计算(Confidential Computing)**用硬件**可信执行环境(TEE)**给出答案:把计算关进一个内存对外加密隔离的「飞地(enclave)」,只有飞地内部能解密使用数据。关键转折是 **GPU TEE**——**NVIDIA H100/H200 Confidential Computing**(首款支持机密计算的 GPU),配合 CPU 侧的 **AMD SEV-SNP / Intel TDX** 机密虚拟机,让 prompt、权重、[[015 KV-Cache 的显存账(逐层手算)|KV-Cache]] 全在飞地内明文计算、对外加密。它把信任边界从「信云厂商」收缩到「信芯片厂」,是医疗/金融/法务等场景上云推理的合规底座,直接关系 [[AI 安全/AI 安全|AI 安全]] 与 [[111 多租户隔离、配额与限流|多租户隔离]];与 [[122 端侧与边缘部署：量化、蒸馏与移动推理|端侧部署]] 形成「云端可信」与「数据不出端」两条隐私路线,也是 [[110 成本与 TCO：每百万 token 成本怎么算|成本 TCO]] 里需计入开销的一项。

## 直觉类比
普通云推理像**把保险箱密码写在明信片上寄给酒店前台代办**:酒店(云厂商/运维)全程能看到内容。机密推理像**租了一间带防弹玻璃的密室**:你的资料(prompt、权重)加密送进去,只有密室里的处理器能拆封处理,玻璃外谁都看不见;而且密室门口有一套**公证机制(远程证明)**——它出示一张由制造商签名、防伪的「身份证 + 监控录像」,向你证明「这确实是正品密室、里面跑的正是你指定的程序」,你验证通过后才把钥匙交进去。GPU TEE 则是把这间密室从「只有 CPU」扩展到「连显卡算力也在密室内」。

## 小数字例子
设一条机密推理请求:模型权重 14 GB、单 GPU。
- **保护对象**:加密的 prompt(如患者病历)+ 加密的权重在 **H100 显存里始终密文**,即便云厂商有物理/管理员权限也导不出明文。
- **性能开销**:H100/H200 机密计算模式下约保 **95–99% 原生性能**;开销主要来自 CPU↔GPU 经「加密 bounce buffer」搬数据。小批/短序列相对开销更明显(搬运占比高),大批吞吐趋近原生。
- **证明流程**:GPU 生成一份由 **NVIDIA 签名**的密码学报告,证明①是真 H100/H200、②运行的正是你指定代码;客户端验证通过**才**把权重/数据密钥下发进飞地——验证失败则一个字节明文都不进去。
- **信任收缩**:不开机密计算时你得信「云厂商 + 运维 + Hypervisor + 同租户」一长串;开了之后理论信任根收缩到「芯片厂硬件信任根 + 固件」。

## 原理:飞地、加密搬运与远程证明
TEE 给出**机密性**(外部读不到飞地内存明文)与**完整性/可验证性**(能证明里面跑的是约定代码)。CPU 侧由 SEV-SNP / TDX 建立内存加密的机密 VM;**H100/H200** 把 GPU 纳入这条信任链:片上**硬件信任根(root of trust)**锚定,模型权重在显存中保持加密,CPU 与 GPU 间数据走**加密 bounce buffer**、PCIe 总线加密。把可信集合记作 TCB(可信计算基),机密计算的目标是**最小化 TCB**:

$$
\text{TCB} = \{\text{CPU/GPU 硬件信任根},\ \text{飞地内固件/代码}\},\quad
\text{攻击面} \downarrow\ \text{当}\ |\text{TCB}|\downarrow
$$

**远程证明(remote attestation)**是信任的闭环:验证方在下发密钥前校验飞地报告,通过才解封(seal/unseal)密钥,且**无需改应用代码**。注意边界:TEE **不**自动防全部侧信道、**不**修复应用自身逻辑漏洞,信任根仍依赖芯片厂诚实与固件无后门——它把信任收缩、不是消灭。机密性可粗记为:数据在「传输中、存储中、**使用中(in-use)**」三态都加密,而 TEE 补的正是最难的「使用中」一态。

## 配置 / 代码
```yaml
# 在机密 GPU 上跑推理:先证明环境可信,验证通过才下发密钥
# 1) 机密 VM(Intel TDX 或 AMD SEV-SNP)+ H100/H200 机密计算模式
runtime:
  cvm: tdx                 # 或 sev-snp:内存对宿主加密隔离
  gpu: h100-cc-on          # GPU Confidential Computing 开启

# 2) 客户端侧的证明门控(伪流程)
attest_then_serve:
  - fetch_gpu_report       # GPU 产出 NVIDIA 签名的密码学报告
  - verify:                # 校验:真 H100/H200 + 期望的代码度量
      vendor_signature: nvidia
      measurement: <expected-hash>
  - if_ok: release_keys    # 仅在证明通过后解封 权重/数据 解密密钥
  - else: abort            # 任一不符 → 拒绝,不下发任何明文密钥
```

## 面试高频
- **机密推理到底保护什么、防谁?** 保护「使用中(in-use)」的 prompt、模型权重、KV-Cache;防云厂商、宿主 OS、Hypervisor、运维管理员、同机其他租户读取明文或导出权重。把信任从「信云厂商」收缩到「信芯片厂硬件信任根」。
- **GPU TEE 和 CPU TEE 的关系?** CPU 侧 SEV-SNP/TDX 建机密 VM(内存对宿主加密);H100/H200 把 GPU 纳入信任链,权重在显存保持加密、CPU↔GPU 走加密 bounce buffer、PCIe 加密,使 GPU 算力也在飞地内。
- **远程证明(attestation)解决什么?** 让验证方在下发密钥前确信「环境是真硬件 + 跑的是约定代码」:GPU 出示芯片厂签名的密码学报告,验证通过才解封密钥,且无需改应用代码——没有它,飞地「自说自话」不可信。
- **性能开销有多大,来自哪?** H100/H200 机密计算约保 95–99% 原生;开销主要来自 CPU↔GPU 加密搬运与启动证明,小批/短序列相对更明显,大批趋近原生。
- **它的安全边界/局限?** 不自动防所有侧信道、不修应用自身逻辑漏洞、信任根仍依赖芯片厂诚实与固件无后门;是「收缩信任」而非「消灭信任」。
- **机密推理 vs 端侧部署,隐私上怎么选?** 机密推理 = 数据上云但在飞地内加密计算(要大模型/弹性算力时);端侧 = 数据根本不出设备(要离线/极致隐私、模型可压到端上时)。二者互补。

## 关键事实
- **NVIDIA H100** 是首款支持机密计算的 GPU,**Hopper Confidential Computing(HCC)**于 **2024 年(约 2 月发布、3 月 GA)**进入通用可用,CUDA 12.4 起支持单卡直通;H200 延续。
- 机制:片上**硬件信任根**锚定 TEE,**模型权重在 GPU 显存保持加密**(云厂商也导不出),CPU↔GPU 经**加密 bounce buffer**搬数据;CPU 侧配 **AMD SEV-SNP**(EPYC)或 **Intel TDX**(Xeon)机密 VM。
- 性能:H100/H200 机密计算模式约保 **95–99% 原生**;**远程证明**由 GPU 产出 NVIDIA 签名报告,证明真硬件 + 指定代码,**无需改应用代码**。
- 生态(2025–2026):Azure 已 GA「H100 + 机密 VM」;Phala 等用 **Intel TDX + H100/H200** 提供机密 LLM 推理、可验证计算;Akamai 等亦推机密推理云。
- 与 [[122 端侧与边缘部署：量化、蒸馏与移动推理|端侧部署]] 互补(云端可信 vs 数据不出端),开销需计入 [[110 成本与 TCO：每百万 token 成本怎么算|成本 TCO]];隐私/合规动机详见 [[AI 安全/AI 安全|AI 安全]]、[[111 多租户隔离、配额与限流|多租户隔离]]。
