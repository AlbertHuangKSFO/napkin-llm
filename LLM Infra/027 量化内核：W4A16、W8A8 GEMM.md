[[027 量化内核：W4A16、W8A8 GEMM]] 是把量化模型真正跑快的"最后一公里":把低比特权重的**反量化(dequant)和矩阵乘(GEMM)融合进一个 GPU 内核**,避免先解压回 FP16 再算的两趟 HBM 往返。**W4A16**(权重 4-bit、激活 16-bit)代表内核有 Marlin、Machete;**W8A8**(权重激活都 8-bit)则用整数/FP8 Tensor Core 直接算。没有这类专用内核,[[LLM/095 GPTQ|GPTQ]]、[[LLM/096 AWQ 与 SmoothQuant|AWQ]] 量出来的模型只省显存、不提速。

## 直觉类比
量化把模型权重压成了"压缩包"(INT4)。朴素做法:先把整个压缩包**解压到磁盘**(反量化成 FP16 写回 HBM),再读出来算——解压写回那一趟白白浪费带宽。融合内核的做法是**边解压边用**:从 HBM 只搬压缩包(小 4 倍),在芯片内的寄存器/SMEM 里解压一小块、立刻喂给 Tensor Core 算,算完即丢。压缩包始终没在显存里"摊开过"。

## 小数字例子
一层 $4096 \times 4096$ 权重矩阵,decode 时 batch=1:
- **FP16 权重**:$4096^2 \times 2 = 33.5$ MB,要从 HBM 全搬一遍。
- **INT4 权重**:$4096^2 \times 0.5 = 8.4$ MB,搬运量降到 ¼。
decode 是 memory-bound(瓶颈在搬权重),所以**搬运量降 4 倍 ≈ 提速接近 4 倍**——前提是反量化不另起一趟 HBM 写回。若朴素地"先 dequant 写回 33.5 MB、再读 33.5 MB 算",反而多搬了 67 MB,得不偿失。这就是为什么必须**融合**。

## 原理:三种量化的内核差异
非对称量化把 FP16 权重 $w$ 编码为整数 $q$,配每组(group)的缩放 $s$ 与零点 $z$:

$$
q = \text{round}\!\Big(\frac{w}{s}\Big) + z,\qquad
\hat{w} = (q - z)\cdot s
$$

- **W4A16(权重 4bit / 激活 16bit)**:GEMM 仍走 FP16 Tensor Core,内核在算之前**就地把 INT4 反量化成 FP16**,与 GEMM 融合。省的是**带宽与显存,算力不变**;激活保 16-bit 故精度损失小。代表:**Marlin**(Ampere 及以后,INT4 weight-only)、**Machete**(Hopper SM90a,vLLM 0.6.2+ 的 w4a16/w8a16 后端)。常配 **SplitK** 把 K 维切分以提升小 batch 下的并行度。
- **W8A8(权重 8bit / 激活 8bit)**:权重和激活都量化,直接用 **INT8 / FP8 Tensor Core** 计算——算力相对 FP16 **翻倍**。但激活也量化,精度更敏感,需 [[LLM/096 AWQ 与 SmoothQuant|SmoothQuant]] 把激活离群值"平移"到权重端;计算时 $Y_{int32} = X_{int8} \cdot W_{int8}^\top$,输出再 requantize 回 FP16。仅 Hopper/Ada 官方支持。

**W8A8 为什么非要 SmoothQuant:迁移离群值的变换式推导。** 激活 $X$ 有少数通道是离群值(幅度大几十倍),按整张量量化时大数撑大尺度、小数全压成 0,INT8 精度崩。SmoothQuant 的招是引入一个**逐通道**的平滑因子对角阵 $s$,把难量化的激活离群"平移"给天生好量化的权重——靠的是 GEMM 里插一对互逆缩放、乘积不变:

$$
Y = X W = (X\,\mathrm{diag}(s)^{-1})\,(\mathrm{diag}(s)\,W) = \hat{X}\,\hat{W},\qquad
s_j=\frac{\max_i |X_{ij}|^{\alpha}}{\max_i |W_{ij}|^{1-\alpha}}
$$

$\hat X=Xs^{-1}$ 把激活的离群通道**除小**、$\hat W=sW$ 把对应权重**乘大**,两边动态范围都被拉回好量化的区间($\alpha$ 常取 0.5,平分难度)。$s$ 离线算好折进前一层,推理零额外开销;于是 $\hat X,\hat W$ 都能稳稳走 INT8 Tensor Core。这就是 W8A8 的前提——不做这步平滑,激活直接 INT8 几乎必掉点。

一句话:**W4A16 解 decode 的带宽墙,W8A8 解 prefill/大 batch 的算力墙**。

## 内核伪码与命令
```python
# W4A16 融合内核骨架(Triton 风格,反量化-GEMM 融合 + SplitK)
@triton.jit
def gemm_w4a16(X_ptr, Wq_ptr, scale_ptr, zero_ptr, Y_ptr, M, N, K, GROUP):
    pid_m, pid_n, pid_k = tl.program_id(0), tl.program_id(1), tl.program_id(2)  # SplitK
    acc = tl.zeros((BM, BN), dtype=tl.float32)
    for k in range(K_start, K_end, BK):
        x = tl.load(X_block)                       # FP16 激活,直接搬
        q = tl.load(Wq_block)                       # INT4 权重(打包),搬运量 ¼
        s = tl.load(scale_ptr + (k // GROUP))       # 该组 scale
        z = tl.load(zero_ptr  + (k // GROUP))
        w = (q.to(tl.float16) - z) * s              # ① 就地反量化,不落 HBM
        acc += tl.dot(x, w)                          # ② Tensor Core GEMM,与①融合
    tl.atomic_add(Y_block, acc.to(tl.float16))     # SplitK:多个 pid_k 原子累加
```

## 面试高频
- **为什么量化要写专用 kernel,不能直接 dequant?** 朴素反量化要把权重摊回 FP16 写 HBM 再读,多两趟带宽;decode 本就 memory-bound,这样反而更慢。融合内核只搬压缩权重、在片上解压即用。
- **W4A16 和 W8A8 区别与适用场景?** W4A16:只量权重、GEMM 仍 FP16,省带宽,适合小 batch decode;W8A8:权重激活都 8bit、用整数/FP8 Tensor Core,算力翻倍,适合大 batch/prefill。
- **W4A16 算力为什么没提升?** GEMM 还是 FP16 计算,只是搬运的权重变小;它解的是带宽墙不是算力墙。
- **Marlin 和 Machete 是什么?** vLLM 里的混合精度 GEMM 内核:Marlin 面向 Ampere+ 的 INT4 weight-only,Machete 面向 Hopper(SM90a)动态生成 w4a16/w8a16 内核。
- **W8A8 为什么更难?** 激活也量化,激活有离群值,精度敏感,需 SmoothQuant 等把离群值迁移到权重;且仅 Hopper/Ada 官方支持。
- **SplitK 解决什么?** 小 batch 下 M 维太小、SM 占用率低,把 K 维切给多个 block 并行再原子累加,提升利用率。

## 关键事实
- **Marlin**:INT4 weight-only(W4A16)GEMM,Ampere 及以后;vLLM 的 `gptq_marlin`/`awq_marlin` 后端。
- **Machete**:Hopper(SM90a)混合输入 GEMM,Red Hat/Neural Magic,**vLLM 0.6.2+**(2024),w4a16/w8a16、GPTQ 模型后端,按 dtype 动态生成内核。
- **W8A8**:权重激活均 8-bit(INT8 或 FP8),官方仅 **Hopper/Ada** 支持;FP8 W8A8 见 [[LLM/098 FP8 训练推理与 AQLM 极低比特|FP8]]。
- 融合 W4A16 + **SplitK** 工作分解显著加速量化推理(arXiv 2402.00025,2024)。
- 量化来源:[[LLM/095 GPTQ|GPTQ]]、[[LLM/096 AWQ 与 SmoothQuant|AWQ]];内核用 [[002 GPU 架构：SM、CUDA Core 与 Tensor Core|Tensor Core]]。可用 [[028 Triton：用 Python 写 GPU kernel|Triton]] 实现。
