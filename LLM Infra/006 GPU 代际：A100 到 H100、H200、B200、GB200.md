[[006 GPU 代际：A100 到 H100、H200、B200、GB200|GPU 代际]] 串起 Ampere → Hopper → Blackwell 三代数据中心卡:**显存与带宽的增长往往快于算力**(因为 [[001 LLM 推理的系统视角：从一次请求到一张卡|decode]] 是带宽活),每代还新增更低[[005 数值格式：FP32、TF32、BF16、FP8、FP4|数值格式]](Hopper 加 FP8、Blackwell 加 FP4),并用 [[002 GPU 架构：SM、CUDA Core 与 Tensor Core|NVLink]] 把多卡乃至整机架拼成"一张大 GPU"。

类比汽车换代:不是单纯堆马力(算力),而是**同时加宽油管(带宽)、加大油箱(显存)、换更省油的引擎(FP8/FP4)**。H200 尤其典型——它和 H100 算力几乎一样,只把 HBM3 换成更大更快的 HBM3e,因为厂商清楚瓶颈在带宽不在算力。

各代关键规格(SXM/单卡,dense;TFLOPS 为概数):

| 维度 | A100 (Ampere) | H100 (Hopper) | H200 (Hopper) | B200 (Blackwell) |
|---|---|---|---|---|
| 显存 | 80GB HBM2e | 80GB HBM3 | 141GB HBM3e | 192GB HBM3e |
| 带宽 | 2.0 TB/s | 3.35 TB/s | 4.8 TB/s | 8.0 TB/s |
| FP16 Tensor | 312 TFLOPS | ~989 TFLOPS | ~989 TFLOPS | ~2250 TFLOPS |
| FP8 Tensor | — | ~1979 TFLOPS | ~1979 TFLOPS | ~4500 TFLOPS |
| FP4 Tensor | — | — | — | ~9000 TFLOPS |
| NVLink | 3 代 600 GB/s | 4 代 900 GB/s | 4 代 900 GB/s | 5 代 1.8 TB/s |
| SM 数 | 108 | 132 | 132 | 双 die、208B 晶体管 |

具体感受这对 LLM 的意义(70B FP16,decode 单 token = 权重/带宽):A100 $140/2.0\approx70$ ms → H100 $140/3.35\approx42$ ms → H200 $140/4.8\approx29$ ms → B200 $140/8.0\approx18$ ms。**纯换卡、不改模型,decode 就快了近 4 倍**,全来自带宽。

**GB200 NVL72**(机架级,2024–2025):
- 72 个 B200 + 36 个 Grace CPU,液冷整机架。
- GB200 Superchip = 2×B200 + 1×Grace,经 **NVLink-C2C 900 GB/s** 缓存一致互联。
- 全机架 **13.4 TB 统一 GPU 显存**,NVSwitch 全互联 **130 TB/s** all-to-all。
- **1.44 EFLOPS FP4**(含稀疏),整机 ~120 kW。

原理:为何带宽优先于算力?decode 受限于 $t_{\text{token}} \ge 2P/\text{BW}_{\text{HBM}}$([[004 算力 vs 带宽：Roofline 与算术强度|Roofline]] 斜屋顶),而 [[003 GPU 内存层级：HBM、L2、SRAM、寄存器|HBM 带宽]] 是分母——堆 Tensor Core(平屋顶)对 decode 没用,只有抬带宽或合并 batch。NVLink 则解决另一维度:大模型一张卡装不下,需多卡张量并行/流水并行,卡间每步要交换激活,**NVLink 带宽决定多卡协同的通信开销**。GB200 把 72 卡用 130 TB/s 全互联,逼近"当成一张大卡"用,使万亿参数模型的并行通信不再是瓶颈。

代际选型与 decode 上限速查:

```python
gens = {  # name: (HBM_GB, BW_TBs, FP16_TFLOPS_dense)
    "A100": (80, 2.0, 312), "H100": (80, 3.35, 989),
    "H200": (141, 4.8, 989), "B200": (192, 8.0, 2250),
}
P = 70  # 70B 模型
for name, (gb, bw, tf) in gens.items():
    fits = "✅装得下" if gb >= P*2 else "❌单卡装不下(需多卡)"
    ms = (P*1e9*2) / (bw*1e12) * 1e3
    print(f"{name}: HBM {gb}GB {fits} | decode 上限 {1000/ms:.0f} tok/s ({ms:.0f}ms)")
# A100: 80GB ❌单卡装不下(140>80,需多卡) | 14 tok/s
# H100: 80GB ❌单卡装不下 | 24 tok/s
# H200: 141GB ✅装得下 | 34 tok/s   ← 141>140,单卡刚好能装 70B FP16
# B200: 192GB ✅装得下 | 48 tok/s
```

```python
# ❌ 选型只看 FP16 TFLOPS("谁算力高选谁")
# ✅ 推理选型先看:能否装下(HBM 容量)→ decode 多快(HBM 带宽)→ 再看算力(prefill)
# 这也是 H200 卖点:算力同 H100,但更大显存+更高带宽,推理体验显著更好
```

输出点明 H200 的实战价值:141GB 让 70B FP16 单卡刚好装下(H100 的 80GB 装不下),省去多卡通信开销。

## 面试高频
- **Q:H100 和 H200 算力一样,差别在哪?为什么这么设计?** A:H200 把 HBM3(80GB/3.35TB/s)换成 HBM3e(141GB/4.8TB/s),算力不变。因为推理 decode 是 memory-bound,瓶颈在带宽和容量;更大显存还能单卡装下更大模型/更长上下文。陷阱:以为新一代必然算力更高——同架构改款可只升带宽。
- **Q:每代 GPU 新增了什么低精度格式,意义是什么?** A:Hopper(H100)新增 FP8、Blackwell(B200)新增 FP4。每降一档位宽,Tensor Core 吞吐翻倍、显存和 HBM 流量减半,直接利好显存受限和带宽受限场景。陷阱:忽略低位宽需缩放(FP8 per-tensor/block、FP4 MXFP4 块缩放)保精度。
- **Q:GB200 NVL72 是什么,解决什么问题?** A:把 72 个 B200 + 36 个 Grace CPU 用第 5 代 NVLink/NVSwitch(130 TB/s 全互联)拼成一个机架级"超级 GPU",13.4TB 统一显存,目标是让万亿参数模型的多卡并行通信不再是瓶颈,把整机架当一张大卡用。陷阱:把它当成"72 张独立卡"——关键是高带宽全互联让它们协同如一。
