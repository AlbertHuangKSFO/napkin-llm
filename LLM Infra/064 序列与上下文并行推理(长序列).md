这是 [[LLM Infra]] 域里专治"长 prompt 单卡放不下"的一维并行,与训练侧的 [[LLM/073 序列并行与上下文并行|序列上下文并行]] 同源。**上下文并行 / 序列并行(context parallelism, CP)**把一条**长序列沿 token 维切成 P 段**分到 P 张卡,每卡只持有本段的 Q/K/V 与 [[015 KV-Cache 的显存账(逐层手算)|KV-Cache]];注意力是全局的(每个 token 要看到前面所有 token),于是用 **Ring Attention** 让 **KV 块沿环单向流转**:每一步各卡把手里的 KV 块传给下游邻居、同时收上游的块,配合 [[023 online softmax 与数值稳定|online softmax]] 增量累加,转 P-1 步后每段 Q 就看全了整条序列。它和 [[057 张量并行推理：延迟换显存|TP]] 正交——TP 切的是隐藏维(每层 all-reduce),CP 切的是序列维(KV 绕环点对点),专门让显存随卡数近线性下降。

把它想成一桌人传阅一摞档案。每人(GPU)手里先拿到全卷宗的一段(序列段),还要逐页核对自己段里每个问题和整摞档案的关系(全局注意力)。与其把整摞复印给每个人(单卡存全部 KV,放不下),不如**绕桌传阅**:每一轮你把手上这叠传给右邻、同时接左邻传来的那叠,边接边把相关页的笔记累加进去(online softmax);转一圈,每人都"看过"全部档案,但任一时刻桌上只多出一叠的量。传阅(通信)和做笔记(计算)同时进行,几乎不额外耗时,这正是 Ring Attention 把 KV 通信和分块注意力**完全重叠**的精髓。

小数字感受。设隐藏维 $h$、序列 $s=1{,}000{,}000$,单卡存全序列 KV 远超 80 GB → 放不下。上 **CP=8**:每卡只存 $s/8=125\text{K}$ token 的 KV,显存降到约 1/8;通信上每层每卡需绕环交换 7 次 KV 块,但每次交换都被本段的分块注意力计算掩盖。Ring Attention 原论文在 TPUv4-1024 上把可支持上下文相对前序高效注意力扩大约 **512 倍**,达 1600 万+ token——靠的就是"序列长度可随设备数线性放大,且不引入额外通信/计算开销"。

$$
\text{每卡 KV 显存}\approx\frac{\text{KV}_{\text{总}}}{P},\qquad
\text{Ring 步数}=P-1,\qquad
\text{每步通信}\approx O\!\left(\frac{s}{P}\cdot h\right)
$$

通信被分块注意力计算重叠后,长序列吞吐近似只受**计算**而非传输限制——这是 CP 相对"复制全 KV"的根本优势。

## 面试高频
- **CP 和 TP 有何区别、能否叠加?** TP 切隐藏维(每层 all-reduce、压延迟),CP 切序列维(KV 绕环点对点、压长序列显存);两者正交,可叠加(TP×CP)。长上下文场景常 TP 管单层、CP 管序列长度。
- **Ring Attention 为什么"几乎零额外开销"?** 它把 KV 块的环形点对点通信与本段的分块(blockwise)注意力计算**完全重叠**,通信时间被算时间掩盖;且用 online softmax 增量合并,无需把全 KV 物化在一张卡。
- **CP 让显存怎么变?** 每卡只存约 1/P 的序列 KV 与激活,显存∝1/P,从而 P 张卡可支持约 P 倍长的上下文。
- **推理时 prefill 和 decode 用 CP 的差别?** prefill 长 prompt 切段最划算(算量大、可掩盖通信);decode 每步只 1 个新 token、KV 已分布,主要收益是长上下文下显存仍均摊。
- **CP 的负载均衡坑?** 因果掩码使靠后的段计算更重,需 zigzag/load-balanced 分段让各卡工作量均衡。

## 关键事实
- Ring Attention with Blockwise Transformers(Liu et al., **2023**,arXiv:2310.01889):KV 块绕环传与分块注意力完全重叠,序列长度随设备数线性扩展,无额外通信/计算开销;TPUv4-1024 上达 1600 万+ token(约 512× 提升)。
- Meta《Context Parallelism for Scalable Million-Token Inference》(**2025**):把 CP 用于推理侧,支持百万 token 上下文的低延迟服务,配合 ring/all-gather 两种 KV 通信策略。
- CP 与 TP 正交:设备总数含 CP 维(可写为 DP×TP×PP×EP×CP 的组合),CP 专管"序列放不下"。
- 因果注意力下需负载均衡分段(zigzag),否则尾段卡成为瓶颈。
