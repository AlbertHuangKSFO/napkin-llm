这是 [[LLM Infra]] 域 [[056 推理并行总览：TP、PP、EP、DP、SP 各管什么|推理并行总览]] 里最简单也最常被忽视的一维,对应 [[LLM/068 并行总览：DP、TP、PP、EP、SP|并行总览]] 的 DP。**数据并行(DP)/ 副本扩展**=把**整个模型复制成多份**,每份是一个独立副本(各有自己的 KV-Cache),来的请求由前面的**负载均衡**分流到不同副本。推理里 DP 的关键特征:**前向没有任何跨副本通信**(训练 DP 要 all-reduce 梯度,推理无反向所以全省了),因此吞吐**近线性扩展**——QPS 不够,就加副本。

类比:开连锁店。一家店(副本)能服务的客流有限,客流(QPS)涨了就**在别处再开一家一模一样的店**,店与店之间不需要互相通气。这和 TP/PP「把一家大店拆给多人合开同一单」完全不同——DP 是「多开几家独立的店」。

小数字:8B 模型 BF16 ≈ 16 GB,单张 H100(80 GB)绰绰有余。若单副本能扛 250 QPS,要服务 2000 QPS → 开 $\lceil 2000/250\rceil = 8$ 个副本即可,8 张卡每张跑一个完整模型,**互不通信**。对比:同样 8 卡若硬上 TP=8,反而要付每层 all-reduce、还可能 OOM 风险更低但延迟更差。所以判据是:**单卡放得下 → 优先 DP**;只有放不下才上 TP/PP。

$$
N_{\text{replica}} = \Big\lceil \frac{\text{目标 QPS}}{\text{单副本 QPS}}\Big\rceil,\qquad
\text{throughput} \approx N_{\text{replica}}\times \text{单副本吞吐}
$$

DP 与 TP/PP 是**正交的、可叠加**的:实际部署常是「外层 DP、内层 TP/PP」——每个副本内部用 TP(机内 NVLink)放下一个大模型,外层再用 DP 复制多个副本扛 QPS。例如 70B 用 TP=4 放进一个副本,再开 4 个这样的副本 = 16 卡。配套要点:DP 必须搭**请求路由 / 负载均衡**(轮询、最少在途、或按 KV-Cache 命中率亲和路由),否则副本间负载不均会拖垮尾延迟。

## 面试高频
- **推理 DP 和训练 DP 区别?** 训练 DP 每步要 all-reduce 同步梯度;推理无反向,DP **前向零跨副本通信**,纯水平复制。
- **什么时候用 DP 而非 TP?** 模型单卡放得下、瓶颈是 QPS/吞吐时用 DP;放不下或要降延迟才用 TP。
- **DP 能降延迟吗?** 不能。单请求仍在一个副本内串行跑;DP 只扩并发吞吐。
- **DP 怎么和 TP/PP 组合?** 正交叠加:外层 DP 扩副本扛 QPS,内层 TP/PP 放下大模型(如 70B TP=4 × DP=4 = 16 卡)。
- **DP 的配套是什么?** 负载均衡 / 请求路由(轮询、最少在途、KV 亲和),否则负载不均拉高尾延迟。

## 关键事实
- 推理 DP 前向无集合通信,吞吐近线性扩展(Meta Engineering,**2025**:DP 提供近线性吞吐、零额外集合通信)。
- 副本数 $N=\lceil \text{目标QPS}/\text{单副本QPS}\rceil$;每副本独立持有完整权重 + 独立 KV-Cache。
- DP 与 TP/PP 正交,典型组合「外层 DP × 内层 TP」。
- 选型口诀:**QPS 不够 → DP;显存不够 → TP/PP;延迟敏感 → TP**。
