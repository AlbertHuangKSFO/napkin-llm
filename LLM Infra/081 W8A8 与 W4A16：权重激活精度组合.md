[[081 W8A8 与 W4A16：权重激活精度组合|W8A8 与 W4A16：权重激活精度组合]]是服务量化里最该搞清楚的一对选择:**W4A16**(权重 4-bit、激活仍 16-bit)和 **W8A8**(权重激活都 8-bit)打的瓶颈完全不同。一句话——**W4A16 省显存、小 batch 快;W8A8 解锁整数/FP8 算力、大 batch 吞吐高**。这是 [[080 服务量化总览：W、A、KV 三处|三处量化]]里"W only vs WA"那条决策的具体落地,内核细节回链 [[027 量化内核：W4A16、W8A8 GEMM|量化内核]]。

## 直觉

**生活类比**:把模型当照片存档。**W4A16 = 把原图压到 1/4 极致省硬盘**:一个人慢慢翻相册时瓶颈是"从硬盘读图",压小后秒开——70B 权重 **140GB→35GB** 进单卡,单图(batch=1)打开 **+80~100%**;但坑在"看图前要先解压回原图",一次冲一大批时解压开销吃掉收益(batch=256 只 **+~10%**)。**W8A8 = 整数流水线批量冲印**:底片和冲印机都用统一整数规格,影楼一次冲 256 张时瓶颈是"冲印机算力",整数机峰值 **~2 倍**,大批量稳定 **+~40%**;代价是底片也得量化、先校准压掉"过曝的怪光点"(离群值),否则成片掉色。所以单人看图/单卡放不下选 W4A16,影楼批量冲印/榨吞吐选 W8A8——不是谁更省,是打哪个瓶颈。

![[sq-081类比照片存档.svg]]

回到 [[004 算力 vs 带宽：Roofline 与算术强度|Roofline]]:**小 batch 的 decode 是访存受限**——瓶颈是把权重从 [[003 GPU 内存层级：HBM、L2、SRAM、寄存器|HBM]] 搬进来。W4A16 把权重压到 1/4,搬运字节锐减,直接提速;它在 GEMM 里把 INT4 权重**反量化回 FP16** 再算,算力没变(混合精度内核),所以**大 batch 时反而被反量化开销拖累**,提速很小。**W8A8 反过来**:它让权重和激活都是 8-bit,GEMM 直接跑在 **INT8/FP8 [[002 GPU 架构：SM、CUDA Core 与 Tensor Core|Tensor Core]]** 上,峰值算力是 BF16 的 ~2×——**大 batch 算力受限时一路领先**,但代价是激活也得量化,必须**校准 + 压离群值**([[096 AWQ 与 SmoothQuant|SmoothQuant]]),否则掉点明显。

## 例子

实测量级(vLLM,相对 BF16 基线):

- **W4A16**:`batch=1`(decode)吞吐 **+80–100%**;`batch=256` 只 **+~10%**(反量化开销吃掉算力收益)。同步/低并发部署最划算。
- **W8A8**:`batch=1` **+~40%**;`batch=256` 仍 **+~40%**(prefill-heavy),decode-heavy 大 batch 约 **+15–20%**。异步连续批处理高吞吐场景占优。

显存侧:70B 权重 BF16 140GB → W4A16 **35GB**(进单卡)、W8A8 **70GB**。所以"单卡放不下"时优先 W4A16;"放得下但要榨吞吐"时上 W8A8。

## 原理

两者的根本差异在 **GEMM 在什么精度域算**:

$$
\text{W4A16: } Y = (\underbrace{\hat W}_{\text{INT4}\to\text{FP16}})\,X_{\text{FP16}}
\qquad
\text{W8A8: } Y = \underbrace{W_{\text{INT8}}\,X_{\text{INT8}}}_{\text{INT32 累加}}\cdot\, s_W s_X
$$

W4A16 的乘加发生在 **FP16**(反量化后),算力 = FP16 峰值;省的是权重的**存储与带宽**。W8A8 的乘加发生在 **INT8/FP8**,累加到 INT32 后用 $s_W s_X$ 缩放回来,算力 = INT8/FP8 峰值(~2× BF16);它**同时**省显存和换算力。代价对称:W8A8 多量化了激活,而激活有**逐通道离群值**(见 [[085 校准、精度回退与离群值|离群值]]),需要 SmoothQuant 把离群值从激活"迁移"到权重,或用 per-token 动态 scale,否则 INT8 范围被离群值拉爆。

## 代码

```bash
# W4A16:加载 AWQ checkpoint,激活保持 FP16,适合单卡放大模型 / 低并发
vllm serve TheBloke/Llama-3-70B-AWQ --quantization awq --max-num-seqs 16

# W8A8:FP8 权重+激活,适合高并发大 batch 榨吞吐(Hopper/Blackwell)
vllm serve meta-llama/Llama-3-70B --quantization fp8 --max-num-seqs 256
```

❌ 误区:无脑选 W4A16(比特数少=最优),结果高并发服务吞吐反而不如 W8A8。
✅ 正解:按部署模式选——**低并发/同步、单卡装不下 → W4A16**;**高并发/异步连续批、要最大吞吐 → W8A8(FP8 优先)**。两者不是"谁更省",而是"打哪个瓶颈"。

## 面试高频

- **Q:W4A16 大 batch 为什么提速很小?** 它在 FP16 算 GEMM,只省了搬权重的带宽;大 batch 是算力受限,算力没变,且反量化本身有开销。
- **Q:W8A8 为什么需要校准而 W4A16(权重 only)不太需要?** W8A8 量化了**激活**,激活有动态离群值,必须校准/压离群值;W4A16 只量权重,权重分布静态、可用 GPTQ/AWQ 离线最小化误差。
- **Q:同步 vs 异步部署各选哪个?** 同步(逐请求、低并发)选 W4A16;异步连续批处理选 W8A8。

## 关键事实

- 2025 SqueezeBits/vLLM 实测:W4A16 在 `batch=1` 增益 80–100%、`batch=256` 仅 ~10%;W8A8 在大 batch 稳定 ~40%(prefill-heavy)。
- W8A8 有两种:**INT8**(Ampere 起广泛支持)和 **FP8**(Hopper/Blackwell 原生,见 [[082 FP8 服务：H100、Blackwell 原生|FP8 服务]])。
- 权重 1/4 vs 1/2:W4A16 让 70B 进单卡 80GB,W8A8 不行(需 ~70GB+ 激活+KV)。
