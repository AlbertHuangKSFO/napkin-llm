[[005 数值格式：FP32、TF32、BF16、FP8、FP4|数值格式]] 决定每个数用几位存:1 位符号 + **指数位 E(管动态范围)** + **尾数位 M(管精度)**。位宽越窄,[[003 GPU 内存层级：HBM、L2、SRAM、寄存器|显存]]越省、[[002 GPU 架构：SM、CUDA Core 与 Tensor Core|Tensor Core]] 吞吐越高,但要靠合理的 E/M 分配和缩放保住精度。

类比尺子:**指数位 E 决定尺子能量多长**(从纳米到光年),**尾数位 M 决定刻度多密**(每段分多少格)。FP16 和 BF16 都是 16 位,但 BF16 把位数更多分给指数(量得长、不溢出),FP16 更多分给尾数(刻度密、但量程短易爆表)——这就是 BF16 训练友好的根源。

各格式位域(S/E/M)与量程:
- **FP32** = 1/8/23,范围 ±3.4e38,训练精度基准。
- **TF32** = 1/8/10(实际只存 19 位,Tensor Core 内部用),保 FP32 的范围、砍尾数换速度。
- **BF16** = 1/8/7,**范围同 FP32**(±3.4e38),尾数少 → 精度低但不溢出。
- **FP16** = 1/5/10,范围窄(±65504),易上溢/下溢,训练需 loss scaling。
- **FP8 E4M3** = 1/4/3,最大 ±448,**精度优先**,用于前向/权重/激活。
- **FP8 E5M2** = 1/5/2,最大 ±57344,**范围优先**,用于梯度。
- **FP4 E2M1** = 1/2/1(Blackwell),位太少必须配 **per-block 缩放(MXFP4,块大小 32 共享一个 8 位 scale)** 才可用。

原理:一个规格化浮点数的值为
$$x = (-1)^{S} \times 2^{E - \text{bias}} \times \big(1 + \frac{M}{2^{m}}\big)$$
其中 $m$ 是尾数位数。**指数位数 $e$ 决定 $2^{E-\text{bias}}$ 的取值跨度 → 动态范围**;**尾数位数 $m$ 决定 $1+M/2^m$ 的分辨率 → 相邻可表示数的相对间隔约 $2^{-m}$**。所以同样 16 位:BF16($e=8$)动态范围等于 FP32 但相对精度仅 $2^{-7}\approx0.8\%$;FP16($e=5$)精度好($2^{-10}$)但范围只到 $\pm6.5\times10^4$,大激活/梯度一乘就溢出。低于 8 位时单值范围撑不住,于是引入**块缩放**:一组数共享一个缩放因子,把"绝对量程"问题外包给 scale,让 4 位只负责块内相对值。

PyTorch 看精度/范围差异,以及对显存的直接影响:

```python
import torch
# 范围对比:一个大数,FP16 溢出而 BF16 安然
x = torch.tensor(70000.0)
print("FP16:", x.half())                  # inf  ← 超出 ±65504,上溢
print("BF16:", x.bfloat16())              # 70144  ← 范围够,精度略损

# 精度对比:一个需要细分辨率的数
y = torch.tensor(1.0009765625)
print("FP16:", y.half().item())           # 1.0009...  尾数 10 位,分得清
print("BF16:", y.bfloat16().item())       # 1.0      ← 尾数仅 7 位,糊成 1.0

# 显存账:位宽 → 字节/参数 → 70B 权重占用
for fmt, bytes_ in [("FP32",4),("BF16",2),("FP8",1),("FP4",0.5)]:
    print(f"{fmt}: 70B 权重 ≈ {70e9*bytes_/1e9:.0f} GB")
# FP32: 280 GB / BF16: 140 GB / FP8: 70 GB / FP4: 35 GB
```

# ❌ 训练直接用 FP16 全程,不加 loss scaling → 梯度下溢、loss 变 NaN

## 面试高频
- **Q:BF16 和 FP16 都是 16 位,区别和取舍是什么?** A:FP16 是 E5M10、BF16 是 E8M7。BF16 用更多指数位换来与 FP32 相同的动态范围(不易溢出),代价是尾数少、精度低;FP16 精度高但范围窄。训练多用 BF16(无需 loss scaling),FP16 训练需 loss scaling 防梯度下溢。陷阱:答"BF16 更精确"——恰相反,BF16 精度更低,优势在范围。
- **Q:FP8 的 E4M3 和 E5M2 分别用在哪、为什么?** A:E4M3(±448,精度优先)用于前向的权重和激活;E5M2(±57344,范围优先)用于反向的梯度——梯度动态范围大,需要更多指数位。陷阱:记反了用途,或忽略 FP8 训练需 per-tensor/per-block 缩放。
- **Q:位宽减半对推理有哪些好处?** A:权重显存减半(70B FP16=140GB→FP8=70GB)、KV-Cache 减半(同显存装更长上下文/更大 batch)、HBM 流量减半直接加速 memory-bound 的 decode、Tensor Core 吞吐翻倍。陷阱:只说"省显存"——对 decode 来说"省带宽流量→提速"同样关键。

## 关键事实
- FP8 E4M3 最大 ±448;E5M2 最大 ±57344(含 inf/nan)。来源:FP8 Formats for Deep Learning(Micikevicius et al., NVIDIA/Arm/Intel, 2022, arXiv:2209.05433);NVIDIA Transformer Engine 文档。
- BF16 为 E8M7(8 指数 7 尾数),动态范围同 FP32(~1e-38 ~ 1e38)。来源:Google Brain bfloat16 规范;NVIDIA Hopper 文档。
- FP4 为 E2M1;OCP Microscaling MXFP4 以 32 个元素为一块共享一个 8 位(E8M0)缩放因子;NVIDIA Blackwell 原生支持 MXFP4/MXFP6。来源:OCP Microscaling Formats (MX) Specification v1.0(2023);NVIDIA Blackwell Architecture(2024)。
- 切换到更低位宽近似使 Tensor Core 吞吐翻倍(FP8≈2×FP16,FP4≈2×FP8)。来源:NVIDIA H100/B200 Datasheet。
