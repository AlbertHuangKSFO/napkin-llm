[[073 投机解码系统：draft-verify 全流程|投机解码]](speculative decoding,Leviathan et al. 2023)是把 [[014 Decode 阶段：访存受限|访存受限]] 的 decode 提速的核心系统手段:用一个**便宜的草稿模型连出 k 个 token**,再让大模型**一次前向并行验证**这 k 个位置,用拒绝采样规则决定接受多少。关键洞察有二:其一,decode 每步搬一遍全模型权重却只算 1 个 token,**算力被浪费**(算术强度极低,见 [[004 算力 vs 带宽：Roofline 与算术强度|Roofline]]);把 k 个待验证 token 拼成一批,大模型一次前向就能验完,**用闲置算力换步数**。其二,接受/重采规则经过精心设计,使输出分布**和原模型逐 token 采样完全一致**——这是无损(lossless)的,不是近似。它是 [[LLM/104 投机解码与 Medusa、Lookahead|投机解码]] 的系统视角,下游有 [[074 EAGLE-3：工业标准投机解码|EAGLE-3]]、[[075 Medusa 与多头草稿|Medusa]]、[[076 lookahead 解码与 n-gram|lookahead]] 等具体草稿器,并须与 [[079 投机解码与连续批、前缀缓存的兼容|连续批、前缀缓存兼容]]。

## 直觉

想象大模型是一位**慢而权威的主编**,草稿模型是一位**快而平庸的实习生**。逐 token 解码 = 主编亲自一个字一个字写,每写一字都要把整本词典搬上桌(搬权重),太慢。

投机解码让实习生先**抢着写 4 个词**(便宜、可能写错),然后主编**扫一眼这 4 个词**——扫一眼和写一个字的代价几乎一样(都是搬一遍词典,但扫 4 个词时词典只搬一次)。主编从左往右核对:对的就采纳,碰到第一个不满意的就**就地改一个词、后面全作废**。这样主编一次搬词典(一次前向)平均能敲定 2–3 个词,而不是 1 个。

主编从不降低标准:被采纳的词,概率上和他亲自写出来的一模一样——这就是无损。

**生活类比**:实习生(小草稿模型)先一口气连写 **5 句**草稿,几乎不占主管时间;主管(大模型)把这 5 句**一眼扫过**——扫一眼和亲手写一句的代价一样(都搬一次"词典"=一次前向),但这一眼能同时批 5 句。主管从左往右核对:**句1 ✓、句2 ✓** 留着,到**句3 ✗** 就地亲笔重写,**句4、句5 全作废**下轮再来。这一轮主管只"写"了 **1 次**,却敲定了 **3 句**(句1、句2 + 重写的句3),比逐字写快约 **3 倍**。关键:留下的句子和主管自己一句句写出来**一模一样**——主管从不降标准,所以是无损,只是更快。

## 例子

草稿长 $k=4$,逐位接受率 $\alpha=0.7$。一轮 draft-verify 的**期望接受 token 数**(含拒绝处重采的 1 个)为几何级数:

$$
\mathbb{E}[\#\text{tok}] \;=\; \frac{1-\alpha^{k+1}}{1-\alpha}
\;=\; \frac{1-0.7^{5}}{1-0.7} \;=\; \frac{1-0.168}{0.3} \;\approx\; 2.77
$$

即:大模型每跑 **1 次前向**,平均吐出 **2.77 个 token**,而朴素 decode 是 1 个。理想加速 ≈ 2.77×(忽略草稿开销)。扣掉草稿模型连跑 4 步的成本(若草稿是大模型的 1/20 算力,4 步 ≈ 0.2 次大前向),实测净加速约 **2×**。接受率越高、模型越大(草稿相对越便宜),收益越大——细节见 [[078 接受率、草稿长度与收益分析|收益分析]]。

## 原理

设大模型分布 $p(x)$、草稿分布 $q(x)$。逐位置接受规则(Leviathan 2023):草稿采出 $x \sim q$,以概率 $\min\!\left(1, \frac{p(x)}{q(x)}\right)$ **接受**;否则**拒绝**,并从**残差分布**重采一个 token:

$$
x' \sim p'(x)=\frac{\big(p(x)-q(x)\big)_+}{\sum_{x}\big(p(x)-q(x)\big)_+},\qquad (\cdot)_+=\max(\cdot,0)
$$

**无损性证明直觉**:最终采出某 token $x$ 的概率 = $P(\text{草稿出 }x)\cdot P(\text{接受}) + P(\text{走到重采})\cdot p'(x)$。代入可逐项验证恰好等于 $p(x)$——接受那部分贡献 $\min(q,p)$,重采那部分恰好补上 $\big(p-q\big)_+$,两者相加 $=p(x)$。所以**无论草稿质量好坏,输出分布永远等于大模型自己采样的分布**;$q$ 只影响速度(接受率),不影响正确性。这就是它能在工业部署中"白嫖"加速而无需重新评测质量的根本原因。

逐位接受率定义为 $\alpha=\mathbb{E}_{x\sim q}\big[\min(1,p(x)/q(x))\big]$,$q$ 越接近 $p$,$\alpha$ 越高。

## 代码

vLLM V1 用「草稿模型」做投机解码的最简配置:

```python
from vllm import LLM, SamplingParams

# ✅ 标准 draft-verify：独立小草稿模型 + 大目标模型
llm = LLM(
    model="meta-llama/Llama-3.1-70B-Instruct",       # 目标(大)模型
    speculative_config={
        "model": "meta-llama/Llama-3.2-1B-Instruct",  # 草稿(小)模型，词表须对齐
        "num_speculative_tokens": 4,                  # 草稿长 k
    },
)
# 输出分布与不开投机时逐 token 一致（无损），只是更快
out = llm.generate("解释投机解码：", SamplingParams(temperature=0.7))
```

```python
# ❌ 反例一：草稿模型选得太大/太慢
#    草稿本身的串行开销吃掉收益，甚至负优化
"model": "meta-llama/Llama-3.1-8B-Instruct"   # 草稿和目标算力比太接近 → 净加速 < 1

# ❌ 反例二：以为投机解码会改变输出、需要重测质量
#    错。接受+残差重采保证分布严格不变，质量评测无需重跑
```

`❌` 草稿太大 = 草稿开销 > 验证省下的步数;`✅` 草稿应是目标的 1/10–1/20 量级,且词表/分词与目标一致(否则 $p/q$ 无法对齐)。注意 temperature/top-p 等采样参数会进入 $p$ 和 $q$ 的计算,投机解码对它们**透明无损**。

## 面试高频

- **Q:投机解码为什么能加速,本质是什么?** decode 访存受限,每步搬全模型权重却只算 1 token,算力闲置;把 k 个草稿 token 拼批,大模型一次前向并行验证,用闲置算力换步数。
- **Q:为什么是无损的,如何保证分布不变?** 接受规则 $\min(1,p/q)$ + 拒绝处从残差分布 $(p-q)_+$ 重采,可证最终采样概率严格等于 $p(x)$;草稿质量只影响速度不影响正确性。
- **Q:草稿模型怎么选?** 要快(1/10–1/20 算力)又要 $q$ 接近 $p$(高接受率),且**词表/分词必须与目标一致**;两者矛盾,故衍生出 EAGLE/Medusa 等"轻量草稿头"路线。
- **Q:期望加速怎么算?** 每轮期望产出 $\frac{1-\alpha^{k+1}}{1-\alpha}$ 个 token,除以(1 次大前向 + 草稿开销)即净加速;$\alpha$、$k$ 是两个旋钮(见 [[078 接受率、草稿长度与收益分析|收益分析]])。
- **Q:batch 很大时还有用吗?** 收益下降——大 batch 时大模型本就算力受限,验证 k 个 token 不再"白嫖"(见 [[079 投机解码与连续批、前缀缓存的兼容|与连续批兼容]])。

## 关键事实

- **Fast Inference from Transformers via Speculative Decoding**,Leviathan, Kalman, Matias(Google),arXiv:2211.17192,ICML 2023;同期 Chen et al.(DeepMind)independent 提出等价方案(arXiv:2302.01318)。
- 无损保证:接受概率 $\min(1,p/q)$ + 残差分布 $(p-q)_+$ 重采,严格保持目标模型分布;**对采样温度/top-p 透明**。
- 期望每轮接受数 $\frac{1-\alpha^{k+1}}{1-\alpha}$;原论文在 T5/GPT 类模型上报告 **2–3× wall-clock 加速**。
- 已成为 vLLM、SGLang、TensorRT-LLM 标配能力(2025);现代主流不再用独立草稿模型,而用 EAGLE-3/MTP 等轻量草稿头(见后续笔记)。
