## ① 类比:搭一家「token 餐厅」的开业 checklist

开店不是一步到位。先用一台灶(单卡)把菜做出来、能上桌(124);再请人来吃、数清楚上菜多快多稳(benchmark,126);发现食材太贵就换便宜配方(量化,127);灶台没烧满就调火候(调优,128);单灶不够大就拼多灶炒一道大菜(多卡 TP,125);点单和炒菜互相挤就分两个厨房(PD 分离,129);最后开连锁、自动加店、装监控大屏(K8s + 自动扩缩 + 监控,130)。**每一步都先量再改**——没有 benchmark 的调优是玄学。

## ③ 原理:为什么是这个顺序

**先单卡、后多卡。** 多卡引入 [[058 TP 的通信：每层 all-reduce 与 NVLink 依赖|all-reduce 通信]]、[[066 NCCL：集合通信库与原语|NCCL]]、拓扑等一堆新变量;单卡先把端点跑通、把 benchmark 脚本调对,再加并行,出问题才好二分定位。

**先 benchmark、后调优。** [[105 SLO、SLA 设计：为推理定指标|SLO]] 没定、基线没测,任何 flag 都不知道是变好还是变坏。126 的脚本是 127/128/129 反复复用的「尺子」。

**量化与调优在多卡之前。** 单卡能放下的模型先用 [[080 服务量化总览：W、A、KV 三处|量化]] 压一压,可能根本不需要多卡;前缀缓存/chunked prefill 是**零成本**开关,先吃满单卡再考虑加硬件。

**PD 分离与 K8s 在最后。** PD 分离([[049 DistServe：goodput 优先的解耦|DistServe]] 思想)和 [[096 Kubernetes 上部署 LLM：基本盘|K8s]] 编排是「规模化」动作,只有当单节点榨干、SLO 仍不达标或要多副本弹性时才上,否则是过度工程。

## ④ 实操环境前提(一次性)

```bash
# 1. 验证 GPU 与驱动
nvidia-smi                          # 看到卡、显存、CUDA 版本
nvidia-smi topo -m                  # 多卡时看 NVLink 互联(NV# = NVLink)

# 2. 装 vLLM(2025 推荐 uv,也可 pip)
pip install vllm                    # 或:uv pip install vllm

# 3. HF 鉴权(拉 gated 模型如 Llama)
export HF_TOKEN=hf_xxx
huggingface-cli login

# 4. 冒烟:一行起 8B,另开终端 curl
vllm serve meta-llama/Llama-3.1-8B-Instruct --port 8000 &
curl http://localhost:8000/v1/models     # 列出已加载模型 = 起来了
```

❌ 反模式:直接上 70B + 多卡 + K8s,一处报错全栈瘫,无法定位。
✅ 正解:**8B 单卡跑通整条链(起服务→压测→看监控)**,再逐步替换为大模型、多卡、量化、PD、K8s——每换一个变量只动一处。

## 面试高频

- **「给你一个新模型要上线,流程怎么走?」** 选引擎→单卡起端点→**先压测定基线**→量化/调优榨单卡→不够再多卡 TP→SLO 仍不达标上 PD 分离→K8s 编排+自动扩缩+监控。强调「先量再改」。
- **「什么时候才需要多卡/PD 分离/K8s?」** 多卡:单卡放不下或延迟不达标;PD 分离:prefill/decode 互相干扰、goodput 上不去;K8s:要多副本弹性、声明式运维。不是默认就上。
- **「调优为什么必须配 benchmark?」** 没有 TTFT/TPOT/吞吐基线就无法判断 flag 是改善还是劣化;同一压测脚本要在量化/调优/PD 各阶段复用。
- **「单卡 8B 跑通有什么意义?」** 把端点协议、压测脚本、监控面板这些「与模型大小无关」的部分先验证对,再换大模型只剩并行/显存这一类问题。

## 关键事实

- 推荐顺序:模型→引擎→单卡→压测→量化→调优→多卡→PD→K8s→监控,**先量再改**。
- 装 vLLM:`pip install vllm`(或 `uv pip install vllm`);冒烟用 8B 单卡跑通全链。
- `nvidia-smi topo -m` 看 NVLink;`/v1/models` 确认服务起来。
- 量化/前缀缓存/chunked prefill 优先于加硬件(成本低甚至零成本)。
- benchmark 脚本是贯穿 127/128/129 的同一把「尺子」,先做。
