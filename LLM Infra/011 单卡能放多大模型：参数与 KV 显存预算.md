[[011 单卡能放多大模型：参数与 KV 显存预算|显存预算]] 是推理选型的第一道算术题:一张卡的显存 = 权重(参数×字节)+ KV-Cache + 激活 + 碎片;先把这本账算清,才知道某模型在某卡上能不能单卡装下、能扛多大并发。

## 直觉:行李箱装箱
显存就是行李箱(80GB)。**权重**是必带的硬壳行李(模型一上来就占,固定大小);**KV-Cache** 是边走边买的纪念品(每多一个并发请求、每长一段上下文就鼓一点);**激活**是手上临时拎的东西(算完就放下,瞬时占用);**碎片**是塞不进缝隙的空气(分配粒度浪费 5–15%)。箱子就这么大,纪念品买太多(高并发长上下文)就关不上盖——于是要么换大箱子(MI300X 192GB),要么拆成两个箱子(张量并行)。

## 小数字例子:三档模型手算
权重显存 = 参数量 × 每参数字节(fp16=2B,int4≈0.5B):

| 模型 | fp16 权重 | int4 权重 | 单卡结论 |
|---|---|---|---|
| 7B | 14 GB | ~3.5 GB | 24GB 卡轻松,消费级可跑 |
| 13B | 26 GB | ~6.5 GB | 40GB 卡 fp16 勉强,80GB 舒适 |
| 70B | 140 GB | ~35 GB | fp16 单 80GB 卡**装不下**;int4 单 48–80GB 卡可装;或 MI300X 192GB 单卡 fp16 装下 |

70B fp16 在 H100 80GB 上必须张量并行到 ≥2 卡(走 [[008 片内互联：NVLink、NVSwitch、NVLink-C2C|NVLink]]),这正是 [[009 节点与机架：PCIe、GB200 NVL72、scale-up 与 scale-out|节点与机架]]里 TP 的由来;而 MI300X 192GB 能单卡装下,省掉跨卡通信(见 [[007 异构加速器：TPU、Trainium、MI300X|异构加速器]])。

## 原理:KV-Cache 随并发与序列长线性增
KV-Cache 每个 token 存所有层的 K 和 V(详见 [[LLM/102 KV-Cache|KV-Cache]]):

$$\text{KV bytes} = 2 \times L \times n_{kv} \times d_{head} \times \text{bytes} \times \underbrace{B}_{\text{并发}} \times \underbrace{S}_{\text{序列长}}$$

其中 $L$=层数,$n_{kv}$=KV 头数(GQA 下远小于注意力头数),$d_{head}$=每头维度。关键:KV 与**并发 × 序列长**成线性正比。所以可用显存 = 总显存 − 权重 后,**剩下的全归 KV** → 直接定吞吐天花板:

$$B_{\max} \cdot S \;\approx\; \frac{\text{显存} - \text{权重} - \text{激活} - \text{碎片}}{2 L\, n_{kv}\, d_{head}\,\text{bytes}}$$

这把「装得下」和「并发上限」统一成一个预算约束。完整估算法见 [[LLM/076 显存占用估算(参数、梯度、优化器、激活、KV)|显存估算]]。

## 显存四大块速查

| 块 | 大小来源 | 特性 |
|---|---|---|
| 权重 | 参数量 × 字节(fp16=2, int8=1, int4=0.5) | 固定;decode 每步整读(带宽限,见 [[010 显存墙与 LLM 推理的本质约束\|显存墙]]) |
| KV-Cache | 2·L·n_kv·d_head·bytes·B·S | 随并发×序列长线性增,常是并发上限瓶颈 |
| 激活 | ∝ batch × hidden(瞬时) | 推理小;PagedAttention 下被压得很低 |
| 碎片 | 分配粒度 / 内存池浪费 | 5–15%;PagedAttention 用分页大幅降碎片 |

## 代码/配置:先算账再设并发

```python
# ❌ 不留 KV 余量,把显存占用率拉满 → 一上并发就 OOM
llm = LLM(model="llama-13b", dtype="float16",
          gpu_memory_utilization=0.99)     # 权重26GB已占大半,KV无处可放

# ✅ 留足 KV 预算,显式控住并发与序列长
llm = LLM(
    model="llama-13b", dtype="float16",
    gpu_memory_utilization=0.90,           # 留 10% 给激活/碎片
    max_num_seqs=64,                       # 并发上限,由 KV 预算反推
    max_model_len=8192,                    # 序列长上限,直接乘进 KV
    kv_cache_dtype="fp8",                  # KV 用 fp8 → KV 显存减半,并发翻倍
)
# ✅ 装不下就量化权重 + 多卡 TP
llm = LLM(model="llama-70b", quantization="awq",     # int4 权重 140→35GB
          tensor_parallel_size=2)                    # 仍不够再切 2 卡
```

## 面试高频
- **怎么估一个模型单卡能不能装下?** 权重 = 参数 × 字节(fp16=2B),再留出 KV+激活+碎片余量。70B fp16=140GB > 80GB → 装不下需 TP;int4≈35GB → 单卡可装。
- **显存由哪几块组成?** 权重(固定)+ KV-Cache(随并发×序列长线性增)+ 激活(瞬时)+ 碎片(5–15%)。推理时 KV 常是并发瓶颈。
- **KV-Cache 怎么随负载变?** 与「并发数 × 序列长度」成线性正比;装下权重后剩余显存全给 KV,直接决定最大并发 × 上下文长度的乘积。
- **装不下怎么办?优先级?** ① 量化权重(int4/int8,最划算)② KV 量化(fp8,翻倍并发)③ 张量并行多卡 ④ 换大显存卡(MI300X 192GB)。先省字节,再加卡。
- **为什么 MI300X 受推理欢迎?** 192GB 单卡能装下别人要 2 张 80GB 卡 + NVLink 才能跑的 70B fp16,省掉跨卡通信复杂度和成本。

## 关键事实(2025–2026)
- **权重显存** = 参数量 × 每参数字节:fp16=2B、int8=1B、int4≈0.5B。7B/13B/70B 的 fp16 权重 = 14/26/140 GB。
- **70B fp16(140GB)** 单张 80GB 卡装不下,需 TP≥2 卡;int4(~35GB)单卡可装;MI300X 192GB 可单卡 fp16 装下。
- **KV-Cache** 与并发×序列长线性正比;装下权重后,剩余显存 ÷ 单 token KV 字节 = 最大「并发×序列长」乘积,即吞吐天花板。GQA 减少 n_kv、fp8 KV 减半字节,都能放大并发。
- **碎片** 5–15%;PagedAttention 用分页把碎片与激活占用压到很低,是现代推理引擎(vLLM 等)的关键。
