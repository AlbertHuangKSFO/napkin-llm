[[080 服务量化总览：W、A、KV 三处|服务量化总览：W、A、KV 三处]]站在**部署视角**回答一个问题:一个模型有三处可以量化——**权重 W、激活 A、KV-Cache**,各自省什么、难在哪、该不该上。算法怎么求 scale、怎么压离群值,回链 [[LLM/092 量化基础：对称非对称、per-tensor、per-channel、per-group|量化基础]];这里只关心**对吞吐、显存、精度、硬件支持的影响**。三处互相**正交**:可以只量化 W,也可以 W+A,再叠加 KV,每加一处松绑一个不同的瓶颈。

## 直觉

**生活类比**:搬家时三类东西都能压缩,各有压法和代价。**家具(权重 W)**常驻不动、占地最大——拆件压实最省仓库又搬得快,把 **140GB 压到 35GB** 就能塞进单卡,而且几乎不掉东西,所以最常先动它。**随身行李(激活 A)**是路上正在处理的东西——压成统一整数尺寸,搬运流水线直接翻倍(大批量 **+40%** 吞吐),但得先量尺校准,压坏怪东西会掉 ~1%。**储物柜(KV-Cache)**堆历史档案、越久越满——档案压缩存放(**10GB→5GB**),同一个柜能塞更多并发或更长上下文,属正交补丁、柜满才动。三类对应三个独立旋钮,别当成一个"压到底"的开关。

![[sq-080类比搬家三类压缩.svg]]

把一次推理想成一座工厂:**权重 W** 是常驻的机床(参数),占地大、每次开工都要从仓库([[003 GPU 内存层级：HBM、L2、SRAM、寄存器|HBM]])搬出来——压小它,既省仓库又省搬运,这是 [[014 Decode 阶段：访存受限|decode 访存受限]]时的直接收益。**激活 A** 是流水线上正在加工的料(逐 token 的中间张量),把它也降到 INT8/FP8,就能让 GEMM 跑在**整数或 FP8 的 [[002 GPU 架构：SM、CUDA Core 与 Tensor Core|Tensor Core]]** 上,算力直接翻倍,这是 [[013 Prefill 阶段：计算受限|prefill]] 和大 batch [[016 batch 如何改变算术强度|算力受限]]时的杀手锏。**KV-Cache** 是堆在仓库角落的历史档案,越长越占地——压它就能在同一张卡上塞更多并发或更长上下文(见 [[034 KV 量化部署：FP8、INT8 KV|KV 量化部署]])。三处对应三个不同的旋钮,别混为一谈。

## 例子

Llama-3 70B 在 80GB H100 上(BF16 基线权重 140GB,根本放不下,必须量化或多卡):

- **只量权重 W4A16**:权重 140GB → **35GB**,单卡放得下,小 batch decode 因搬运字节少而提速 ~1.5–2×,几乎不掉点(<0.5% 任务指标)。
- **加激活 W8A8 (INT8/FP8)**:大 batch(256)吞吐再 +~40%,因为 GEMM 走整数/FP8 算力;但需校准,可能掉 ~0.5–1%。
- **再叠 FP8 KV**:32k 上下文单序列 KV 从 10GB → **5GB**,同卡并发或上下文翻倍。

三处全开,等于在显存、算力、KV 三条线上同时松绑。

## 原理

统一的对称量化映射(细节见 [[LLM/092 量化基础：对称非对称、per-tensor、per-channel、per-group|量化基础]]):

$$
x_q=\mathrm{round}(x/s),\qquad \hat x=x_q\cdot s,\qquad s=\frac{\max|x|}{q_\max}
$$

记号 **W$a$A$b$**:权重 $a$ 比特、激活 $b$ 比特。三处省的东西不同,用一张账区分:

$$
\underbrace{M_W = P\cdot b_W}_{\text{权重显存}}\quad
\underbrace{\text{算力} \propto \tfrac{1}{b_A}}_{\text{激活定算力}}\quad
\underbrace{M_{KV}=2LH_{kv}d_h SB\cdot b_{KV}}_{\text{KV 显存}}
$$

关键洞察:**权重量化省显存与带宽,激活量化换算力,KV 量化省 KV 显存**——分别打的是 [[010 显存墙与 LLM 推理的本质约束|显存墙]]、算力墙、KV 墙三堵不同的墙。所以"该量化哪里"取决于你的瓶颈在哪:单卡放不下 → 先 W;大 batch 吞吐卡算力 → 加 A;长上下文/高并发卡 KV → 加 KV 量化(见 [[083 KV 量化与服务吞吐|KV 量化与服务吞吐]])。

## 代码

vLLM 三处分别用不同开关,可叠加:

```bash
# ① 仅权重:加载 AWQ/GPTQ 的 W4A16 checkpoint(--quantization 自动识别)
vllm serve meta-llama/Llama-3-70B-AWQ --quantization awq

# ② 权重+激活:FP8 W8A8(Hopper/Blackwell 原生)
vllm serve meta-llama/Llama-3-70B --quantization fp8

# ③ 叠加 KV 量化(与上面正交,单独开)
vllm serve meta-llama/Llama-3-70B --quantization fp8 \
     --kv-cache-dtype fp8_e4m3
```

❌ 误区:以为"量化"是一个开关,一刀切量到底。
✅ 正解:W / A / KV 是三个独立旋钮,按瓶颈分别决策——单卡装不下先动 W,吞吐卡算力再动 A,KV 占满才动 KV;每加一处都要单独评测掉点。

## 面试高频

- **Q:模型有哪几处可以量化,各打什么瓶颈?** W(显存+带宽)、A(算力)、KV(KV 显存)。三者正交,对应显存墙、算力墙、KV 墙。
- **Q:为什么"只量权重"最常见?** 几乎不掉点、省显存最直接、能让大模型进单卡,且 decode 访存受限时直接提速;激活量化才需要校准和压离群值,风险更高。
- **Q:W only 和 WA 的吞吐特征差别?** W only 在小 batch(memory-bound)收益大;WA 在大 batch(compute-bound)收益大,因为它解锁了整数/FP8 算力(见 [[081 W8A8 与 W4A16：权重激活精度组合|W8A8 与 W4A16]])。

## 关键事实

- 2025 现状:生产部署默认从 **W only(W4A16 AWQ/GPTQ)** 起步;高吞吐场景上 **FP8 W8A8**(Hopper/Blackwell 原生,近无损);KV 量化作为正交补丁叠加。
- vLLM、TensorRT-LLM 均把三处做成独立开关,可组合。
- 极低比特(NVFP4/MXFP4)是 2025 新方向,仅 Blackwell 原生,需 QAT/蒸馏回收精度,属第四级、风险最高。
