[[047 准入控制与排队论：队列长度到延迟|准入控制与排队论]]给 [[044 调度器设计：waiting、running 队列与抢占|调度器]]装上"过载保护"的理论刻度。核心事实来自排队论:当系统**利用率 ρ = 到达率/服务率**逼近 1,排队延迟会**非线性爆炸**(趋于无穷)。**Little's Law** $L=\lambda W$ 把队列长度、到达率、停留时间三者锁死;M/M/1 模型给出 $W=1/(\mu-\lambda)$ 的直觉——别让 ρ 越过拐点(约 0.7–0.8)。**准入控制(admission control)** 就是据此在过载时**主动拒绝/限流**(返回 429),宁可早拒少数,也别让 ρ→1 拖垮全体 [[018 TTFT、TPOT、ITL 与 goodput：服务指标定义|SLO]]。这是 [[017 吞吐与延迟：根本性张力|吞吐延迟张力]]在系统层的兜底。

## 直觉

把推理服务想成**一条结账队伍**。收银员(GPU)每分钟能结 $\mu$ 个人,顾客每分钟来 $\lambda$ 个。

- $\lambda$ 远小于 $\mu$(ρ 小):队伍几乎不排,来了就结,等待 ≈ 0。
- $\lambda$ 接近 $\mu$(ρ→1):收银员满负荷,**任何到达波动都来不及消化**,队伍越排越长,等待时间**急剧膨胀**——不是线性变慢,是指数式爆炸。
- $\lambda > \mu$(ρ>1):队伍**无限增长**,系统永远追不上,所有人延迟趋于无穷,系统"雪崩"。

关键反直觉:在 ρ=0.95 时,等待时间已经是 ρ=0.5 时的**十几倍**——利用率拉到极限榨吞吐,延迟代价是非线性的。所以 **admission control 的活,就是把 ρ 钳在拐点之前**:过载时拒掉一部分新请求,保住已接纳请求的 SLO,而不是来者不拒最后全体崩盘。

**生活类比**:把服务想成一家餐厅,收银员(GPU)每分钟能结 μ=100 人,客人按 λ 速率进店。客人少时(λ=50,ρ=0.5)座位大半空、来了就坐,平均停留 W=1/(100−50)=20ms;快满座时(λ=80,ρ=0.8)开始排队但还能忍,W=50ms;逼近满座时(λ=95,ρ=0.95)任何小波动都消化不了,W=1/(100−95)=200ms——比 ρ=0.5 时**贵了 10 倍多**,这就是「越等越久」的非线性爆炸。Little's Law 把这串数字锁死:店里同时有多少人 = 进店速率 × 平均停留,ρ=0.95 时 L=95×0.2=19 人挤在店里(每人都占 KV 显存!),ρ=0.5 时只有 1 人。准入控制就是当店满到拐点(ρ≈0.7–0.85),**在门口主动拦客**——预估排队超 SLO 就直接拒(返回 429),把 ρ 钳在 ~0.9,牺牲少数门外客,保住店里所有人的体验;若来者不拒,λ&gt;μ 时队伍无限增长,**全体**延迟趋于无穷,餐厅雪崩。

## 例子

服务率 μ = 100 req/s(单实例 goodput 上限)。

| 到达率 λ | 利用率 ρ | M/M/1 平均响应 W=1/(μ−λ) | 体验 |
|---|---|---|---|
| 50 | 0.50 | 1/50 = 20 ms | 队列短,延迟低 |
| 80 | 0.80 | 1/20 = 50 ms | 拐点附近,可接受 |
| 90 | 0.90 | 1/10 = 100 ms | 延迟翻倍,开始危险 |
| 95 | 0.95 | 1/5 = 200 ms | 排队主导端到端延迟 |
| 99 | 0.99 | 1/1 = 1000 ms | 几近雪崩 |
| 100+ | ≥1 | → ∞ | 队列无限增长,崩 |

- 从 ρ=0.8 到 0.95,λ 只涨 18%(80→95),W 却涨 **4×**(50→200 ms)——这就是非线性。
- **Little's Law 验证**:ρ=0.95 时 $L=\lambda W = 95 \times 0.2 = 19$ 个请求同时在系统里;ρ=0.5 时 $L=50\times0.02=1$ 个。负载稍增,在途请求数(占 KV 显存!)暴涨,反过来加剧抢占。
- **准入控制**:设阈值"预估排队延迟 > 150 ms 即拒新请求"。则 ρ 被钳在 ~0.9 附近,已接纳请求 SLO 保住,溢出流量收到 429 去重试/降级,而非全体陪葬。

## 原理

**Little's Law**(对任何稳态系统都成立,与分布无关):

$$
L = \lambda\, W
$$

$L$ = 系统内平均请求数,$\lambda$ = 平均到达率,$W$ = 平均停留时间(排队 + 服务)。

**M/M/1**(泊松到达、指数服务、单服务器)给出停留时间的闭式:

$$
W = \frac{1}{\mu - \lambda} = \frac{1}{\mu(1-\rho)},\qquad \rho = \frac{\lambda}{\mu}
$$

$\rho\to 1$ 时 $W\to\infty$——这就是延迟爆炸的来源。排队延迟(扣掉服务时间 $1/\mu$):

$$
W_q = W - \frac{1}{\mu} = \frac{\rho}{\mu(1-\rho)}
$$

**排队延迟占比** $W_q/W=\rho$:ρ=0.9 时,端到端延迟里 **90% 是排队**(而非真正的 prefill+decode 计算)——过载时排队主导 TTFT。

**准入控制策略**(Naor 经典结论:静态阈值最优):

$$
\text{若 } \hat L > L_\text{thresh}\ \text{或}\ \hat W_q > W_\text{thresh}:\ \text{拒绝新请求(429)}
$$

把 ρ 钳在拐点(经验 0.7–0.85)之前,在吞吐(利用率)与延迟(SLO)间取最优。注意真实 LLM 服务非严格 M/M/1(服务时间随输出长度重尾、连续批让多请求并行),但"ρ→1 延迟爆炸、需准入控制"的定性结论普适。

## 代码

基于排队预估的准入控制:

```python
def estimate_queue_delay(queue_len, service_rate):
    # 粗估:队列里每个请求平均要等前面的服务完
    # 用 Little's Law / M/M/1 直觉:等待 ≈ 队长 / 服务率
    return queue_len / service_rate            # 秒

def admit(req, waiting_queue, service_rate, slo_queue_delay):
    est = estimate_queue_delay(len(waiting_queue), service_rate)
    if est > slo_queue_delay:
        # ✅ 过载保护:预估排队延迟超 SLO → 早拒,保住已接纳请求
        raise Overloaded(429, retry_after=est)
    waiting_queue.append(req)                   # 未过载才接纳

# ❌ 反模式:来者不拒,无准入控制
def admit_naive(req, waiting_queue):
    waiting_queue.append(req)
    # λ>μ 时队列无限增长 → ρ→1 → 全体 W 爆炸
    # 所有请求(含本能达标的)一起破 SLO,goodput 反而归零(雪崩)
```

`❌` 无准入控制在过载时让队列无限膨胀,ρ→1 使**全体**请求延迟爆炸、goodput 归零(雪崩);`✅` 准入控制在拐点前主动拒绝溢出流量,牺牲少数换全局 SLO 稳定。生产中常配**负载脱落(load shedding)、降级、自动扩容**联动,而非裸 429。

## 面试高频

- **Q:Little's Law 是什么,为什么有用?** $L=\lambda W$,系统内平均请求数 = 到达率 × 平均停留时间;对任何稳态系统成立,可在不知分布细节下把队长、吞吐、延迟三者互推。
- **Q:为什么利用率不能拉到接近 100%?** ρ→1 时排队延迟 $W=1/(\mu-\lambda)$ 非线性爆炸;ρ=0.95 时延迟已是 ρ=0.5 的十几倍,且排队占端到端延迟 ρ 比例(90%+),SLO 必破。
- **Q:准入控制做什么,为什么要主动拒绝?** 过载时按队长/预估排队延迟拒绝溢出流量(429),把 ρ 钳在拐点前;不拒则队列无限增长、全体延迟爆炸、goodput 归零,牺牲少数保全局。
- **Q:LLM 服务和标准 M/M/1 有何不同?** 服务时间随输出长度重尾(非指数)、连续批让多请求并行(非单服务器)、KV 显存是额外硬约束;但"ρ→1 延迟爆炸、需准入控制"的定性结论仍成立。
- **Q:排队延迟和计算延迟怎么区分?** 端到端 TTFT = 排队等待 + prefill 计算;过载时排队占比 ρ 主导(ρ=0.9 时 90% 是排队),此时加卡/扩容比优化 kernel 更有效。

## 关键事实

- **Little's Law** $L=\lambda W$ 是排队论基石(Little 1961,与到达/服务分布无关),用于推断在途请求数、吞吐与延迟关系;在途请求数 $L$ 直接对应 KV 显存占用。
- **M/M/1** 给出 $W=1/(\mu-\lambda)$:利用率 ρ→1 时延迟趋于无穷,经验拐点在 **ρ≈0.7–0.85**,生产系统据此设准入阈值。
- **准入控制 / 过载保护**(429、load shedding、降级)是生产 LLM 服务的标配(截至 2025);Naor 经典结论表明已知参数下**静态阈值准入**最优,实际系统在其上叠加自动扩容与优先级分级。
