[[086 量化叠加投机解码、PD 分离的坑|量化叠加投机解码、PD 分离的坑]]讲量化和其他系统优化**组合**时容易翻车的地方。量化([[080 服务量化总览：W、A、KV 三处|三处量化]])单独用很稳,但和 [[073 投机解码系统：draft-verify 全流程|投机解码]]、[[048 为何分离 prefill 与 decode|PD 分离]]叠加时,会冒出**接受率下降、跨实例 KV 格式错位、误差累积**三类坑。面试时这类"组合题"最能区分是否真在生产里调过参。

## 直觉

每个优化单看都是赚的,叠起来可能**互相拆台**。三个典型:① **投机解码**靠草稿模型猜、目标模型验,**接受率**是命门——草稿量化太狠,它的输出分布偏离目标,**接受率掉**,省下的草稿算力被"猜不中、白验"吃回去,净收益可能为负。② **PD 分离**把 KV 从 prefill 实例传给 decode 实例([[053 KV 传输：NIXL、点对点与带宽|NIXL 传输]]);如果 KV 是量化的,**两端的 KV 格式和 scale 必须一致**,否则 decode 端按错误的 scale 反量化,数值直接崩。③ **误差累积**:W4 + A8 + FP8 KV 三处误差,沿着自回归**逐 token 叠加**,长生成时被放大,掉点**不是单处之和**那么简单。一句话:量化的全家桶要**端到端评测**,不能只测单处就上线。

## 例子

- **投机解码接受率**:草稿用激进 W4A4 → 接受率从 ~80% 掉到 ~60%,有效加速被抵消;改用与目标对齐的 W4A16 草稿(2025 研究 ML-SpecQD/QuantSpec),接受率仍 >90%、端到端 ~2.5× 加速。结论:**草稿宁可量得保守一点**,保接受率。
- **PD 分离 KV**:Prefill 实例产出 FP8 E4M3 KV,传给 Decode;若 decode 实例配置成 FP8 E5M2 或 scale 没随 KV 一起传 → 反量化错位、输出乱码。必须**P/D 两端 KV dtype + scale 严格一致**。
- **累积掉点**:单测 FP8 KV 掉 0.2%、单测 W4A16 掉 0.4%,叠加后**长上下文**可能掉 1.5%(非 0.6%);短任务看不出来,长任务暴露。

## 原理

**投机解码的净收益**(出自 [[073 投机解码系统：draft-verify 全流程|投机解码]]):

$$
\text{加速} \approx \frac{\text{每轮接受 token 数}}{1 + \text{草稿开销/目标开销}},\qquad \text{接受率} \downarrow \Rightarrow \text{加速} \downarrow
$$

量化草稿降低了"草稿开销",但若**拉低接受率**,分子也跟着掉——存在最优量化强度,过犹不及。**PD 分离的约束**:KV 是带 scale 的量化张量 $(K_q, s_K)$,跨实例传输必须把 $s_K$ 一并传、且两端反量化逻辑一致,否则 $\hat K = K_q\cdot s_K$ 在 decode 端算错。**误差累积**:自回归每步输出喂回输入,量化误差 $\epsilon_t$ 沿序列传播,$\epsilon_{t}$ 依赖 $\epsilon_{<t}$,不是独立相加——这就是长生成放大效应的来源。工程纪律:叠加任何两项,都要**用长上下文 + 长生成的端到端 benchmark** 重新评测,逐项加码(先单项达标,再两两叠加,最后全开)。

## 面试高频

- **Q:量化草稿模型有什么坑?** 量太狠会拉低投机解码**接受率**,省下的算力被"猜不中"抵消,可能净负;草稿宜保守、与目标对齐。
- **Q:PD 分离下 KV 量化要注意什么?** Prefill 产出的量化 KV 跨实例传给 Decode,**dtype 和 scale 必须两端一致**且 scale 随传,否则反量化错位崩掉。
- **Q:多处量化叠加,掉点能直接相加估计吗?** 不能。自回归下误差**逐 token 累积**,长生成被放大,必须端到端评测整条叠加链。
- **Q:叠加优化的上线纪律?** 单项达标 → 两两叠加评测 → 全开;全程用长上下文/长生成 benchmark,而非短样本。

## 关键事实

- 2025 研究(ML-SpecQD、QuantSpec):4-bit 量化草稿/4-bit 量化 KV 可保持 **>90% 接受率、~2.5× 端到端加速**——前提是草稿与目标**对齐**,不是越省越好。
- PD 分离(DistServe/Mooncake/Dynamo)传输量化 KV 时,**KV dtype + scale 必须跨实例一致**,这是常见的静默故障点。
- 误差累积在**长上下文/长生成**才暴露;短任务 benchmark 会低估叠加掉点 → 评测必须覆盖长序列。
- 组合优化纪律:量化、投机、PD 分离正交但非免费,**逐项加码 + 端到端评测**是唯一稳妥路径。
